# 新项目工作方式建议

基于 `00-诊断报告.md` 里的三个具体病因，给出对应的、可以直接落地成规则的做法。不是泛泛的"要小步快跑"，是针对你们实际踩过的坑逐条对应。

## 病因一：任务一次性批量生成，中间无人工检查点 → 对策：把"人工确认"做成硬性阻塞点

上次是 66 个 ticket + 46 份 ADR 一次性生成，agent 连续跑了近两周。这次建议：

- **每次生成任务不超过 5~8 个**，跑完这一批，人工过一遍再决定下一批要不要生成、生成什么。不追求一次规划到底。
- 每个任务的验收标准里，**必须包含"人工可验证的产出"**，例如一段可运行的截图、一次真实调用目标平台接口的日志、一份能让你亲眼看到差异的对比——而不是只让 agent 自己跑完 checklist 打勾。你们这次 66 个任务里，Element Plus 相关的六轮"completed"最后被证明不可靠，就是因为验收标准只是"任务描述里的勾都打上了"，不是"有人真的看过效果"。
- 用 walking skeleton 思路：先打通一条最小可运行链路（比如"新发起一个最简单的两节点流程，跑完，看到真实结果"），验证过后再逐步加宽覆盖面，而不是先把 90 个任务的范围都定义好再开始跑。

## 病因二：UI 被推倒重来三次，从没让人在动手前确认过方向 → 对策：界面先出静态稿，冻结后再写代码

你们这次是 Naive UI → 手写 Element Plus（六轮"最终收口"）→ Vben Admin 官方脚手架，没有一次是先出个静态原型给人看过再动工的。这次建议：

- **技术选型先定，定完不再换**——尤其是 UI 框架/组件库这种一换就要重写几十个页面的决定，写进 PRD 或架构决策记录里，动之前需要人工签字确认，不能让 agent 在执行过程中自己决定"这次真的要换了"。
- 每个新页面先出静态原型（哪怕是 HTML/Figma/低保真截图都行），你看过、确认过交互和布局之后，再让 agent 写实际代码。这一步现在完全没做，是"界面很垃圾"的直接原因。
- 页面级别的验收，**必须有你本人在浏览器里点一遍**，不能只信"类型检查通过 + 单元测试通过 + 构建成功"。你们 PRD 里其实自己也写了这条（"页面视觉和真实目标交互由用户手工验证，不由任务自动启动浏览器"）——但上次显然没有被真正执行到位，六轮返工就是证据。

## 病因三：规格在执行过程中变了，但已产出内容没有同步核对 → 对策：单一权威文档 + 变更后强制重新核对已完成部分

- 新项目**只维护一份 CONTEXT/PRD 文档**，放在项目根目录，谁都不能在别的地方另起一份"更简化的版本"绕过它（这正是 `v2/CONTEXT.md` 当初发生的事）。
- 如果执行过程中发现 PRD 需要修改，**修改后要有一个明确步骤去核对"哪些已完成的任务受这次修改影响"**，而不是让新旧规则的产物在代码库里共存。可以简单到一句话："这次改了 X 规则，受影响的任务是 A、B、C，需要重新跑一遍验收"。
- 每份任务/ticket 文件在开始时都应该引用 PRD 的版本或修改时间，一旦 PRD 更新，能一眼看出哪些任务是对着旧版本写的，需要重新审视。

## 一些更具体的落地建议

1. **先把 `参考代码/`（目标平台源码）稳定接入新项目**，作为只读依赖或子模块，明确"这是业务规则的唯一来源"，避免重演"业务逻辑该信谁"的混乱。
2. **新项目起步时先做一次小范围的 spike**：挑一个最简单的真实流程（比如两三个节点、没有并行分支），端到端跑通"选择流程→配置路径→运行→看到真实结果"，用这个小闭环验证技术选型（后端框架、前端框架、和目标平台的对接方式）都可行，再铺开范围。这比一上来就按 PRD 全量拆解任务安全得多。
3. **给 agent 的每一批任务加一条"停下来"的规则**：完成后必须停下来等待人工确认，不能自动衔接下一批。这在很多 agent 工作流里就是把任务文件按"批次"拆开，一批一批地手动触发，而不是一次性把整份 ticket 列表都交出去。
4. **保留这次的复盘材料**（`00-诊断报告.md` + 原来的 `问题收集/`），新项目启动会上过一遍，让所有参与的人（包括后续可能加入的 agent session）都知道"这几个坑已经踩过了，不要再踩"。

## 关于要不要继续用类似 "Matt 的技能" 这类 PRD/任务生成工具

工具本身没有问题，问题出在"生成完之后怎么执行"。批量生成 PRD 和任务清单是可以的，但**执行阶段一定要分批次、留检查点**，不能让 agent 拿到任务清单后连续跑几天不间断。如果这次继续用同一套技能库，建议明确要求它：一次只生成/执行一小段任务，每段结束主动汇报进度并等待确认，而不是把"生成"和"无监督连续执行"当成一件事。
