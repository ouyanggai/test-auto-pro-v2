# 诊断报告：v2 为什么跑偏了

本报告基于对 `test-auto-pro` 仓库完整 git 历史（2868 次提交，2026-05-11 至 2026-07-22）的分析，不是推测，是从提交记录、任务文件和状态标记里直接读出来的事实。目的不是追责，是让下一次重构避开同样的坑。

## 1. 节奏：v1 是人的节奏，v2 是"批量生成后无监督狂跑"

| 阶段 | 时间 | 提交量 | 日均 |
|---|---|---|---|
| v1 开发期 | 05-11 ~ 07-08（约2个月） | ~470 次 | 5~25 次/天，符合人工review节奏 |
| v2 重构期 | 07-10 ~ 07-21（12天） | ~2390 次 | 峰值 386 次/天（07-14） |

v2 阶段的提交量占了整个项目历史的 83%，却只用了不到 2 周时间。这不是"重构进度快"，是**大量任务被一次性丢给 agent 连续执行，中间几乎没有人工检查点**——这和你说的"跑了几天"完全对得上。

## 2. 前端框架被推倒重来了三次，一次都没让人看过就又换了

1. **v1**：`frontend/` 用 Vue3 + **Naive UI** + Pinia，这是唯一经过真实使用验证的界面。
2. **v2 第一次**：在 `v2/` 目录下另起炉灶，改用 **Element Plus**。围绕它产生了 `44A`、`46A`、`48A`、`50A`、`56A`、`66` 六个任务，标题分别是"全量切换 Element Plus 页面与布局"→"收口全部页面元素与布局"→"全部页面元素与布局统一"→"每个页面元素与布局"→"最终收口全部页面元素与布局"→**"真实完成 Element Plus 全页面与布局切换"**。
   六轮，一轮比一轮"更彻底"，最后一轮的标题里还特意加了"真实"二字——这基本可以确认前五轮的"completed"标记并不可靠，是 agent 自己给自己打的勾，不是真正验收过的结果。
3. **v2 第二次**：`v2/web` 目录整个是从 `vue-vben-admin` 官方脚手架克隆下来的 monorepo（`turbo.json`、`apps/web-ele`、`packages/@core` 等都是该框架的标准结构），在里面的 `apps/web-ele/src/workbench/` 又重新实现了一遍 `WorkbenchShell.vue` 等页面。而且这个方向是最新的（根目录 `CONTEXT.md` 最后一次修改于 07-21，明确写下"V2 以 Vue Vben Admin 5 为应用基座"）——也就是说，**前面六轮 Element Plus 切换的产出，连最新规格自己都已经不认了**。

三套前端、六轮"最终收口"，没有一次是先出静态原型给你确认过再往下走的。"界面很垃圾"几乎是必然结果，不是运气问题。

## 3. 任务被拆分了三波，一波比一波大，但验收标准没有跟着变严

- **第一波**：`task/00-*` ~ `task/08-*`，共 40 个任务文件，产出了 v1。
- **第二波**：`task/v2/tickets.md` 里的 T01~T20，是第一次"替换式重构"尝试，卡在 T20 没走完就被放弃了。
- **第三波**：`v2/docs/tickets/` 下 66 个 ticket 文件 + `v2/docs/adr/` 下 46 份架构决策记录（ADR），几乎全部标记为 `completed`。

三波任务量依次放大，但"completed"的判定标准始终是 agent 自己跑完 checklist 就打勾，没有一个强制的"人工看一眼再继续"环节。90+ 个任务、46 份 ADR 在没有人工中途验收的情况下批量产出，个别环节走偏后不会被及时发现，只会被后面的任务继续叠加。

## 4. 规格本身在执行过程中还在剧烈变动

`v2/CONTEXT.md`（07-10 创建，07-18 定稿，47 行，术语较简单）和根目录 `CONTEXT.md`（07-17 开始写，07-21 最后修改，293 行，术语详尽得多）**几乎是同一时间窗口并行存在的两份"权威文档"**。后者内容更完整、更晚，说明团队在 v2 重构进行到一半时已经意识到 `v2/` 目录下第一版规格不够用，转头回到根目录重写了一份更严谨的版本——但这时 `v2/` 下已经按第一版规格生成了几十个 ADR、上百个提交。这就是你现在看到"v1 和 v2 融合在一起、很难推进"的根本原因：**不是文件物理上没分开，是没有一份文档在整个过程中始终保持权威、始终被所有任务对齐**。

## 5. 核心结论

失败不是某个任务写得不好，是工作方式本身缺了三样东西：
1. **小批量**：一次性生成几十上百个任务，等于把所有风险都压到最后才暴露。
2. **人工检查点**：agent 自报的"completed"不是验收标准，没人中途看过实际效果。
3. **规格的单一权威来源**：规格在执行过程中变了，但已经产出的内容没有被同步核对，导致新旧规格的产物混在一起。

下一次重构，这三点必须在流程上强制保证，而不是靠"这次注意一点"。具体建议见 `03-新项目工作方式建议.md`。
