# 仅依据目标源码的性能、可靠性与切换计划

- 日期：2026-10-13。
- 依据：本次独立阅读的目标前端、FormMaking、网关、用户服务和流程服务源码；不采用此前任何项目、架构、功能或历史文档作为业务依据，也不沿用前一份计划的规则。
- 本轮交付：源码结论、优化机会、功能不变量、分阶段切换与验证条件。首个可审批切片见本次新建的 `docs/features/F-045-target-source-execution-baseline.md`。
- 当前状态：仅规划。没有修改执行器、目标源码、配置或数据库；没有启动浏览器或调用真实目标接口。

## 1. 独立结论

可靠性与效率的平衡应按**依赖、身份上下文和副作用边界**决定，而不能统一采用“全部串行”“等固定时间”“看到 HTTP 成功就结束”或“所有失败都可以重试”。

从目标源码能直接推出的优先方向：

1. 同一稳定身份/平台/项目上下文内，把互不依赖、已确认业务只读的请求有界并行；完全相同读取在同一短读取轮次内去重。
2. 利用原生数据/业务阶段的实际完成事实，减少反复深复制整张表单及机械等待；所有异步依赖未收口前不提交。
3. 同一实例只安排一个动作所有者，完整执行原生写链；不同实例的吞吐优化同时审查共享身份和关联业务资源。
4. 把展示读取与可提交组件隔离，减少不必要的全文/人员读取，但保留最新批次、真实处理人、会签人数、代理树和节点权限的事实意义。
5. 页面/资源复用放在最后，先证明事件总线、存储、身份、监听器和迟到异步回调不会串实例。

源码不能给出现有工具每个热点的真实耗时，也不能证明运行环境与参考快照完全相同。本计划不承诺提速倍数；先建立版本一致的动作与耗时基线，再逐项切换。

## 6. 不破坏功能的对照标准

每个候选上线前建立一份**源码驱动原生动作清单**，按动作、表单族、身份上下文和实例状态列出：

- 原生校验、确认、模板选择、当前任务/批次/节点/权限、表单取值与衍生规则。
- 代理准备/权限探测、业务前置写、主写、分支/人员选择、附言/绑定等后置写和允许的错误分支。
- 结果证据、已发生副作用、需要重读的事实域、失败/悬挂/不确定时应禁止的动作。

比较不只看最终状态或 HTTP 200。必须比较原生请求集合与因果顺序、用户/实例/任务/批次/节点/代理归属、字段和伴生键、必要业务保存/绑定/附言、最新审核记录及实际处理人。时间/新 UUID 等差异只通过预先列出的确定性对应关系比较，不能放宽到任意字段。

仅动态脚本的实际输入才能决定它的全部请求，源码不能提前承诺穷尽。动态脚本/未知组件不采用未证明的裁剪，走完整原生依赖；不恢复旧工具规则或发明替代业务链。目标特殊全权限账号不能作为普通用户权限正确性的唯一证据。

性能基准应至少分：无人观察/持续观察、首次装载/已装载、同上下文/切换、同实例顺序/独立实例、正常目标/延迟/中断。记录 P50/P95/最大值、真实物理请求、正文完成、脚本及后置回调、队列、资源数、累计分配和峰值；耗时重叠按覆盖关系呈现，不对并发请求总和或包含网络的页面墙钟重复相减。

|---|---|---|---|
| P0：源码一致性与基线 | 冻结参考/部署版本；原生链清单；非侵入分段计时；对照夹具 | 不删请求、不缩等待、不改并发/重试/结果 | 原生业务请求数/顺序/载荷与基线一致，采集没有新增副作用，用户验收 |
| P1：读取等价与上下文 | 同轮去重、精确过滤/批次、稳定上下文有界并行 | 不换权限链、不缓存跨写当前事实、不自动刷新互踢 SID | 缓存/身份/分页/缺失/上下文切换矩阵全部通过，收益实测 |
| P2：表单和业务完成屏障 | 事件驱动回读、最后 setter 收敛、完整回调收口 | 保留原生校验/动态脚本/后置业务/错误分支 | 延迟/乱序/四类选择/悬挂/虚拟值/自定义表单逐族通过 |
| P3：动作和调度效率 | 实例动作单所有者、独立资源有界调度、等待可取消 | 不取消已发写、不重发未知写、不压缩完整业务链 | 双放行、跨实例事件、共享业务、在途失败和迟到回调不重复写、不误放行 |
| P4：观察及资源 | 明细按需读，有界资源生命周期，具证明的复用 | 不把观察缓存当门禁、不用静态配置替代真实处理人 | 全部节点/批次/会签信息完整，长跑无泄漏，真实身份隔离通过 |

当前只规划首切片 P0；P1～P4是用户要求的整体切换顺序与准入条件，不是实施授权或批量功能任务。每次只批准一个可独立验收的变更，完成后停人工验收；阶段内部也按动作/表单族缩到可验证范围。

### 7.1 P0 具体步骤

1. 记录本文源码 HEAD；核对目标部署/API/前端组件/实际 FormMaking 构建来源，无法对应时先补该差异，不拿本地 HEAD 冒充部署版本。
2. 从源码建立动作分类：首先覆盖普通 FormMaking 发起/同意与转发完整链，接口采集可通用于其他动作但不能宣称其语义验收完成。
3. 在现有调用点只观察原有调用，记录输入身份/实例/批次归属、时间、完整响应或错误、业务回调开始/结束；不为观测额外调用 getData、setData、权限探测、登录、表单脚本或目标请求。
4. 捕获 transport、Vue 初始化、setter/watcher、脚本、业务链、实例/任务读写的覆盖关系。观察超时只标未收口，不通过观测逻辑取消动作或修改其终局。
5. 用源码提取纯函数/原生调用协议假件验证行为不变，再由用户从页面执行受控流程建立真实基线；不双跑同一实例，不自动发送真实写。
6. 给每项候选填写真实重复量、耗时与正确性差异，再选择 P1 或 P2 中一个最小切片。没有测量不按收益排序或承诺倍数。

基线观察本身也要测开销：以相同假件输入比较采集前后的墙钟、分配和尾延迟，记录成本及对截止时间的影响。采集不得引入额外等待、替换Promise或改变业务调度；出现功能变化或明显退化时先减轻采集，不拿它作为可信基准。

### 7.2 后续每次切换操作

1. 审批冻结：列出此次动作族/表单族、被减少的依赖、保留的屏障和目标源码证据，明确哪些动态配置尚未证明。
2. 本地候选：单一实现，替换时删除被取代逻辑和测试；不建立新旧两套自动执行回退，不双发真实写。
3. 离线对照：先通过功能和副作用矩阵，后测性能；已知源码的错误/悬挂不能当作新实现可凭空成功的依据。
4. 原子交付：接口/执行协议若变化，相关前后端/服务同一可运行版本切换；保留可恢复的前一个完整产物，数据库或事实口径变化另行规划。
5. 发布前静止：停止新启动和新放行，等所有已发业务写、必要后置回调、目标 HTTP 转发、WS pending/工作队列、落账完成；检查实际页面/Context 和资源归零。逻辑会话表空、暂停或页面关闭均不单独证明排空。
6. 整体切换：只运行一个候选版本；需要时刷新旧页面。先只读检查版本/身份/健康，再由用户按场景手工执行真实流程，记录完整证据。
7. 人工门禁：确认功能完整且性能改善后才能考虑下一变更。发生重复写、错身份、丢字段、错批次/节点、附言或绑定缺失、错误放行、资源不收口或显著尾延迟退化，立即停止扩展并返工。

### 7.3 退出与恢复

退出仅在确认在途业务收口的静止状态更换为前一个完整产物；不回写历史运行，不逆向恢复目标数据，不借换版本重新发送可能已发生的写。

对于主写成功而附言/绑定失败，保留分段副作用与失败事实，不以重新执行整个动作补救。恢复操作是否能单独补一个后置动作，必须从该目标端点和当前事实另行证明、获得明确授权；本计划不给默认补写权限。

如果当前系统不能证明实际在途调用已结束，先补只读诊断或等待人工核实；不能用“超时已过”“会话数是 0”替代排空证据。

## 8. 验证矩阵

| 类别 | 至少覆盖 | 通过条件 |
|---|---|---|
| 身份上下文 | 同 loginType/user/platform 重登、不同 platform、不同 project/customer、401、视角用户 | 无旧 SID 覆盖新代次；不跨上下文缓存/并发错误；无偷偷扩大权限 |
| 查询 | exact LinkID 与 jobTaskId不同、pending/done会签、ids多页/缺项、目录主岗位范围 | 仍走原权限链，完整分页，缺项/失败不变成允许操作 |
| 表单 | 1000/200 ms初始化、下一tick多级联动、延迟/乱序选项、未settle脚本、虚拟值、大数字 | 原生校验和最终请求一致，未知/未收敛不提交，不用历史JSON否定合法衍生 |
| 原生业务链 | first预检复制代理、前置保存、主写、四类选择、绑定、转发空附言 | 所有合法子链与顺序完整；方法/URL同但语义不同能分开 |
| 失败副作用 | 前置成功主写失败、主写响应丢失、主写成功后置失败、后置悬挂 | 不自动重发整个动作；保留已发生/未知事实，不能伪装零副作用 |
| 并发隔离 | 同实例双放行、不同实例同SID上下文、跨项目、共享业务对象、全局bus迟到事件 | 无错实例/错角色/错链，容量有界，不能绕目标实例锁争抢来提速 |
| 显示 | 最新批次、会签人数、真实处理人、并行活动节点、代理重建、跳过后继证据 | 展示和可操作事实各自正确，旧图/配置人员不能放行 |
| 资源与切换 | 初始化失败、长跑、关闭时在途请求/回调、旧页面、进程退出 | 可证明无遗留实际调用；产物完整切换；无恢复后重写 |

比较的用户操作区间固定：首屏从进入页到信息可用，第一次展开从点击到完整明细可用，动作从准备到必要后置业务和事实确认收口。按需读取的第一次展开不能拿旧预装模式的零网络点击时间单独对比，也不能把工作转移到后台就算提速。

## 9. 尚未证明与当前交付边界

尚未证明：源码与部署完全一致、运行配置 TTL/限流、所有动态脚本和具体表单配置、所有跨服务失败的副作用回滚、所有写端点幂等性、同上下文高并发的实际容量、业务回调最大可见时间、当前工具各段真实耗时。

因此不能从源码静态分析承诺“绝对零风险”。本计划将“不能破坏当前功能”落实为**不减依赖直到等价证明、失败副作用完整、功能矩阵先通过、静止切换、每步用户验收**，并把未知显式保留，而不是用旧文档或猜测填空。
