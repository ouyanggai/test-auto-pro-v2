# 执行引擎改造文档

本目录只记录“由无头浏览器加载真实 form-runtime，再由 Go 编排和转发请求”的执行引擎改造。无头浏览器只运行 Vue、FormMaking 和目标自定义组件，不做坐标点击、DOM 查找、按钮文字匹配、键盘模拟或鼠标模拟。

## 文档顺序

1. `01-执行引擎设计.md`：架构、边界、消息格式、状态和安全规则。
2. `02-执行任务清单.md`：按依赖顺序实施，每项任务完成后单独验证和中文提交。

## 当前结论

- Go 仍是流程编排、账号/SID、并发、日志、写后核验和最终结果裁决的唯一负责人。
- form-runtime 通过 Playwright + Chromium 无头实例加载真实 Vue 组件，不使用 jsdom/happy-dom。
- runtime 通过注入的桥接方法调用 Vue 组件业务方法；路由只负责装载页面，不负责驱动业务。
- runtime 的所有目标请求都被 Playwright 网络拦截转给 Go 的 `TargetClient`，不能由浏览器直接访问目标平台。
- 先做独立执行服务和一个真实表单闭环，再接入现有 Go 七阶段执行器；不得一开始替换全部动作。
- 写请求响应丢失、发送状态不明或业务完成事件不完整，都进入现有“结果待确认”规则，禁止整段重放。

## 本目录不做的事

- 不修改目标平台源码、权限、数据库或基础设施。
- 不重新实现一套 FormMaking。
- 不把所有业务 JSON 脚本翻译成 Go。
- 不用 RPA 选择器、坐标、截图识别或按钮点击。
- 不在没有真实请求和目标结果证据时声明支持某个表单或动作。
