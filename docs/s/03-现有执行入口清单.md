# 现有执行入口清单（T001）

本清单只记录改造前（分支 `执行引擎改造` 起点）每个动作的既有执行入口、form-runtime 既有命令与请求拦截能力，作为后续任务「每个动作只有一个执行入口」的对照基线。所有文件与符号均可由 `rg` 复核。

## 1. Go 侧动作写入口现状

### 1.1 唯一目标写出口

所有目标写请求最终经过 `internal/adapter/target.Client.CallWrite`（`internal/adapter/target/client.go`）。
写前协议校验为 `ValidateFinalWriteBody`（`internal/adapter/target/protocol_matrix.go`），
写后响应经 `internal/engine/verdict` 判定。改造不得新增第二个目标 HTTP 客户端。

### 1.2 执行器分派点

`internal/engine/step/executor.go` 的 `refreshAndSubmit` 按载荷类型三分派：

| 载荷类型 | 调用的适配层方法 | 覆盖动作 |
| --- | --- | --- |
| `*target.SubmitFlowInstanceRequest` | `Client.SubmitFlowInstance`（`internal/adapter/target/write.go`） | `submit`、`save_draft`（`data.status=draft` 区分） |
| `*target.AuditCurrentTaskRequest` | `Client.AuditCurrentTask`（`internal/adapter/target/write.go`） | `approve`（`auditStatus=pass`） |
| `*target.ActionWriteRequest` | `Client.ExecuteActionWrite`（`internal/adapter/target/write_actions.go`） | 其余全部动作（见 1.3） |

载荷构造与发送严格同源：`BuildSubmitBody`、`BuildAuditBody`（`write.go`）与
`BuildActionBody`（`write_actions.go`）。执行器侧构造在 `internal/engine/step/gate.go` 的
`buildRequestWithFacts`。

### 1.3 动作 → 端点 → 现执行方对照

动作键常量定义在 `internal/model/action_orchestration.go`（`ActionKey`）。

| 动作键 | 目标端点 | 现执行方（改造前） | 改造后执行位置 |
| --- | --- | --- | --- |
| `save_draft` | `/web/flowInstanceApi/submit`（`status=draft`） | Go `SubmitFlowInstance` | `runtime` |
| `submit` | `/web/flowInstanceApi/submit` | Go `SubmitFlowInstance` | `runtime` |
| `resubmit` | `/web/flowInstanceApi/reSubmit` | Go `ExecuteActionWrite` | `runtime` |
| `storage_form_data` | `/web/flowInstanceApi/storageFormData` | Go `ExecuteActionWrite` | `runtime` |
| `approve` | `/flowInstanceApi/audit`（`pass`） | Go `AuditCurrentTask` | `runtime` |
| `reject` | `/flowInstanceApi/audit`（`no_pass`） | Go `ExecuteActionWrite` | `runtime` |
| `forward` | `/web/flowInstanceApi/transpond`（+按需 `/web/flowInstancePostscript/save`） | Go `ExecuteActionWrite`（仅主请求；附言端点当前无实现） | `runtime`（复合动作） |
| `add_sign` | `/web/flowInstanceApi/updateFlowProxy` | Go `ExecuteActionWrite` | `go_target`（不变） |
| `transfer` | `/web/flowInstanceApi/approverAppend` | Go `ExecuteActionWrite` | `go_target`（不变） |
| `rollback_previous` | `/web/flowInstanceApi/rollBackThePreviousLevel` | Go `ExecuteActionWrite` | `go_target`（不变） |
| `retrieve` | `/web/flowInstanceApi/retrieveProcess` | Go `ExecuteActionWrite` | `go_target`（不变） |
| `withdraw` | `/web/flowInstanceApi/revocation` | Go `ExecuteActionWrite` | `go_target`（不变） |
| `urge` | `/web/urgeHandleRecord/sendUrgeMessage` | Go `ExecuteActionWrite` | `go_target`（不变） |
| `follow` / `unfollow` | `/web/flowInstanceApi/flowTracking`（`tracking` 布尔） | Go `ExecuteActionWrite` | `go_target`（不变） |
| `system_automatic` | 无用户写接口 | 执行器导航步骤只读（`RunApprovedStep` 的 `preview.Navigation` 分支） | `read_only`（不变） |

附注：

- `reject` 的载荷在 `BuildActionBody` 的 `case "reject"` 中构造，与 `approve` 共用端点
  `WriteEndpointAudit`，差别只在 `auditRecord.auditStatus`。
- `forward` 当前只有主请求 `/web/flowInstanceApi/transpond`；附言端点
  `/web/flowInstancePostscript/save` 尚无任何 Go 实现，改造中作为转发的第二个写请求
  （`writeSequence=2`）在 runtime 闭环内补齐。
- 特殊业务前置保存走 `Client.CallBusinessSave`（`internal/adapter/target/special_business_write.go`），
  不是流程主实例写端点，不改变上述归属。

### 1.4 禁止重复发送的流程端点（一次写纪律）

以下 12 个端点在单次动作尝试中至多发出一次（现有 `CallWrite` 无重试；会话失效重发仅在
目标确认未进入业务时发生一次）。runtime 接管 7 个动作后，同一动作的 Go 写方法不得再被调用：

```text
/web/flowInstanceApi/submit                 （save_draft / submit）
/web/flowInstanceApi/reSubmit               （resubmit）
/web/flowInstanceApi/storageFormData        （storage_form_data）
/flowInstanceApi/audit                      （approve / reject）
/web/flowInstanceApi/transpond              （forward 主请求）
/web/flowInstancePostscript/save            （forward 附言，writeSequence=2）
/web/flowInstanceApi/updateFlowProxy        （add_sign）
/web/flowInstanceApi/approverAppend         （transfer）
/web/flowInstanceApi/rollBackThePreviousLevel（rollback_previous）
/web/flowInstanceApi/retrieveProcess        （retrieve）
/web/flowInstanceApi/revocation             （withdraw）
/web/urgeHandleRecord/sendUrgeMessage       （urge）
/web/flowInstanceApi/flowTracking           （follow / unfollow）
```

`/web/flowInstanceApi/delete`（待发删除）不在动作目录，任何执行路径不得发送。

## 2. form-runtime 既有能力

### 2.1 `form-runtime/src/main.js`

- 完整加载 `@runtime`（`runtime-source`）入口，注册真实 FormMaking、自定义组件、Vuex 与原生路由。
- 追加隔离路由 `/test-auto-form`，子路由挂 `runtime-source/src/views/GroupApproveManage/Submitted/components/OtherSteps2.vue`。
- 阻断目标 axios 401 时的 `/login` 导航，保护工作区。

### 2.2 `form-runtime/src/runtime/protocol.js`

- `FORM_RUNTIME_VERSION = 'f007-form-runtime/v1'`。
- 既有命令：`load`、`setData`、`refresh`、`getValues`、`validateAndGetValues`、`restore`、`destroy`、`cancel`。
- 既有响应：`ready`、`state`、`result`、`error`。
- 校验函数 `isRuntimeCommand` / `isRuntimeResponse` 强制 `version`、`sessionId`、`requestId`。

### 2.3 `form-runtime/src/App.vue`

- 纯 iframe `postMessage` 模式（`parentOrigin` + `window.parent`），无执行模式命令处理。
- 会话代次保护（`sessionGeneration`/`operationGeneration`/`assertActiveSession`）。
- `load` 命令完成身份注入（`memoryAuth` + Vuex commit + storage facade）、模板准备、FormMaking `setData`、远程选项等待与选项补丁协调。
- `capture` 调 `captureFormValues(form, validate)`（内部走 FormMaking `getValues`，validate 时走 `getData`）。

### 2.4 `form-runtime/src/runtime/requestPolicy.js`

- `createTargetRequestTracker`：XHR/fetch 计数器，`waitForIdle()` 等待目标请求归零稳定（250ms 稳定窗）。
- `installReadOnlyRequestPolicy`：包装 `XMLHttpRequest.open/send` 与 `window.fetch`，按只读清单放行 GET/登记 POST，写请求与未知 POST 阻断（`shadow` 观察）。
- 注意：这是 iframe 模式的「只读防线」，不是请求转发；请求仍由浏览器直接发往目标网关（`setRuntimeEnvironment` 注入 `baseUrl`）。改造后执行模式下必须改为 `page.route()` 全量拦截转发给 Go，浏览器不得直连目标。

### 2.5 `form-runtime/runtime-source`（目标同步源码，保持原样）

- `GroupApproveManage/Submitted/components/`：`FlowDialog.vue`（发起提交/草稿入口、`submitFinal`、`handleSaveBranchChooseNode`、`handleSaveParallelChooseNode`、`getSelectPerson`、`flowErrorHandle`）、`OtherSteps2.vue`、`Steps2.vue`（分支列表生成）。
- `GroupApproveManage/components/`：`EnterpriseExamineOpinion.vue`（暂存/同意/不同意/重提/加签入口、`submitCheckBefore`、`formMakingFormBusiness`）、`flowTypeMixin.js`（转发入口）、`AddCounterSign.vue`、`FlowTranspondDialog.vue`、`Postscript.vue`。
- `Backlog/index.vue`（移交/回退）、`Finished/index.vue`（取回/关注）、`Submitted/index.vue`（撤回/催办）、`components/mixin.js`（关注/回退）。
- `DueOut/index.vue` 的待发删除（`/web/flowInstanceApi/delete`）不纳入自动化动作。

## 3. 执行入口唯一性结论

1. 改造前每个动作只有一个 Go 写入口（1.2/1.3 表），没有第二套载荷拼装。
2. 改造后归属变化只有 7 个表单动作转 runtime；8 个管理动作与系统节点保持现入口不变。
3. runtime 接管的动作在 runtime 已发出写请求后，`internal/engine/step.Executor` 不得再对同一动作调用 `TargetClient` 写方法（T012 的路由约束）；Go 直连动作也不得让 runtime 重放（T010A 的静态扫描约束）。
