# 审批页面全量动作对照

## 1. 使用范围

本表只根据 `form-runtime/runtime-source/src/views/GroupApproveManage` 及其直接引用的组件整理。页面名称、流程名称和按钮名称不进入工具配置；工具只保存动作键、节点、顺序、人员策略和动作参数。

每个动作执行前，Go 都必须重新读取目标实例和当前任务事实。下面的“成功后重读”是必须执行的读取，不是可选日志。

执行位置只有三种：

- `runtime`：Go 发送业务命令给无头 Chromium 中的真实 Vue/FormMaking 组件；页面产生的目标请求由 runtime 拦截并转给 Go。
- `go_target`：Go 直接调用现有 `internal/adapter/target` 唯一写出口；不启动表单组件。
- `read_only`：只读取目标事实和导航状态，不发用户写请求。

## 3. runtime 动作

### 3.1 保存草稿 `save_draft`

**输入**

- 主实例 ID；新建草稿时为空。
- 表单代理 ID、完整表单原始数据、实例业务关联列表、工具流程名称、发起人和公司。
- 当前动作参数中的草稿说明和附件变化。

**执行顺序**

1. runtime 创建发起表单组件并装载表单原始数据。
2. 调用真实表单 `getData(false)` 完成目标校验，不把校验返回值当作最终表单正文。
3. 调用真实表单 `getValues()` 取得包含虚拟字段、显示值和人员伴生字段的完整正文。
4. 调用 JSON 中的 `beforeSubmitAndDraft`。
5. 按页面逻辑处理附件新增、删除和业务关联。
6. 调用 `beforeSubmitAndDraftNoBiz`。
7. 向 `/web/flowInstanceApi/submit` 发送 `data.status=draft`，名称使用工具流程名称。
8. 目标成功后调用 `afterSaveFlowInstance` 和页面的附件后置处理。

**成功后重读**

- 主实例必须存在，状态为 `draft`。
- 主实例表单正文与 runtime 最终正文一致。
- 不得生成待办，不得改变当前节点。
- 业务保存接口、附件接口和业务关联接口的成功结果必须全部有记录。

**失败规则**

- 表单校验、前置业务、附件处理或流程写入明确失败：停止本步，标记失败，不发送后续写请求。
- 流程写请求已发出但响应丢失：不再次调用保存草稿，进入结果待确认并等待目标事实核对。
- 后置业务响应丢失：不重新保存草稿，按“主实例已写入、后置业务未确认”记录业务失败或待确认。

### 3.2 提交 `submit`

**输入**

- 新实例或草稿实例 ID、表单代理 ID、完整表单原始数据、业务关联、公司、手动分支入口和下一节点人员。

**执行顺序**

1. 创建发起表单组件，完成远程选项、人员字段和附件状态加载。
2. 执行目标表单校验并读取 `getValues()`。
3. 执行 `beforeSubmitAndDraft`，再执行 `beforeSubmitAndDraftNoBiz`。
4. 按目标页面补齐 `nextAuditorList`、手动分支入口、人员字段伴生键和附件关联。
5. 向 `/web/flowInstanceApi/submit` 发送提交正文（回退后与草稿同端点）；名称使用工具流程名称。同一端点上带 `checkPermissions` 的权限预检不算写，目标返回选择要求时保留当前 runtime 组件和未完成动作，不关闭会话。
6. Go 使用路径配置的分支和人员数据发出继续命令，runtime 调用目标页面的继续方法完成提交。
7. 成功后执行 `afterSaveFlowInstance`、附件绑定和目标页面的业务后置方法。

**成功后重读**

- 主实例状态为 `run` 或目标明确的结束状态。
- 真实当前节点、当前处理人、首个待办、实例代理和实际路径与目标返回一致。
- 提交后的业务保存、附件绑定和业务关联均已完成。

**失败规则**

- 目标返回手动分支或选人缺失：先记录目标返回的节点和原因，补齐用户已配置的分支/人员后重新放行；不能猜测分支。
- 目标明确拒绝：标记目标拒绝，不重发。
- 响应丢失或 runtime 崩溃且无法确认是否写出：标记结果待确认，不重发。

### 3.3 重新提交 `resubmit`

**输入**

- 已存在的主实例 ID、实时表单代理 ID、完整表单正文、业务关联、手动分支入口和下一节点人员。

**执行顺序**

1. 只允许发起人操作状态为草稿、不同意或撤回的主实例。
2. 创建审批页面中的发起表单组件，按目标页面补齐当前公司和人员字段。
3. 执行重新提交前的 `beforeSubmitAndDraft` 和 `beforeSubmitAndDraftNoBiz`。
4. 向 `/web/flowInstanceApi/reSubmit` 发送 `id`、`formProxyId` 或 `flowProxyId`、表单正文、业务关联和下一节点人员。同端点带 `checkPermissions` 的预检不算写；目标返回选择要求时保留当前 runtime 组件和未完成动作，不关闭会话。
5. Go 使用路径配置的分支和人员数据发出继续命令，runtime 调用目标页面的重新提交继续方法。
6. 成功后执行目标页面的 `afterSaveFlowInstance` 和附件后置处理。

**成功后重读**

- 实例状态离开 `draft`、`rejected` 或 `withdraw` 并进入 `run`，或目标明确返回结束状态。
- 当前节点、当前待办、当前处理人和实际路径重新读取成功。
- 不能创建第二个主实例。

**失败规则**

- 当前账号不是实例创建人、实例状态不允许重提或代理类型不匹配：写前阻止。
- 目标拒绝或响应不明确时不重发；保留原实例状态和原请求轨迹。

### 3.4 审批暂存 `storage_form_data`

**输入**

- 主实例 ID、当前节点代理 ID、当前待办处理人、审批说明和完整表单正文。

**执行顺序**

1. 创建审批表单组件，装载当前节点字段权限和表单正文。
2. 执行表单校验和 `getValues()`；目标页面允许暂存时只保存检查点，不调用同意或不同意方法。
3. 向 `/web/flowInstanceApi/storageFormData` 发送实例 ID、当前节点代理 ID、审批说明和正文。

**成功后重读**

- 暂存记录存在，记录的实例、节点、处理人和正文与本次输入一致。
- 实例状态、任务状态、当前节点和当前待办保持不变。

**失败规则**

- 缺少当前节点代理 ID或当前处理人事实：写前阻止。
- 目标拒绝或响应不明确：不调用审批接口，不重发暂存。

### 3.5 同意 `approve`

**输入**

- 实例 ID、当前待办任务 ID、当前节点代理 ID、当前实际处理人、审批意见、完整表单正文、手动分支入口和下一节点人员。

**执行顺序**

1. 创建审批页面真实组件，注入当前处理人和原发起人两套身份。
2. 按目标审批权限读取可编辑字段并执行表单校验。
3. 调用同意专用表单业务方法；不得调用不同意分支。
4. 调用目标审批方法，发送 `/flowInstanceApi/audit`，`auditRecord.auditStatus=pass`。目标返回选择要求时保留当前 runtime 组件和未完成动作，不关闭会话。
5. Go 使用路径配置的分支和人员数据发出继续命令，runtime 调用目标页面的同意继续方法。
6. 等待审批后业务回调、附件处理、自动字段写回和页面完成事件全部结束。

**成功后重读**

- 当前任务已完成，实例当前节点、下一个待办、处理人、批次和状态与目标事实一致。
- 目标自动生成的 `auto_audit_info_<n>`、`auto_audit_info_obj_<n>` 和 `auto_audit_info_obj_list_<n>` 以目标返回值为准。

**失败规则**

- 表单校验失败、处理人不匹配或目标明确拒绝：停止本步，不发送第二次审批。
- 响应丢失、页面崩溃或后置业务未完成：结果待确认，不重发同意。

### 3.6 不同意 `reject`

**输入**

- 实例 ID、当前待办任务 ID、当前处理人、审批意见和完整表单正文。

**执行顺序**

1. 创建审批组件并装载当前节点权限。
2. 按目标不同意分支处理审批意见和必要表单数据；不调用同意专用业务方法。
3. 发送 `/flowInstanceApi/audit`，`auditRecord.auditStatus=no_pass`。
4. 等待目标不同意后置事件和自动字段更新结束。

**成功后重读**

- 当前待办完成，实例进入 `rejected` 或目标实际返回的退回状态。
- 发起人重新提交入口可见，实例表单数据保持目标保存结果。

**失败规则**

- 处理人或任务 ID不匹配、目标明确拒绝、响应丢失均不得重发。
- 不同意产生的恢复链由 Go 编译器在后续步骤处理，不在本动作内偷偷调用重新提交。

### 3.7 转发 `forward`

转发是一个复合动作，不能按普通提交处理。它不会推进主实例，而是创建独立辅助实例。

**输入**

- 主实例 ID、转发接收人 ID、原始表单正文、表单模板数据、当前流程类型、业务 ID、已有业务关联、历史转发记录、审批意见和附言选项。

**执行顺序**

1. 创建转发页面组件，读取主实例表单正文、流程日志和附言。
2. 生成 `dynamicParam`：保留历史转发记录；本次记录写入审批人、时间、审批意见、附言和流程日志。
3. 生成 `transpondFlowInstance`、`transpond_formExist`、`transpond_auditWay`、`transpond_originalName` 和原实例 ID业务关联。
4. 组装辅助实例表单正文；实例名称只用于目标辅助实例，不能改写工具主流程名称。
5. 发送 `/web/flowInstanceApi/transpond`，携带 `receiverId`、辅助实例 `data.name`、业务关联和完整表单正文。
6. 目标返回辅助实例 ID后，按页面逻辑发送 `/web/flowInstancePostscript/save` 保存转发意见；没有意见时记录“未发送附言请求”。

**成功后重读**

- 主实例 ID、状态、节点、批次和待办完全不变。
- 新辅助实例存在，接收人正确，表单正文、`dynamicParam` 和业务关联完整。
- 有意见时附言记录存在且关联辅助实例 ID；没有意见时不得伪造附言记录。

**失败规则**

- 转发主请求响应丢失：不再次创建辅助实例，进入结果待确认；通过主实例与辅助实例事实确认。
- 辅助实例已确认创建但附言保存响应丢失：不再次创建辅助实例，只核对附言记录；核对失败时把“辅助实例已创建、附言未确认”单独记录。
- 转发接收人缺失、表单数据无法读取或业务关联冲突：写前阻止。

### 3.8 提交、重新提交和同意的选择闭环

目标页面的“提交”“重新提交”“同意”都可能在第一次调用时打开选择窗口。自动执行不显示窗口，但必须使用同一套目标数据和继续方法完成这一步。

1. Go 在第一次命令中传入路径已保存的 `branchSelections`、每个 `run_node_choose` 节点的 `nextNodeAuditors`，以及本次动作会跨过的后续自选节点人员。
2. runtime 首次调用目标页面方法，监听返回的 `isSuccess` 和 `data.errorType`。只有 `isSuccess=false` 且 `errorType` 为 `custom_choose`、`parallel_choose` 或 `run_node_choose` 时，才返回 `choice_required` 事件；这三种返回表示目标没有推进流程，只要求补选择。
3. `custom_choose` 使用 `data.branchNodes`。Go 必须找到与已保存分支入口 ID完全相同的一项；没有匹配或匹配多项都阻止。目标分支为 `run_node_choose` 时，还必须找到该分支人员。
4. `parallel_choose` 使用 `data.branchNodes` 中每个 `run_node_choose` 分支的真实节点 ID；每个节点单独匹配人员，缺任一节点人员都阻止。
5. `run_node_choose` 使用 `data.node.id` 或 `data.nodeProxy.id` 匹配已保存节点；人员 ID、姓名、节点代理 ID和 `auditDetailType=personnel` 必须同时存在。
6. Go 把匹配结果作为 `choice_continue` 命令发回同一个 runtime 会话。runtime 将分支写入目标组件的 `chooseBranchList`/`nextAuditorList`，将人员写入对应节点的 `nextAuditorList`，然后调用目标页面原本在选择窗口确认按钮中调用的继续方法。
7. 继续方法与原动作一致：提交继续调用提交入口，重新提交继续调用重新提交入口，同意继续调用同意入口。Go 不另发 `/web/flowInstanceApi/submit`、`/web/flowInstanceApi/reSubmit` 或 `/flowInstanceApi/audit`，也不得把同端点权限预检当成正式写。
8. `choice_required` 期间不得重新加载表单、重新执行一次初始动作或新建 BrowserContext；必须保留同一表单数据、业务保存结果、附件状态和页面回调。
9. 选择继续命令只能发送一次。继续后目标仍返回三种选择错误时，记录返回节点、配置值和缺少字段并阻止；不能循环发送。
10. 响应丢失、连接中断、未知错误、目标已返回 `isSuccess=true` 但后置业务未完成，都不是选择等待，禁止发送 `choice_continue`，按现有结果待确认或业务失败规则处理。

## 4. Go 直连动作

### 4.1 加签 `add_sign`

- **写前读取**：实例私有流程代理树、当前节点代理、当前待办和实时新增人员。
- **发送**：`/web/flowInstanceApi/updateFlowProxy`，完整发送 `flowProxyProtocol.data`；不能只发送当前节点片段。
- **主操作**：在当前节点追加目标人员；必要时先创建实例私有代理。
- **成功后重读**：实例私有代理树、当前节点、当前待办、处理人和代理任务映射。
- **阻止条件**：代理树为空、节点不属于当前实例、人员未解析或目标已结束。
- **失败处理**：目标拒绝或响应不明确不重发；写后只读取代理树和待办确认。

### 4.2 移交 `transfer`

- **写前读取**：当前待办任务 ID、当前节点代理 ID、当前批次、当前真实处理人和新处理人 ID。
- **发送**：`/web/flowInstanceApi/approverAppend`，`auditStatus=transfer`，携带 `batchNo`、`flowNodeProxyId` 和 `userIds`。
- **主操作**：把当前待办处理人改为选定人员，节点位置不变。
- **成功后重读**：当前待办处理人、任务 ID、批次和节点代理。
- **阻止条件**：缺少 batchNo、任务已完成、选定人员不在实时允许名单或当前节点已变化。
- **失败处理**：不重发；不能把移交失败改写为同意或加签失败。

### 4.3 回退上一节点 `rollback_previous`

- **写前读取**：当前待办任务 ID、实例当前节点、目标流程代理的直接前驱节点和前驱处理人。
- **发送**：`/web/flowInstanceApi/rollBackThePreviousLevel`，携带实例 ID和当前待办任务 ID。
- **主操作**：回到目标定义的直接前一审批节点；不允许指定任意节点。
- **成功后重读**：实例当前节点、前驱待办、当前处理人、批次和任务列表。
- **阻止条件**：没有直接前驱、直接前驱是发起节点、当前待办已处理或实例已结束。
- **失败处理**：目标拒绝和响应不明确均不重发；后续路径从新节点事实重新编译。

### 4.4 取回 `retrieve`

- **写前读取**：操作者拥有的已办任务 ID、已办任务节点、后继任务是否已处理、是否已经取回过、会签/并行是否已有其他人处理。
- **发送**：`/web/flowInstanceApi/retrieveProcess`，携带实例 ID和已办任务 ID。
- **主操作**：目标建立新批次并恢复该审批节点的待办。
- **成功后重读**：新批次、恢复节点、当前待办、当前处理人和后继处理状态。
- **阻止条件**：已办任务属于发起节点、后继已处理、该任务已经取回、会签/并行已有其他处理事实或实例已结束。
- **失败处理**：不重发；恢复成功后必须从新批次继续，不沿用旧任务 ID。

### 4.5 撤回 `withdraw`

- **写前读取**：实例状态、实例创建人、当前账号是否为创建人和当前待办。
- **发送**：`/web/flowInstanceApi/revocation`，携带实例 ID和撤回说明。
- **主操作**：创建人撤回运行中的主实例。
- **成功后重读**：实例状态、创建人归属和当前待办。
- **阻止条件**：当前账号不是创建人、实例不是运行中或实例已结束。
- **失败处理**：不重发；后续重新提交由单独的 `resubmit` 动作负责。

### 4.6 催办 `urge`

- **写前读取**：实例存在、当前待办接收人存在、当前账号有催办权限。
- **发送**：`/web/urgeHandleRecord/sendUrgeMessage`，顶层发送 `flowInstanceId`，并发送目标页面使用的 `data={}`。
- **主操作**：创建一条催办记录并通知当前待办接收人。
- **成功后重读**：催办记录数量或最新记录、实例状态、节点和待办。
- **阻止条件**：没有待办接收人、实例不存在或目标已结束。
- **失败处理**：不重发；催办失败不能改变流程结果。

### 4.7 关注 `follow` 与取消关注 `unfollow`

- **写前读取**：实例存在和当前账号的关注状态。
- **发送**：`/web/flowInstanceApi/flowTracking`，顶层 `tracking=true` 或 `tracking=false`，正文 `data.id` 为实例 ID。
- **主操作**：只改变当前账号的关注状态。
- **成功后重读**：当前账号关注状态；实例状态、节点和待办必须保持不变。
- **阻止条件**：实例不存在、目标已明确拒绝或请求状态与动作相反。
- **失败处理**：不重发；不能把关注状态变化当作流程推进。

## 5. 系统自动动作 `system_automatic`

系统自动动作包括条件分支、并行分支、汇聚、空节点和结束节点。它们不出现在用户动作下拉框，不发送写请求，也不由 runtime 调用按钮方法。

Go 只做以下工作：

1. 读取目标实例当前节点和流程代理树。
2. 按目标返回的实际节点确认是否已经越过、是否需要用户选择分支、是否需要等待处理人生成。
3. 对手动分支保存的 `nodeProxyId` 和已选人员原样带入下一次真实提交或同意请求。
4. 对结束节点读取实例终态；目标事实未到达结束节点时不能提前判定完成。

## 6. 待发删除和业务数据删除

`DueOut/index.vue` 的待发删除调用 `/web/flowInstanceApi/delete`，部分业务类型还会删除对应业务数据。这是破坏性管理操作，不加入当前动作目录，不由一键配置生成，不由 runtime 或 Go 执行器自动调用。

如果以后需要自动化删除，必须单独定义：删除对象、业务类型白名单、前置确认、业务数据删除顺序、失败后的残留处理、写后核对和人工确认步骤；在单独功能获批准前，所有计划遇到该入口都显示“不纳入自动化动作”。

## 7. 配置与执行方式的最终结论

用户已经保存的 `action`、`scope`、`nodeKey`、`order`、`parameters` 和 `actorPolicy` 不需要重新录入。改造只改变服务端执行动作的方法：七个表单相关动作使用 runtime，八个页面管理动作继续使用 Go 目标客户端，系统节点只读。

只有以下情况需要用户修改配置：动作本身、节点顺序、处理人或业务参数发生了业务变化；或者目标前端版本变化导致该表单/动作尚未登记 runtime 能力。后者不能静默改用另一条写路径，必须在运行前明确阻止并指出缺少的能力登记。
