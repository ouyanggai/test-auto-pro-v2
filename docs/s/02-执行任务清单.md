# 执行引擎改造任务清单

## 使用规则

- 按任务编号顺序执行，不得跳过依赖任务。
- 每个任务完成后先运行本任务的验证命令，再用中文提交一次。
- 任务失败时保留日志和错误，不修改目标平台，不用空实现掩盖问题。
- 本分支只做执行引擎；不自动开始其他功能切片。
- 所有测试放根目录 `test/`，按 `test/unit`、`test/integration`、`test/contracts` 分类。

## 配置兼容规则

- 不修改用户已经保存的动作键、节点键、动作顺序、人员策略和业务参数；这些字段继续表达测试人员的业务意图。
- 在服务端编译结果中增加内部执行归属：`runtime`、`go_target`、`read_only`。该值由动作键、表单能力登记和目标前端版本计算，浏览器不能提交或覆盖。
- `save_draft`、`submit`、`storage_form_data`、`approve`、`reject`、`resubmit`、`forward` 由 runtime 执行；`add_sign`、`transfer`、`rollback_previous`、`retrieve`、`withdraw`、`urge`、`follow`、`unfollow` 由 Go 现有目标客户端执行；`system_automatic` 只读。
- `submit`、`resubmit`、`approve` 执行时必须把已配置的手动分支和审批人自选结果传给 runtime；不能只传动作名称和表单数据。
- 待发删除和业务数据删除不加入现有动作键，必须作为单独的破坏性功能获得批准后再设计；本清单不得把它当作普通动作补进去。
- 普通动作只有一个写出口。runtime 执行成功、失败或结果待确认后，Go 都不能再次发送同一动作的目标写请求；转发是唯一的复合动作，固定按“转发主请求、成功后保存附言”顺序执行，不能重复已写出的步骤。

## 阶段 1：runtime 会话和命令桥

### T003：实现 BrowserContext 会话管理

**做什么**

- 每个会话创建新 BrowserContext。
- 保存 `sessionId`、账号键、页面、创建时间、请求和关闭状态。
- 实现创建、查询、关闭；关闭时移除监听器并关闭 Context。
- 同账号队列由 Go 实现，runtime 不调度任务。

**文件**：`form-runtime/executor/src/session-manager.ts`、`form-runtime/executor/src/types.ts`。

**测试**：`test/unit/form-runtime/session-manager.test.ts`。

**验收**：两个会话的 localStorage、sessionStorage、Vuex 和页面状态隔离；关闭会话后不能执行新命令；页面崩溃会通知 Go 并释放会话。

**依赖**：T002。

### T004：定义 Go/runtime 消息协议

**做什么**

- 定义创建、加载、执行、请求转发、响应返回、事件、结果和销毁消息。
- 每条消息必须有 `requestId`、`sessionId`、`runId`、`pathRunId`、`stepId`。
- 固定结果值：`success`、`failed`、`target_rejected`、`uncertain`、`business_failed`、`unsupported`、`timeout`。
- runtime 不返回 Vue 实例，只返回 JSON 数据。

**文件**：`form-runtime/executor/src/protocol.ts`、`internal/runtimeexec/protocol.go`。

**测试**：`test/contracts/form-runtime/protocol_test.go`、`test/unit/form-runtime/protocol.test.ts`。

**验收**：缺少会话、运行、步骤或请求编号的消息被拒绝；未知动作被拒绝；旧协议版本被拒绝，不静默兼容。

**依赖**：T003。

### T005：增加 runtime 根桥接

**做什么**

- 在 `form-runtime/src/App.vue` 增加执行模式命令处理，保留现有 iframe 模式。
- 组件树装载完成后主动注册 `window.__runtimeBridge__`。
- 只暴露 `loadInitiate`、`loadApprove`、`capture`、`validate`、`execute`、`destroy`。
- 外部调用不通过 `$parent` 层数寻找组件。

**文件**：`form-runtime/src/App.vue`、`form-runtime/src/runtime/protocol.js`、`form-runtime/src/runtime/executionBridge.js`。

**测试**：`test/unit/form-runtime/execution-bridge.test.js`。

**验收**：Go 只发送命令即可得到结果；没有业务按钮点击代码；`destroy` 后桥接对象不可执行。

**依赖**：T004。

## 阶段 2：请求转发

### T006：实现 Playwright 网络拦截

**做什么**

- 使用 `page.route()` 拦截目标 `/web`、`/flowInstanceApi` 和文件请求。
- runtime 不直接向目标平台发送请求。
- runtime 自身脚本、样式和静态资源继续正常加载。
- 请求头、请求正文、响应头和响应正文原样转发，不脱敏。

**文件**：`form-runtime/executor/src/target-route.ts`、`form-runtime/executor/src/request-trace.ts`。

**测试**：`test/unit/form-runtime/target-route.test.ts`、`test/contracts/form-runtime/request-route_test.go`。

**验收**：XHR、Fetch、上传请求都能捕获；未登记目标写请求不能绕过 Go；请求顺序和响应顺序可回放。

**依赖**：T004、T005。

### T007：在 Go 接入 runtime 客户端

**做什么**

- 新增 `internal/runtimeexec/client.go`，负责连接 runtime、发送命令、接收请求和回传响应。
- 请求必须交给现有 `internal/adapter/target.Client`，不能新增第二个目标 HTTP 客户端。
- 复用现有账号 SID、重登、读写重试和完整日志。
- runtime 连接断开时，按目标请求是否已经写出决定失败或结果待确认。

**测试**：`test/unit/backend/runtimeexec/client_test.go`、`test/integration/runtimeexec/request_roundtrip_test.go`。

**验收**：页面请求经过 Go TargetClient 后能继续执行；SID 失效使用现有会话管理器；写响应丢失不会重发原写请求。

**依赖**：T006。

## 阶段 3：真实表单动作

### T008：实现发起表单装载

**做什么**

- runtime 接收目标模板、历史表单值、权限、工具流程名称、发起人和当前操作人。
- 创建 `OtherSteps2.vue` 及真实 FormMaking、自定义组件树。
- 等待表单远程读取请求结束。
- `capture` 返回 `getValues()` 的完整数据，包括虚拟字段和显示值。

**测试**：`test/integration/runtimeexec/form_load.test.ts`。

**验收**：普通 FormMaking 表单加载成功；远程选项完成后值、显示值和虚拟字段一致；加载失败不允许写动作。

**依赖**：T007。

### T009：实现审批表单装载和身份注入

**做什么**

- 创建审批页面真实组件树。
- 注入当前审批人、原发起人、公司、部门、岗位、SID、实例、任务和节点。
- 当前审批人和原发起人分开保存，禁止当前人覆盖发起人字段。
- 每次审批使用新 Context。

**测试**：`test/integration/runtimeexec/actor_isolation.test.ts`。

**验收**：两个审批人依次或并行执行时用户信息不串；旧表单、Vuex 和 localStorage 不残留。

**依赖**：T008。

### T010：实现七个 runtime 业务动作

**做什么**

- 通过业务命令调用目标组件入口，不点击页面控件。
- 接入 `save_draft`、`submit`、`storage_form_data`、`approve`、`reject`、`resubmit`、`forward`。
- 保留目标代码不同动作的校验、前置事件、后置事件和参数差异。
- 工具流程名称在最终请求中保持工具值，目标页面拼接的原发人名称不能覆盖工具流程名称；其他业务脚本结果不能丢失。
- `forward` 必须执行表单读取、`dynamicParam` 追加、原实例业务关联复制、辅助实例创建和成功后的附言保存；主实例不得被推进或改名。
- `submit`、`resubmit`、`approve` 必须调用 T010B 的选择闭环；第一次收到明确选择错误时不能直接把动作判定为失败。

**测试**：`test/integration/runtimeexec/actions.test.ts`、`test/contracts/form-runtime/action_entry_test.go`。

**验收**：JSON `beforeSubmitAndDraft` 能执行；`beforeSubmitAndDraftNoBiz` 按目标分支执行；`afterSaveFlowInstance` 能执行；同意和不同意不误走对方分支；`storage_form_data` 不推进任务；草稿不提前提交；转发创建独立辅助实例并保存附言，主实例状态、节点和待办保持不变。

**依赖**：T008、T009。

### T010B：执行手动分支和审批人自选

**做什么**

- 不新增手动分支或审批人自选配置页面；直接读取现有路径的 `BranchSelections`、节点人员策略解析结果和 `NextNodeAuditors`。
- 实现时必须对照目标前端：`Submitted/components/FlowDialog.vue` 的 `submitFinal`、`handleSaveBranchChooseNode`、`handleSaveParallelChooseNode`、`getSelectPerson`、`flowErrorHandle`；`Submitted/components/Steps2.vue` 和 `OtherSteps2.vue` 的分支列表生成；`components/EnterpriseExamineOpinion.vue` 的 `submitCheckBefore`、`formMakingFormBusiness`、`flowErrorHandle`、`getSelectPerson`、`handleSaveBranchChooseNode`、`handleSaveParallelChooseNode`。
- 在 Go 发给 runtime 的动作命令中固定传递 `branchSelections`、`nextNodeAuditors` 和本次会跨过的后续自选节点人员。
- `branchSelections` 使用路径已经保存的“分支节点 ID → 选中分支入口节点 ID”。
- `nextNodeAuditors` 的每条人员记录必须包含目标节点代理 ID、目标用户 ID、姓名和 `auditDetailType=personnel`。
- runtime 执行 `submit`、`resubmit`、`approve` 前，把这些数据放入目标页面动作上下文，不通过 DOM、按钮或弹窗文字操作。
- 第一次调用目标业务方法后，只允许把 `data.errorType` 为 `custom_choose`、`parallel_choose` 或 `run_node_choose` 的明确业务返回解释为“目标尚未提交，等待选择”。
- `custom_choose`：从 `data.branchNodes` 中匹配已配置的分支入口；分支为 `run_node_choose` 时同时带该分支的人员。
- `parallel_choose`：逐个处理返回的并行 `run_node_choose` 分支，每个分支使用自己的节点代理 ID和人员。
- `run_node_choose`：按返回节点的真实 ID匹配已配置人员，形成 `{nodeProxyId,bizId,name,auditDetailType:"personnel"}`。
- 选择数据完整后，调用与第一次相同的目标方法继续执行：提交仍调用提交入口，重新提交仍调用重新提交入口，同意仍调用审批同意入口。不能由 Go 另发接口绕过表单前后置代码。
- 不得重新实现分支和人员计算：直接使用现有 `branchEntriesForStep`、`nextAuditorsForTransition`、`NextNodeAuditors` 和 `BranchSelections` 的结果；runtime 只负责接收、装入目标组件并触发目标页面原有的继续方法。手动分支和自选人员统一进入 `nextAuditorList`，不能用姓名代替 `bizId`，不能用空人员代替配置结果，也不能新增 `fixedExecuteNodeId` 旁路。
- 只有第一次响应明确为 `isSuccess=false` 且属于上述三种选择错误时才允许继续调用；响应丢失、连接中断、未知错误、目标已经成功但后置未完成，都禁止继续调用。
- 最终请求必须携带完整 `nextAuditorList`；分支只传 `nodeProxyId`，自选审批人同时传 `bizId`、`name` 和 `auditDetailType=personnel`。
- 选择数据不完整、节点不匹配或目标仍返回“未设置审批人”“手动条件分支,请选择”时，记录具体节点、目标 ID和缺少字段，阻止当前动作，不使用空人员或计划账号代替。

**文件**：`form-runtime/src/runtime/executionBridge.js`、`form-runtime/executor/src/protocol.ts`、`internal/runtimeexec/protocol.go`、`internal/engine/step/gate.go`、`internal/engine/step/branch.go`、`internal/engine/step/types.go`。

**测试**：`test/contracts/runtimeexec/selection_payload_test.go`、`test/integration/runtimeexec/manual-branch-selection.test.ts`、`test/integration/runtimeexec/parallel-auditor-selection.test.ts`、`test/integration/runtimeexec/approve-selection-continuation.test.ts`。

**验收**：

1. 手动分支请求带正确的分支入口 `nodeProxyId`，目标不再返回“手动条件分支,请选择”。
2. 普通审批人自选请求带正确的 `nodeProxyId`、`bizId`、`name` 和 `auditDetailType=personnel`，目标不再返回“未设置审批人”。
3. 并行自选的多个节点分别携带人员，不能把一个节点人员发到另一个节点。
4. 三种明确选择错误只允许在确认没有流程推进后继续一次；响应丢失和未知错误不得继续调用。
5. 选择数据不完整时动作阻塞并显示具体节点与缺少字段。

**依赖**：T004、T005、T008、T009、T010。

### T010A：固定非 runtime 动作的 Go 唯一写出口

**做什么**

- 保留 `internal/adapter/target/write_actions.go` 对 `add_sign`、`transfer`、`rollback_previous`、`retrieve`、`withdraw`、`urge`、`follow`、`unfollow` 的现有载荷构造和一次写规则。
- 逐个核对以下目标页面入口与 Go 载荷：`Backlog/index.vue` 的移交、回退，`Finished/index.vue` 的取回和关注，`Submitted/index.vue` 的催办，`mixin.js` 的关注/回退，`EnterpriseExamineOpinion.vue` 的加签/审批辅助逻辑。
- 对每个动作写明目标请求前必须重新读取的实例、任务、节点、处理人或关注事实；读取失败不得发送写请求。
- 禁止为这些动作启动 runtime 后再发送同一接口；禁止在 Go 直连成功后让 runtime 重放接口。

**文件**：`internal/adapter/target/write_actions.go`、`internal/adapter/target/protocol_matrix.go`、`internal/engine/step/gate.go`、`internal/engine/step/verify.go`、`docs/s/03-审批页面全量动作对照.md`。

**测试**：`test/contracts/runtimeexec/action-routing_test.go`、`test/contracts/runtimeexec/no_duplicate_write_test.go`。

**验收**：八个 Go 动作各有一个固定端点和一个固定载荷构造函数；每个动作均有写前事实、写后重读和失败分类；静态扫描确认 runtime 路由不会发送这八个端点。

**依赖**：T001、T007。

## 阶段 4：完成检测和安全接入

### T011：实现动作完成检测

**做什么**

- 统计页面业务请求、流程请求、附件请求和后置请求。
- 将转发标记为复合动作：记录 `writeSequence=1` 的辅助实例创建和 `writeSequence=2` 的附言保存；第一步未确认时不得发第二步，第二步未确认时不得重建辅助实例。
- 监听 `pageerror`、未处理 Promise rejection、runtime 异常和业务完成事件。
- 实现网络空闲稳定窗口、动作硬超时和 Context 崩溃处理。
- 返回每笔请求的轨迹和业务阶段摘要。

**测试**：`test/unit/form-runtime/completion.test.ts`、`test/integration/runtimeexec/completion_failure_test.go`。

**验收**：流程接口成功不能代替全部业务成功；后置未完成返回 `business_failed`；响应丢失返回 `uncertain`；超时后不执行新写请求。

**依赖**：T006、T010。

### T012：接入现有 Go 七阶段执行器

**做什么**

- 在 `internal/engine/step.Executor` 增加可选 runtime 执行能力。
- 只有 `save_draft`、`submit`、`storage_form_data`、`approve`、`reject`、`resubmit`、`forward` 和已登记对应能力的流程走 runtime。
- `add_sign`、`transfer`、`rollback_previous`、`retrieve`、`withdraw`、`urge`、`follow`、`unfollow` 继续使用现有 TargetClient；`system_automatic` 不发送写请求。
- runtime 成功后继续调用现有 `verify` 和 `FinalReview`。
- runtime 失败、目标拒绝、结果待确认和业务失败映射到现有运行状态。
- 同一动作不得同时走 runtime 和旧 Go 写出口。

**文件**：`internal/engine/step/executor.go`、`internal/engine/step/types.go`、`internal/runtimeexec/client.go`、`internal/adapter/target/special_business.go`。

**测试**：`test/unit/backend/runtimeexec/step_routing_test.go`、`test/contracts/runtimeexec/no_duplicate_write_test.go`。

**验收**：已登记 runtime 动作只产生一条主流程写请求和其目标页面必需的后置请求；Go 动作只产生一条对应管理接口写请求；runtime 成功后仍做目标事实核验；未登记表单阻塞，不回退到旧接口造成双写；结果待确认没有重试入口。

**依赖**：T007、T011。

### T013：实现 runtime 状态和运行详情

**做什么**

- 在现有运行记录中保存 runtime 会话、业务阶段、请求轨迹、错误和能力版本。
- 运行详情显示“表单业务处理、流程动作、提交后业务处理”三个阶段。
- 页面不展示 SID、密码和完整正文；完整正文继续由现有日志入口查看。
- 不增加独立运行详情页，复用现有运行画布。

**测试**：`test/contracts/runtimeexec/detail_projection_test.go`、`test/unit/web/runtime_execution_detail.test.ts`。

**验收**：列表、路径和详情显示同一终态；业务失败不显示为流程失败；结果待确认不显示重试按钮。

**依赖**：T012。

## 阶段 5：真实验证和收口

### T014：建立 runtime 能力登记

**做什么**

- 对表单、动作、目标前端版本、runtime 版本、运行号和日志路径建立登记。
- 只有真实执行成功并完成目标结果核验的组合才标记可运行。
- 未支持组件、在线编辑器和无法确认结果的表单明确记录阻塞原因。

**文件**：`docs/TARGET_SEMANTICS.md`、`docs/s/03-runtime-能力登记表.md`、`internal/runtimeexec/capability.go`。

**验收**：同流程提交成功不自动解锁同流程同意/不同意；同端点一个动作成功不自动解锁另一个动作；能力登记含目标证据和日志引用。

**依赖**：T012、T013。

### T015：真实目标全动作闭环验证

**做什么**

- 使用普通 FormMaking 表单、含 JSON 业务脚本的表单、含附件的表单和含自定义组件的表单。
- 分别执行保存草稿、提交、审批暂存、同意、不同意、重新提交、转发、加签、移交、回退、取回、撤回、催办、关注和取消关注；系统自动节点只验证导航事实；待发删除不在本任务内执行。
- 与人工操作对比业务数据、表单数据、附件关系、流程状态、节点和待办。
- 对转发额外对比辅助实例、`dynamicParam`、业务关联、附言和主实例状态；对回退、取回、移交、加签额外对比当前节点、批次和处理人；对关注/取消关注只对比跟踪状态；对催办只对比催办记录。
- 记录不支持能力，不修改代码伪造通过。

**验证文件**：`test/integration/runtimeexec/real-target-checklist.md`、`test/run-runtime-exec.sh`。

**验收**：自动验证命令实际执行并输出十五个用户动作和系统自动动作的结果；每个动作有独立请求轨迹和目标事实证据；失败动作不会重复提交；转发产生的辅助实例单独记录；待发删除明确显示为未纳入本切片；文档状态停在 `ready_for_manual`，等待用户人工验收。

**依赖**：T014。

## 检查点

### 检查点 A：T001-T005

- [ ] 运行服务可以启动。
- [ ] 协议能创建、加载和销毁会话。
- [ ] 组件桥存在但尚未发送真实目标写请求。

### 检查点 B：T006-T010

- [ ] 请求可以从页面到 Go 再回到页面。
- [ ] 普通表单可以执行提交。
- [ ] 同意和不同意调用链不同。

### 检查点 C：T011-T013

- [ ] 完成判断不会漏掉后置请求。
- [ ] 写响应丢失不会重放。
- [ ] Go 执行器没有双写。

### 检查点 D：T014-T015

- [ ] 能力只按真实证据登记。
- [ ] 目标结果与人工操作对照完成。
- [ ] 停在人工验收，不自动接受。

## 明确禁止

- 不使用 jsdom/happy-dom 作为正式执行引擎。
- 不使用浏览器选择器、DOM 定位、坐标和按钮点击。
- 不在 runtime 内直接访问目标平台。
- 不让 runtime 自己登录或自行刷新 SID。
- 不在 runtime 失败后自动再次调用原写动作。
- 不删除 Go 现有写后核验和结果待确认能力。
- 不把一个真实动作拆成两套并行实现。
- 不为未验证的表单、自定义组件或动作写“已支持”。
