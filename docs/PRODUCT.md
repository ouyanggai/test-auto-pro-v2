# 产品行为

## 产品目标

“流程自动化测试平台”帮助测试人员选择目标平台真实账号和真实流程，为每条执行路径准备独立业务数据与处理人，按目标平台规则执行动作，并在真实流程结构上查看状态和结果。

## 产品原则

- 目标平台代码和真实运行结果决定流程、分支、人员与动作语义。
- 工具问题与目标平台问题必须分开说明；暂时无法判断时按工具问题处理。
- 一个整页只处理一项主任务，界面使用中文，桌面优先。
- 计划首次运行前可调整；产生运行记录后固化，后续运行不覆盖历史事实。
- 每条执行路径独占一个真实流程实例；多条路径不共享实例。
- 写操作结果不明确时先核对真实状态，禁止盲目重发。
- 自动准备、提交和失败反馈必须显示真实状态，不使用虚假进度或内部技术术语阻塞用户。

## 主导航

产品只有三个顶级入口：

- 测试计划：创建、配置和启动计划。
- 运行记录：统一查看等待、运行中及历史结果。
- 系统设置：维护常用账号、排除账号和排除流程。

不设置任务中心、报告中心、表单维护或系统状态等额外顶级入口。

## 计划与运行主线

1. 用户输入真实账号并验证，按流程来源选择可见流程模板、已发流程实例或待发流程实例，再选择串并方式及可选定时启动，创建计划。
2. 用户从真实流程结构选择执行路径，为每条路径独立准备条件、人员、表单数据、动作和成功断言。
3. 运行准备按路径说明阻塞与提醒；用户选择自动、单步或人工控制模式启动。
4. 每次启动生成独立运行记录，使用目标平台真实账号、实例和接口执行。
5. 运行结果按路径展示；单条路径失败不自动终止其他路径。

## 测试计划页面行为

- 测试计划列表支持按计划名称与计划状态筛选，筛选条件可清空；没有匹配项时显示正常空状态。
- 列表使用产品语言展示计划、流程、发起账号、路径数量、运行方式、定时信息、计划状态和最近运行结果。
- 计划在待配置、可运行、运行中、已完成状态下分别提供唯一主要入口：继续配置、开始运行、查看运行、查看结果。
- 新建计划使用独立整页；用户填写计划名称和真实账号，验证账号后选择流程来源、对应流程对象、运行方式、并行最大并发数和可选定时启动。
- 流程来源包括“新发起”“已发”“待发”：新发起选择当前账号可见的流程模板，已发选择当前账号的已发流程实例，待发选择当前账号的待发流程实例；页面不使用统一“目标流程”字段混淆三类对象。
- 流程模板候选优先展示名称、分类、流程分组、表单关联、用途备注和更新时间；有 `groupName` 时以小型标签高亮，编码和启停状态不影响当前选择时不作为主要信息展示。
- 未验证账号时只能保留“新发起”来源，“已发”“待发”不可选择；账号内容变化会立即使验证失效，并清空已有模板或实例选择。
- 并行最大并发数只在并行模式出现；定时启动关闭时不保留定时时间。
- F-001 只提供静态原型：校验成功不保存计划、不加入列表，也不进入路径选择页。
- F-003 起，点击“创建并选择路径”才真正保存计划；成功计划进入“待配置”，刷新页面或重启服务后仍出现在测试计划列表，唯一主要入口为“继续配置”。
- 创建请求失败时保留当前输入并允许重试，不能显示虚假成功；同一次创建操作重复提交只能得到同一条计划。
- 测试计划列表从 F-003 起只显示真实持久化数据，不再混入静态 mock；默认按最近修改时间倒序，读取失败明确提示并允许重试。
- F-003 的继续配置入口只展示已保存计划和“尚未选择执行路径”的真实状态；执行路径必须在读取真实流程结构后才能建立，不预先生成空路径或伪路径。

## 只读真实流程图行为

- F-004 从已保存计划重新读取目标平台当前真实结构：新发起使用流程模板树，已发和待发使用各自流程实例的代理树。
- 页面显示发起、审批、协同、空节点和结束等真实业务节点；条件、手动分支和并行路由不显示为独立卡片，而以分叉树干、真实分支名称和汇合关系表达，不显示节点编码或策略编码。
- 流程结构使用板正的树形布局：主干垂直、同一分叉共用一条水平分支轨、各分支按列向下、分支末端共用一条水平汇合轨后回到主干；不得用通用图压缩产生弯绕和交叉。
- 流程图允许平移、缩放和适配视口，但节点不可拖动、连线、删除或选择为执行路径。
- 大流程默认保持节点与文字可读，不为塞进一屏而压缩整图；画布提供右上角页面全屏入口，在当前浏览器页面内铺满可用视口，用户通过无限画布拖动查看展开结构。
- 连线使用克制的方向流动效果帮助辨认走向；系统开启减少动态效果时必须停止动画并保留清晰静态线条。
- 目标对象已不可见、待发已经处理或流程尚无节点时必须说明当前事实，不使用保存名称、模板结构、V1 mock 或上次结果伪造实例图。
- F-004 不保存流程图或路径；用户选择并持久化执行路径从 F-005 开始。

## 执行路径选择行为

- 用户在 F-004 已核实的真实流程树上逐条建立执行路径；默认由用户逐个选择条件或手动分支。新发起计划可由用户明确触发“一键生成全部路径”，系统才枚举当前真实图中的全部合法完整组合，不把该行为作为隐式默认选择。
- 普通画布不显示右侧路径管理面板，右上角并列提供带文字的“编辑路径”和“页面全屏”按钮。页面全屏只放大查看当前流程图；点击“编辑路径”才进入页面全屏的线路管理。进入页面全屏后显示“已保存的路径”和符合来源及数量限制的“新增路径”，并保留带文字的退出全屏按钮；点击已保存路径进入只读详情并高亮线路，只有明确进入编辑、新增或复制时才开放分支选择。普通浏览和只读详情不得出现可误触的分支控件。
- 条件分支和手动分支在一条执行路径中必须且只能选择一个可达分支；并行节点的全部真实分支同时属于同一条执行路径，不能拆成多条路径，也不能任选一支。
- 嵌套在并行分支中的条件或手动分支仍需分别完成选择；不在当前已选线路上的分支点不要求选择。
- 编辑模式使用轻量悬浮面板显示标题、人工决策进度、名称和实时流向；进度只统计当前可达的条件与手动路由，并行不计。用户每完成一处选择，主画布把下一待选点平滑移动到扣除面板后的操作区域中央，并用带明确箭头的就近气泡指向它，路径完整后明确引导保存，不自动代替用户保存。
- 已选线路使用显著高亮和方向流动效果；当前待选位置使用独立提示状态；未选择、未参与当前路径的线路保持静止并弱化，但候选名称仍可清楚阅读和点击。减少动态效果开启时停止动画，用线宽、颜色和文字继续表达状态。
- “新发起”计划可以保存多条执行路径，也允许复制同一条节点线路，供后续使用相互独立的真实流程实例和业务数据；每条路径拥有不会复用的稳定自动序号，默认名称为“路径 N”，用户可以自定义名称，但界面始终单独显示稳定序号。
- “一键生成全部路径”只放在新发起计划的“已保存的路径”浮层顶部：系统按真实分支顺序计算条件/手动分支的完整组合，并行分支仍全部属于同一条路径；操作前显示待新增和已存在数量，已保存的同线路不会重复创建。组合超过产品上限时必须拒绝并说明原因，不能让页面卡死或静默截断。
- 当前创建页的“已发”和“待发”计划各绑定一个真实流程实例，因此一个计划最多保存一条执行路径；路径从实例当前真实节点或并行活动节点继续配置，已走过且不可再影响的分支不允许重新选择。
- 完整路径保存后才计入计划的路径数量；未完成的本地草稿不计数。用户可以继续编辑或删除尚未产生运行记录的路径。
- 编辑中取消或退出页面全屏时，只有名称或线路真实变化才要求确认；确认放弃后清空本次草稿，不提供“继续选择”恢复入口。保存成功只反馈一次，刷新路径计数并回到没有活动面板的普通画布；保存失败或真实流程变化时保留当前编辑和草稿。
- 目标流程发生变化时，每次打开页面都用当前真实结构重新核对保存的分支选择；仍能精确对应的选择保留，无法对应的路径标记为需要重新选择，不按名称猜测、不自动删除，也不保存版本号、指纹或流程图快照。
- F-005 完成路径拓扑选择后计划仍保持“待配置”；表单条件、真实人员、节点动作、成功断言和运行准备由后续功能完成，不能提前显示“可运行”。

## 路径要求分析行为

- F-006 不提供独立“路径要求核对”入口或页面；计划路径页面继续只承担 F-005 的路径新增、查看、编辑与页面全屏行为。
- 后端可以针对一条已保存路径重新读取当前真实配置，并生成供后续可操作配置直接消费的“进入条件、处理人、节点动作”三类要求；并行分支按真实分组展开，汇合后回到主线，不把并行误写成多条独立路径。
- 条件分支只展示已选分支的真实条件。条件名称、连接关系和比较方式使用中文业务表达；最后一个兜底分支显示“其他条件均不满足时进入”，手动分支显示“运行时选择该分支”，不向用户暴露字段英文名、判断代码、节点 ID 或策略 ID。
- 条件中引用的表单字段优先使用目标平台表单元数据转换为可读名称；字段名称缺失、重复冲突或规则无法识别时标记为“需要人工核对”，不能猜测字段含义或把内部编码直接展示出来。
- 审批与协同节点展示目标平台真实处理人规则、会签或竞签方式、人数要求、已配置范围以及“无处理人是否跳过”。指定人员、角色、组织范围等显示为目标平台已配置规则；审批人自选和表单人员明确标记为后续需要准备；依赖发起人、组织关系或实际任务的人员标记为运行时确定。
- 节点动作只核对后续自动化必须配置的标准动作：发起节点为提交，审批与协同节点为处理结果，空节点和结束节点不要求动作。回退上一级、添加当前节点审批人、转发等特殊操作依赖实际任务状态和权限，本轮只说明“运行时可用性待核对”，不冒充为稳定可配置动作。
- 每项要求使用“待配置”“目标平台自动确定”“运行时确定”“需要人工核对”四种中文状态；汇总只说明还需准备什么，不把尚未配置的计划显示为完成或可运行。
- 新发起按模板规则分析；已发和待发按当前实例代理树及当前入口分析，只包含仍可影响的后续节点。每次请求重新读取当前真实配置；路径已失效时返回稳定错误，不使用历史快照或按名称猜测。
- F-006 只生成只读要求，不填写表单值、不选择真实人员、不保存节点动作、不调用目标平台写接口，也不改变计划状态。F-007 直接复用该能力驱动节点可视化配置，F-006 自身仍不提供配置界面。

## 路径生成与节点配置边界

- F-005 的“配置路径”只负责在真实流程结构上选择分支、形成执行路径并完成路径新增、命名、保存、编辑、复制和删除；这套交互已经通过人工验收，F-007 不得将节点信息配置混入其中，也不得以节点配置返工为由改变其操作方式。
- F-007 的“配置节点”只面向一条已经保存的执行路径。没有已保存路径时，计划详情明确提示用户先“配置路径”，不显示无效的节点配置入口；保存路径后，每条路径才显示独立的“配置节点”入口和节点配置状态。
- “编辑路径”改变分支选择或路径名称；“配置节点”只补齐该路径上各业务节点的人员、动作和节点级规则。路径使用的表单数据是独立的路径级输入，必须通过单独的“配置表单数据”入口完成，不能塞进任一节点的配置面板。

## 路径节点可视化配置行为（F-007）

- F-007 不新增“路径要求核对”入口；用户从已保存路径列表点击“配置节点”，进入这条路径自己的独立可视化配置画布，不进入脱离流程结构的普通表单页面。
- 普通计划详情页在计划摘要与流程结构之间提供紧凑的路径准备区域：无路径时显示“请先配置并保存执行路径”和“配置路径”；有路径时显示稳定序号、名称、节点配置状态和逐条“配置节点”按钮，并汇总已保存、已完成和待配置数量。
- 普通计划详情按当前主内容视口分为上下两屏：第一屏完整容纳返回、计划标题状态、计划摘要和路径准备，第二屏完整容纳流程标题说明、线路操作和流程画布。主内容区是唯一页面纵向滚动容器，使用 CSS scroll-snap 自然对齐；首屏底部“查看流程结构”可主动滚到第二屏，减少动态效果时立即定位。
- 路径准备区域使用与页面和计划信息一致的中性主题卡片表面、边框和主次文字色，不使用大面积成功色；绿色只用于主操作或小型完成状态，橙色只用于未配置标签。已保存路径较多时列表在卡片内部滚动，不能把首屏撑开或让流程画布露出半截。
- 流程图右上角普通状态同时显示文字“编辑路径”和“页面全屏”。“页面全屏”只放大查看当前图，不自动打开路径面板；“编辑路径”才进入页面全屏的线路管理，已有路径显示路径管理入口，无路径直接进入新增线路选择。全屏中的路径列表和新增按钮只是快速切换工具，不是配置数据的唯一入口。
- 节点配置画布只处理当前一条已保存路径，顶部显示返回、路径序号、名称和节点配置进度；主体复用真实流程树并高亮当前路径，非路径节点弱化且只读，并行分支仍属于同一条路径。
- 点击当前路径上的业务节点后，在画布内部固定右侧面板配置该节点的处理人员和动作计划，不展示表单字段输入。模板要求不长期占用侧栏，通过节点标题旁的信息图标按需查看。节点名称区域保持完整，配置状态通过独立的角标、边框或状态点表达，不能与名称叠放；可点击节点必须有明确的 pointer、hover、focus 和选中反馈。
- “配置表单数据”打开独立的表单工作区，使用目标平台 `rsh-flow-components` 固定副本中的真实 FormMaking 运行时渲染完整布局和组件，而不是把模板拆成 Naive UI 文本框、选择框或开关。运行时作为独立 Vue 2 服务与主 Vue 3 应用隔离；旧工作台路由、登录页、Vuex 和流程写操作不进入运行入口。
- “新发起”尚无流程实例时，使用目标表单模板、模板默认值和当前路径已保存的测试数据生成一份运行前表单；用户在真实表单布局中编辑并把数据保存到工具侧，后续发起流程时再使用。它不是目标平台实例，也不得提前调用目标业务保存或提交流程接口。
- 新发起表单工作区提供基础“智能生成”和“换一组”：生成器使用当前模板默认值与选项、当前账号、当前路径条件，以及通过已验证账号限量读取的近期可见已发表单样本生成可复现数据；样本不足时明确说明并使用确定性安全兜底，不直连目标 Mongo。
- 智能生成结果必须先进入真实 FormMaking 运行时，用户可以继续修改；“换一组”只替换仍由生成器拥有的字段，人工修改字段保持不变。保存时记录稳定种子、生成字段和人工覆盖字段。高级 AI 语义生成、跨模板学习和复杂自定义业务组件自动适配不在本切片。
- “已发”“待发”使用所选真实实例的当前表单数据作为初始值并以只读方式展示；本切片不声称能够修改已经存在的目标实例。以后需要节点执行时修改字段，仍复用同一表单运行时并由节点权限决定可编辑范围，不在节点侧栏另造控件。
- 表单组件兼容性只由真实 `rsh-flow-components` 运行时的实际注册表判定，优先使用模板 `el` 识别目标自定义组件；已注册组件正常渲染，无法支持的组件在表单工作区原布局位置说明缺少的适配能力，不能进入节点侧栏、降级成普通文本输入或把表单标记为已完成。
- 独立运行时可在当前 iframe 会话内接收已验证账号缓存的 SID，用于目标自定义表单组件确有必要的只读请求；切换计划、路径、账号或关闭工作区时必须销毁会话并清除 SID，SID 不进入 Git、配置数据库或浏览器长期存储。配置阶段继续禁止目标流程提交、草稿和业务写接口。
- 表单保存前由真实运行时执行 `getData(true)` 校验，最终必须保存 `getValues()` 返回的完整对象，以保留虚拟字段、系统辅助字段和已适配自定义组件产生的数据；配置阶段不得执行可能产生外部业务写入的提交前钩子。
- 节点动作由节点类型、计划来源和目标模板约束。发起节点默认提交且固定只执行 1 次；审批/协同节点默认且固定一条同意作为正常推进基线，不同意、暂存、回退或移交等终止处理结果会替代默认同意，不能与它并存。平铺动作列表还支持可排在终止处理前的加签节点，每行动作直接设置允许的执行次数和必要参数。动作次数表示计划中的真实执行次数，不是网络失败后的自动重试；每次执行仍需重新读取实例、待办、人员与节点状态。第一审批的直接上级为发起人时禁用回退并提示使用不同意驳回；第二审批及后续节点只有在能静态确定唯一直接上一审批节点时才开放回退并自动绑定目标。动作说明、可用状态和静态禁用原因集中在“动作计划”信息弹层，行内保持完整中文名称和紧凑参数。内部仅为存量兼容继续使用 `arrivals`，不向用户暴露该结构；重复动作有明确上限，不允许任意脚本或无限循环。并行、汇聚、空节点和结束节点没有业务动作时保持只读，不统一伪造“同意/不同意”。取回、撤销、废弃、催办、跟踪、删除和转发属于实例管理或辅助操作，不进入 F-007 节点面板。
- 人员配置必须遵守目标模板。目标只读接口能够解析的人员、岗位、岗级、角色、部门、公司、扩展属性和运行节点选择范围，必须显示具体名称及合法候选，不能只显示内部标识或含糊的“运行时确定”。固定规则只读展示；模板允许选择时可采用目标默认、手动选择、确定性随机或模板允许的全选策略。移交使用当前节点已解析的受限候选，至少选择一人且可多选，并结束当前任务处理；加签按目标新增审批节点语义使用独立的“加签节点处理人”策略，不能用当前节点主处理人是否可编辑作为开关。只有确实依赖未来发起人、未来表单值、真实任务上下文或届时组织关系且当前无法读取的数据，才标记为运行时确定，并说明具体依赖原因。
- 节点保存只确认当前选中节点，不得一次保存就把整条路径的所有节点标成已完成；表单数据使用自己的保存动作和状态。路径状态至少区分未配置、部分完成、已配置和配置失效，并由表单状态与逐节点状态共同派生，不能仅根据配置表是否存在一行判断。
- 保存成功后必须以服务端返回或主动重读的状态为准，保留画布位置并自然引导下一待配置节点。网络结果不确定时使用原幂等键核对服务端结果，不能先提示“保存失败”而刷新后又静默变成已配置；确认失败时才保留当前节点和输入并显示具体原因。
- 配置保存前后都重新读取并核对当前目标结构。目标流程、字段权限、选项或节点动作已变化时，只标记受影响项目需要重新配置并保留仍能准确对应的值，不按名称猜测，不静默清空整条路径。
- F-007 只保存工具侧配置，不调用目标平台提交、审批、回退、业务保存、附件或人员写接口；计划仍保持“待配置”，不能因为字段和动作已经填写就显示“可运行”。
- 节点画布应预留后续运行态，但 F-007 不显示不能真实生效的暂停、继续、单步或临时断点按钮。后续运行态必须复用同一流程画布；临时断点属于单次运行，不回写已保存路径。

## 设置行为

- 常用账号、排除账号和排除流程是共享设置，每次只展示一个设置类别。
- 账号和流程必须从目标平台真实候选中选择，不能手填名称冒充真实对象。
- 最近使用账号只保存在当前浏览器，用于排序，不自动选中，也不形成用户体系。
- 系统设置提供“表单运行时维护”入口，只展示固定 `rsh-flow-components` 来源、分支、任务创建时 HEAD、工作树状态、维护阶段、结果、回退结果和有界在线日志；用户只有“一键同步并更新运行时”，不能输入任意仓库、路径、分支、HEAD 或命令。候选构建失败不影响当前版本，实际服务未通过 HTTP 快照核验或切换失败时自动恢复并复核 previous 版本。

## 明确不做

- 场景、版本、指纹、证据面板、仅观测模式和内部标识体系。
- 修改目标平台、绕过业务校验、模拟或替换真实处理人。
- 任意节点跳转、重置目标实例、跳过失败写动作。
- 周期定时、自动删除、归档体系、删除目标平台数据。
- 手机端流程编辑和旧浏览器兼容。
- 独立技术状态与 JSON 配置页面。
