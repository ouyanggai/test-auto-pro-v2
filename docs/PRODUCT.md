# 产品行为

## 产品目标

“流程自动化测试平台”帮助测试人员选择目标平台真实账号和真实流程，为每条执行路径准备历史业务数据、处理人和动作，按目标平台规则执行，并在真实流程结构上查看状态和结果。

## 产品原则

- 目标平台代码和真实运行结果决定流程、分支、人员与动作语义。
- 工具问题与目标平台问题必须分开说明；暂时无法判断时按工具问题处理。
- 一个整页只处理一项主任务，界面使用中文，桌面优先。
- 计划首次运行前可调整；产生运行记录后固化，后续运行不覆盖历史事实。
- 每条执行路径独占一个真实流程实例；多条路径不共享实例。
- 写操作结果不明确时先核对真实状态，禁止盲目重发。
- 自动准备、提交和失败反馈必须显示真实状态，不使用虚假进度或内部技术术语阻塞用户。

## F-012 历史业务数据回放与节点动作编排

- 当前数据方案同时支持真实 FormMaking 运行时及其已注册自定义组件、目标平台 `vue_custom`/NoFormFlow 自定义表单。两者统一由历史业务数据驱动，是否存在 FormMaking 模板不改变数据链路；通用规则目录、智能生成、随机造数和字段语义猜测均退出当前产品。
- 用户从计划账号当前可见的历史实例中选择数据；候选必须精确匹配 `flowCode` 和目标返回的规范数据身份，FormMaking 使用包含公司后缀的完整表单名，自定义表单使用稳定页面/业务数据键及其完整名称。所有状态均可选择，已完成优先，非完成状态明确提示数据可能不完整。
- 历史选择可作为计划默认来源，每条路径可独立覆盖。没有候选时只引导用户先去目标平台发起并填写一次，不提供生成兜底。
- 系统按当前数据协议的真实 JSON 路径完整回显历史业务载荷：FormMaking 使用 values，自定义表单使用目标页面状态/业务对象；只对当前路径所需的分支驱动字段做可证明的最小补丁，普通字段和未知嵌套数据保持历史事实。
- 条件字段允许人工修改。修改导致实际路径变化时必须展示换路和覆盖影响并征求确认；确认后以人工值为准切换路径，并重新核对新路径人员和动作。
- 分支判断严格采用目标引擎当前操作符、顺序连接、首个命中和末分支兜底语义；手动分支保存显式选择，并行保留全部分支。无法唯一证明的结果进入 `needs_input`，禁止猜测。
- 节点动作目录覆盖目标用户真实可操作的保存草稿、提交、重提、审批暂存、加签、移交、同意、不同意、回退、取回、撤回、催办、转发和关注；系统自动节点只读说明，不提供动作配置。
- 发起端“保存草稿”属于实例生命周期；审批端“暂存当前表单”只保存当前任务检查点，不推进任务，也不作为通用实例动作。
- 用户以多条独立记录配置并排序动作。系统将其编译为同一主实例上的用户步骤、恢复步骤和最终导航步骤；不可恢复顺序在保存时阻止，转发产生的辅助流程单独记录。
- F-012 只完成历史回放、人员/动作配置和场景编译，不创建运行记录，不调用目标平台写接口。完整范围与验收见 `docs/features/F-012-history-form-replay-action-orchestration.md`。

## 主导航

产品只有三个顶级入口：

- 测试计划：创建、配置和启动计划。
- 运行记录：统一查看等待、运行中及历史结果。
- 系统设置：维护常用账号、排除账号、排除流程和表单运行时。

不设置任务中心、报告中心、表单维护或系统状态等额外顶级入口。

## 计划与运行主线

1. 用户输入真实账号并验证，按流程来源选择可见流程模板、已发流程实例或待发流程实例，再选择串并方式及可选定时启动，创建计划。
2. 用户从真实流程结构选择执行路径，为每条路径独立准备历史业务数据、人员和动作；成功断言属于后续运行切片。
3. 运行准备按路径说明阻塞与提醒；用户选择运行模式启动属于后续切片，F-012 只完成配置准备。
4. 每次启动生成独立运行记录，使用目标平台真实账号、实例和接口执行。
5. 运行结果按路径展示；单条路径失败不自动终止其他路径。

## 测试计划页面行为

- 测试计划列表支持按计划名称与计划状态筛选，筛选条件可清空；没有匹配项时显示正常空状态。
- 列表使用产品语言展示计划、流程、发起账号、路径数量、运行方式、定时信息、计划状态和最近运行结果。
- 计划公开状态只有“未运行、运行中、已完成”；未运行的唯一主要入口是“继续配置”，运行中和已完成阶段保持只读边界。节点配置与历史业务数据准备完成度只在路径双状态中展示。
- 新建计划使用独立整页；用户填写计划名称和真实账号，验证账号后选择流程来源、对应流程对象、运行方式、并行最大并发数和可选定时启动。
- 流程来源包括“新发起”“已发”“待发”：新发起选择当前账号可见的流程模板，已发选择当前账号的已发流程实例，待发选择当前账号的待发流程实例；页面不使用统一“目标流程”字段混淆三类对象。
- 流程模板候选优先展示名称、分类、流程分组、表单关联、用途备注和更新时间；有 `groupName` 时以小型标签高亮，编码和启停状态不影响当前选择时不作为主要信息展示。
- 未验证账号时只能保留“新发起”来源，“已发”“待发”不可选择；账号内容变化会立即使验证失效，并清空已有模板或实例选择。
- 并行最大并发数只在并行模式出现；定时启动关闭时不保留定时时间。
- F-001 只提供静态原型：校验成功不保存计划、不加入列表，也不进入路径选择页。
- F-003 起，点击“创建并选择路径”才真正保存计划；成功计划进入“未运行”，刷新页面或重启服务后仍出现在测试计划列表，唯一主要入口为“继续配置”。
- 创建请求失败时保留当前输入并允许重试，不能显示虚假成功；同一次创建操作重复提交只能得到同一条计划。
- 测试计划列表从 F-003 起只显示真实持久化数据，不再混入静态 mock；默认按最近修改时间倒序，读取失败明确提示并允许重试。
- F-003 的继续配置入口只展示已保存计划和“尚未选择执行路径”的真实状态；执行路径必须在读取真实流程结构后才能建立，不预先生成空路径或伪路径。

## 只读真实流程图行为

- F-004 从已保存计划重新读取目标平台当前真实结构：新发起使用流程模板树，已发和待发使用各自流程实例的代理树。
- 页面显示发起、审批、协同、空节点和结束等真实业务节点；条件、手动分支和并行路由不显示为独立卡片，而以分叉树干、真实分支名称和汇合关系表达，不显示节点编码或策略编码。
- 流程结构使用板正的树形布局：主干垂直、同一分叉共用一条水平分支轨、各分支按列向下、分支末端共用一条水平汇合轨后回到主干；不得用通用图压缩产生弯绕和交叉。
- 流程图允许平移、缩放和适配视口，但节点不可拖动、连线、删除或选择为执行路径。
- 大流程默认保持节点与文字可读，不为塞进一屏而压缩整图；画布提供右上角页面全屏入口，在当前浏览器页面内铺满可用视口，用户通过无限画布拖动查看展开结构。
- 连线使用克制的方向流动效果帮助辨认走向；系统开启减少动态效果时必须停止动画并保留清晰静态线条。
- 目标对象已不可见、待发已经处理或流程尚无节点时必须说明当前事实，不使用保存名称、模板结构、V1 mock 或上次结果伪造实例图。
- F-004 不保存流程图或路径；用户选择并持久化执行路径从 F-005 开始。

## 执行路径选择行为

- 用户在 F-004 已核实的真实流程树上逐条建立执行路径；新发起计划创建后后台自动解析全部合法完整组合，用户可查询、取消或恢复解析任务，不需要手动触发生成。
- 普通画布不显示右侧路径管理面板，主入口使用带文字的“新增路径”，页面全屏只负责查看流程结构；点击已保存路径进入只读详情后，详情内才提供“编辑路径”。普通浏览和只读详情不得出现可误触的分支控件。
- 条件分支和手动分支在一条执行路径中必须且只能选择一个可达分支；并行节点的全部真实分支同时属于同一条执行路径，不能拆成多条路径，也不能任选一支。
- 嵌套在并行分支中的条件或手动分支仍需分别完成选择；不在当前已选线路上的分支点不要求选择。
- 编辑模式使用轻量悬浮面板显示标题、人工决策进度、名称和实时流向；进度只统计当前可达的条件与手动路由，并行不计。用户每完成一处选择，主画布把下一待选点平滑移动到扣除面板后的操作区域中央，并用带明确箭头的就近气泡指向它，路径完整后明确引导保存，不自动代替用户保存。
- 已选线路使用显著高亮和方向流动效果；当前待选位置使用独立提示状态；未选择、未参与当前路径的线路保持静止并弱化，但候选名称仍可清楚阅读和点击。减少动态效果开启时停止动画，用线宽、颜色和文字继续表达状态。
- “新发起”计划可以保存多条执行路径，也允许复制同一条节点线路，供后续使用相互独立的真实流程实例和业务数据；每条路径拥有不会复用的稳定自动序号，默认名称为“路径 N”，用户可以自定义名称，但界面始终单独显示稳定序号。
- 全路径解析按后台批次执行，列表展示每条路径和总进度，任务支持查询、取消与恢复；不存在固定业务数量上限，服务端仅以批次大小、并发和超时保护资源，不把合法路径静默截断。
- 当前创建页的“已发”和“待发”计划各绑定一个真实流程实例，因此一个计划最多保存一条执行路径；路径从实例当前真实节点或并行活动节点继续配置，已走过且不可再影响的分支不允许重新选择。
- 完整路径保存后才计入计划的路径数量；未完成的本地草稿不计数。用户可以继续编辑或删除尚未产生运行记录的路径。
- 编辑中取消或退出页面全屏时，只有名称或线路真实变化才要求确认；确认放弃后清空本次草稿，不提供“继续选择”恢复入口。保存成功只反馈一次，刷新路径计数并回到没有活动面板的普通画布；保存失败或真实流程变化时保留当前编辑和草稿。
- 目标流程发生变化时，每次打开页面都用当前真实结构重新核对保存的分支选择；仍能精确对应的选择保留，无法对应的路径标记为需要重新选择，不按名称猜测、不自动删除，也不保存版本号、指纹或流程图快照。
- F-005 完成路径拓扑选择后计划仍保持“未运行”；历史业务数据、真实人员和节点动作由 F-012 配置，成功断言和真实运行准备属于后续切片，不能把路径完成度写入计划公开状态。

## 路径要求与配置边界

- F-006 的真实流程树、已选分支、人员规则和节点类型仍是 F-012 的只读输入；不再维护独立要求页面或第二套拓扑。
- 条件名称、分支关系、人员规则和系统节点继续以目标平台真实配置投影，公开界面不显示字段英文名、内部 ID 或判断代码；无法精确对应时定位为需人工处理。
- F-005 只负责在真实流程结构上选择、命名、保存、编辑、复制和删除执行路径。它不保存表单值、人员、动作或运行事实。
- F-012 在已保存路径上分别配置人员、历史业务数据和用户动作。路径拓扑改变与数据实际命中路径是两个明确操作；实际换路必须经过用户确认并重新核对新路径配置。
- 已发和待发计划继续从真实实例代理树读取可影响的后续节点；新发起从真实模板读取结构。任何准备操作都不调用目标平台写接口，也不把历史数据当作流程图快照。

## 路径节点与表单配置工作区

- 保留 F-005 已验收的路径选择与编辑交互。没有已保存路径时先配置路径；每条已保存路径分别进入节点配置和历史业务数据配置。
- 节点配置页复用真实 Vue Flow 结构并高亮当前路径；路径外节点只读。点击当前路径业务节点后，在固定侧栏配置人员和 F-012 有序动作，系统自动节点只展示自动语义。
- 人员配置继续遵守目标模板和当前账号可见候选。能够读取到的人员、岗位、岗级、角色、部门和公司必须显示业务名称；真正依赖未来实例事实的项才标记为运行时确定。
- 数据工作区根据 `renderType` 选择 FormMaking iframe 或自定义表单运行时，但两者都使用历史业务载荷、真实校验、数据捕获和会话销毁；身份与 SID 只存在当前会话，关闭或切换上下文后销毁。
- 数据工作区只提供历史来源、来源差异、恢复历史快照、分支补丁说明和保存。智能生成、换一组、规则状态、旧 Vue 生成桥接和旧样本兜底不再出现。
- 节点保存只确认当前节点，数据保存只更新当前路径载荷；保存后以服务端重读结果为准。节点状态为 `pending | partial | configured | affected`，数据状态为 `empty | needs_input | ready | affected`。
- 保存前后重新读取当前目标结构和数据协议；精确对应的值保留，模板/页面、路径、人员或动作变化只把受影响项标记为待核对，禁止按名称猜测。
- 配置阶段只写本测试工具数据库，计划保持“未运行”，不创建运行记录，不向目标平台发送流程或业务写请求。

## F-012 动作配置交互

- 当前节点的动作工作区显示真实可用动作、必要参数、门禁和中文禁用原因；用户以多条独立记录表达重复动作，并通过拖拽调整执行顺序，不再使用次数、循环或复制模型。
- 保存动作时同时生成只读场景预览，明确区分用户动作、系统恢复和系统导航，并展示演员、预期节点、前置状态、预期效果及重读屏障。
- 保存草稿和审批暂存使用不同名称与位置；加签、移交、取回、撤回、回退、催办、转发和关注均按目标实际上下文显示，不能用统一节点动作入口掩盖实例或任务门禁。
- 动作顺序无法在同一主实例上恢复时不能保存，并定位第一条问题；界面不得通过新建主实例、隐藏系统步骤或跳过目标门禁来伪造可执行性。
- 计划详情的批量入口改为历史回放，只处理用户勾选路径；展示真实任务进度、当前路径、`ready`、`needs_input` 和失败数量，支持取消、刷新恢复和继续未完成项。

## 设置行为

- 常用账号、排除账号和排除流程是共享设置，每次只展示一个设置类别。
- 账号和流程必须从目标平台真实候选中选择，不能手填名称冒充真实对象。
- 最近使用账号只保存在当前浏览器，用于排序，不自动选中，也不形成用户体系。
- 系统设置提供“表单运行时维护”入口，只展示固定 `rsh-flow-components` 来源、分支、任务创建时 HEAD、工作树状态、维护阶段、结果、回退结果和有界在线日志；用户只有“一键同步并更新运行时”，不能输入任意仓库、路径、分支、HEAD 或命令。候选构建失败不影响当前版本，实际服务未通过 HTTP 快照核验或切换失败时自动恢复并复核 previous 版本。

## 明确不做

- 配置版本管理、指纹面板、证据面板、仅观测模式和面向用户的内部标识体系。
- 修改目标平台、绕过业务校验、模拟或替换真实处理人。
- 任意节点跳转、重置目标实例、跳过失败写动作。
- 周期定时、自动删除、归档体系、删除目标平台数据。
- 手机端流程编辑和旧浏览器兼容。
- 独立技术状态与 JSON 配置页面。

## F-000 应用壳主题决策

- 用户已在 2026-07-27 的 F-000 人工反馈中确认：应用壳提供浅色与深色主题切换，选择保存在当前浏览器并在刷新后保持。
- 此决定覆盖此前“只做浅色、不提供主题切换”的历史约束；主题仅影响应用壳呈现，不增加业务页面或业务行为。

## 人工验收原则

每个功能切片自动验证完成后必须停下，由用户在浏览器或真实目标环境中核对；没有用户明确确认，不得标记为已验收或继续下一功能。
