# 流程自动化测试平台 - 项目概况

## 项目背景

流程自动化测试平台是针对目标业务系统（润世华集团全过程管理平台）开发的专用测试工具。该平台帮助测试人员基于真实账号和真实流程，准备不同执行路径所需的人员、动作与表单数据，并逐步形成可运行、可追溯的流程测试方案。

**核心价值**：
- 基于目标平台真实代码和运行结果验证流程行为
- 支持复杂流程的多路径覆盖测试
- 自动化准备测试数据和执行环境
- 提供可追溯的测试记录

## 项目定位

- **产品名称**：流程自动化测试平台
- **目标平台**：参考代码目录中的现有业务系统（全过程管理平台）
- **用户群体**：测试人员、质量保证团队
- **使用场景**：流程功能测试、回归测试、多路径覆盖测试

## 技术架构

### 技术栈

**后端**：
- 语言：Go 1.25
- 框架：标准库 `net/http`
- 数据库：MySQL（独立工具数据库 `test_auto_pro_v2`）
- 热重载：Air

**前端主应用**：
- 框架：Vue 3 + Vite
- 路由：Vue Router
- 状态：Pinia
- UI 组件：Naive UI
- 端口：19000

**表单运行时**：
- 框架：Vue 2（独立服务）
- UI 组件：Element UI + FormMaking
- 端口：19001
- 说明：专门渲染目标平台 FormMaking 表单，通过 iframe 接入主应用

**后端服务**：
- 端口：19080
- 健康检查：`http://127.0.0.1:19080/api/health`

## 运行环境

### 开发环境要求
- **Go**：1.25+
- **Node.js**：≥20.19
- **pnpm**：10.25
- **MySQL**：可连接的 MySQL 服务
- **配置文件**：项目根目录 `.env.local`（包含 MySQL 和目标平台配置）

### 环境配置

`.env.local` 文件包含：
- `PLAN_DB_*`：工具侧 MySQL 数据库配置
- `TARGET_*`：目标平台连接配置（网关、账号、密钥等）

**安全说明**：`.env.local` 由项目负责人私下提供，已被 Git 忽略，不得提交到仓库或共享其中的凭证。

### 启动步骤

1. **安装依赖**：
```bash
pnpm install
```

2. **确认配置**：确保项目根目录存在 `.env.local`

3. **启动服务**（三个终端）：

```bash
# 终端一：后端服务
pnpm dev:b
```

```bash
# 终端二：主前端
pnpm dev:f
```

```bash
# 终端三：表单运行时
pnpm dev:form
```

4. **访问应用**：[http://127.0.0.1:19000](http://127.0.0.1:19000)

### 健康检查

```bash
curl -fsS http://127.0.0.1:19080/api/health
```

### 常见问题

**端口被占用**：
停止占用 19080、19000 或 19001 的本机进程后重试。

**缺少 .env.local**：
向项目负责人索取本机配置，不要自行提交或共享凭证。

**MySQL 不可用**：
确认 `.env.local` 中的 `PLAN_DB_*` 配置和数据库服务可连接。

**目标配置缺失**：
确认 `.env.local` 中的 `TARGET_*` 配置有效；健康检查可以正常，但读取目标流程会失败。

## 开发规范

### Git 提交规范
- 提交信息使用中文
- 遵循 Conventional Commits 格式
- 类型：feat、fix、refactor、docs、test、chore、perf、ci

### 测试策略
- 目标覆盖率：80%+
- 包含单元测试、集成测试、契约测试
- 每个功能切片有专用验证脚本（`test/run-f*.sh`）

### 代码风格
- 后端：遵循 Go 官方代码规范
- 前端：使用 TypeScript，ESLint + Prettier
- 优先不可变数据结构
- 小文件原则（200-400 行，最多 800 行）

### 功能切片管理
- 每个功能切片（F-XXX）独立规划、实施、验证
- 状态流转：awaiting_approval → implementing → ready_for_manual → accepted
- 每个切片有独立文档（`docs/features/F-XXX.md`）
