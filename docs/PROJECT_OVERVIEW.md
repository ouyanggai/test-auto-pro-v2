# 项目核心痛点

## 我们在做什么

为目标平台流程测试自动生成测试数据。用户选择一条流程路径后，系统需要智能生成满足该路径所有条件的表单数据。

## 当前卡点：表单数据生成规则引擎缺失

### 问题现状

系统已经有这些能力，但**各自为政、缺少统一规则引擎**：

1. **模板规则解析**（`internal/formruntimemaintenance`）
   - 已能解析 735 个流程模板
   - 提取 FormMaking JSON 配置
   - 识别字段类型、校验规则、选项列表

2. **自定义组件解析**（`internal/formruntimemaintenance`）
   - 已适配 20+ 真实 Vue 自定义组件
   - 识别组件值形态（字符串、数组、对象）
   - 获取外部候选数据源（部门、人员、项目等）

3. **条件字段绑定**（`internal/formdata/generator.go`）
   - 已能解析路径条件（如：金额 > 1000 进分支 A）
   - 自动锁定关键字段
   - 基础约束生成

4. **智能生成器**（`internal/formdata/generator.go`）
   - 基础字段类型生成（文本、数字、日期）
   - 缺少统一约束求解

### 核心缺陷

**没有通用规则引擎统一处理**：
- 路径条件约束（金额 > 1000）
- 字段校验规则（必填、范围、正则）
- 字段间依赖（A 选了 X，B 必须是 Y）
- 自定义组件约束（项目必须属于当前部门）
- 数据一致性（同一表单多个日期字段的先后顺序）

### 典型场景

用户选择路径：金额 > 10000 → 部门经理审批 → 总经理审批

**期望**：
- 生成金额 = 15000（满足 > 10000）
- 项目归属 = 用户所在部门
- 申请日期 < 审批截止日期
- 所有必填字段有值
- 所有字段符合格式校验

**现状**：
- 只能生成基础类型随机值
- 不能保证约束一致性
- 自定义组件靠硬编码特殊处理
- 字段间依赖关系靠人工检查

## 需要什么

### 设计一个通用规则引擎

**输入**：
1. 完整 FormMaking 模板规则（已有）
2. 自定义组件元数据（已有）
3. 路径条件约束（已有）
4. 用户身份上下文（已有）

**输出**：
- 满足所有约束的完整表单数据

**核心能力**：
1. **约束收集**：统一表达各种规则
   ```
   - 路径条件：amount > 10000
   - 必填约束：required = true
   - 范围约束：0 < amount < 1000000
   - 依赖约束：if projectType == "A" then department != null
   - 自定义约束：project.department == user.department
   ```

2. **约束求解**：生成满足所有约束的值
   - 处理数值范围交集
   - 处理字段间依赖
   - 处理枚举选项过滤
   - 处理日期先后顺序

3. **冲突检测**：识别无解场景
   ```
   amount > 10000 AND amount < 5000  → 无解，提示用户
   ```

4. **扩展性**：新增组件类型不改引擎核心

### 关键代码位置

- 生成器入口：`internal/formdata/generator.go`
- 条件解析：`internal/analyzer/condition.go`
- 组件适配：`internal/formruntimemaintenance/component_registry.go`
- 规则目录：`internal/repository/template_catalog.go`

### 参考方向

可能的技术选型（需调研）：
- 约束求解器（CSP Solver）
- 规则引擎（如 Rete 算法）
- 基于 AST 的表达式求值
- 类型系统 + 约束传播

---

**核心诉求**：如何设计一个通用、可扩展的规则引擎，统一处理表单数据生成的所有约束？
