# 项目概览

## 我们在做什么

“流程自动化测试平台”让测试人员从目标平台真实流程结构中选择执行路径，为每条路径准备人员、表单数据和动作，之后在同一个真实流程实例上执行并记录结果。

## 当前方案

复杂表单不再依赖规则解析器、随机生成器或大模型。用户先在目标平台产生一份真实历史实例，工具按计划账号当前可见范围、精确 `flowCode` 和完整表单名称选择历史数据，并深复制完整 FormMaking values。回放到当前模板时，只对当前路径的分支驱动字段做可证明的最小补丁，其他字段原样保留；无法唯一证明的字段由用户在真实 FormMaking 工作区补齐。

F-012 只支持真实 FormMaking 运行时和已注册的 FormMaking 自定义组件。`vue_custom`、NoFormFlow、模板规则目录、通用 ConstraintIR、智能生成、随机造数和无历史兜底均被删除，不保留兼容链路。

## 流程动作方案

动作规则以目标工作流后端和 `GroupApproveManage` 的实际按钮、请求和门禁为准。动作按以下边界组织：

- 发起生命周期：保存草稿、提交、重新提交。
- 当前待办：审批暂存、同意、不同意、回退上一节点、加签、移交。
- 已办与实例管理：取回、撤回、催办、转发、关注/取消关注。
- 系统自动：条件、手动分支、并行、汇聚、空、结束、定时、子流程和回调。

发起“保存草稿”改变实例生命周期；审批端 `storageFormData` 只保存当前用户、批次和节点的任务检查点，不推进任务，也不是通用实例动作。加签仅在当前活动人工待办且代理可编辑时成立；回退只允许目标后端提供的直接前驱；不可恢复的删除/作废不进入编排。

用户动作按独立记录排序。系统将其编译为同一主实例上的用户步骤、恢复步骤和导航步骤，遇到驳回或撤回后重提、同意后取回、回退重走、移交换演员、加签重读代理等情况，都必须重新读取目标事实。不能恢复的顺序在保存时阻止，不创建新的主实例，不使用数据库快照恢复。

## F-012 交付边界

本切片交付历史候选与快照、路径级来源覆盖、批量回放、分支最小补丁、人员/动作配置和只读场景编译。它只写测试工具自己的 MySQL，不创建运行记录，不调度，不向目标平台发送流程或业务写请求。目标平台数据库、Mongo、实例和源码均保持不变。

详细执行任务、接口、数据表、删除清单、自动验证和人工验收步骤见 `docs/features/F-012-history-form-replay-action-orchestration.md`。
