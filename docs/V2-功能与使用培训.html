总览

工具是做什么的

这个页面做什么：帮测试人员在目标平台上自动跑通多级审批流程并记录结果，全程用真实账号、真实流程、真实历史数据、真实执行。
功能点
  • 用途：替代手工登录多个账号、逐个节点点"同意"、手工造测试数据的重复劳动。
  • 四个菜单：测试计划（建计划、配置、启动）、任务中心（看任务和过程）、报告中心（真实度量）、系统设置（账号与运行时）。
  • 一条主线：建计划 → 选执行路径 → 配数据 / 人员 / 动作 → 检查并启动 → 看结果。
  • 底线：工具只读取和驱动目标平台，绝不改它的数据、权限和业务规则。
设计思路
界面一页只做一件事，桌面优先，全中文。下面按左侧菜单从上到下，逐个页面讲清功能点。

01
测试计划

测试计划列表

这个页面做什么：所有测试计划的入口，看到已有计划，进去继续配置或运行。
功能点
  • 筛选：按计划名和计划状态筛选，条件可清空；没有匹配项时显示正常空状态。
  • 列表信息：一行看清计划、流程、发起账号、路径数量、运行方式、定时信息、计划状态和最近一次运行结果。
  • 计划状态：只有未运行 / 运行中 / 已运行三种，由真实运行事实决定；"已运行"只表示有过运行记录，不代表最近一次成功。
  • 每行入口：所有计划都提供"编辑计划""编辑路径""运行"（未配置完时为"继续配置"）。
设计思路
状态只用于展示和筛选，不决定能不能改、能不能再跑；改计划只影响以后的运行。列表只显示真实持久化数据，默认按最近修改时间倒序，读取失败会明确提示并允许重试。
02
测试计划

新建计划

这个页面做什么：用一个整页填完一个计划的基本设置。
功能点
  • 计划名 + 账号验证：填计划名和一个真实账号，先验证这个账号能不能登录目标平台。
  • 流程来源：新发起（选流程模板）、已发（选已发实例）、待发（选待发实例），三类分开，不用一个字段混着。
  • 对象选择：按来源列出候选，显示名称、分类、流程分组、表单关联、更新时间等真实信息供挑选。
  • 运行方式：串行或并行；并行时可设最大并发数。
  • 定时启动：可选；关掉后不保留定时时间。
设计思路
账号一改，验证立即失效、已选的模板 / 实例清空，防止拿旧账号跑错配置；未验证账号时只能用"新发起"。点"创建并选择路径"才真正保存，成功后计划进入"未运行"，刷新或重启后仍在列表里。
03
测试计划

执行路径选择

这个页面做什么：在目标平台当前真实的流程图上，选出这次要测的一条条路径。
功能点
  • 只读流程图：实时读回目标真实结构，可平移、缩放、适配视口，但节点不能拖动、连线或删除。
  • 新增路径：用"新增路径"在流程图上逐处选择分支走向，完成后保存。
  • 分支规则：条件分支、手动分支每处必须且只能选一个可达走向；并行分支的全部真实分支自动同属一条路径。
  • 复制路径：同一条线路可复制多份，各自使用相互独立的真实实例和数据；每条路径有稳定序号。
  • 全路径解析：新发起计划创建后后台自动算出全部合法完整路径，可查询、取消或恢复，不用手动触发。
设计思路
一条执行路径 = 一个真实流程实例；已发 / 待发计划各绑定一个实例，最多一条路径。目标流程变了，每次打开都用当前结构重新核对，对得上的保留，对不上的标"需重选"，不按名字猜、也不自动删。
04
测试计划

节点配置 · 人员

这个页面做什么：给路径上需要选人的节点，配好由谁来处理。
功能点
  • 人员规则展示：每个业务节点都显示人员规则、来源、能不能手选和当前状态，能读到的人员 / 岗位 / 部门都显示业务名称。
  • 随机 / 手动：目标开放选人的节点，可一键在合法范围内随机选一人，也可手动在同一范围内选。
  • 会签 / 竞签：会签按目标规定的人数约束，竞签只选一人。
  • 主处理人 vs 动作接收人：节点主处理人与加签 / 移交 / 转发的接收人是两个独立配置域，一键配置不会互相覆盖。
设计思路
固定人员、发起人关系、职级、表单人员等由目标运行时决定的项，只标"运行时确定"，工具不伪装成可手选候选。候选失效或范围解析失败时阻止保存。
05
测试计划

历史数据配置

这个页面做什么：给这条路径准备表单数据——挑一条真实历史实例来回放。
功能点
  • 选历史来源：从当前账号可见的历史实例里挑一条作为数据来源，已完成状态优先。
  • 原样回显：历史表单数据按原始 JSON 结构完整回显到复制的表单运行时里。
  • 最小分支补丁：只对影响这条路径分支走向的字段做可证明的最小改动，普通字段和未知数据保持历史事实。
  • 条件字段可改：允许手动修改条件字段；修改导致实际换路时会展示影响并要你确认，确认后重新核对新路径。
设计思路
没有候选时只引导你先去目标平台发起、填写一次，不提供造数兜底；非完成状态会提示数据可能不完整。这一步只写工具自己的库，不向目标平台发任何写请求。

测试计划

动作配置

这个页面做什么：配每个节点要执行哪些动作、按什么顺序执行。
功能点
  • 动作工作区：显示当前节点真实可用的动作、必要参数、门禁和中文禁用原因。
  • 多条记录 + 拖拽排序：用多条独立记录表达重复动作，拖拽调整执行顺序，不用次数或循环模型。
  • 一键配置：自动给每个可配置节点补一个合理的额外动作，省得逐个点；没有安全动作的节点会说明原因。
  • 固定尾动作只读：发起节点固定"提交"、审批节点固定"同意"，由系统生成、永远排在最后、不可增删移动。
  • 场景预览：保存后生成只读预览，区分用户动作、系统恢复步骤和系统导航。
设计思路
系统会自动补"回退 / 撤回后重新走一遍"这类恢复步骤；动作顺序在同一实例上恢复不了就不让保存，并指出第一条问题。所有动作名称统一用中文显示。
07
测试计划

运行前检查与启动

这个页面做什么：启动前把问题摆清楚，再选怎么跑。
功能点
  • 阻塞 vs 提醒：阻塞必须先解决，能点着直接跳到要修的地方；提醒不挡启动，交给你判断。
  • 运行模式：自动跑完、单步、或人工逐步放行，三选一后启动。
  • 人工控制按钮："执行这一步""继续执行后续步骤"，按钮旁写明会不会发真实写请求、停止何时生效。
设计思路
每次启动生成一条独立、改不了的运行记录，并冻结当次配置快照；单条路径失败不会自动终止其他路径。

任务中心

任务列表

这个页面做什么：统一看所有任务的状态和结果（页面名"任务列表"）。
功能点
  • 三类一起看：等待中、运行中、历史结果放在一个列表里查看。
  • 结果状态：成功 / 失败 / 已停止 / 已取消 / 等待运行 / 运行中，另有一个诚实的"结果待确认"。
  • 进入详情：点任意任务进入运行画布，看这次到底怎么跑的。
设计思路
真结果只有成功和失败；"结果待确认"表示写请求发出去了但确认不了成没成（超时、响应丢失等），不给重试，只能重新发起，工具绝不盲目重发。状态一律以真实运行事实为准。
09
任务中心

运行画布与节点详情

这个页面做什么：看一次运行的全过程，以及每个节点到底发生了什么。
功能点
  • 节点三态：已执行、正在执行、待执行，用不同主题色区分，一眼看清进度。
  • 节点动作详情：谁在哪个节点做了什么动作、什么结果、用了多久、调了哪些接口。
  • 大白话优先：首屏说清动作 / 节点 / 处理人 / 结果 / 下一步；技术阶段、参数和原始报文收进"查看日志"折叠区。
  • 重试：确定失败可从失败那一步重试；"结果待确认"没有重试入口，只能从计划重新发起。
设计思路
路径实际走向和配置对不上时会硬停下并显示预期与实际节点，不提供绕过入口；运行期新增的加签等节点也会按实例最新结构投影出来。工具绝不自动继续或重发写请求。

报告中心

报告中心 · 总览与下钻

这个页面做什么：用真实运行记录看测试度量，从全局逐级钻到单次运行。
功能点
  • 总（计划全景）：全部计划的总览：计划数、运行次数、路径运行次数、结果分布、最近运行。
  • 分（计划详情）：点进一个计划，看它各条路径的运行次数、成功率、平均步骤、平均耗时、覆盖动作。
  • 分（路径详情）：点进一条路径，看它每次运行实例的状态、结果、步骤数、总耗时、调了哪些接口及耗时分解。
  • 专业指标：成功率、一次通过率、路径覆盖度、耗时分位、停机分类、重试统计等，每个都随卡片写清算法和分母。
设计思路
所有数字只来自真实运行记录，不造数、不预估；耗时按真实计时，没有记录就写"未知"，不用 0 毫秒冒充。图表用成熟图表库渲染，不手写。

系统设置

系统设置 · 账号与流程

这个页面做什么：维护建计划时常用到的账号和流程范围。
功能点
  • 常用账号：维护常用的目标真实账号，建计划时方便选。
  • 排除账号：标记不参与的账号；加签排除名单会自动过滤停用账号，避免选到登录不了的人导致运行卡住。
  • 排除流程：标记不测的流程。
设计思路
账号和流程都必须从目标平台真实候选里选，不能手填名字冒充真实对象；最近使用只存在当前浏览器、用于排序，不自动选中。
12
系统设置

系统设置 · 表单运行时维护

这个页面做什么：维护渲染表单用的运行时组件，保持最新可用。
功能点
  • 一键同步更新：一个按钮把表单运行时从固定来源同步并更新到最新。
  • 状态展示：展示来源、分支、HEAD、工作树状态、维护阶段、结果和有界在线日志。
设计思路
用户只能一键同步，不能输入任意仓库、路径、分支或命令；候选构建失败不影响当前版本，实际服务没通过核验或切换失败时会自动回退到上一个可用版本。

小结

记住这几件事

这个页面做什么：一页回顾这个工具最核心的取舍。
记住三点
  • 全真实：真实账号、真实流程结构、真实历史表单数据、真实发请求执行。
  • 三条底线：一次写、写完重读目标确认、拿不准就停下，绝不乱重发。
  • 只读驱动：只读取和驱动目标平台，不改它的数据、权限和业务规则。
明确不做
不改目标平台、不绕过业务校验、不模拟或替换真实处理人；不做周期定时、不自动删除、不删目标平台数据。
