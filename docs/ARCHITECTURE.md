# 技术架构

## F-012 历史业务数据回放与动作场景编译

F-012 取代旧的规则目录、ConstraintIR、通用生成器和路径准备数据链路。当前唯一产品数据来源是目标平台当前可见的历史表单数据实例，覆盖 FormMaking 与 `vue_custom`/NoFormFlow 自定义表单；当前唯一动作来源是目标平台后端与 GroupApproveManage 已证明的用户入口及其运行时门禁。各种表单的渲染由复制的目标平台 `form-runtime` 负责，测试工具只负责选择、保存和传递数据。

### 历史表单数据回放

- `internal/adapter/target` 只读读取计划账号可见实例，服务端沿目标接口原字段过滤候选；有表单时精确匹配完整表单名（含公司后缀），无表单时使用目标返回的流程/页面名称等原始字段。全状态可选，已完成优先，响应只返回不透明候选键和业务摘要。
- 用户确认候选后，在同一只读会话内深复制目标接口返回的完整表单数据、实例摘要和模板/页面摘要，写入 `test_history_data_snapshots`。候选后续变化不能改变快照；工具侧不直连目标 Mongo，也不改变目标数据结构。
- `internal/formdata` 只按目标流程条件返回的真实 JSON 路径处理历史表单数据，保留嵌套对象、数组、子表、虚拟字段、系统字段和无表单页面数据；禁止按标签、中文名、组件类型或页面位置猜测。新增普通必填字段进入人工输入清单，删除字段进入差异摘要。
- `form-runtime` 是从目标平台复制的运行时，负责 FormMaking、有表单自定义组件和无表单自定义页面的渲染、回显、编辑、校验和数据捕获。测试工具只按其既有协议传入目标表单数据及必要上下文，不新增页面运行时、数据包装或字段绑定规则。

### 条件与路径补丁

- 独立的 `internal/formdata/branchoverlay` 只实现目标 Java 已核实的 `lt`、`gt`、`lte`、`gte`、`eq`、`neq`、`contains`、`is_update`、`is_not_null`、`boolean_value`。
- 比较按目标 BigDecimal 转换、固定值/字段右值和真实 `contains`（B 包含 A）方向执行；条件组保持保存顺序及实际 `and/or` 连接，不做代数重排。
- 同一路由按目标顺序取第一个成立分支，最后分支是兜底；手动分支记录显式选择，并行保留全部线路。目标 `boolean_value` 当前实现若出现自相矛盾，返回不可满足，不修正语义。
- 在目标原始表单数据上只做最小字段补丁，候选来源限于历史现值、目标条件字段真实选项、常量和边界；按修改字段数、值偏移、字段路径稳定排序确定唯一结果。无唯一解或无法证明时返回 `needs_input`，不生成值。
- 表单数据保存必须重算实际路径。路径变化需要用户确认令牌；确认后人工值优先，原路径配置保留，新路径原始数据原子写入并把受影响人员/动作标记为 `affected`。

### 动作目录与门禁

- `internal/engine/actioncatalog` 将动作分为发起生命周期（保存草稿、提交、重新提交）、当前待办（审批暂存、同意、不同意、回退、加签、移交）、已办恢复（取回）、实例管理（撤回、催办、转发、关注/取消关注）和系统自动节点。
- 发起“保存草稿”是实例生命周期；审批 `storageFormData` 是当前用户/批次/节点检查点，不改变任务或实例状态，不作为通用实例动作。删除/作废等不可恢复终止能力不进入编排。
- 目录按目标当前实例、代理、任务、演员和权限计算 `enabled`、中文禁用原因、参数、预期效果及重读要求。加签只允许当前活动人工节点且会通过 `updateFlowProxy` 处理私有代理；移交使用 `approverAppend`；取回、撤回、催办、转发和关注分别遵守目标页面与服务端门禁。
- 条件、手动、并行、汇聚、空、结束、定时、子流程和回调只展示系统自动语义，不提供用户动作配置。

### 同一主实例场景编译

- 用户动作以多条独立 `ConfiguredAction` 保存，使用语义节点键和动作键，不保存临时 task/proxy ID；重复动作由重复记录表达，用户可排序。
- `internal/engine/scenario` 把动作编译为 `CompiledActionStep`：用户步骤、系统恢复步骤和系统导航步骤分别记录演员、节点、参数、前置事实、预期效果、恢复策略和强制重读屏障。
- 编译器只允许同一个主流程实例：同意后取回、取回前准备同意、驳回/撤回后重提、回退后重走、移交换演员、加签后重读私有代理、转发旁支、催办/关注无状态迁移和最终导航均按目标事实编译。不能恢复的顺序在保存时拒绝；不使用数据库快照恢复或新建主实例。
- 编译结果为未来单步执行游标预留，但本切片不调用目标写接口、不创建运行记录、不调度执行。

### 工具侧接口与并发

- 新增历史数据候选、默认来源、路径来源、历史回放任务、任务明细、取消/恢复和编译预览接口；保留配置读取、节点保存和数据保存接口但重定义为 F-012 协议。
- 所有写入要求配置修订号和 `Idempotency-Key`；服务端在事务内核对计划/路径归属、目标只读快照、当前修订和实际路径，网络不确定时以同一幂等键对账。
- 历史回放任务按计划单活动、路径明细独立终态、游标分页、租约和可恢复检查点实现；单路径失败不回滚其他路径，取消不删除已完成结果。

## 固定选型

- 主前端：Vue 3、Vite、Vue Router、Pinia、Naive UI；F-012 的 `form-runtime/` 是唯一隔离例外，直接使用从目标平台复制的 Vue 2、Element UI 和多表单运行时，并通过 iframe 接入主应用。
- 后端：Go 单体，一个二进制进程；F-000 使用标准库 `net/http`。
- 包管理：pnpm。
- 本地端口：前端 `19000`，后端 `19080`；前端开发服务器将 `/api` 代理到后端。
- Go module：`test-auto-pro-v2`。

主应用不采用 Vben Admin、Element Plus 或其他中后台应用基座，也不直接混用 Vue 2 组件；历史 PRD 中相反描述已被本文件取代。

## 本地开发方式

- 根目录 `package.json` 仅提供全栈开发与检查命令；Go 依赖仍只由 `go.mod` 管理。
- F-012 继续使用根目录 `pnpm-workspace.yaml`，只包含 `web` 与 `form-runtime`，从根目录执行 `pnpm install` 仍只生成一个 `pnpm-lock.yaml`。
- 前端在一个前台终端执行 `pnpm dev:f`，仅启动主 Vue 3 应用并监听 `127.0.0.1:19000`；表单运行时在独立前台终端执行 `pnpm dev:form`，监听 `127.0.0.1:19001` 并提供热更新，主应用通过固定 iframe 地址使用它。
- 后端在另一个前台终端执行 `pnpm dev:b`，实际命令为 `go tool air -c .air.toml`。Air 固定为 Go 1.25 tool dependency，构建 `cmd/server` 到被忽略的 `.runtime/`。
- 两个前台进程的日志留在各自终端，用户通过 `Ctrl+C` 停止；不使用后台守护、PID 文件、日志文件、`concurrently` 或后台重启命令。
- `.air.toml` 只监听项目 Go 源码，排除 `.git`、`.runtime`、根目录 `node_modules`、`web`、`参考代码`、`test`、`docs` 和历史资料。

## 系统边界

```text
浏览器 -> Vue 单页应用 -> Go HTTP API -> 目标平台适配层 -> 目标平台
                              |
                              -> 工具侧存储（后续功能）
```

- `cmd/server`：唯一服务入口。
- `internal/api`：HTTP 路由、参数校验和响应。
- `internal/engine`：后续执行状态机与调度。
- `internal/adapter/target`：后续唯一可直接调用目标平台的区域。
- `internal/analyzer`：真实流程树和路径拓扑；`internal/formdata`：目标原始表单数据的最小字段补丁；`internal/engine`：动作目录和场景编译。
- `internal/repository`：后续存储访问，不包含业务判断。
- `internal/model`：领域类型。
- `internal/config`：配置加载。
- `web`：单个 Vue 应用。

## 前端边界

- 应用壳只提供产品名、三个中文导航、主题切换和路由内容区；不在 F-000 实现计划列表、创建页或其他业务页面。
- 应用壳使用 Naive UI 文档站式的扁平布局：顶栏横跨全宽，侧栏从顶栏下方开始，主内容占用剩余空间；`NLayoutHeader bordered` 与 `NLayoutSider bordered` 负责肉眼可见的 1px 语义分隔线，不使用卡片套层、渐变、阴影或装饰图形。
- 顶栏、侧栏、工作区与主内容均使用未嵌入的 Naive `NLayout` 层级，浅色和深色下保持同一基础表面色；普通 DOM 不依赖 Naive 组件局部 `--n-*` 背景或边线变量。
- 侧栏使用 `NLayoutSider` 的 `collapse-mode="width"`、`show-trigger="arrow-circle"` 与 `collapsed-width="0"`；圆形触发器真实点击区至少为 `32px × 32px`，零宽收缩态通过定位覆盖完整留在 viewport 内，收缩时不展示无依据图标。
- 浏览器根节点固定为 `100dvh` 且不滚动；顶栏固定，侧栏可收缩，主内容区独立 `overflow-y: auto`，侧栏仅在菜单超出时自身滚动。Flex/Grid 子项使用最小尺寸约束，避免撑出 viewport。
- 通过 `NConfigProvider`、`NGlobalStyle` 与 `darkTheme` 实现深浅主题；默认浅色，主题值保存到 `localStorage`，所有表面、文字、边线和选中态使用 Naive UI 语义变量随主题切换。
- 保持中文、桌面优先；计划列表继续使用 F-001 的静态计划行，新建页从 F-002 起通过 `web/src/features/plans/api.ts` 读取真实账号与候选，不建立通用表格、表单或远程列表框架。
- F-003 将计划列表切换到 Go API 和 MySQL 真实数据；创建成功后进入独立 `/plans/:id/paths` 路由。该路由在 F-003 只读取计划摘要和展示无路径空状态，不提前创建流程画布或通用 CRUD 页面。
- Vue Flow 与真实流程布局统一延后到 F-004；F-000 不安装也不预留画布抽象。
- F-004 使用目标平台结构化分叉—汇合语义的专用树布局；只有真实样本证明该结构假设不成立时，才另行规划其他布局引擎。

## F-002 目标平台只读接入

- `internal/config` 按“进程环境 > 项目根目录 `.env.local` > 非敏感代码默认值”的顺序读取 `TARGET_*`。`.env.local` 被 Git 忽略且只在当前机器保存；Air 从项目根启动时会自动读取，不修改进程环境，也不进入浏览器。
- `TARGET_API_GATEWAY`、`TARGET_LOGIN_PASSWORD`、`TARGET_LOGIN_AES_KEY`、`TARGET_LOGIN_CODE` 必需；本地文件不存在时仍允许纯环境变量运行。本地文件解析失败、关键配置缺失或 AES key 长度非法时，服务和 health 正常启动，三个 target API 稳定返回 `TARGET_CONFIG_MISSING`。
- `cmd/sync-v1-target-config` 只在维护时读取显式指定的 V1 YAML，将目标网关、平台/租户代码和 AES key 与既有本机登录配置合并，使用 `0600` 临时文件原子替换 `.env.local`，并在清空当前进程 `TARGET_*` 后做完整性检查。命令不含 V1 绝对路径或登录值，不回显配置值；正常启动不依赖 V1 仓库。
- `TARGET_PLATFORM_CODE` 默认 `200001`、`TARGET_TEMPLATE_PLATFORM_CODES` 默认 `200001,999999`、`TARGET_SESSION_TTL` 默认 `8h`、`TARGET_HTTP_TIMEOUT` 默认 `120s`，均来自用户批准沿用的 V1 非敏感约定；`TARGET_CUSTOMER_CODE` 可为空。敏感配置没有代码默认值。
- `internal/adapter/target` 是唯一拼装目标 URL、加密登录密码、传递 SID 和解析目标响应的区域。SID 只在当前已验证会话内存中按目标协议进入 body、query、header；不得写入日志、配置数据库、历史快照或浏览器长期存储。
- `internal/session` 使用单进程内存缓存，按去除首尾空白的账号键控，默认绝对 TTL 为 8 小时；每个账号独立锁定登录，不同账号不互相阻塞。会话失效后只允许删除缓存、重登和重放当前只读请求一次。
- 缓存条目只保存 SID、必要账号摘要和目标代码，不保存密码、AES key 或 code；进程退出自然清空。F-002 不引入 Redis，多实例共享需求出现后再单独评估。
- 对浏览器提供三个独立边界：`POST /api/target/accounts/verify`、`GET /api/target/flow-templates`、`GET /api/target/flow-instances`。公开响应只含验证摘要、候选 DTO、分页或稳定错误，不含 SID、凭证、customerCode、platformCode 或目标敏感原文。
- 模板、已发、待发分别映射 `/web/flowTemplateApi/list`、`/web/flowInstanceApi/list`、`/web/flowJobTaskLink/list`；三类 DTO 独立，不用同一个模糊目标类型覆盖字段差异。
- 模板 DTO 只补充实施平台列表已使用的 `formExist` 与 `formTemplateCount`；`groupName` 是模板既有分组字段，前端只在其非空时以内联标签高亮，不请求公司目录或公开额外公司字段。已发 DTO 保留原始 `status` 并提供集中派生的中文 `statusName`。候选虚拟列表固定行高 `96px`、视口 `480px`，常见桌面一次完整显示 5 行，加载、空、错误与来源切换共用 `574px` 稳定外壳。
- 前端搜索以 250ms 防抖触发真实分页请求，通过 `AbortController` 和 account/source/query/version 联合身份取消或忽略旧结果；追加按三类真实 ID 去重，错误不回退 mock。

## F-003 最小计划持久化

- 工具侧计划使用 MySQL；Go 通过 `database/sql` 和 MySQL 驱动访问，不引入 ORM。`internal/repository` 定义计划仓储边界，MySQL 实现只负责迁移、SQL 和行映射，业务校验与幂等语义位于 `internal/service`。
- 工具数据库连接只读取 `PLAN_DB_*`，配置优先级沿用“进程环境 > 根目录 `.env.local` > 非敏感默认值”。本机配置从 V1 `runnerDb` 安全同步，禁止使用目标平台 `target.mysql*` 作为工具库。
- F-003 建议在同一 MySQL 服务上创建独立数据库 `test_auto_pro_v2`；数据库名只允许字母、数字和下划线。同步和启动日志不得输出 DSN、用户名密码或配置值。
- 版本化 SQL 通过 `schema_migrations` 记录；后端在监听端口前完成数据库连接、建库和向前迁移，失败则直接退出。迁移不自动 down，不修改 V1 原数据库或目标平台数据库。
- F-003 只建立 `test_plans`。`scheduled_at IS NULL` 表示未开启定时，串行计划的 `max_concurrency` 为 `NULL`；时间统一以 UTC 保存并用 RFC 3339 传输。
- 创建使用 `Idempotency-Key` 和数据库唯一键保证同一次网络重试返回同一条计划。公开响应不返回幂等键、SID、目标凭证或数据库内部字段。
- 执行路径表延期到 F-005：F-004 先用保存的账号、来源和目标对象 ID 重新读取真实流程结构，F-005 再依据真实节点和分支建立路径数据，不在 F-003 保存无业务依据的占位路径。

## F-004 只读真实流程图

- `GET /api/plans/{id}/flow-graph` 是唯一公开图读取入口。服务端先读取计划，再使用计划内账号、来源和目标 ID 调用目标平台；浏览器不得覆盖这些字段。
- `new` 先通过模板列表精确核对可见性，再调用 `/web/flowTemplateApi/findById`；`started` 通过已发列表精确取得当前 `flowProxyId`；`pending` 通过待发列表精确取得当前 `flowProxyId`。后两类再调用 `/web/flowProxy/findById`，禁止把实例 ID 当代理 ID。
- 多个目标只读调用放在 F-002 `session.Manager.DoRead` 的一次操作中；任一调用发现会话失效时，整个核对与详情读取链只允许重新登录并重放一次。
- `internal/adapter/target` 解析最小目标树；`internal/analyzer` 将 `childFlowNodeTemplate`、`conditionNodes`、`parallelNodes` 规范化为独立图 DTO。图 DTO 仅把节点和分支 ID 当作结构操作所需的不透明标识，不额外透传 `flowProxyId`、目标 envelope、审批配置、字段权限或凭证。
- 分支解析以真实节点 ID 和策略 ID 标识结构；各分支只能通过路由节点的真实主线后继显式汇合，显式汇合点之前重复引用同一节点、分支入口直接等于汇合点、自连接、循环、关键 ID 缺失、空分支入口或超过 500 节点/200 深度时都拒绝半图。路由节点额外公开自身真实主线后继 `mergeTargetId` 作为只读布局提示，前端不显示该 ID。
- 前端保留 `@vue-flow/core` 与 `@vue-flow/controls`，使用针对目标平台结构化分叉—汇合模型的确定性树布局，不再使用 dagre 通用 DAG 排布。主干垂直居中；每个路由递归计算各分支内容块宽高，按后端边顺序从左到右排列；`mergeTargetId` 让每个分支在共享后继前停止，后继只布局一次并回到主干。只允许画布平移、缩放、适配视口和进入/退出全屏；关闭节点拖动、连接、删除、选择和位置持久化。
- 布局同时生成自定义正交边路径：分叉边共用一条水平分支轨，汇合边共用一条水平汇合轨，普通主干保持垂直；嵌套路由在各自分支内容块中递归展开，不允许自动绕线或交叉。连线使用主题色的克制方向动画，`prefers-reduced-motion: reduce` 下禁用动画。
- 前端布局仍对 API 图执行防御校验；若收到无法按结构化树解释的节点或边，画布区域显示稳定的结构异常说明，不允许 Vue 渲染异常穿透为白屏。
- 画布使用 Naive UI 主题变量并与内容区保持同一表面色。首次图数据稳定后只执行一次根节点定位；后续重绘和窗口尺寸变化不得反复重置用户视口。
- 首次适配只把根节点置于画布上方并保持可读缩放，不把整张大图压进当前视口；右上角入口通过页面内 `fixed` 覆盖层铺满浏览器内容视口，不调用 Fullscreen API，退出页面全屏后保留当前浏览位置。
- F-004 不增加数据库迁移、不缓存图、不生成拓扑指纹和路径。F-005 才依据真实节点与分支建立路径持久化。

## F-005 执行路径选择与持久化

- F-005 复用 F-004 的真实图读取和结构化布局，不引入第二套图模型或布局引擎。流程图响应增加 `entryNodeIds`：新发起使用真实根节点；已发从精确实例记录的 `currentNodeProxyId` 及当前活动节点集合确定入口；待发从精确待发任务的 `flowNodeProxyId` 集合确定入口。入口必须存在于本次代理树，否则返回稳定的当前位置异常，不猜测名称。
- 路径解析器位于 `internal/analyzer`，前后端共享同一业务约束并各自防御：普通节点沿 `sequence` 前进；条件和手动路由只接受一个分支选择；并行路由自动包含全部分支；汇合节点只访问一次。请求中的选择必须恰好覆盖当前可达的条件/手动路由，禁止缺失、重复、额外或指向其他计划图的选择。
- 浏览器提交的最小选择为 `{routeNodeId, branchId}`；后端必须用计划中保存的账号、来源和目标对象重新读取当前真实图后再验证，不能信任浏览器提交的节点集合、入口、流程名称或目标 ID。
- 新增 `test_execution_paths` 保存计划、稳定路径序号、可编辑路径名称、幂等创建键和时间；新增 `test_execution_path_choices` 保存每条路径在真实条件/手动路由上的分支选择，主键保证同一路由只有一个选择。并行分支、派生节点集合和整张流程图不落库。已有表通过独立向前迁移增加名称字段，历史空名称在读取时按稳定序号兼容为“路径 N”。
- 两张路径表使用独立向前迁移；另以单语句向前迁移为 `test_plans` 增加内部字段 `next_path_sequence_no`，默认值为 1，不进入 API。创建路径时先锁定所属计划行，以该计数器分配序号并在同一事务中递增；兼容已有路径时取计数器与当前最大序号加一的较大值。这样硬删除最高序号后仍不会复用，且并发创建不会得到相同序号。
- 路径删除级联删除自己的选择，不删除计划或目标平台数据，也不回退 `next_path_sequence_no`。已有路径不重排，保证后续配置和运行记录引用稳定。
- `internal/repository` 增加路径仓储和事务边界；创建、替换选择、删除与更新计划 `updated_at` 在同一事务完成。创建继续使用 `Idempotency-Key`，相同键重试返回同一路径；新发起允许不同路径记录拥有相同分支选择，已发和待发由服务层限制最多一条。
- `GET /api/plans/{id}/execution-paths` 只返回轻量状态、纳入标记和修订号；`GET /api/plans/{id}/execution-paths/{pathId}` 在进入单条编辑时按需返回 choices；`POST /api/plans/{id}/execution-paths` 创建单条路径；`PUT` 更新线路；`POST /api/plans/{id}/path-generations` 启动后台解析，随后使用同一路径的 `GET` 查询、`cancel` 取消、`resume` 恢复；`DELETE` 删除路径。
- 全路径枚举由 `internal/analyzer` 基于同一真实图语义完成，后台任务按批次持久化并以幂等键对账；不设置固定业务路径数量上限，批次大小、任务并发和上下文超时是资源保护边界，取消不会删除已经提交的路径。
- 批量幂等由 `test_execution_path_batches` 和 `test_execution_path_batch_items` 持久化：批次保存计划归属与计数，明细只关联该批次实际创建的路径顺序；同键重试先返回已提交批次，不再次读取目标图。批次、明细、路径和选择同事务写入，不保存流程图或另一份路径快照。
- 计划列表和详情的 `pathCount` 改为真实路径计数，但 F-005 不改变计划公开状态；新建计划和未运行计划使用 `not_started`。流程图和路径响应只返回完成选择所需的不透明节点/分支标识，不返回幂等键、SID、凭证或目标接口原始响应。
- 前端在同一现有画布上区分普通浏览、已保存路径只读详情和页面全屏查看，不复制主图节点或引入第二套图引擎。普通画布主入口为“新增路径”，已保存路径详情内才开放“编辑路径”；列表使用虚拟渲染，单条 choices 通过详情端点按需加载。
- 编辑态使用覆盖在画布右侧的轻量 DOM 面板，只显示标题、人工决策进度、名称、实时流向和固定底部取消/保存；进度由当前路径分析结果派生，只计可达的条件/手动路由。面板内部独立滚动，并以保持 `320px` 宽度、缩短高度的方式纵向折叠；不得退化为侧边窄条。已保存列表使用独立 `NVirtualList` 小浮层，后台解析任务只展示进度，不提供手动生成入口。
- 画布边状态显式区分 `selected`、`candidate`、`dimmed`：只有已选和自动必经线路运行动画并使用高对比主题主色与更粗线宽；已选分支显示不可重复点击状态，同一路由其他候选仍可用于改选；尚未到达的后续分支静止弱化并保留名称，暂不允许越级选择。`prefers-reduced-motion: reduce` 下全部停止动画，状态仍由线宽、颜色与文字表达。
- 进入选择态以及每次分支选择后，前端按确定性遍历顺序取得下一待选路由；保持当前缩放，把目标平滑移动到扣除悬浮面板后的操作区域中央，并在目标旁显示带 CSS 箭头、短暂、可关闭且支持 `aria-live` 的操作提示。路径完整时改为提示保存，不自动提交。
- 路径草稿只保存在当前编辑会话，完整且有真实变化后由明确的“保存路径”提交；保存中的重复点击被禁用，失败保留草稿。取消或退出页面全屏时，无真实修改直接清理，有修改先确认再丢弃名称、选择、幂等键和编辑状态，不保留“继续选择”入口；保存成功同样清理并回普通画布。主入口使用“新增路径”，已保存路径详情内才提供“编辑路径”；复制和删除收在“更多”菜单，删除需要确认。
- 实时流向摘要继续由当前分析结果投影，不建立第二套图模型；摘要中的节点和连接使用轻量 CSS 方向动画与主图状态同步。Vue Flow 右下角缩放、适配按钮必须使用项目主题变量覆盖图标、背景、边框、悬停和禁用状态，深浅模式都保持可见。
- F-005 不读取或保存历史业务数据、条件表达式值、审批人、人员范围、节点动作、附件或成功断言，不调用任何目标平台写接口，也不生成运行记录。

## F-006 路径要求分析

- 新增只读接口 `GET /api/plans/{planId}/execution-paths/{pathId}/requirements`。服务端先核对计划与路径归属，再按计划保存的账号、来源和目标对象重新读取当前真实流程；浏览器不能覆盖账号、目标 ID、入口或分支选择。
- 目标读取继续复用 F-004/F-005 的同一棵结构树，不建立第二套拓扑模型。`internal/adapter/target` 在一次详情解码中把节点审批配置、分支条件、字段权限和关联表单引用拆入内部要求元数据；现有公开流程图仍只返回结构字段，不因 F-006 泄露新增原文。
- 新发起通过 `/web/flowTemplateApi/findById` 读取模板树，并按关联表单引用调用 `/web/formTemplateApi/findById` 补充被条件或人员规则实际引用的字段名称；已发和待发通过 `/web/flowProxy/findById` 读取代理树，并通过 `/web/formProxy/findById` 读取对应实例表单字段元数据。全部只读调用纳入一次 `session.Manager.DoRead`，会话失效时整条操作最多重登重放一次。
- 表单字段字典只保留要求翻译需要的名称、英文名、类型和来源；英文名只用于后端关联，不进入公开 DTO。相同英文名能用表单名称消歧时显示“表单 / 字段”，不能消歧时产生“需要人工核对”项，不按经验猜测。
- `internal/analyzer` 复用 F-005 路径遍历结果，只投影当前保存路径可达的节点和已选分支。分支条件保持目标顺序与 `and/or` 连接关系；目标执行逻辑中的最后分支为兜底，即使条件列表非空也必须显示为“其他条件均不满足时进入”，不能把它解释成普通独立条件。
- 要求分析将内部规则统一翻译为四类状态：`required`、`automatic`、`runtime`、`review`，公开响应分别返回中文“待配置”“目标平台自动确定”“运行时确定”“需要人工核对”。未知节点、人员类型、判断方式或缺失元数据优先降级为 `review`，只有结构无法安全对应当前路径时才整体返回路径失效。
- 人员分析仅说明规则和准备责任，不在 F-006 解析或保存未来真实处理人。审批人自选、表单人员归为后续待配置；固定人员、角色和已配置组织范围归为目标平台自动确定；依赖发起人、主管、分管关系、职级或扩展属性的结果归为运行时确定。`isSkip`、会签/竞签和人数约束作为同一节点要求返回。
- 动作分析只提供真实节点类型和目标配置作为 F-012 动作目录的输入；发起、审批、协同、空和结束的基础语义来自目标实现，回退、加签、移交、取回和转发的可用性由 F-012 按当前实例门禁重新计算。
- 公开 DTO 按路径结构返回汇总和只读分组：路径序号与名称、四类状态计数、主线/并行分组、业务节点名称、进入条件、处理人规则、动作要求和节点约束。节点 ID、分支 ID、字段英文名、目标枚举代码、SID、表单原始 JSON 和目标 envelope 均不返回。
- F-006 不保留前端入口、路由、页面或页面专用要求模块。后端只读接口、目标元数据读取和分析器是配置功能的单一要求来源；F-012 直接消费该结果，不复制分析规则或建立第二套拓扑。
- F-006 本身不新增表或配置快照；F-012 负责历史表单数据快照、人员和动作配置的持久化，并在每次保存前以当前目标配置复核。

## F-005/F-006 路径基础（保留）

## form-runtime 受控维护流水线

- 维护语义迁移自旧 V2 ADR-0016，固定状态机为 `INSPECT → SYNC → SYNC_CHECK → BUILD → RESTART → VERIFY → COMPLETED`。当前项目不复制旧 Docker/Colima 部署：`PnpmOperator` 在任务工作区同步完整候选源码，并构建到 `.runtime/form-runtime-maintenance/versions/candidate-job-N`；静态健康完成前不触碰 current。切换同时替换 `runtime-source/` 与 `web/dist/form-runtime` 并持久化 current 指针，切换或最终 HTTP 健康失败时从 previous 源码/产物版本恢复并再次核验。
- 同步来源固定为 `参考代码/rsh-flow-components` 的规范仓库、远端和 `master`，但不把历史 HEAD 永久写死在代码中。更新参考仓库仍先经过 `make refs-sync`/`make refs-status` 的干净、分支和快进约束；维护任务创建时持久化当刻 HEAD，Worker 执行前复核同一快照。维护 API 不接受路径、分支、HEAD、构建命令或环境选择，任务中途来源变脏或变化即失败。
- 候选同步与构建在 `.runtime/form-runtime-maintenance` 隔离目录完成，实际构建显式消费候选 `runtime-source/`。切换时同时替换 19001 Vue CLI 监听的真实源码和生产 `web/dist/form-runtime` 产物；`runtime-health.json` 公开非敏感仓库/分支/HEAD/摘要，运行中的 HTTP 地址必须报告同一快照才能完成。候选失败不影响 current，切换或健康失败恢复源码与产物 previous 并再次核验。
- `form-runtime/sync-manifest.json` 是唯一项目同步映射：当前来源本身已是独立组件仓库，因此完整镜像其 tracked `src/`、`public/`、原生同步清单/脚本和构建资产；旧 V2/上游的 35 项生成映射继续随源码保留。项目同步执行逐文件 `SYNC_CHECK`、完整目标摘要、本地适配保护和实际运行源码未知修改拒绝。状态通过 `make form-runtime-status`，一键任务通过 `make form-runtime-sync` 或系统设置页触发，两者都不能覆盖参数。
- `test_form_runtime_sync_jobs` 是维护任务正确性来源，数据库唯一键保证单活动任务。Worker 使用租约续期与 fencing token；旧 Worker 不能推进阶段或完成任务，进程重启后从持久化的 `RESTART/VERIFY` 和 candidate/previous 事实恢复，不能重新同步或覆盖既有候选。在线日志写入运行目录，API 最多返回最新 512 KiB 并标记截断，SID 与表单数据不会进入维护任务或日志。
