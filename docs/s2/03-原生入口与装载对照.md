# 原生入口与装载对照

本表只根据 `参考代码/rsh-flow-components` 的原生路由和 `GroupApproveManage` 直接引用整理。规划时工作区 `test` HEAD 为 `24f3a28`；实施快照必须是 `make refs-sync` 后的 `be355ae`。

## 1. 路由

| 路由 | 组件 | 执行用途 |
| --- | --- | --- |
| `/flow/initiate` | `src/views/FlowInitiate.vue` | 保存草稿、提交 |
| `/flow/detail/:id?mode=audit` | `src/views/FlowDetail.vue` | 审批暂存、同意、不同意、转发 |
| `/flow/detail/:id?mode=edit` | 同上 | 重提、待发编辑 |
| `/flow/detail/:id?mode=view` | 同上 | 只读回读 |

hash 模式，`base=/flow/`。认证参数：`sid`、`platformCode=200001`、`customerCode`。

## 2. 发起选模板

`InitFlowDialog.vue` `mounted`：

1. 读取 `params.auditWay`；没有 `auditWay` 则不查询。
2. `POST` 模板列表，`data.auditWayList`、`useScope=invest`、`showMe=true`。
3. 0 条：提示无权限。
4. 1 条：`flowTemplateFindById(res.data[0].id)`。
5. 多条：`chooseFlowDialog`，确认后按选中 `id` 再 `findById`。

执行约束：Go 必须同时给 `auditWay` 和计划绑定 `flowTemplateId`。查询返回后按 ID 精确匹配；匹配失败阻塞。不能把 `flowTemplateId` 直接当查询条件，也不能默认第一项。

## 3. 详情 `taskContext`

`FlowDetail.getTaskContext` 优先解析 query `taskContext` JSON，否则收集散字段。执行装载应传完整 JSON，字段至少包括：

`id`、`flowInstanceId`、`flowName`/`formName`、`flowStatus`/`status`、`auditWay`、`initiatorId`/`createrId`、`jobTaskId`、`batchNo`、`formExist`、`formProxyId`、`flowProxyId`、`flowNodeProxyId`、`currentNodeProxyId`、`nextNodeProxyId`、`tracking`/`trackingFlag`、`flowInstanceBizRelevanceList`。

mode 映射：

| mode | isExamine | operaType | 动作 |
| --- | --- | --- | --- |
| audit | true | examine（费用无表单审核为 edit） | 暂存、同意、不同意、转发 |
| edit | false | reEdit | 重提 |
| view | false | check | 回读 |

`rollback`/`tracking`/`retrieve`/`transfer` 是原生直接 API mode，本切片不经页面执行。

## 4. 身份字段

`src/utils/runtimeAuthSync.js`：`sid`、`customerCode`、`userId`、`userName`、`companyId`、`companyName`、`userDepartmentName`、`topCompanyId`、`groupDepartment`。写入 `token`/`sid` 等 localStorage 别名。执行服务按同一套键注入，不复用 `form-runtime/src/runtime/memoryAuth.js`。

## 5. 弹窗工厂

`src/components/InitFlowDialog/index.js`：

- `$initFlow` → `InitFlowDialog` 实例，返回 `{ instance, close, setData }`。
- `$flowDetail` → `flowDetail` 全局弹窗实例，返回 `{ instance, close }`。

薄桥接只保存该 `instance`，再取到内部 `FlowDialog` / `EnterpriseExamineOpinion` 引用。

## 6. 数据接口

原生装载完成后才补丁。优先使用页面已挂载表单的现有方法：

| 能力 | FormMaking | 自定义 / NoFormFlow |
| --- | --- | --- |
| 写入 | `setData` | 页面已有 `setData` 或等价方法 |
| 校验读取 | `getData` | 页面已有校验入口 |
| 完整回读 | `getValues` | 页面已有取值入口 |

没有上述入口则 `unsupported`，不手写字段映射器。默认「所有表单」= 当前原生组件已支持的表单。

## 7. 七个动作入口

与 `docs/s/03-审批页面全量动作对照.md` 的目标接口和重读规则一致，执行位置改为原生页面方法：

| 动作键 | 页面方法 | 目标写接口 |
| --- | --- | --- |
| `save_draft` | `FlowDialog.sumbitFlow('draft')` | `/web/flowInstanceApi/submit`，`status=draft` |
| `submit` | `FlowDialog.sumbitFlow('submit')` | `/web/flowInstanceApi/submit`（回退后与草稿同端点，无 `checkPermissions` 预检键的正式提交） |
| `resubmit` | 审批页重新提交入口 | `/web/flowInstanceApi/reSubmit`（回退后老端点，预检带 `checkPermissions`） |
| `storage_form_data` | 审批暂存入口 | `/web/flowInstanceApi/storageFormData` |
| `approve` | 同意入口 | `/flowInstanceApi/audit`（`qualityManage.submitTask`），`pass` |
| `reject` | 不同意入口 | `/flowInstanceApi/audit`（`qualityManage.submitTask`），`no_pass` |
| `forward` | `flowTypeMixin` 转发入口 | `/web/flowInstanceApi/transpond` + 按需附言 |

选择继续仍用 `handleSaveBranchChooseNode`、`handleSaveParallelChooseNode`、`getSelectPerson`。八个管理动作保持 Go 直连。
