# 独立执行服务任务清单

## 使用规则

- 按任务编号顺序执行，不得跳过依赖任务。
- 每个任务完成后先运行本任务的验证命令，再用中文提交一次。
- 任务失败时保留日志和错误，不修改目标平台，不用空实现掩盖问题。
- 本切片只做独立执行服务与原生装载；不自动开始其他功能切片。
- 所有测试放根目录 `test/`，按 `test/unit`、`test/integration`、`test/contracts` 分类。
- 不兼容 `exec-engine/v1`：删除旧执行宿主、执行路由、能力登记门禁和 Go 进程托管，不留别名。

## 配置兼容规则

- 不修改用户已经保存的动作键、节点键、动作顺序、人员策略和业务参数。
- 七个表单动作改走独立执行服务；`add_sign`、`transfer`、`rollback_previous`、`retrieve`、`withdraw`、`urge`、`follow`、`unfollow` 继续 Go 直连；`system_automatic` 只读。
- 普通动作只有一个写出口。执行服务成功、失败或结果待确认后，Go 都不能再次发送同一动作的目标写请求。
- 待发删除不加入本清单。

## 阶段 0：独立源码与产物

### T001：建立独立执行服务骨架

**做什么**

- 在根目录新建 `executor-service/`：Playwright 执行进程、独立页面构建包目录、独立组件快照目录。
- 从 pnpm workspace 移除 `form-runtime/executor`；新增独立包，不与 `form-runtime` 共用源码别名。
- 固定 Chromium 版本、启动参数、默认端口 `19011`。
- 提供独立构建、启动、健康检查命令。健康检查只证明进程可听端口，不访问目标。

**文件**：`executor-service/package.json`、`executor-service/src/server.ts`、`executor-service/src/probe.ts`、`pnpm-workspace.yaml`、根 `package.json`。

**验收**：`pnpm --dir executor-service probe` 能启动无头 Chromium；代码中没有 `locator`、`click`、`fill`、坐标或选择器；Go 源码不再引用 `form-runtime/executor` 路径。

**依赖**：无。

## 阶段 1：协议 v2 与会话

### T003：BrowserContext 会话迁入新服务

**做什么**

- 每个会话创建新 BrowserContext。
- 保存 `sessionId`、账号键、页面、创建时间、请求和关闭状态。
- 关闭时移除监听器并关闭 Context。同账号队列仍由 Go 实现。

**测试**：`test/unit/executor-service/session-manager.test.ts`。

**验收**：两个会话的 localStorage、sessionStorage、Vuex 和页面状态隔离；关闭后不能执行新命令；页面崩溃通知 Go 并释放会话。

**依赖**：T001。

### T004：升级协议为 `exec-engine/v2`

**做什么**

- 生命周期接口保持 `/runtime/session` 与 WebSocket 转发通道。
- 装载载荷改为身份、原生流程/任务上下文、当前节点数据补丁；删除 `template` 渲染 JSON 必填。
- 旧 `exec-engine/v1` 与缺编号消息直接拒绝。
- 删除能力登记作为执行门禁；`unsupported` 只表示原生缺少入口或数据接口。

**文件**：`executor-service/src/protocol.ts`、`internal/runtimeexec/protocol.go`、`internal/runtimeexec/loader.go`。

**测试**：`test/contracts/executor-service/protocol_test.go`、`test/unit/executor-service/protocol.test.ts`。

**验收**：v1 夹具全部被拒绝；v2 装载夹具不含 template 仍可通过；含 template 的旧载荷被拒绝。

**依赖**：T003。

## 阶段 2：原生装载与拦截

### T005：导航前拦截与转发通道

**做什么**

- 创建会话后、`page.goto` 前安装 `page.route()`。
- WebSocket 转发通道必须在装载前连接成功；失败则不导航。
- 目标 `/web`、`/flowInstanceApi`、文件请求转 Go；未登记外部请求本地拒绝。
- 请求头、正文、响应原样转发，不脱敏。

**测试**：`test/unit/executor-service/target-route.test.ts`、`test/contracts/executor-service/request-route_test.go`、`test/integration/executor-service/forward-before-load.test.ts`。

**验收**：装载前断开转发通道则页面不发出目标请求；导航后的 XHR/Fetch/上传都能捕获；顺序可回放。

**依赖**：T004。

### T006：原生发起装载与精确选模板

**做什么**

- 注入参考项目身份后导航 `#/flow/initiate`。
- 捕获 `$initFlow` 实例。
- 传入 `auditWay` 触发原生 `getFlowByTemplate`；查询结果中精确匹配计划绑定 `flowTemplateId` 再确认。
- 单模板直接进入；多模板不得取第一项；结果不含绑定模板则阻塞。
- 等待原生读完模板和权限，再应用当前节点数据补丁并回读。

**测试**：`test/integration/executor-service/initiate-template-select.test.ts`。

**验收**：同 `auditWay` 两条模板时选中计划绑定项；只传 `flowTemplateId` 不传 `auditWay` 时阻塞；查询空列表阻塞且无写请求。

**依赖**：T002、T005。

### T007：原生详情装载与身份切换

**做什么**

- 导航 `#/flow/detail/:id`，`mode` 为 `audit/edit/view`，附完整 `taskContext`。
- 捕获 `$flowDetail` 实例。
- 当前审批人与原发起人分开保存。
- 每次审批使用新 Context。

**测试**：`test/integration/executor-service/detail-load.test.ts`、`test/integration/executor-service/actor-isolation.test.ts`。

**验收**：`audit/edit/view` 分别打开对应原生语义；两个审批人依次执行时用户信息不串；缺少 `jobTaskId` 的审批装载阻塞。

**依赖**：T006。

### T008：数据补丁与回读

**做什么**

- 原生装载完成后，只通过组件现有数据接口写入当前节点允许的配置值。
- 等待远程选项、人员关联和联动结束再 `getValues()` 回读。
- FormMaking、已注册自定义组件、NoFormFlow 走原生页面已有能力；缺少数据接口时 `unsupported` 阻塞。

**测试**：`test/integration/executor-service/data-patch-readback.test.ts`。

**验收**：补丁后绑定值、显示值和虚拟字段一致；未完成选项加载不得执行写动作；无数据接口的页面不写目标。

**依赖**：T006、T007。

## 阶段 3：七个动作与完成检测

### T009：薄桥接七个原生动作

**做什么**

- 通过捕获的原生实例调用目标业务方法，不点击控件。
- 接入保存草稿、提交、审批暂存、同意、不同意、重提、转发。
- 保留不同动作的校验、前置事件、后置事件和参数差异。
- 工具流程名称在最终请求中保持工具值。
- 提交、重提、同意接入选择闭环：三种明确选择错误只允许继续一次。

**测试**：`test/integration/executor-service/actions.test.ts`、`test/contracts/executor-service/action-entry_test.go`、`test/integration/executor-service/choice-continue.test.ts`。

**验收**：草稿不提前提交；暂存不推进任务；同意和不同意不误走对方分支；转发创建辅助实例且主实例不变；选择数据不完整时阻塞。

**依赖**：T008。

### T010：完成检测与失败分类

**做什么**

- 统计页面业务、流程、附件和后置请求。
- 转发记录 `writeSequence`；第一步未确认不得发第二步。
- 网络空闲稳定窗口、动作硬超时、Context 崩溃处理。
- 覆盖：装载失败、校验失败、选择继续、SID 失效、写响应丢失、超时、后置业务失败、服务断开；确认无重复写请求。

**测试**：`test/unit/executor-service/completion.test.ts`、`test/integration/executor-service/completion-failure.test.go`。

**验收**：流程接口成功不能代替全部业务成功；响应丢失返回 `uncertain` 且不重发；超时后不执行新写请求。

**依赖**：T005、T009。

## 阶段 4：Go 接入与清理配置侧

### T011：Go 客户端改接 v2 并取消托管

**做什么**

- `internal/runtimeexec.Client` 只发 v2。
- 七个动作继续走 runtime 路由；未启动执行服务时写前阻塞，不回退 Go 写路径。
- 删除 `StartExecutorSupervisor`、默认托管和验证模式。
- 删除能力登记执行门禁；运行详情仍返回前后数据、请求轨迹和组件版本。
- 服务健康失败只阻止相关运行。

**测试**：`test/unit/backend/runtimeexec/client_test.go`、`test/unit/backend/runtimeexec/step_routing_test.go`、`test/contracts/runtimeexec/no_duplicate_write_test.go`。

**验收**：静态扫描确认 runtime 路由不会发送八个 Go 直连端点；Go 启动不再拉起 19011 子进程；执行服务停止时七个动作阻塞、配置 API 仍 200。

**依赖**：T004、T010。

### T012：清理 form-runtime 执行能力

**做什么**

- 删除 `form-runtime/executor/`。
- 删除 `form-runtime/src/ExecutionHostInitiate.vue`、`ExecutionHostApprove.vue`、`runtime/executionBridge.js`。
- `main.js` 去掉 `/test-auto-form/exec*` 路由，只保留配置 iframe 入口。
- 配置侧协议 `f007-form-runtime/v1` 的 load/setData/getValues/destroy 保持。
- 系统设置「表单运行时维护」只更新配置服务。

**测试**：`test/contracts/form-runtime/no_execution_host_test.go`、现有配置侧数据协议回归。

**验收**：`form-runtime` 源码不含 `__runtimeBridge__`、`ExecutionHost`、`exec-engine`；配置 iframe 仍能显示、编辑和取回数据。

**依赖**：T011。

### T013：服务隔离验证

**做什么**

- 停止执行服务后走配置表单显示/编辑/取回。
- 独立改执行快照或配置快照之一，断言另一侧源码摘要与产物不变。
- 确认两套构建命令互不覆盖输出目录。

**测试**：`test/integration/executor-service/isolation.test.ts`。

**验收**：执行服务停止后配置 iframe 会话仍可 `getValues`；改一侧快照文件不改变另一侧 HEAD 元数据。

**依赖**：T012。

## 明确禁止

- 不使用 jsdom/happy-dom。
- 不使用浏览器选择器、DOM 定位、坐标和按钮点击。
- 不在执行服务内直接访问目标平台。
- 不让执行服务自己登录或刷新 SID。
- 不在失败后自动再次调用原写动作。
- 不把 Go 渲染模板重新加回装载载荷。
- 不把 `form-runtime/runtime-source` 当作执行快照。
- 不恢复能力登记门禁或验证模式。
- 不新增数据库迁移。
