# 独立执行服务（原生页面装载）

本目录只记录把页面执行能力迁到根目录 `executor-service/` 的切片。无头 Chromium 装载参考项目原生路由、身份和流程上下文；配置侧 `form-runtime/` 继续只做数据显示、编辑和数据取回。

`docs/s/` 是上一轮「手工执行宿主 + form-runtime 内嵌执行服务」的历史设计。本切片不兼容旧执行协议，不复用其执行宿主、执行路由和能力登记门禁。

## 文档顺序

1. `01-执行服务设计.md`：隔离边界、原生装载、薄桥接、协议 v2、启动与安全规则。
2. `02-执行任务清单.md`：按依赖顺序实施，每项完成后单独验证和中文提交。
3. `03-原生入口与装载对照.md`：原生路由、身份、`taskContext`、`auditWay` 精确选模板、数据接口与七个动作入口。

## 当前结论

当前切片状态：`ready_for_manual`。聚合验证：`bash test/run-executor-service.sh`。可见页面和真实目标动作等待人工验收。


- 配置服务与执行服务独立源码、独立快照、独立构建、独立启动。执行服务停止时，配置表单仍可显示、编辑和取回数据。
- 执行服务使用独立的 `rsh-flow-components` 副本，初始快照为已核实的 `test` 分支 `be355ae`；必须先 `make refs-sync` 再复制，禁止复用 `form-runtime/runtime-source`。
- 实例通过 `/flow/detail/:id` 的 `audit/edit/view` 模式装载；发起通过 `/flow/initiate` 装载。传参对齐参考项目身份及 `taskContext`。
- 发起必须按 `auditWay` 查询模板并精确选中计划绑定模板；不能假定只传 `flowTemplateId` 就完成选择。
- 薄桥接捕获原生 `$initFlow`、`$flowDetail` 创建的实例，通过明确组件引用调用页面业务方法。不再手工拼装发起或审批宿主。
- 原生页面自行读取模板、实例数据和字段权限；装载完成后只对当前节点允许的配置值做补丁，等待选项及联动完成再回读。
- 七个表单动作（保存草稿、提交、审批暂存、同意、不同意、重提、转发）走新服务；其余动作继续由 Go 执行。
- 协议升级为 `exec-engine/v2`：装载输入是身份、原生流程/任务上下文和当前节点数据补丁，Go 不再提供渲染模板。
- 取消能力登记门禁和验证模式。执行依据原生页面能力和目标权限。
- Go 保留调度、账号会话、请求出口、结果核验和运行记录；不再托管执行服务进程。默认端口 `19011`，沿用 `RUNTIME_EXECUTOR_URL`。
- 页面请求必须在导航前安装拦截，转发通道必须在装载前连接成功。

## 本目录不做的事

- 不修改目标平台源码、权限、数据库或基础设施。
- 不新增目标业务能力，不扩展其余审批动作，不改造整套 Go 执行引擎。
- 不把配置侧 form-runtime 改成执行页面。
- 不复用现有 form-runtime 副本、身份适配、请求策略或构建产物。
- 不用 RPA 选择器、坐标、截图识别或按钮点击。
- 不新增数据库迁移。
