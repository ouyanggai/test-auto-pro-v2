# 独立执行服务设计

## 1. 完成标准

本切片只有满足以下条件才算完成：

1. 根目录存在独立的 `executor-service/`：含无头 Chromium 执行服务、独立页面构建包和独立 `rsh-flow-components` 源码快照。
2. 初始快照来自 `make refs-sync` 后的参考仓库 `test` 分支 `be355ae`，与参考项目当前使用版本一致；不复用 `form-runtime/runtime-source`。
3. 实例通过原生 `/flow/detail/:id` 的 `audit/edit/view` 模式装载；发起通过原生 `/flow/initiate` 装载。身份、`taskContext` 与参考项目入口对齐。
4. 发起时按 `auditWay` 查询模板并精确选中计划绑定模板；同 `auditWay` 多模板时不得选错。
5. 捕获原生 `$initFlow`、`$flowDetail` 创建的实例，通过明确组件引用调用页面业务方法。保留原生表单选择、权限、校验、业务保存、审批和后置处理。
6. 原生页面自行读取模板、实例数据和字段权限。装载完成后只通过组件现有数据接口应用当前节点允许的配置值，等待选项及联动完成再回读。
7. 七个动作（保存草稿、提交、审批暂存、同意、不同意、重提、转发）经新服务执行；其余动作继续由 Go 执行。
8. 协议为 `exec-engine/v2`，拒绝旧 `exec-engine/v1`。装载输入不再包含 Go 提供的渲染模板。
9. 页面请求在导航前安装拦截并经 Go 转发；转发通道在装载前必须连接成功。
10. 取消能力登记门禁和验证模式。动作完成仍须满足业务完成信号、请求收敛和异常检查，并由 Go 重读目标事实裁决。写结果未知时禁止重发或回退 Go 写路径。
11. 执行服务独立构建、启动和健康检查，默认端口 `19011`，沿用 `RUNTIME_EXECUTOR_URL`。Go 不再托管进程。服务不可用时只阻止相关运行，后端和配置功能继续可用。
12. `form-runtime/` 删除执行路由、执行宿主和执行桥接，保留配置侧协议及数据功能。两套服务不互相引用源码、身份适配、请求策略或构建产物。
13. 停止执行服务后，配置表单仍能显示、编辑和取回数据；独立更新任一组件副本不会改变另一服务。

## 2. 总体结构

```text
Go cmd/server
  ├─ 计划、路径、动作编排
  ├─ 账号和 SID 会话管理
  ├─ runtime 会话客户端（exec-engine/v2）
  ├─ WebSocket 指令发送、请求转发和事件接收
  ├─ 目标事实读取、写后核验、结果裁决
  └─ 完整请求/响应和运行事实落盘
  （不托管执行服务进程）

form-runtime/                         配置侧，端口 19001
  ├─ 现有 iframe 数据协议
  ├─ 独立 runtime-source 快照
  └─ 无执行路由、无执行宿主、无执行桥接

executor-service/                     执行侧，端口 19011
  ├─ Playwright + Chromium 无头实例
  ├─ 独立页面构建包（原生 /flow 路由）
  ├─ 独立 rsh-flow-components 快照（be355ae）
  ├─ 独立 FormMaking 库产物
  ├─ 每次任务独立 BrowserContext
  ├─ 导航前 page.route() 拦截
  ├─ 薄桥接：捕获 $initFlow / $flowDetail 实例
  └─ 事件、请求、异常和完成状态回传
```

### 2.1 无头浏览器使用边界

无头 Chromium 提供真实 DOM、定时器、XHR、Fetch、Vue 生命周期和组件挂载。禁止：

- `page.locator()`、`page.$()`、XPath、CSS 选择器找业务控件；
- `page.click()`、`page.fill()`、键盘、鼠标和坐标；
- 根据按钮文字或页面截图判断动作；
- 通过页面视觉变化代替目标请求和事实核验。

允许：启动/关闭浏览器、创建/关闭 BrowserContext、导航原生路由、注入身份与 `taskContext`、安装请求拦截、捕获原生弹窗实例引用、调用组件现有业务方法和数据接口、监听异常和收集页面事件。

### 2.2 两套服务隔离

| 项 | 配置服务 `form-runtime/` | 执行服务 `executor-service/` |
| --- | --- | --- |
| 职责 | 数据显示、编辑、数据取回 | 七个表单动作的原生页面执行 |
| 组件快照 | 现有 `runtime-source/`，由系统设置维护 | 独立副本，初始 `test`/`be355ae` |
| 入口 | iframe `#/test-auto-form` | 原生 `#/flow/initiate`、`#/flow/detail/:id` |
| 身份适配 | 现有 memoryAuth / 配置协议 | 参考项目 `runtimeAuthSync` 同源字段 |
| 请求策略 | 配置侧只读策略 | Playwright 全量拦截转 Go |
| 构建产物 | `web/dist/form-runtime`，`publicPath=/form-runtime/` | 执行服务自有产物，`publicPath=/flow/` |
| 启动 | `pnpm dev:form`（19001） | 独立命令（19011） |
| 维护入口 | 系统设置「表单运行时维护」只更新配置服务 | 独立构建/同步命令，不走配置维护 API |

禁止：互相 import 源码、共用身份适配模块、共用请求策略、共用构建产物目录、共用 `runtime-source`。

独立更新任一侧组件副本，不得改变另一服务的源码摘要、构建产物或运行行为。

## 3. 原生入口

### 3.1 发起 `/flow/initiate`

参考实现：`FlowInitiate.vue` 在 `mounted` 调用 `$initFlow({ params })`。`InitFlowDialog` 只在存在 `params.auditWay` 时按 `auditWayList` 查询模板：

- 0 条：原生提示无权限并关闭；
- 1 条：直接 `flowTemplateFindById`；
- 多条：打开 `chooseFlowDialog` 让用户选。

因此执行装载必须传入计划绑定的 `auditWay`（及 `companyId` 等身份上下文），查询结果出来后精确选中计划绑定模板 ID。禁止：

- 只传 `flowTemplateId` 就认为选择完成（原生查询入口不走该字段）；
- 多模板时取第一项；
- 绕过 `getFlowByTemplate` 直接把 Go 准备的模板 JSON 塞进页面。

查询失败、结果不含计划绑定模板、或原生缺少选择确认入口时明确阻塞。

### 3.2 实例 `/flow/detail/:id`

参考实现：`FlowDetail.vue` 读取 `mode` 与 `taskContext`，再调用 `$flowDetail`。

| mode | 用途 | 原生语义 |
| --- | --- | --- |
| `audit` | 同意、不同意、审批暂存、转发 | `isExamine=true`，`operaType=examine`（费用无表单审核走 `edit`） |
| `edit` | 重提、待发编辑 | `isReInitiate=true`，`operaType=reEdit` |
| `view` | 只读核对、回读 | `operaType=check` |

`taskContext` 必须按参考项目字段传入，至少覆盖实例 ID、`auditWay`、`jobTaskId`、`formProxyId`、`flowProxyId`、`flowNodeProxyId`、`formExist`、`tracking`、业务关联和流程名称。缺失导致原生打不开对应动作入口时阻塞。

### 3.3 身份

对齐 `runtimeAuthSync` 与 direct-url 入口：`sid`、`platformCode`、`customerCode`、`userId`、`userName`、`companyId`、`companyName`、部门等。SID 只来自 Go 当前账号会话，执行服务不自行登录或刷新 SID。每次操作人切换必须使用新 BrowserContext。

### 3.4 数据补丁时机

1. 导航前安装拦截，转发通道已连接。
2. 注入身份并导航原生路由。
3. 捕获 `$initFlow`/`$flowDetail` 实例，等待原生自行读完模板、实例数据和字段权限。
4. 仅通过组件现有数据接口（FormMaking `setData`/`getValues`/`getData`，自定义页和 NoFormFlow 的现有数据方法）应用当前节点允许的配置值。
5. 等待远程选项、人员关联和联动请求结束。
6. 回读完整值（含虚拟字段和显示值）交给 Go。
7. 再调用原生业务方法执行动作。

缺少入口或数据接口时明确阻塞，不手写第二套绑定规则。

## 4. 薄执行桥接

执行服务在页面脚本中拦截或包装 `$initFlow`、`$flowDetail` 的返回值，保存 `instance` 引用。外部只通过该引用调用页面已有方法，例如：

| 动作 | 原生入口（保持目标方法） |
| --- | --- |
| 保存草稿 | `FlowDialog.sumbitFlow('draft')` |
| 提交 | `FlowDialog.sumbitFlow('submit')` |
| 审批暂存 | `EnterpriseExamineOpinion` 暂存入口 |
| 同意 | 同意入口（不得走不同意分支） |
| 不同意 | 不同意入口（不得走同意专属业务） |
| 重提 | 重新提交入口 |
| 转发 | `flowTypeMixin` 转发入口（复合写：transpond → 按需附言） |
| 选择继续 | 原生 `handleSaveBranchChooseNode` / `handleSaveParallelChooseNode` / `getSelectPerson` |

禁止新增 `ExecutionHostInitiate.vue`、`ExecutionHostApprove.vue` 或把 `/test-auto-form/exec*` 搬进执行服务。目标 JSON 脚本内部仍可使用自己的 `$parent`/`$refs`/`$store`；外部调用不按 `$parent` 层数查找。

## 5. 协议 `exec-engine/v2`

生命周期接口保持：

```text
POST /runtime/session                 创建执行会话
POST /runtime/session/{id}/load       装载身份、原生流程/任务上下文和当前节点数据补丁
WS   /runtime/session/{id}/execute    执行业务命令并推送事件
GET  /runtime/session/{id}/status     查询当前状态（不执行、不触发目标请求）
POST /runtime/session/{id}/destroy    关闭会话
```

不兼容旧协议：`version` 必须是 `exec-engine/v2`；收到 `exec-engine/v1` 或缺少编号的消息直接拒绝。

装载载荷不再包含 `template` 渲染 JSON。Go 提供：

- 当前操作人身份（不含密码；SID 由会话现场持有，按参考项目方式注入页面存储/URL）；
- 发起：`auditWay`、计划绑定 `flowTemplateId`、`companyId`、工具流程名称；
- 实例：`flowInstanceId`、`mode`、完整 `taskContext`；
- 当前节点允许覆盖的数据补丁与变更字段；
- 分支选择、下一节点人员、审批意见、转发接收人等动作上下文。

缺少原生装载所需字段时拒绝装载，不允许用 Go 拼好的表单模板顶替。

结果七值保持：`success`、`failed`、`target_rejected`、`uncertain`、`business_failed`、`unsupported`、`timeout`。`unsupported` 仅表示原生缺少入口或数据接口，不再表示「能力未登记」。

取消：

- `CapabilityRegistry` 未登记即阻塞；
- `RUNTIME_EXEC_VERIFICATION` 验证模式；
- 额外成功证据登记作为执行门禁。

运行详情仍返回执行前后数据、请求轨迹和组件版本（快照 HEAD），复用现有运行详情与日志存储。

## 6. 请求转发与一次写

- 在 `page.goto` 之前安装 `page.route()`；先连 WS 转发通道，失败则不导航。
- 目标 `/web`、`/flowInstanceApi`、文件请求一律转 Go 的 `internal/adapter/target`，不新增 HTTP 客户端。
- 未登记外部请求本地拒绝。
- 普通动作一次只允许一个目标流程写请求；转发按「创建辅助实例 → 保存附言」最多两个写请求，同属一个动作编号。
- runtime 已发出写请求后，Go 不得再调用同一动作的 `TargetClient` 写方法。
- 写响应丢失、发送状态不明或业务完成事件不完整：进入结果待确认，禁止重发，禁止回退 Go 写路径。

## 7. 完成判断

不能以「调用方法返回」或「流程接口返回成功」单独判定完成。必须同时满足：

- 业务入口返回或发出明确完成事件；
- 请求计数归零并保持稳定窗口；
- 页面没有 `pageerror` 或未处理 Promise rejection；
- 业务完成事件没有失败项；
- 没有正在执行的附件、文件状态、业务回调或后置处理；
- runtime 返回表单前值、最终值和请求轨迹；
- Go 重新读取实例、任务、节点和表单并按现有 `verify` 规则裁决。

响应丢失为 `uncertain`；目标明确拒绝为 `target_rejected`；流程未发出且页面业务异常为 `failed`；流程成功但后置业务失败为 `business_failed`；Context 崩溃且无法确认写出状态为 `uncertain`。

## 8. 启动、健康与失败

- 默认 `127.0.0.1:19011`，环境变量 `RUNTIME_EXECUTOR_URL`。
- 提供独立构建、启动、健康检查命令；健康检查只证明服务进程与原生入口可装载，不访问目标平台。
- 删除 `internal/runtimeexec` 的进程托管（`StartExecutorSupervisor`）和 `RUNTIME_EXECUTOR_MANAGED` 默认拉起。
- 执行服务不可用：七个 runtime 动作写前阻塞并说明服务未启动；Go 直连动作、计划配置、表单维护和只读接口继续可用。
- 参考源码、依赖、FormMaking 产物、构建产物和凭证不提交 Git。
