# F-043 配置期表单数据准备：缺失必填安全补齐与计划账号身份注入

- 状态：`implementing`（2026-09-24 用户明确批准开始实施；用户确认目标接口可调用，但文件上传接口有时较慢，必须处理好超时/一次性上传缓存复用，不阻塞其余补齐）
- 提出时间：2026-09-24
- 依赖：F-012 历史业务数据回放与节点动作编排、F-035 真实处理人与有效表单数据闭环、F-036 独立执行服务（form-runtime 预览装载）。均已落地；本切片只修配置期数据准备的两个正确性缺口，不改运行期写协议、动作语义或调度。

## 1. 背景与问题（用户 2026-09-24 报告，含截图）

用户在「一键配置 / 表单数据准备预览」（配置期，工具栏为「返回节点画布 / 更换历史数据 / 恢复已保存数据 / 保存表单数据」）选择了一个历史实例后发现两个缺陷：

### 缺陷 1：当前规则必填字段缺失被放行

选中的历史实例当时的模板校验规则，某些字段非必填；但当前模板规则这些字段已变为必填（截图：「出入事由」现在必填、历史值为空，表单显示红色「请输入出入事由」）。一键配置生成表单数据时**没有把缺失必填标记为需人工补充，仍判为就绪（ready）放行**。

- 根因（已核实）：配置期数据就绪判定唯一出口是 `internal/service/path_data_workspace.go` 的 `workspaceDataStatus`（L758-768）——只要没有 `Blocking` 问题就返回 `ready`；`_ = validation` 明确不依赖 form-runtime 浏览器校验（F-035 裁决）。`GetData`（L113-139）与 `SaveData`（L419-449）汇总的 `issues` 只包含：分支/overlay 条件问题、静态下拉绑定问题、公司同步问题、身份问题、`unfillableKeyFieldIssues`（**仅决定性分支条件字段**）。**没有任何一处按当前模板的「必填 + 该字段在可达节点可编辑」校验有效值是否为空**。因此「现在必填、历史为空」的普通字段（非分支决定字段，如出入事由）不产生 `Blocking` 问题，直接判 `ready`。一键配置（历史回放自动生成，无浏览器）尤其如此：`input.RuntimeValidation` 为空，浏览器端红色必填提示根本不参与服务端判定。
- 事实可得：目标模板字段详情已带 `Required`（`internal/adapter/target/client_fact_reads.go:706`；`internal/adapter/target/types.go:288/346`）；字段可编辑时机由 `initiatorFieldPowers` / `formPermissions`（`path_runtime_projection.go`）算出。校验所需事实齐备，缺的是判定。

### 缺陷 2：表单未注入计划账号身份，仍显示历史发起人

表单数据预览没有把「计划中配置的账号（如 欧阳改）」的基本信息注入进去，表单「申请人 / 部门 / 公司」等仍显示原历史实例发起人（如 黄成礼）的信息。对取当前环境人员信息的字段，这是错的。

- 根因（已核实）：配置期 form-runtime 会话 `RuntimeSession`（`path_config.go:150`）用的是**计划账号**的 SID/userId/companyId/companyName/departmentId/departmentName/accountName（accountName=显示名，来自 `target_read.go:479`），前端 `FormRuntimeFrame.vue` 的 `load` 载荷（L141-158）也把这些透传给了 iframe——身份会话是对的。但表单字段值来自历史 `effectiveFormData`：`GetData`/`SaveData` 通过 `replaceUserIdentityValues` → `target.ApplyUserIdentityForAction`（`internal/adapter/target/protocol_matrix.go:525-562`）**只覆盖固定键集**（`global_user_basic_information`、`handledBy`、`expenseUserId/Name`、`myUserName` 等 F-035 费用/资金类映射）。「机房进入申请表」的申请人/部门/公司字段键不在该映射内，于是保留历史发起人值（黄成礼）。
- 参考项目佐证：`D:/work/bigsys/rsh-unified-vue3-web-test`（目标平台门户，通过 iframe 嵌入真实流程平台）在 `src/composables/useFlowApproval.ts` 的 `buildFlowUrl`（L239-296）把当前登录用户身份 `sid/platformCode/customerCode/userId/companyId` 及可选 `userName/companyName/userDepartmentName`（`userName = visibleUser.displayName || name`）作为 URL 参数传给被嵌入的流程平台；流程平台据此建立「当前登录用户」上下文，FormMaking 表单据此自动带出申请人等当前环境字段。要点：**当前用户身份（尤其显示名 userName、公司名、部门名）必须完整传入，供表单解析当前环境人员字段**。

## 2. 单一用户结果

配置期生成/预览的表单数据，**按当前模板校验规则完整、按计划账号身份呈现，且能安全自动补齐可确定的缺失必填**：能确定有效值的缺失必填字段自动补齐、无需逐条手填；不能安全补齐的（自定义组件、业务敏感字段、需真实引用的远程/上传）标 `needs_input` 并支持一次填写跨路径传播；取当前环境人员的字段显示计划配置账号而非历史发起人。全程不随机伪造业务数据。

## 3. 范围（2026-09-24 用户选定「有限安全补齐」方案）

### 包含
- 缺陷 1 补齐：在配置期数据准备链路（`GetData`/`SaveData`）对「当前模板 `Required=true` 且在本路径可达节点可编辑、当前有效值为空」的字段做**按类型确定性安全补齐**：
  - 普通 FormMaking 字段按类型取**确定性有效默认**（模板 `defaultValue` 优先；单/多选取首个可用 options 值；日期/时间取今天/当前按目标格式；数字取模板默认或满足 min 的最小值；布尔取模板默认或 false；无约束文本取固定占位如「自动补齐」）——**不随机**，避免违反长度/正则/枚举约束。
  - 文件上传字段：把项目内一个占位文件**一次性真实上传到目标文件服务**，缓存目标返回的文件引用（fileId/url 等），后续补齐复用同一引用；不使用项目内静态文件冒充目标可识别的上传结果。
  - 无法确定有效值的字段（自定义组件、业务敏感字段如金额/证件/绑定真实实体的人员、需真实 id 的远程下拉且无法唯一解析）：不猜值，落一条带字段中文名的 `needs_input`/阻断 `HistoryDataIssue`（`REQUIRED_FIELD_EMPTY`，字段名取自 `keyFieldLabels`），并支持**一次填写、跨共享该字段的路径自动传播**，避免逐路径重复手填。
  - 自定义组件（vue_custom/NoFormFlow）赋值：先摸清已实现自定义页的既有赋值口径（`setData`/等价接口），能安全确定默认的纳入补齐；其余保持 `needs_input` 并给出原因，不逐个反向工程覆盖全部自定义组件（避免无上限维护）。
- 缺陷 2：让配置期表单正确呈现计划账号身份——
  - (a) 核对并对齐传入 form-runtime 的身份键，确保携带解析当前用户所需的完整身份（显示名 userName、companyName、userDepartmentName、userId、companyId、customerCode、sid），键名与目标契约一致（对照 `buildFlowUrl`）。
  - (b) 把历史正文中「当前环境人员」字段（申请人/部门/公司等）覆盖为计划账号身份，覆盖判据取自**当前模板 FormMaking 组件「默认取当前登录用户」的标记**（与目标自动带出同一信号），而非硬编码字段名清单；无法从模板判定时回落到扩展 `ApplyUserIdentityForAction` 覆盖真实模板中出现的申请人类字段。

### 不包含（禁止预判式扩张）
- 不随机伪造业务数据；不用项目内静态文件冒充目标可识别的上传结果；不逐个反向工程覆盖「所有」自定义组件赋值。
- 不改运行期写协议、动作语义、调度、核验；不调用目标写接口（文件上传占位是目标只读文件服务的常规上传，作为数据补齐资源，不是业务写）；配置期不创建运行记录。
- 不改 `rsh-flow-components` fork 源码（form-runtime 按 `make refs-sync` + 一键同步维护，保持原样）；补齐与身份修复放在工具 Go/前端侧。
- 不引入字段映射器、渲染适配层或新的自定义页面状态模型；沿用现有 `effectiveFormData` + 既有 identity 覆盖链路。
- 不新增表或迁移；不改 `data_status` 语义（仍是 ready/needs_input/affected/empty）。

## 4. 口径

- 必填判定只用**当前模板**的 `Required` 与字段可编辑时机；历史实例当时的规则不作依据。
- 「有效值为空」按目标口径判定（空字符串、空数组、null、缺键均视为空；已填 0/false 不算空）。
- 只对「在本路径可达节点可编辑」的必填字段处理：整条路径都不可编辑的字段属目标运行时自动带值，不补也不误报。
- 安全补齐只填「能确定有效」的值；一旦类型/约束无法确定有效值即转 `needs_input`，绝不随机凑数或提交违规值。
- 文件上传占位文件放项目内固定资源，真实上传发生在目标文件服务；缓存的目标引用按账号/会话复用，失效时重新上传。
- 身份注入只覆盖「当前环境人员」字段，不改业务数据字段；身份读取失败或岗位缺失沿用 F-035 现有阻断语义。
