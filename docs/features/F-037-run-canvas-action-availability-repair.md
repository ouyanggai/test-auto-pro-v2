## 实现边界

运行期动态结构读取复用现有目标会话和图分析能力，不新增数据库表或迁移。运行详情按路径运行的主实例引用重新核对当前代理树；读取失败不覆盖计划图和已落账事实。动态节点只在静态计划图没有相同真实 ID 时标记为可点击，避免路径外静态节点被误判为运行路径。

路径偏离仍由执行控制服务的强制断点决定。详情只投影已落账的写后当前节点集合和配置路径预期节点，无法证明时明确显示证据缺失；不在详情层增加任何放行、重试或绕过入口。

步骤时间线由后端统一生成，已落账步骤优先，当前预览和下一条编译步骤只补不重复的序号。前端不再从多个旧字段猜测同一步骤的状态。

## 用户人工验收

1. 打开任意真实计划的节点动作配置，确认每条动作都有清晰的“删除动作”入口，删除后保存并重新进入确认确已删除。
2. 在运行画布点击多个节点，确认画布视口不自动跳动；点击“定位当前节点”时仍能主动定位。
3. 在真实流程发生加签后刷新运行详情，确认动态节点可见且可点击；若结构读取失败，页面应保留静态图并说明原因。
4. 构造或观察真实路径偏离，确认页面显示预期/实际节点和停止原因，操作区没有放行入口。
5. 打开节点检视面板，确认已执行、正在执行、等待执行步骤同时显示且颜色可区分；终态或空节点显示明确空态。
