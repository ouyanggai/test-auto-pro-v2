# F-026 配置动作原序直执行

- 状态：awaiting_approval
- 用户结果：用户配置多少条动作、排成什么顺序，运行器就逐条执行多少次；不再由工具改写、补动作或因顺序语义阻止保存。
- 用户提出时间：2026-09-10
- 依赖：复用 F-016 至 F-019 已有运行状态机、真实写适配、运行控制、写后核验和不确定写终局，不增加目标写端点。

## 本轮完成标准

1. 编译结果与用户动作严格一一对应，动作键、节点、参数、重复次数和顺序保持不变。
2. 不再插入重新提交、取回、准备同意、重走前驱、系统导航或最终同意等隐藏步骤，也不把“提交”转换成“重新提交”。
3. 保存动作时不再校验动作先后是否可恢复；重复关注、无来源重新提交、节点回跳等顺序都允许保存。
4. 执行器每步仍从目标实时解析实例、待办、人员和权限，保留一次写、写后核验、结果不确定即终止等安全边界；目标当前状态不接受该动作时，本步按真实原因失败，不自动换动作、跳过或继续。
5. 既有路径无需重新打开配置页保存；新运行直接从 `user_actions` 生成一一对应步骤，不消费历史 `compiled_steps` 中的旧隐藏步骤。已经开始的运行不改写事实，需停止后重新发起。
6. 计划 `oyg测试1003` 的 `路径1` 新运行前三步必须是“保存草稿 → 保存草稿 → 提交”，不出现系统重新提交；每步结果完全以目标接口和写后重读为准。

## 范围

### 包含

- 将 `internal/engine/scenario` 收敛为有序动作投影：稳定排序后每条 `ConfiguredAction` 生成且只生成一条用户步骤。
- 删除动作状态推演、恢复步骤插入、自动节点步骤和最终导航步骤。
- 删除保存阶段针对动作排列的阻断，包括重新提交来源、关注状态、节点回跳、移交后演员连续性和回退前驱等顺序判断。
- 保留配置输入的结构与安全校验：动作必须来自已开放目录，作用域与节点类型匹配，节点属于当前路径，参数不得固化目标临时实例、任务、代理或人员标识，人员策略仍受当前合法范围约束。
- 运行启动、运行详情和运行恢复统一从保存的用户动作生成直接步骤，避免旧编译结果继续影响新运行。
- 配置预览只显示用户配置动作，不再展示系统恢复或系统导航动作。
- 删除或改写与旧自动恢复语义绑定的测试，新增直接执行契约。

### 不包含

- 不取消执行时的账号、权限、实例、待办、人员和目标状态实时检查。
- 不绕过目标平台业务校验，不伪造目标临时标识，不跳过失败写动作。
- 不把一个动作失败后自动改成其他动作，也不自动创建第二主实例。
- 不修改路径偏离的真实事实判定和断点规则；本轮仅保证偏离判定不再被隐藏步骤污染。
- 不新增或删除目标写端点，不调整数据库表结构。
- 不包含运行记录单条删除和批量删除；该需求登记为 F-027，待本切片完成后独立规划。

## 关键行为

### 保存

- 重复动作继续以多条独立记录保存，不折叠成次数，也不去重。
- 服务端仍校验浏览器不能伪造未知动作、错误节点、错误作用域或目标临时标识。
- 服务端不根据前后动作推演目标状态，不判断顺序是否“可恢复”。

### 运行

- 新运行按 `order` 读取 `user_actions`，每条动作对应一个运行步骤。
- 动作名称决定真实目标端点：“提交”始终执行提交，“重新提交”始终执行重新提交；运行器不代替用户改写选择。
- 相同动作连续配置 N 次就执行 N 个独立步骤。每一步都重新读取目标事实并重新解析必要的实例、任务和人员标识。
- 若第二次动作已不满足目标当前状态，执行器在写前门禁或目标返回处如实失败并停止；不把失败解释成配置错误，也不偷偷插入恢复动作。
- 系统自动节点由目标引擎自己推进，工具只在写后重读实际节点和路径，不创建可放行的伪动作步骤。

### 已有配置与运行

- `compiled_steps` 不再作为新运行的权威输入；新运行以 `user_actions` 为唯一动作顺序来源。
- 配置保存仍可写入一一对应的 `compiled_steps` 供只读预览，后续可在独立数据模型切片中评估删除冗余列，本轮不改表。
- 已经产生步骤事实的运行保持原样，避免同一运行前后使用两套动作语义。

## 实施任务

1. 更新场景编译器和保存服务，移除顺序状态机、恢复与导航步骤，保留结构和安全校验。
