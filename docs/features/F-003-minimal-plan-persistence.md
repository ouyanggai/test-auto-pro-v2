# F-003 最小计划持久化

- 状态：implementing
- 产品依据：`docs/PRODUCT.md` 的“计划与运行主线”“测试计划页面行为”
- 架构依据：`docs/ARCHITECTURE.md` 的“系统边界”“数据与部署演进”
- 计划形成时间：2026-07-28
- 计划确认时间：2026-07-28

## 单一用户结果

用户在新建计划页完成账号验证和流程选择后，点击“创建并选择路径”会真正创建一条“待配置”计划；刷新页面或重启前后端后，该计划仍能在测试计划列表中查到，并可通过“继续配置”回到这条计划的独立配置入口。

F-003 只建立“创建计划—持久保存—列表读取—继续配置入口”的最小闭环。真实流程图和执行路径必须依赖后续读取到的真实流程结构，因此本切片不创建没有业务依据的空路径或伪路径记录。

## 切片决定

此前路线图把“最小计划与路径配置”写在同一阶段。规划核对后将其拆开：

- F-003 只持久化计划创建页已经确定的业务字段和目标流程快照。
- F-004 读取并显示真实流程结构。
- F-005 在真实流程结构上选择执行路径，并首次建立执行路径持久化。

这样可以避免 F-003 先设计一套没有真实节点、分支和实例语义的路径表，随后在 F-004/F-005 返工。该切片调整需要用户和本计划一起批准。

## 范围

包含：

- 引入 MySQL 作为工具侧计划存储，使用 Go 标准库 `database/sql` 和一个 MySQL 驱动，不引入 ORM。
- 从 V1 `runnerDb` 安全同步本机开发连接参数，使用独立数据库 `test_auto_pro_v2`；日常 `pnpm dev:b` 不要求用户手工填写数据库参数。
- 版本化创建最小计划表和迁移记录表；后端启动时只执行尚未应用的迁移。
- 创建计划 API、计划列表 API和单条计划 API。
- 新建页提交真实创建请求，防止连续点击产生重复计划；成功后进入独立计划配置入口。
- 测试计划列表移除静态 mock，真实读取持久化计划，支持名称和状态筛选、空状态、加载失败与重试。
- 独立计划配置入口读取并展示已经保存的计划摘要；路径尚未选择时明确显示空状态，并允许返回列表。
- 只运行 F-003 相关测试、类型检查和构建，并由用户人工核对持久化结果。

不包含：

- `execution_paths`、节点、分支、表单数据、人员、动作和成功断言等路径结构。
- Vue Flow、dagre、真实流程结构读取与路径选择；这些分别属于 F-004、F-005。
- 修改计划、删除计划、复制计划、自动保存路径配置和计划状态流转。
- 运行准备、定时调度、运行记录、执行引擎和目标平台业务写操作。
- MongoDB、Redis、Docker、Nacos、微服务、独立迁移服务或通用数据访问框架。
- 将 V1 业务表、V1 计划数据或目标平台 MySQL 数据复制进新库。

## 产品行为

### 创建计划

- 点击主要操作前不保存空计划。
- 创建请求必须来自当前已验证账号和当前已选流程；账号编辑后原验证与选择继续按 F-002 规则失效。
- 创建期间主要按钮进入 loading 并禁止重复提交；同一次提交的网络重试使用同一个幂等键，服务端返回同一条计划。
- 成功后显示简短成功反馈并进入 `/plans/{id}/paths`。
- 参数错误保留用户已填写内容并就地提示；数据库不可用时保留内容，提示“暂时无法创建计划，请重试”，不得显示成功或清空表单。
- 新计划状态固定为“待配置”，路径数量为 `0`，最近运行结果为空。

### 计划列表

- 列表数据来自 MySQL，不再混用 F-001 mock。
- 支持计划名称包含搜索和计划状态筛选；F-003 真实数据只有“待配置”，接口仍使用稳定状态枚举。
- 默认按最近修改时间倒序；相同时间按计划 ID 倒序。
- 空数据和无筛选结果都显示正常空状态；读取失败显示重试，不回退 mock。
- “待配置”计划的唯一主要操作是“继续配置”，进入 `/plans/{id}/paths`。

### 继续配置入口

- 页面按 URL 中的计划 ID 读取计划，展示计划名称、目标流程、发起账号、流程来源、运行方式和定时信息。
- F-003 不伪造路径列表；空状态使用产品语言说明“还没有选择执行路径，计划已经保存，可以稍后继续”。
- 计划不存在显示明确空状态并提供返回测试计划，不跳到另一条计划。

## 最小数据模型

### `test_plans`

| 字段 | 约束 | 说明 |
| --- | --- | --- |
| `id` | `BIGINT UNSIGNED AUTO_INCREMENT` 主键 | 内部计划标识，页面不把它作为业务信息展示 |
| `create_key` | `CHAR(36)` 唯一、非空 | 同一次创建提交的幂等键，不显示给用户 |
| `name` | `VARCHAR(60)` 非空 | 去除首尾空白后的计划名称 |
| `account` | `VARCHAR(100)` 非空 | 已验证的目标平台账号 |
| `account_display_name` | `VARCHAR(100)` 非空默认空串 | 创建时验证摘要快照，仅用于展示 |
| `flow_source` | `VARCHAR(16)` 非空 | `new`、`started`、`pending` |
| `target_object_id` | `VARCHAR(100)` 非空 | 模板 ID、已发实例 ID 或待发实例 ID |
| `target_object_name` | `VARCHAR(255)` 非空 | 创建时所选流程名称快照 |
| `run_mode` | `VARCHAR(16)` 非空 | `serial`、`parallel` |
| `max_concurrency` | `SMALLINT UNSIGNED` 可空 | 串行为 `NULL`；并行沿用当前页面已验收范围 `2..20` |
| `scheduled_at` | `DATETIME(3)` 可空 | `NULL` 表示关闭定时；保存 UTC，接口使用 RFC 3339 |
| `status` | `VARCHAR(32)` 非空 | F-003 只允许 `pending_configuration` |
| `created_at` | `DATETIME(3)` 非空 | 创建时间，UTC |
| `updated_at` | `DATETIME(3)` 非空 | 最近修改时间，UTC |

数据库只增加 `(status, updated_at, id)` 排序筛选索引。当前数据规模和名称包含搜索不证明需要全文索引，F-003 不提前增加。

`schedule_enabled` 不单独保存，`scheduled_at IS NULL` 已完整表达关闭状态；`target_object_kind` 不重复保存，`flow_source` 已决定目标对象类型。SID、密码、验证码、AES key、customerCode、platformCode、目标响应原文和候选编码一律不进入数据库。

## API 边界

### 创建计划

`POST /api/plans`

请求头：

- `Idempotency-Key`：前端为一次创建操作生成的 UUID；重复请求返回原计划。

请求体只包含当前业务字段：

```json
{
  "name": "采购申请主流程回归",
  "account": "tester01",
  "accountDisplayName": "测试专员",
  "flowSource": "new",
  "targetObjectId": "template-id",
  "targetObjectName": "采购申请",
  "runMode": "serial",
  "maxConcurrency": null,
  "scheduledAt": null
}
```

后端重新校验名称、枚举、来源与目标 ID、串并发约束和未来定时时间。F-003 不为了创建计划再次调用目标平台，也不把浏览器传入的显示名称当作目标平台业务事实；F-004 读取真实流程结构时必须用保存的账号、来源和目标 ID 重新核对。

成功返回 `201` 和计划摘要；同一幂等键重试返回 `200` 和同一计划。不同幂等键允许创建内容相同的两条计划，计划名称不承担唯一标识职责。

### 计划列表

`GET /api/plans?name=...&status=...`

- `name` 可空，按去除首尾空白后的包含匹配。
- `status` 可空；非法枚举直接返回 `400 INVALID_ARGUMENT`。
- F-003 不做无依据的复杂分页，先返回最多 200 条最近计划；达到真实规模上限后再单独引入游标分页。

### 单条计划

`GET /api/plans/{id}`

- ID 非法返回 `400 INVALID_ARGUMENT`。
- 不存在返回 `404 PLAN_NOT_FOUND`。
- 响应只含计划业务摘要和时间，不含 `create_key` 或数据库内部字段。

### 稳定错误

| 场景 | HTTP / 错误码 | 页面行为 |
| --- | --- | --- |
| 字段或筛选非法 | `400 INVALID_ARGUMENT` | 保留输入并显示对应业务提示 |
| 计划不存在 | `404 PLAN_NOT_FOUND` | 配置入口显示不存在并允许返回 |
| 数据库未配置 | 后端启动失败 | 终端只列缺少的配置名，不输出连接串或密码 |
| 数据库连接或查询失败 | `503 PLAN_STORAGE_UNAVAILABLE` | 创建或列表保留当前页面并允许重试 |
| 服务端数据异常 | `500 PLAN_DATA_INVALID` | 显示“计划数据异常，请联系维护人员” |

## MySQL 与迁移

- 工具侧连接只读取 `PLAN_DB_HOST`、`PLAN_DB_PORT`、`PLAN_DB_USER`、`PLAN_DB_PASSWORD`、`PLAN_DB_NAME`；优先级继续使用“进程环境 > 根目录 `.env.local` > 非敏感默认值”。端口默认 `3306`，库名默认 `test_auto_pro_v2`，凭证没有代码默认值。
- 本机同步只读取用户已批准沿用的 V1 `runnerDb`，不读取 `target.mysql*`。后者属于目标平台数据源，禁止混作工具数据库。
- 同步工具保留现有 `TARGET_*`，只合并 `PLAN_DB_*`，原子写回被 Git 忽略的 `.env.local`，权限保持 `0600`；命令、测试和日志不回显真实值。
- 数据库名只允许字母、数字和下划线。首次实施在已批准的 V1 MySQL 服务上创建独立 `test_auto_pro_v2` 数据库；不改动 V1 原数据库和表。
- 使用版本化 SQL 和 `schema_migrations` 记录。后端启动时先连接、创建数据库、执行未应用迁移，再开始监听端口；配置缺失、连接失败或迁移失败时直接退出，避免 health 正常但写入必然失败。
- MySQL 连接使用 `utf8mb4`、明确时区和 `parseTime`；应用与数据库统一保存 UTC，前端按浏览器时区展示。
- F-003 只允许向前迁移，不自动执行 down 或删除表。数据库和表的创建是本计划需要用户明确批准的基础设施变更。

## 代码边界

- `internal/model`：计划领域类型和状态枚举。
- `internal/repository`：计划仓储接口；`internal/repository/mysql` 只实现 SQL、迁移和行映射，不放业务规则。
- `internal/service`：创建校验、幂等语义、计划查询编排。
- `internal/api`：HTTP 解析、稳定错误和响应 DTO。
- `web/src/features/plans`：计划 API、展示映射和当前页面状态；不建立通用 CRUD 框架。
- `web/src/views/PlanPathsView.vue`：F-003 的独立继续配置入口，只展示已保存摘要和真实空状态，不预画流程图。

## 回退与失败边界

- 应用回退不自动删除数据库或计划数据；F-003 迁移只新增独立数据库和表。
- 若需要彻底移除，必须由用户另行明确授权后再删除精确的 `test_auto_pro_v2` 数据库；本功能不提供自动 down 或清库命令。
- MySQL 不可用时不回退内存或 localStorage 保存，避免用户误以为计划已经持久化。
- 创建响应不明确时，前端使用同一幂等键重试；禁止生成新键盲目重发。
- F-004 读取真实流程时若发现保存的目标对象已不可见或结构变化，只报告并要求用户处理，不在 F-003 猜测版本或复制目标数据。
