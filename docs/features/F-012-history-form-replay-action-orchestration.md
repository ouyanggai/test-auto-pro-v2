## 目标

交付一个可独立验收的“配置准备完成”闭环：用户从当前账号可见的同流程历史实例选择一份真实历史业务数据，系统按目标平台现有数据协议完整回放，只对当前执行路径必需的条件字段做最小修改；用户再按真实节点和实例门禁配置有序动作，系统把这些动作编译为同一个主流程实例上可执行、可恢复、可逐步核对的只读场景。FormMaking 与无表单流程（目标平台实际是 `vue_custom`/NoFormFlow 自定义页面）共享同一数据链路，是否存在 FormMaking 模板不决定数据链路是否启用。

本切片完成后，路径的人员、历史业务数据和动作都能保存并形成明确的准备状态，但不会创建运行记录，也不会向目标平台发送任何写请求。

### 数据原则

- 历史实例返回的表单数据按目标平台原始结构保存和传递，不在测试工具中再包一层新的数据对象、不扁平化、不删字段、不把对象转成展示文本。
- `form-runtime` 是从目标平台复制的完整运行时，已经负责 FormMaking、有表单自定义组件和无表单自定义页面的渲染、回显、编辑和校验。测试工具只按它现有协议传入目标历史数据及必要上下文，不在主应用或后端另建渲染适配层。
- `formExist=noForm/notForm` 与目标返回的 `vue_custom` 仍纳入同一历史数据来源和回放任务；区别只由现有 `form-runtime` 协议处理，不参与候选、快照、分支、状态或动作门禁判断。
- 历史数据读取不完整、目标运行时无法接受或路径条件字段无法按目标原路径复验时，进入 `needs_input` 并说明证据缺口；不跳过、不猜测、不生成。

## 已确认产品决策

### 统一数据范围

- 本次切片同时纳入 FormMaking 和无表单自定义表单；无表单不是缺失数据，而是目标平台 `vue_custom`/NoFormFlow 的另一种渲染协议。
- 所有候选、快照、回放、分支补丁、数据状态和保存接口都直接使用目标表单数据；`renderType` 仅作为复制的 `form-runtime` 现有协议所需的运行时参数。
- 无表单自定义表单不要求测试工具重建页面脚本、绑定或校验；原始数据直接交给复制的 `form-runtime`，runtime 无法接受时进入 `needs_input`。

### 历史候选与来源

- 候选只读取计划所用账号在目标平台当前可见的历史数据。
- 候选筛选只使用目标平台返回的原字段：精确匹配 `flowCode`；有表单时匹配包含公司后缀的完整表单名称，无表单时匹配目标返回的流程/页面名称等原始身份字段，不由测试工具拼装新的身份键。目标没有足够字段时选择后标记 `needs_input`。
- 所有实例状态均可选择；已完成实例优先排序，草稿、运行中、驳回、撤回等候选显著提示“数据可能不完整”。
- 选择弹窗至少显示目标返回的表单/流程名称、实例标题或业务摘要、发起人、所属公司、发起时间、当前状态和完整性提示；浏览器只持有不透明候选键，不暴露目标内部标识。
- 用户可以为计划设置一个默认历史来源；每条路径默认继承，也可以选择自己的历史来源。路径覆盖不反写计划默认值。
- 没有候选时直接提示“请先在目标平台发起一次该流程并填写业务数据，再回来刷新”；不再调用任何智能生成或样本兜底。
- 模板版本不一致的历史数据仍允许选择，但必须展示版本差异和复制的 `form-runtime` 可接受性结果，不静默阻断。

### 快照与回显

- 用户确认候选后，后端立即读取并深复制目标接口返回的完整表单数据、来源摘要和目标模板/页面摘要，形成工具侧不可被候选后续变化覆盖的历史快照；不改变目标数据结构。
- 字段只按目标流程条件和现有 `form-runtime` 协议提供的真实 JSON 路径处理；禁止按标签、中文名、相似字段名、组件类型或页面视觉位置猜测。
- 历史快照中的嵌套对象、数组、子表、虚拟字段、系统辅助字段、已注册自定义组件值和无表单页面数据完整保留。
- 当前目标运行时新增但历史快照不存在的普通必填字段进入人工补充清单；系统只保留运行时默认值或空值，不生成内容。
- 当前目标数据结构已删除的历史字段不写入本次有效数据，但在差异摘要中列出；保存后的有效数据以复制的 `form-runtime` 现有数据捕获协议为准。
- 数据统一在复制的 `form-runtime` 中回显、编辑、校验和保存。页面提供“更换历史来源”和“恢复本次历史快照”，不再出现智能生成、换一组、随机种子、示例值或规则状态。

### 分支最小补丁

- 历史来源不需要命中过当前用户选择的路径。系统在目标原始表单数据上只修改决定当前路径的字段，其他字段原样保留。
- 条件字段不再锁定，用户可在复制的 `form-runtime` 中编辑。保存前后均以当前目标表单数据重新计算实际路径。
- 用户修改条件字段导致路径变化时，页面必须展示“原路径 → 新路径”、关键字段差异和受影响配置，并询问是否仍然保存。
- 用户取消时保持原路径和当前编辑，不写入；用户确认时以人工值为准，把该份历史业务数据切换到实际命中的路径。
- 目标路径已有数据或节点配置时，确认框必须明确说明将覆盖哪些历史表单数据、需要重新核对哪些人员和动作；确认后保留旧路径配置，更新新路径数据并把新路径相关人员/动作重新校验为 `affected` 或合法状态。
- 手动分支保存显式分支选择，不修改目标表单数据；并行节点的全部真实分支仍属于同一执行路径。
- 最小补丁只能使用历史现值、目标条件字段真实选项、规则常量和规则边界构造候选；按“改动字段数最少，其次值偏移最小，最后字段路径稳定排序”选择唯一结果。
- 无法得到唯一且可复验的最小补丁时，不制造数值，返回 `needs_input` 并定位需要用户修改的字段和原因。

### 目标条件语义

条件计算必须逐项复刻目标 Java 当前实现，而不是使用旧 `ConstraintIR`：

- 支持且仅支持当前引擎已证明的 `lt`、`gt`、`lte`、`gte`、`eq`、`neq`、`contains`、`is_update`、`is_not_null`、`boolean_value`。
- 数值比较按目标的 `BigDecimal` 转换与失败边界；比较右值既可能是固定值，也可能来自另一个字段。
- `contains` 按目标实现的“B 包含 A”方向计算，不能沿用常见库的相反直觉。
- 条件组按目标保存顺序逐条应用实际 `and/or` 连接，不自行重排或归一化。
- 同一路由节点按真实分支顺序取第一个成立分支；最后一个分支作为兜底，不把其条件当作普通独立分支。
- 当前目标 `boolean_value` 实现先要求 Y/N 形态、随后又与“是”比较，存在无法同时满足的分支时必须报告目标规则不可满足并阻止准备，禁止改写成产品认为合理的布尔语义。
- 未知操作符、转换失败、字段缺失、字段对字段循环依赖和无法证明的脚本条件全部进入 `needs_input`。

## 动作目录与门禁

### 动作分类

| 分类 | 用户动作 | 配置位置 | 关键语义 |
| --- | --- | --- | --- |
| 发起生命周期 | 保存草稿、提交、重新提交 | 发起节点/实例步骤 | 保存草稿产生或保持草稿实例；重新提交只用于目标允许的草稿、驳回或撤回状态。 |
| 当前待办处理 | 暂存当前表单、加签、移交、同意、不同意、回退上一节点 | 当前审批/协同节点 | “暂存当前表单”只保存当前用户、当前批次、当前节点的任务检查点，不推进任务。其余动作按真实状态迁移。 |
| 已办恢复 | 取回 | 已完成任务对应节点 | 只能在后继尚未处理且目标运行时门禁全部满足时恢复当前待办。 |
| 实例管理 | 撤回、催办、转发、关注、取消关注 | 实例上下文步骤 | 撤回受创建人和运行状态限制；催办面向当前待办接收人；转发创建独立辅助流程；关注不迁移主流程。 |
| 系统自动 | 条件、手动分支、并行、汇聚、空、结束、定时、子流程、回调 | 只读展示 | 显示引擎会自动执行或等待的语义，不提供用户动作配置。 |
| 排除 | 删除、作废及其他不可恢复终止能力 | 不进入场景 | 可以在说明中标识，但不允许被编排。 |

“暂存”必须在模型和界面中拆成两个不同概念：发起端“保存草稿”是实例生命周期动作；审批端 `storageFormData` 是节点任务检查点。审批暂存不得作为通用实例动作，也不得改变实例状态、任务状态或当前节点。

### 关键门禁

- 加签只允许当前实例的当前活动待办、人工审批或协同普通节点、非转发上下文、流程代理可编辑且候选结构完整时配置。发起、条件、手动、并行、汇聚、空、结束、非当前节点、无待办或转发流程均不可加签。
- 加签执行会通过 `updateFlowProxy` 在必要时把公共代理复制为实例私有代理并重映射任务，属于结构变化；后续步骤必须重新读取私有代理、当前任务和语义节点，不能持有旧 proxy ID。
- 移交通过当前待办的 `approverAppend` 语义改变当前处理人，只能从实时受限候选中选择；动作后立即切换演员并重读任务。
- 取回必须同时满足：操作者拥有已完成任务、下一任务尚未处理、实例仍在运行且未结束、不是发起限制场景，并满足会签、并行和后继数量限制。任何条件无法静态证明时显示运行时阻断，不宣称一定可执行。
- 撤回只允许运行中的实例创建人；催办只发送给当前待办接收人；关注/取消关注按当前用户保存，不迁移任务。
- 转发可以从待办、已发和已办上下文发起，创建“系统默认转发流程”辅助实例；原主实例继续存在，辅助实例单独记录，不能冒充主实例节点跳转。
- 回退只使用真实当前待办的直接前一待办，不接受用户指定任意目标，且前驱为发起节点时按目标规则阻止。
- 所有目录项均返回 `enabled`、中文 `disabledReason`、所需参数、前置状态、预期状态变化和是否需要运行时重读；页面不得只隐藏动作而不解释真实门禁。

## 同一主实例的动作编排

### 用户配置模型

- 用户在节点或实例上下文内拖拽排序动作；同一动作需要重复时添加多条独立记录，不使用“次数”字段隐式展开。
- 保存项使用稳定语义键，不保存临时 task ID、proxy ID 或目标内部可变对象；运行时再按语义节点和当前事实解析。
- 每条 `ConfiguredAction` 至少包含：稳定动作键、作用域、语义节点键、用户顺序、参数、演员策略、用户说明和配置修订号。
- 保存动作配置时服务端立即编译全场景；只要存在无法回到预期节点、演员不连续、状态不可恢复或后续动作必定失效，就拒绝保存并定位第一条不合法动作。

### 恢复与导航规则

| 用户动作 | 编译器插入或验证的步骤 |
| --- | --- |
| 保存草稿 | 后面仍有动作时插入重新提交，并重新解析当前路径。 |
| 提交/重新提交 | 重读实例、代理、当前节点和待办，确认实际进入所选路径。 |
| 暂存当前表单 | 不插入状态恢复；重读当前任务表单检查点后仍停留当前节点。 |
| 加签 | 重读实例私有代理和任务映射，后续步骤仅按语义节点继续。 |
| 移交 | 切换当前演员，重读待办；后续需要原演员的动作必须显式证明可切回。 |
| 同意 | 后面还有同节点动作时必须立即取回并证明可回到当前节点；取回不合法时，同意只能作为离开该节点的最后动作。 |
| 取回 | 若当前上下文尚无可取回的已办任务，可先插入一次满足门禁的同意作为准备；准备动作和取回均在预览中显示。 |
| 不同意 | 等待实例进入驳回状态，插入重新提交，并按当前表单值重新驱动路径回到目标节点。 |
| 撤回 | 等待实例进入撤回状态，插入重新提交，并重新驱动路径；无法回到目标节点时阻止。 |
| 回退上一节点 | 执行真实前驱回退，切换到前驱演员和待办，再按已配置路径处理前驱直至返回当前节点。 |
| 催办 | 不改变状态；重读当前待办和接收人后继续。 |
| 转发 | 将辅助流程 ID 和状态记录为旁支结果，主实例游标不移动。 |
| 关注/取消关注 | 只核对当前用户关注状态，主实例游标不移动。 |

- 系统为通过条件/手动/并行/空等自动节点而插入的步骤标记为“系统导航”，不得显示为用户配置动作。
- 当前业务节点的用户动作完成后，编译器插入最终导航同意；最终节点的最终导航结束主流程。
- 不使用数据库快照恢复目标实例，不创建新的主实例来模拟恢复，也不绕过目标平台真实门禁。

### 编译结果

只读 `CompiledActionStep` 至少包含：全局顺序、来源动作键、步骤来源（用户/系统恢复/系统导航）、当前演员策略、预期语义节点、动作和参数、前置事实、预期效果、失败后的停止条件、恢复策略及强制重读屏障。

编译结果为未来单步执行器预留持久游标：每个目标写动作完成并重读事实后才允许游标前进。但 F-012 只保存配置和编译结果，不实现该游标执行器。

## 数据状态与派生规则

- 节点配置状态沿用 `pending | partial | configured | affected`，只由人员和动作当前有效性派生。
- 历史表单数据状态重建为 `empty | needs_input | ready | affected`：
- `empty`：尚未选择历史来源或没有有效目标表单数据。
- `needs_input`：存在缺失必填字段、无法满足的分支、未知精确映射或需要用户确认的问题。
- `ready`：复制的 `form-runtime` 校验和当前路径复验均通过。
- `affected`：目标模板/页面、路径、来源或人工条件字段变化使已保存结果需要重新核对。
- 路径只有节点为 `configured` 且历史表单数据为 `ready` 时才达到“配置准备完成”。计划公开状态仍保持 `not_started`，不因准备完成而产生运行事实。
