## 目标

在启动之前给出一句用户能直接照做的中文结论：这条路径现在能不能跑；不能跑的，逐条说清为什么，并且每条都能点进具体路径的具体位置去改。

阻塞只保留用户自己能处理的那几类。跑到哪里算成功由后续的断点功能表达，本切片不再有成功断言。

## 单一用户结果

用户在计划的路径列表上勾选要跑的路径，点运行，先看到运行前检查结论：要么"这 3 条路径可以启动"，要么"2 条可以启动，1 条被阻塞"并逐条列出阻塞原因，例如"节点人员与动作配置尚未完成""基础表单数据尚未就绪""编译场景为空，没有可执行的步骤"。每条阻塞项都可点击，直接落到那条路径的对应配置面板。

预检只检查本次勾选的路径——运行只跑勾选的，预检也必须只检查勾选的，否则用户看到的阻塞与本次要跑的东西不是一回事。首次进入页面时，已配置且数据就绪的路径默认勾选。

提醒与阻塞分区展示：提醒不挡启动，阻塞挡。

启动按钮、运行模式选择、断点与运行记录都不在本切片。

## 设计要点

### 结论结构

一个计划一句总结论，加逐条路径明细。每条阻塞项复用既有的 `model.PathConfigAffectedItem` 形状（`kind`/`name`/`reason`），另加可点击定位所需的路径标识与面板锚点。

| 阻塞来源 | 判断依据 | 说明 |
| --- | --- | --- |
| 节点配置未完成 | `ExecutionPath.ConfigurationStatus != configured` | 复用既有状态，不重算 |
| 基础表单数据未就绪 | `ExecutionPath.DataStatus != ready` | 复用既有状态 |
| 配置已记录的问题 | `test_execution_path_configs.issues` 中 `blocking=true` 的条目 | 原样透出，不改写文案 |
| 路径配置读取失败 | `GetPathConfig` 返回错误 | 与「没有配置记录」严格区分，见下节 |
| 编译场景为空 | `compiled_steps` 为空 | 不静默放行 |
| 动作尚未验证可执行 | 路径动作不在 F-016 已登记的已验证子集内 | 纲领第 9 节要求直接阻塞，不做静默降级 |
| 路径拓扑已变 | 路径与当前真实流程结构复验不一致 | 目标结构变化必须挡住启动 |

仅提醒不阻塞的条目：用户看不懂或无法处理的说明性内容（例如"表单校验会在打开表单数据页时完成"），以及计划已固化的只读提示。提醒与阻塞在界面上分区，不允许把提醒混成阻塞。

### 读不到配置必须阻塞

`GetPathConfig` 返回错误与返回「不存在」含义完全不同：后者是"确实还没配"，前者是"不知道配没配"。把两者合并会造成一个危险方向——路径摘要恰好是「配置完成、数据就绪」时，读取失败不产生任何阻塞，这条其实无法判断的路径会被判成可以运行。因此读取失败单独成一类阻塞，文案为可重试的中文提示。

### 错误语义

- 计划确实不存在：404 语义，文案"计划不存在"。
- 计划 ID 不合法：参数错误语义。
- 存储不可用或数据异常：存储类错误，文案可重试（"暂时无法读取计划，请重试"）。不得把存储故障说成"计划不存在"，那是不可重试的说法，用户看到就不会再试。
- 真实结构读取失败：目标类错误，明确说明结论不完整并可重试。

### 默认勾选

首次读到路径列表时套用默认勾选：已配置且数据就绪的路径默认勾上，用户点运行时通常就是要跑这些。用户已经做过勾选后一律尊重用户的选择，不再覆盖。

## 详细执行任务

### T01：运行前检查聚合与领域类型

纯聚合函数与结论类型：按路径产出阻塞与提醒、可点击锚点、一句中文结论；阻塞与提醒严格分开。

### T02：服务层读齐既有事实

真实流程结构每个计划读一次；路径摘要与路径配置按路径读数据库；拓扑复验复用现有分析器。配置读取失败单独成阻塞，计划与存储错误按语义分开映射。

### T03：只读 API

读取一个计划在给定勾选下的运行前检查结论。失败统一经 `writeFailure`，中文文案与日志同源，响应不暴露目标临时标识。

### T04：前端运行前检查

路径列表页的运行前检查弹窗：阻塞与提醒分区、阻塞项可点击跳到对应路径与面板、已配置路径默认勾选、空态与失败态都有中文说明并可重试。

### T05：测试与汇总入口

纯聚合函数逐类用例；真实 MySQL 集成测试覆盖真实事实读取与两种错误语义；API 与前端结构契约；写端点白名单为空断言；成功断言不得回归的反向锁定；`test/run-f015.sh` 汇总入口，集成用例不得静默跳过。

## 人工验收

1. 打开一个已有多条路径的计划：确认已配置且数据就绪的路径**首次进入就默认勾选**，不需要手动再勾一遍；取消勾选后再刷新，确认默认逻辑不会覆盖你刚做的选择。
2. 点运行：确认弹出运行前检查结论，一句中文总结论 + 逐条路径明细，并且只检查你勾选的路径。
3. 确认阻塞与提醒是分开的两块，提醒不挡启动。
4. 故意制造一条阻塞（例如清空一条路径的基础表单数据）：确认该路径立刻变为阻塞、原因是中文可读的、点击后落到那条路径的对应面板。
5. 确认所有阻塞都是你能自己去改的事；看不懂或改不了的内容应出现在提醒区而不是阻塞区。
6. 确认界面上没有成功断言相关的入口、卡片或字段——该功能已整体移除。
7. 确认页面上没有出现启动按钮之外的运行模式选择、断点或运行记录入口——它们属于 F-016 之后的切片。
8. 在项目根执行 `./test/run-f015.sh`，确认全部通过、没有跳过用例，并确认输出里包含「真实 MySQL 集成测试」与「写端点白名单为空」两项。
