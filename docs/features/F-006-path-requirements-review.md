系统可以针对任一已保存路径，按当前目标平台真实配置分析后续自动执行需要准备的条件数据、处理人和节点动作，并区分哪些由目标平台自动确定、哪些只能在运行时确定、哪些规则当前无法可靠识别。该结果保留为后续可操作配置的直接输入，不再单独呈现给用户核对。

## 真实行为依据

- 目标模板和代理详情的 `flowNodeTemplate` 同时包含 `conditionNodes`、`parallelNodes`、节点审批配置和字段权限；当前工具只提取了结构，F-006 可以在同一次详情解码中补充内部要求元数据，无需再建立一棵流程图。
- 目标条件包含字段 A、字段 B 或固定值、判断方式和 `and/or` 连接关系。目标执行服务按分支顺序判断，并在前序条件均不成立时无条件选择最后一个分支，因此最后分支必须按兜底表达，不能只看它是否携带条件列表。
- 目标审批配置支持指定人员、角色、公司、部门、岗位、职级、发起人、部门主管、分管副总、扩展属性、表单人员和审批人自选，并包含会签/竞签、人数、配置明细、范围和无处理人跳过规则。
- `GroupApproveManage/CheckFlow` 按上述规则展示人员配置；待办页面把审批/协同作为主要处理入口，同时提供回退上一级、向当前节点添加审批人和转发等依赖真实任务状态的操作。这些特殊操作不能仅凭静态树判定当前一定可用。
- 表单模板详情和表单代理详情都能返回字段元数据；字段英文名只适合作为目标内部关联键，后续配置界面必须使用字段名称，并对无法消歧的引用明确提示人工核对。

## 包含范围

### 用户界面边界

- 路径配置页不显示“核对路径要求”，路由表不注册 `/plans/:id/requirements`，项目不保留独立核对页面和页面专用前端要求模块。
- F-005 画布继续保持普通态、页面全屏、已保存路径、新增、查看、编辑、复制、删除和批量生成的既有行为。
- F-006 不创建任何表单、人员或动作控件；后续配置页面必须直接消费当前后端分析结果，不能在前端复制要求推导规则。

### 条件要求

- 只显示当前路径已选条件分支；未选分支不进入要求清单。
- 保留条件在目标中的顺序和 `and/or` 连接语义，比较方式转换为中文；固定业务值允许显示，字段英文名和判断枚举代码不显示。
- 字段引用通过关联表单字段元数据转换为名称。唯一匹配直接显示字段名；跨表单同名键可消歧时显示“表单 / 字段”；无法匹配或无法消歧时显示“未识别的表单字段”并标记“需要人工核对”。
- 最后一个条件分支统一显示“其他条件均不满足时进入”，并提示后续数据仍需保证前序分支不成立；不把其自身残留条件当成独立判定。
- 手动分支显示“运行时选择该分支”并标记“待配置”；并行路由显示“全部分支并行必经”且归为目标平台自动确定，不生成虚假条件。
- F-006 不反推满足条件的具体表单值，也不执行真实条件验证；这些工作进入 F-007。

### 人员要求

- 审批和协同节点显示规则名称、会签或竞签方式、会签人数、范围摘要、表单人员字段以及无处理人是否跳过；没有配置时不能显示“正常”。
- 指定人员、角色、公司、部门、岗位等已经由目标配置明确的范围归为“目标平台自动确定”；有名称时显示名称，没有名称时只显示业务类型和数量，不展示业务 ID。
- 发起人、部门主管、分管副总、职级和扩展属性依赖发起人或运行组织关系，归为“运行时确定”；结果说明依赖项，不提前伪造人员名单。
- 审批人自选归为“待配置”，由 F-007 为该路径准备候选处理人；表单人员也归为“待配置”，并关联到对应表单字段要求。
- 无法识别的人员类型、缺失关键范围或自相矛盾的会签人数归为“需要人工核对”，但不阻断同一分析结果中的其他可识别要求。

### 节点动作与约束

- 发起节点需要配置“提交”；普通审批和协同节点需要配置处理结果；空节点、结束节点和纯路由结构不要求动作。
- 审批与协同的初始稳定动作只核对“同意/不同意”结果要求，实际意见、表单事件和业务前置校验留到 F-007 结合表单实现。
- 回退上一级、向当前节点添加审批人、转发等操作统一说明为“运行时可用性待核对”，不放入当前稳定动作候选，也不承诺后续一定自动化。
- 节点延时、自然日或工作日限制以及无处理人跳过作为只读约束展示；目标未配置时不补默认值。

### 四类状态

| 状态 | 含义 |
| --- | --- |
| 待配置 | F-007 必须为当前路径准备数据、人员或动作。 |
| 目标平台自动确定 | 目标流程配置已经决定，不要求工具侧再次选择。 |
| 运行时确定 | 必须等真实发起人、组织关系或任务状态形成后才能得到结果。 |
| 需要人工核对 | 目标元数据缺失、歧义或出现当前工具尚未确认的规则。 |

汇总只统计要求项，不把“目标平台自动确定”理解为整条路径已经可运行。只要 F-006 尚未进入后续配置，计划继续保持“待配置”。

## API

### 读取单条路径要求

`GET /api/plans/{planId}/execution-paths/{pathId}/requirements`

- 校验计划存在、路径属于计划且当前真实图仍能精确对应保存选择。
- 成功返回路径序号和名称、四类汇总、主线/并行分组以及每个业务节点的条件、人员、动作和约束。
- 请求无 body，不接受浏览器传入账号、来源、目标对象、入口、节点或分支 ID。
- 每次读取当前真实配置，不写数据库，不产生目标平台写操作。

### 稳定错误

| 错误 | 行为 |
| --- | --- |
| 计划或路径不存在、归属错误 | 复用现有计划与执行路径稳定错误，不泄露其他计划信息。 |
| 路径已不符合当前真实结构 | 返回 `EXECUTION_PATH_INVALID`，引导返回重新选择路径。 |
| 目标对象不可见、实例结束、配置缺失、会话失败、超时 | 复用现有 `TARGET_*` / 流程图错误映射并允许重试。 |
| 单项元数据未知或歧义 | 不让整次分析失败，返回“需要人工核对”项。 |
| 目标结构本身无法安全解析 | 返回现有流程结构异常，不输出半份要求。 |

## 代码边界

- `internal/adapter/target`：解码同一目标详情中的条件、审批配置、字段权限和关联表单引用，并按来源读取必要的表单字段元数据。
- `internal/analyzer`：复用执行路径遍历，生成主线/并行要求分组、四类状态和中文业务语义；不访问 HTTP 或数据库。
- `internal/service`：校验计划与路径归属，组织一次目标只读操作，处理路径失效和公开错误映射。
- `internal/api`：提供单条只读路由，不透传目标内部结构。
- `web`：F-006 不保留入口、路由、页面或页面专用 API 模块；F-005 前端不得因移除核对页而回退。
- `internal/repository`：只复用现有计划和路径读取，不增加表、字段或事务写入。
