### 表单运行时生命周期修复（2026-08-18）

表单工作区的宿主页面只负责撤销会话请求、生成/保存请求并切换工作区；`FormRuntimeFrame` 独占 iframe 运行时的销毁责任。同一会话的重复销毁不再重复访问 iframe，加载代次与消息会话共同拦截迟到响应。离开表单、返回计划、路由快速切换或初始化失败后，旧 iframe、会话读取、生成和保存都不得回写已卸载页面；错误状态留在仍然有效的表单工作区，用户可返回节点画布恢复稳定页面。

## 第三次人工验收退回诊断

- 当前 V2 没有接入 `rsh-flow-components` 使用的 FormMaking 运行时。后端只抽取字段元数据，前端 `NodeConfigurationPanel` 再自行渲染 `NInput`、`NSelect` 等基础控件，因此丢失真实表单布局、自定义组件和运行逻辑。
- 保存请求已经成功写入 `test_execution_path_configs` 后，前端 `applyPathConfigDraft` 对 Vue 响应式代理执行 `structuredClone`，浏览器会抛出 `DataCloneError`。异常被统一包装成“保存失败”，刷新后又因为数据库记录真实存在而显示 configured。
- `FlowGraphCanvas` 同时设置 `elements-selectable=false`、`nodes-draggable=false` 且没有注册 Vue Flow 节点事件。Vue Flow 因此给节点包装层计算出 `pointer-events:none`，内部按钮无法接收 hover 或 click，节点详情不能切换。
- 当前保存接口整份替换路径配置并固定写入 `config_status='configured'`；路径列表只判断配置行是否存在。一次点击“保存节点配置”会让整条路径和所有默认动作节点被视为已完成，无法表达逐节点进度。
- 节点固定高度内同时排版类型、名称和状态标签，状态文字与名称争抢空间；表单字段又占满侧栏，使人员、动作和节点规则失去层级。

本轮必须同时纠正表单运行时边界、节点点击与状态呈现、逐节点保存和服务端对账语义；只修 CSS 或错误文案不能通过验收。

4. 节点配置页面以独立画布为主体。顶部提供返回计划详情、当前路径、逐节点进度和单独的“配置表单数据”；中间显示真实流程结构和当前路径；固定右侧面板只显示被选节点的人员、动作与规则。
5. 返回计划详情后保留原路径列表和流程位置；切换另一条路径时重新加载该路径自己的拓扑投影与节点配置，不能串数据。
6. “配置表单数据”打开隔离的真实 FormMaking 工作区；关闭后回到原画布位置，不把表单字段复制进节点侧栏。
7. 新发起表单可基于模板、近期样本、发起人和当前路径条件执行“智能生成”或“换一组”，用户在真实表单中修改后独立校验保存；已发、待发继续只读显示实例当前值。

## 模板约束下的节点内容

- 发起节点：显示发起人规则、独立表单数据入口、提交动作，以及模板允许在发起阶段确定的下一步人员或分支信息；表单字段本身不在节点侧栏展开。
- 审批与协同节点：显示真实审批方式、会签/竞签人数、跳过规则、允许的处理结果和处理人来源。固定人员、角色或组织规则只读展示；只有模板允许“发起时指定”或“运行节点选择”时才显示受约束的人员选择器。
- 条件分支：展示已保存路径选择的真实条件和驱动字段。需要修改线路时返回“编辑路径”；需要影响条件时打开独立表单数据工作区，不能在节点侧栏直接编辑字段编码或内部判断表达式。
- 手动分支：展示当前已保存分支；只有目标模板和当前阶段允许重新选择时才给出合法候选，否则引导返回“编辑路径”。
- 目标平台只读接口能够解析的人员、岗位、岗级、角色、部门、公司及其他范围必须显示具体名称和合法候选；不得因为主模板响应缺少名称就笼统标记“运行时确定”。只有确实依赖未来发起人、未来表单值、真实任务上下文或届时组织关系且当前无法读取的数据才标记运行时确定，并说明具体原因。
- 表单、人员、动作和分支都由后端读取当前目标模板后投影。未知控件、权限不明或目标结构变化时阻止该项完成，不按名称猜测，不用普通输入框冒充真实业务组件。

## 断点、暂停与单步边界

- 节点配置画布是后续运行控制的共同视觉载体，组件必须预留“配置态”和“运行态”，避免以后再做一套与流程脱离的操作页面。
- F-007 只完成运行前的节点配置，不显示无法真实生效的暂停、继续或单步按钮，也不创建虚假的运行状态。
- 后续真实运行时在同一流程画布显示当前、成功、失败、等待状态，并提供暂停、继续、执行下一步和本次运行临时断点；单步一次最多执行一个原子动作后重新暂停。
- 本次运行临时断点属于运行记录，不回写已保存路径。若以后需要“每次运行都在此暂停”，必须作为独立的固定暂停配置命名，不能与临时断点共用语义。

## 数据与组件边界

- `PlanPathsView` 继续负责计划详情、路径列表和现有 F-005 路径编辑入口；无路径时引导配置路径，有路径时提供逐条“配置节点”。
- `PlanPathConfigurationView` 负责节点画布和独立表单工作区的协调；`NodeConfigurationPanel` 只消费人员、动作和规则，不再渲染表单字段。
- `form-runtime/` 的实际 dev/build 源码位于 `runtime-source/`，由 `参考代码/rsh-flow-components` 当前已核实的完整 tracked 源码、原生同步资产与真实 FormMaking 组成；当前落库基线为 `bff4ef8b938db5578c3f7eab1f482a4e9388917c`。主 Vue 3 只通过 iframe 和版本化 `postMessage` 契约通信。
- 真实入口沿用 `rsh-flow-components` 的 FormMaking、自定义组件注册、Vuex、router、axios 和表单样式；`form-runtime/src/`、根 `scripts/`、构建配置、iframe/SID/写阻断适配属于本项目保护区。配置阶段禁用原工作台登录与不安全消息入口并阻断流程/业务写操作；确实依赖外部宿主且未完成独立适配的组件明确 `unsupported`，不能降级成普通控件。
- 主应用把当前已验证账号缓存的 SID 和核实目标网关放入单次 iframe 会话，使目标表单组件可执行必要只读请求；切换计划、路径、账号或关闭工作区时销毁会话并清除 SID/上下文，消息必须核对 origin、source、session 和协议版本。SID 不写入 Git、路径配置、维护任务或浏览器长期存储；配置阶段阻断目标流程提交、草稿和业务写端点。
- 复用现有路径配置表、修订号和幂等能力，但增加配置模式版本、逐节点确认集合、表单数据与表单状态。旧版配置记录保留数据并标记为 `affected`，不得继续按“存在一行即已完成”投影。
- 节点与表单分别保存：节点请求只合并当前节点的人员和动作，表单请求保存 FormMaking 校验后的路径级模型。前端只提交不透明键；服务端返回并重建权威状态，不能在浏览器本地把所有节点批量改成已完成。
- 保存请求必须传入取消信号；响应丢失或客户端后处理异常时用原幂等键重试或 GET 对账。只有服务端确认未保存时才展示失败，成功但响应不确定时明确提示已核对的真实结果。
- 基础智能生成复用 V1 已验证的递归模板解析、样本类型画像、稳定 seed、路径条件约束和人工覆盖合并思想，但按 V2 数据模型重写。样本只经目标适配层限量读取近期可见已发实例，禁止直连 Mongo；缺少样本时明确降级到模板约束与确定性兜底。
- 生成结果必须经真实运行时 `setData`、`refresh` 后由 `getValues()` 捕获完整数据；“换一组”只改生成器拥有字段，人工修改字段不覆盖。服务端保存 seed、`generatedFieldPaths`、`manualOverridePaths`、样本来源摘要、校验结果和表单状态。
- F-009 将这套生成规则扩展为全模板通用盘点：级联保存完整候选路径，子表单/表格保留数组行，标准 FormMaking 组件按真实值形态生成和复验，附件和外部对象只进入人工待补；当前账号的用户、部门和公司上下文由服务端真实目录解析后透传到 iframe，动态脚本或未知组件不能被误报为已生成。全量覆盖证据以目标平台真实分页结果为准，不为单个合同模板增加专用适配器。

## 不包含

- 不修改 F-005 的路径生成、分支选择、路径命名、保存、编辑、复制、删除和全屏交互。
- 不把“配置节点”塞进 F-005 的路径生成面板，也不要求用户在生成路径时顺便配置节点。
- 不调用目标平台提交、审批、人员写入或业务保存接口，不创建运行记录。
- 不在本轮实现真实暂停、继续、单步、临时断点或运行调度；只保证节点画布可以在后续复用于运行态。
- 不复制 V1 的动作库拖拽、全局人员池或复杂工作室布局；仅实现节点内动作列表、次数和必要参数。
- 不把旧 `rsh-flow-components` 工作台页面作为本产品业务入口；运行时只复用目标组件必需的 Vuex/router/axios 内部链路并进入独立配置路由，不启用旧登录流程、目标流程提交或业务写操作。
- 不在本轮实现高级 AI 语义生成、跨模板学习或未知复杂业务组件的自动适配；基础智能生成只覆盖模板和真实样本能够安全证明的字段与路径条件。
