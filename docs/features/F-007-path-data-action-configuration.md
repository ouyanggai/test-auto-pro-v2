# F-007 路径数据与节点动作配置

- 状态：implementing
- 产品依据：`docs/PRODUCT.md` 的“计划与运行主线”“路径要求分析行为”“路径配置工作台行为（F-007）”
- 架构依据：`docs/ARCHITECTURE.md` 的“F-005 执行路径选择与持久化”“F-006 路径要求分析”“F-007 路径数据与节点动作配置”
- 计划形成时间：2026-08-07

## 单一用户结果

用户从一条已保存执行路径直接进入配置工作台，填写该路径需要的基础条件字段并选择标准节点动作；配置按路径独立保存，刷新后可继续编辑，页面不再要求用户先看一份没有操作入口的“路径要求核对”报告。

本切片只完成工具侧配置准备。配置完成不代表目标平台已经提交，也不把计划变成“可运行”。

## 范围

### 包含

1. 将 F-006 的要求结果转换为可操作的路径配置模型；同一条路径的字段和动作按真实节点顺序展示。
2. 增加单条路径配置页 `/plans/:planId/paths/:pathId/configure`，从已保存路径详情进入，提供返回、路径摘要、字段分组、动作配置和保存入口。
3. 首轮支持可靠映射且当前可编辑的文本、数字、日期时间、单选、多选和开关字段；显示中文名称、用途、必填状态、当前值和目标平台真实选项。
4. 新发起使用当前模板默认值，已发/待发从所选真实实例读取当前表单数据作为初始值；只投影与当前路径有关且当前节点允许修改的字段。
5. 对未知控件、业务对象、附件、明细表、表单人员、派生字段和字段权限不明确的项目显示清晰缺口，不使用普通输入框伪造可用性。
6. 发起节点固定提交；审批/协同节点提供同意、不同意，沿已保存路径继续时默认推荐同意，并明确不同意会改变后续线路。
7. 新增路径配置读取和保存 API、路径配置表及修订号；字段值和动作配置必须按路径隔离，重复保存键返回同一结果。
8. 保存前后重新读取当前目标配置并校验字段键、类型、选项、必填、节点和动作；目标结构变化时保留可对应值并标出受影响项。
9. 新增当前切片的后端单测、API 契约、MySQL 集成、前端单测、结构检查、中文注释检查、构建和人工清单。

### 不包含

- 不保留或新增独立“路径要求核对”页面、路由或页面专用报告模块。
- 不接入目标平台提交、审批、回退、加签、移交、转发、取回、附件、业务保存或人员写接口。
- 不实现真实 FormMaking/业务组件运行时，不复制 V1 的全套表单生成、人员池和动作场景引擎。
- 不配置真实处理人、表单人员、业务对象、附件、明细表、派生字段或成功断言；这些项目只展示待补充状态。
- 不改变 F-005 路径拓扑、路径选择规则、计划状态语义或运行记录。
- 不引入搜索、批量跨路径编辑、自动生成测试数据、后台任务、定时执行或 F-008 之后的运行准备。

## 人工验收

1. 在一条已保存路径详情点击“配置路径”，确认进入的是可操作配置工作台，而不是要求核对报告。
2. 检查条件字段的中文名称、控件、选项、必填和缺口说明；确认没有编码、内部 ID 和 JSON 输入框。
3. 新发起核对模板默认值，已发/待发核对实例当前值；修改一条路径的字段和动作并保存，刷新后确认值保留，打开另一条路径确认没有串数据。
4. 把某个审批动作切换为“不同意”，确认页面明确提示会改变/结束后续线路，并且保存结果不伪装为原路径可运行。
5. 模拟或现场触发目标结构变化，确认仍能对应的值保留，失效项被单独标记，不整条清空。
6. 确认保存失败时草稿和错误位置保留，计划仍显示“待配置”，没有目标平台写操作或运行入口。
7. 核对深浅主题、内容滚动、返回确认和页面刷新恢复；完成后由用户明确验收，主任务不自动开始 F-008。
