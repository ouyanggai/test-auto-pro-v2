# F-007 已保存路径的节点可视化配置

- 状态：ready_for_manual
- 产品依据：`docs/PRODUCT.md` 的“路径生成与节点配置边界”“路径节点可视化配置行为（F-007）”
- 架构依据：`docs/ARCHITECTURE.md` 的“F-005 执行路径选择与持久化”“F-006 路径要求分析”“F-007 已保存路径的节点可视化配置”
- 重新规划时间：2026-08-10

## 方向纠正

现有 F-005 路径生成、分支选择、路径命名、保存、编辑、复制和删除交互已经符合需求，本轮不得返工或替换。

此前 F-007 把字段和动作放进独立表单式配置页面，导致用户离开流程结构后无法判断正在配置哪个节点，也无法自然承载人员、断点和运行状态。该页面形态不通过人工验收。现有后端的路径级持久化、目标字段读取、修订号和幂等能力可以复用，但前端必须改为“单条已保存路径的独立可视化节点配置画布”。

## 单一用户结果

用户先用现有画布生成并保存执行路径，再从计划详情的已保存路径列表点击“配置节点”，进入这条路径自己的可视化节点配置画布；用户点击画布节点，只看到目标流程模板允许配置的节点信息，并能始终知道当前路径、当前节点、配置进度和未完成原因。

## 用户流程

1. 计划没有已保存路径时，路径准备区域只说明“请先配置并保存执行路径”，主操作为“配置路径”，进入现有 F-005 路径生成交互；不显示无效的节点配置入口。
2. 计划存在已保存路径时，列表继续显示稳定序号和名称，每条路径增加明确的“配置节点”入口及节点配置状态；不把“编辑路径”和“配置节点”混为同一操作。
3. “编辑路径”继续进入现有 F-005 线路选择，用于改变分支和路径名称；“配置节点”进入 `/plans/:planId/paths/:pathId/configure`，用于配置这条已保存路径上的节点信息。
4. 节点配置页面以独立画布为主体，而不是字段表单列表。顶部提供返回计划详情、当前路径序号和名称、配置进度；中间显示真实流程结构和当前路径；固定右侧面板显示被选节点的配置。
5. 返回计划详情后保留原路径列表和流程位置；切换另一条路径时重新加载该路径自己的拓扑投影与节点配置，不能串数据。

## 节点配置画布

- 使用 F-004 的同一棵真实流程树和 F-005 的同一路径选择结果，不建立第二套拓扑模型。当前路径高亮，非当前路径节点作为流程上下文弱化并保持只读。
- 只有当前路径上、且目标模板证明可配置的业务节点可以打开配置；并行、汇聚、空节点和结束节点没有业务配置时只展示说明，不生成伪配置项。
- 节点直接显示“无需配置”“待配置”“部分完成”“已完成”“运行时确定”“配置失效”等状态。页面顶部汇总节点总数、已完成数和待处理数，并能定位下一待配置节点。
- 点击节点后在画布内部固定右侧面板展示配置，不使用抽屉或脱离画布的整页表单；选择节点不得导致画布尺寸反复跳动。
- 右侧面板只显示当前节点实际需要的区域，内部独立滚动；没有选中节点时给出明确引导并自动将下一待配置节点定位到方便操作的位置。
- 节点配置成功后刷新节点状态，并自然引导到下一待配置节点；失败时保留当前输入和选中节点，把错误定位到具体配置项。

## 模板约束下的节点内容

- 发起节点：显示发起人规则、关联真实表单数据入口、提交动作，以及模板允许在发起阶段确定的下一步人员或分支信息。
- 审批与协同节点：显示真实审批方式、会签/竞签人数、跳过规则、允许的处理结果和处理人来源。固定人员、角色或组织规则只读展示；只有模板允许“发起时指定”或“运行节点选择”时才显示受约束的人员选择器。
- 条件分支：展示已保存路径选择的真实条件和驱动字段。需要修改线路时返回“编辑路径”；需要影响条件时从当前节点进入真实表单数据配置，不能让用户直接编辑字段编码或内部判断表达式。
- 手动分支：展示当前已保存分支；只有目标模板和当前阶段允许重新选择时才给出合法候选，否则引导返回“编辑路径”。
- 目标平台自动确定、依赖组织关系或只能在实例运行时计算的人员，明确标记为只读或“运行时确定”，不伪造全员候选列表。
- 表单、人员、动作和分支都由后端读取当前目标模板后投影。未知控件、权限不明或目标结构变化时阻止该项完成，不按名称猜测，不用普通输入框冒充真实业务组件。

## 断点、暂停与单步边界

- 节点配置画布是后续运行控制的共同视觉载体，组件必须预留“配置态”和“运行态”，避免以后再做一套与流程脱离的操作页面。
- F-007 只完成运行前的节点配置，不显示无法真实生效的暂停、继续或单步按钮，也不创建虚假的运行状态。
- 后续真实运行时在同一流程画布显示当前、成功、失败、等待状态，并提供暂停、继续、执行下一步和本次运行临时断点；单步一次最多执行一个原子动作后重新暂停。
- 本次运行临时断点属于运行记录，不回写已保存路径。若以后需要“每次运行都在此暂停”，必须作为独立的固定暂停配置命名，不能与临时断点共用语义。

## 数据与组件边界

- `PlanPathsView` 继续负责计划详情、路径列表和现有 F-005 路径编辑入口；无路径时引导配置路径，有路径时提供逐条“配置节点”。
- `PlanPathConfigurationView` 改为节点配置画布页面状态容器；复用 `FlowGraphCanvas`、真实流程映射和路径高亮，不再渲染按字段顺序展开的独立表单工作台。
- 新增或提取节点配置面板组件，按选中节点消费后端投影的节点配置模型；画布只负责布局、选择、定位、状态标记和面板容器，不在前端推导目标平台规则。
- 复用现有路径配置表、修订号、幂等保存和目标字段读取能力。后端响应从“路径字段列表”调整为按真实节点分组的配置投影，并补充可靠的人员规则与允许候选；不得重新建立路径或流程快照表。
- 保存仍按路径隔离，并校验计划/路径归属、当前目标模板、修订号和幂等键。前端提交不透明配置键，不能提交或显示目标节点 ID、字段编码、SID 或目标原始 JSON。

## 不包含

- 不修改 F-005 的路径生成、分支选择、路径命名、保存、编辑、复制、删除和全屏交互。
- 不把“配置节点”塞进 F-005 的路径生成面板，也不要求用户在生成路径时顺便配置节点。
- 不调用目标平台提交、审批、人员写入或业务保存接口，不创建运行记录。
- 不在本轮实现真实暂停、继续、单步、临时断点或运行调度；只保证节点画布可以在后续复用于运行态。
- 不复制 V1 的动作程序树、动作库拖拽、全局人员池或复杂工作室布局。

## 人工验收

1. 新计划没有路径时，只能先点击“配置路径”并使用现有路径生成交互；保存路径后列表出现“配置节点”。
2. 打开两条不同路径的节点配置，确认各自路径高亮、节点状态和配置内容互不串联。
3. 依次点击发起、审批、条件、手动分支、并行/结束节点，确认右侧面板内容跟随节点类型与模板规则变化。
4. 核对固定人员节点不可随意选人；模板允许选择时才显示人员选择器，并且候选范围符合目标平台规则。
5. 修改一个节点并保存，刷新后确认配置与节点状态恢复；目标结构变化时只标记受影响节点，不清空整条路径。
6. 核对深浅主题、画布缩放拖动、节点定位、右侧面板滚动、长名称和较大流程；确认原路径生成、编辑、复制和删除没有回归。
