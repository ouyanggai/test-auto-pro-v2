# F-051 表单刷新后币种布局与当前数据一致

- 状态：ready_for_manual（实施与定向自动验证通过，发布核对中，待用户页面验收）
- 授权：2026-10-26 用户报告合同金额（英镑）缺失，确认金额与分类差异来自正常路径回写；完成源码诊断后明确要求“修复并发布，我来核对”。
- 依据：配置侧 App.vue、formTemplate.js、同步的 FormMaking 刷新与 report 生命周期源码，以及实际配置数据的只读诊断。关联 F-012、F-024、F-043；本轮不推进其他功能的验收状态。

## 问题与范围

币种数据已经是英镑，界面却保留默认人民币布局：合同金额标题错误，人民币金额那格隐藏。隔离复现确认两个缺口：FormMaking 刷新沿用实例创建时的 formValue 快照；report 等原生容器使用 beforeUnmount 清理注册，但配置服务实际运行 Vue 2，销毁后旧实例仍留在注册表。

只修改工具侧配置表单接入代码。路径回写继续按所选路径调整数据；不改金额、分类、字段权限、目标模板脚本、FormMaking 库、同步源码、执行器或后端。

## 修改前确定的完成标准

1. 首次装载、更换来源、恢复已保存数据和主动刷新时，在原生刷新执行之前同步当前完整数据到其初始化快照。原生初始化事件从当前数据生成布局，不用默认币种生成后再只补值。
2. 所有同类原生注册组件在 Vue 2 销毁时执行其原有注销逻辑；反复刷新后 getComponent 返回当前实例，不能留下已销毁对象或变成历史实例数组。按实际注入的注册/注销能力限定桥接，覆盖源码查出的 report、card、inline、列、页签与折叠容器，不介入无关组件。
3. 不批量重放所有字段的 onChange；初始化不能被当成用户手动切币种，不能搬移、清空或重新生成已回写金额。用户手动切换仍执行原模板事件。
4. 自动验证覆盖：人民币/英镑及重复刷新、替换整份数据、原生初始化读取值、金额保留、真实 Vue 2 的全部同类容器注销/重新注册、工具接入顺序；实际截图数据与模板仅在忽略目录中复验，不提交业务快照或参考源码。
5. 执行相关前端回归、语法检查和配置表单正式构建；中文原子提交。沿用一键发布，明确检查持久化 live 卷中的表单产物已更新，不能仅以镜像构建成功判上线。
6. 发布前检查没有活跃运行/准备/维护任务，发布后核对服务、源文件、实际 HTTP 表单资源、计划/路径配置和运行事实保持。完成后停在 ready_for_manual，不启动浏览器或代替用户提交审批验收。

## 用户核对

1. 强制刷新页面，重新打开原合同路径的数据配置；应同时看到合同金额（英镑）与合同金额（人民币），两笔数值保持当前路径回写结果。
2. 重复打开、刷新、恢复数据和更换来源，币种与金额区域始终对应，不越刷新越错。
3. 手动在人民币与英镑间切换，仍遵守目标表单本来的金额处理规则；保存后重新进入，布局与保存值对应。
