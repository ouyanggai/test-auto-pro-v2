# F-010 返工计划：全模板规则分析与 Vue 表单流程支持

- 状态：ready_for_manual
- 关联功能：`docs/features/F-010-template-rule-analysis-vue-flow.md`
- 产品依据：`docs/PRODUCT.md` 的 F-010 规则目录、Vue 业务页面和账号权限边界
- 架构依据：`docs/ARCHITECTURE.md` 的 F-010 规则快照、运行时和生成器边界
- 计划目的：补齐全量模板证据、Vue/Java 规则协议、自定义组件能力、发起人使用时过滤和统一生成保存链路

## 一、用户结果

系统设置由“欧阳改”账号建立目标平台当前可见的完整模板规则目录。计划创建和路径配置时，不重新分析目标平台，也不把目录权限当成计划权限；系统根据计划保存的发起人账号重新核对该账号对流程、模板、数据源和候选对象的可见范围，只消费该账号有权使用的本地规则和真实候选。

用户最终可以：

1. 在设置中看到欧阳改账号的全量模板分析任务、覆盖统计、问题和增量更新时间。
2. 用任意有权限的发起人创建计划时，只看到该发起人可使用的流程和模板规则。
3. 对 `formmaking` 和 `vue_custom` 流程进入同一个表单数据工作区，使用真实宿主页面或真实 FormMaking 运行时。
4. 对已识别的自定义组件使用真实值形态、候选和校验规则生成数据；没有当前账号可用候选时得到部分结果和明确原因，不被泛化成“组件不支持”。
5. 保存时由服务端使用同一份规则、发起人权限、候选快照和完整路径进行权威复验。

## 二、边界和明确不做

### 包含

- 欧阳改账号的全量模板规则目录与任务恢复、增量、全量、失败重试。
- 目录快照的目标平台、FormMaking、宿主 Vue、Java 后端和已注册自定义组件规则。
- 计划使用时按发起人账号进行权限过滤和候选隔离。
- `formmaking`、`vue_custom`、`unknown` 三类渲染协议的统一规则模型。
- Vue 页面字段、联动、显隐、校验、提交协议、身份读取和真实组件运行时投影。
- 自定义组件值形态、候选来源、序列化、回显、校验和换一组边界。
- 单条生成、保存复验和 F-009 批量准备共用规则和候选快照。

### 不包含

- 不新增真实运行、调度、运行记录或目标平台业务写接口。
- 不使用 LLM、外部队列、中间件或按合同流程编写专用分支。
- 不在计划操作时重新扫描源码或逐路径请求目标平台模板。
- 不把欧阳改的目录权限扩展成计划发起人的业务权限。
- 不伪造附件、项目、材料、订单、差旅或其他外部对象引用。
- 不保留旧接口、旧数据兼容层或旧规则兜底；新协议直接替换当前开发实现。

## 三、权限分层原则

### 3.1 目录建立权限

- 规则分析任务固定以账号 `欧阳改` 读取目标平台可见模板、流程元数据和只读代码来源。
- 目录记录 `sourceAccount=欧阳改`，并保存来源版本、目标模板版本、源码摘要、Java 源码摘要、分析器版本和组件能力版本。
- 目录任务的总数、处理数、覆盖数和失败数必须来自真实分页结果；不能用固定 196 作为业务上限。
- 设置页可以展示目录覆盖摘要，但不向浏览器返回完整模板正文、宿主源码、Java 源码、目标内部标识或候选对象明细。

### 3.2 计划使用权限

- 计划保存 `initiatorAccount`，所有单条配置、样本、身份上下文、数据源候选和外部对象候选都使用该账号。
- 读取本地规则时先按 `flowCode/sourceTemplateID` 找到欧阳改目录，再执行 `CanInitiatorUseRule` 权限判断。
- 权限判断至少包括流程模板可见性、流程来源类型、表单数据源权限、组织目录范围和外部对象候选权限。
- 目录可以包含发起人暂时不可见的规则，但计划 API、页面列表、生成器、批量任务和错误信息都不能泄露这些规则的名称、字段或候选。
- 发起人无权使用规则时，返回稳定的“当前账号无权使用该流程模板”，不能回退到欧阳改权限，也不能按名称猜测另一个模板。
- 候选缓存键必须包含发起人账号标识、流程编码、模板标识、组件标识和数据源规则版本，禁止跨账号、跨流程和跨模板复用。

## 四、权威规则快照

### 4.1 目录条目

每个模板规则条目必须包含：

- `sourceTemplateId`、`flowCode`、`flowName`、模板类型和 `renderType`。
- `sourceAccount`、目标模板版本、流程快照摘要、FormMaking 模板摘要、Vue 源码摘要、Java 源码摘要。
- `analyzerVersion`、组件能力版本、规则指纹和分析时间。
- `ruleData`：流程条件、页面规则、字段规则、组件规则、候选规则、保存规则和身份规则。
- `coverage`：节点、分支、条件运算、逻辑连接、字段比较、组件、数据源、脚本和提交协议统计。
- `issues`：具体页面、字段、数据源、脚本或提交协议缺口；不得只写“组件不支持”。
- `status`：`complete`、`needs_attention`、`blocked`、`failed`。

### 4.2 增量失效规则

增量分析必须同时比较以下摘要：

1. 目标模板及流程配置版本。
2. FormMaking 模板正文摘要。
3. 宿主 Vue 页面、路由、注册表和配置文件摘要。
4. Java 流程、页面、数据源和提交协议源码摘要。
5. 自定义组件注册表和能力版本。
6. 分析器版本。

任何一项变化都必须重新分析对应模板。不能只比较目标模板 `UpdateDate`，也不能只计算指纹而不参与跳过判断。

### 4.3 未知能力原则

- 未识别页面入口、路由参数、字段路径、动态脚本、数据源响应、提交协议或组件值形态时，写入字段级或页面级 `issues`。
- 未知能力只能进入 `needs_attention` 或生成结果 `blocked`，不得被视为 `complete`、`not_required` 或可安全生成。
- 可以安全生成的部分字段继续保留，单条问题不回滚同批其他路径。

## 五、全量分析流水线

### 阶段 A：真实模板清单

- 通过欧阳改账号分页读取全部可见模板，使用游标或页码推进，不把 196 写成硬上限。
- 对列表页失败执行有界重试；单条模板详情失败只标记该条失败并继续后续模板。
- 记录真实 `total`、已读取模板数、失败数和分页完整性。
- 产生一份轻量覆盖报告，报告中区分真实目标结果和合成单元测试数据。

### 阶段 B：目标平台和 FormMaking 规则

- 读取流程树、分支排序、条件连接、比较方式、字段对字段比较和表单引用。
- 递归读取 FormMaking 容器、嵌套路径、子表单、表格、级联、文件和标准组件。
- 提取真实选项、默认值、必填、只读、隐藏、禁用、数据源请求和安全可解释脚本。
- 动态脚本只记录可证明能力；不能静态解释的脚本进入问题清单。

### 阶段 C：Vue 宿主页面规则

- 从 `settings.js`、路由配置、实际组件注册表、组件 import 路径和真实 `.vue` 文件解析页面入口。
- 同时读取普通配置式 NoForm 页面、Element 表单页面和只读详情页面。
- 识别字段路径、嵌套对象、数组行、初始状态、默认值、必填、只读、显示隐藏和格式校验。
- 识别字段联动、前置请求、选项更新、条件分支和请求响应映射。
- 识别提交按钮对应的 payload 组装、接口、请求方法、成功判定和字段级错误回显；配置工作区只调用本项目保存，不触发宿主业务提交。
- 识别页面读取用户、部门、公司、人员、岗位和组织树的真实键及回显投影。
- Java 后端代码只读分析对应流程、页面、数据源和提交 DTO，和 Vue 页面规则通过流程编码、路由或接口契约对齐。
- 无法证明映射时禁止按字段显示名称猜测；页面进入 `unknown` 或 `needs_attention`。

### 阶段 D：规则归一化

- 将 FormMaking 和 Vue 页面归一成同一份字段、条件、候选、权限、校验和保存复验模型。
- 保留原始字段路径作为后端内部规则键，但前端只接收中文名称和安全状态。
- 条件求解、字段保护、智能生成、页面提示、保存校验和批量任务只能消费这一份权威规则。

### 阶段 E：持久化和任务恢复

- 分析任务持久化总数、检查点、当前模板、已覆盖、需处理、失败和终态。
- 进程重启将活动任务收敛为可重试失败；同一账号只允许一个活动分析任务。
- 增量任务跳过所有来源摘要未变化的条目；失败重试只处理失败和需处理条目。
- 目录查询使用分页和轻量摘要，完整规则只在服务端按流程编码按需读取。

## 六、Vue 自定义页面运行时

### 6.1 真实页面装载

- `formmaking` 继续使用真实 FormMaking iframe。
- `vue_custom` 只装载宿主真实 Vue 组件，不在当前项目重画普通 input/select/textarea。
- `unknown` 不进入可运行或可保存状态，只展示具体分析问题。
- 工作区通过规则目录确认的组件名、路由和页面参数装载页面，不能任意从用户传入组件名。

### 6.2 值回填与读取

- 支持 `form/initForm/editData/params/param/rawData/detail` 等已验证状态入口。
- 根据规则递归回填嵌套对象、数组行、组件虚拟字段和只读投影。
- 读取时优先使用宿主 `getValues` 或等价的真实读值协议；没有协议时按规则字段逐项读取并记录限制。
- `ElForm.validate` 只负责宿主页面已证明的校验；服务端仍必须复验字段形状、必填、条件和权限。

### 6.3 业务写入隔离

- 宿主保存、提交、草稿、上传关联和业务写入按钮在配置工作区不可用。
- XHR/fetch 只允许目录分析和页面回显所需的已证明只读请求；未知写请求阻断并记录中文原因。
- 本项目保存只写执行路径配置表，不调用宿主业务提交接口。

## 七、自定义组件能力注册表

每个已注册组件必须保存以下能力，而不是只有三个粗粒度标签：

- 真实 value 类型、嵌套结构和序列化方式。
- 候选来源、请求方法、参数、响应路径和当前账号权限边界。
- 默认值、最少人工项和“换一组”的候选轮换规则。
- 必填、只读、显示隐藏、格式和业务校验规则。
- 条件求解实际使用的比较值和虚拟显示值。
- FormMaking/Vue 页面回显投影和保存复验方式。

组件分为：

1. 身份组件：用户、部门、公司、岗位、角色，候选来自当前发起人已验证目录。
2. 静态或只读数据源组件：使用规则中真实选项或当前发起人可读接口候选。
3. 外部对象组件：项目、材料、合同、订单、附件、Excel 等，只接受当前发起人真实候选，不接受近期样本直接复用。
4. 动态脚本组件：脚本无法安全解释时返回明确运行时核对项，不伪造 complete。

## 八、统一生成和保存复验

### 8.1 生成输入

生成器输入固定包含：

- 本地规则快照和流程条件。
- 当前计划发起人权限和身份上下文。
- 当前流程编码、模板版本和候选池。
- 已保存值、人工覆盖字段、路径保护字段和稳定 seed。

### 8.2 生成状态

- `complete`：页面规则、完整路径、必填和当前发起人候选均已复验通过。
- `partial`：存在明确的候选不足或运行时核对项，保留安全部分结果。
- `blocked`：页面协议、动态脚本、组件值形态或路径条件无法安全判断。
- 所有状态都返回字段级中文 `issues` 和 `routeVerification`；不能用 HTTP 错误吞掉可展示的生成结果。

### 8.3 字段所有权

- 路径条件关键字段由服务端规则生成并锁定，前端不能解除。
- 普通字段只在生成器拥有且用户未人工修改时生成或换组。
- 人工保存值永不被批量任务覆盖；路径变化导致其失效时保留原值并标记 `needs_attention`。
- 外部对象没有候选时保持空值，不使用历史样本对象 ID。

### 8.4 保存复验

服务端保存必须重新读取本地规则并校验：

- 发起人仍有模板和数据源权限。
- 页面渲染类型、字段形状、必填、只读和关键字段锁定。
- 当前完整路径、分支排序、前置分支排除和日期/数值关联。
- 自定义组件序列化、候选权限和宿主校验结果。
- 版本或规则指纹没有变化；变化时返回明确的“规则已更新，请重新生成/核对”。

## 九、批量准备复用边界

- 任务创建只处理当前勾选路径，使用计划发起人账号读取权限和候选。
- 同一批任务只读取一次流程快照、规则快照、身份目录、组件能力和同流程近期样本。
- 路径处理使用分页/游标和有界内存，不对目标平台逐路径分析模板。
- 单条 Vue 页面规则缺失、候选不足或保存复验失败，只将该路径标记为 `needs_attention`，其余路径继续处理。
- 人工节点和人工表单值永不覆盖。
- 任务详情返回真实计数、当前路径、成功/需处理/失败结果，支持取消和恢复；不新增真实运行接口。

## 十、原子实施阶段和提交边界

### 阶段 0：证据和基线

- 核对欧阳改真实模板分页总数、发起人权限差异、可见 Vue 页面、Java 服务模块和组件注册表。
- 输出不含凭证和原始响应的覆盖摘要。
- 补测试夹具和审查文档，不改业务代码。

### 阶段 1：目录权限协议

- 增加规则来源摘要、源码摘要、能力版本和发起人过滤接口。
- 完成欧阳改目录全量建立、计划发起人过滤、无权流程不泄露和缓存键隔离。
- 验证后提交：`建立全量规则目录与发起人权限过滤`。

### 阶段 2：Vue/Java 规则提取

- 扩展页面规则 DTO、Vue 分析器和 Java 只读分析器。
- 覆盖页面入口、状态、联动、显隐、校验、数据源、提交协议和身份读取。
- 未知协议进入 `unknown/needs_attention`，不误报完成。
- 验证后提交：`补齐Vue与Java页面规则分析`。

### 阶段 3：组件能力和候选池

- 将已注册组件能力改为完整规则注册表。
- 按发起人读取和缓存真实候选；禁止外部对象复用样本引用。
- 补齐序列化、校验、回显和换组策略。
- 验证后提交：`完善自定义组件能力与候选隔离`。

### 阶段 4：统一运行时、生成和保存

- FormMaking/Vue 使用同一条件、字段保护、生成状态和保存复验协议。
- 修复 known custom 值的服务端形状校验和保存往返。
- 让不可安全判断的 Vue/组件问题返回 `blocked` 结果而不是吞成技术错误。
- 验证后提交：`统一Vue与FormMaking生成保存复验`。

### 阶段 5：批量任务接入

- 批量任务消费同一规则和候选快照。
- 验证单快照读取、发起人过滤、人工值保留、单条失败隔离、取消恢复和真实计数。
- 验证后提交：`接入全模板规则批量准备`。

### 阶段 6：全量证据和人工门禁

- 使用欧阳改真实账号执行全量分析并记录真实模板数、类型数、流程编码数和问题数。
- 使用至少一个不同发起人账号验证模板列表、候选、Vue 页面和保存权限过滤。
- 运行所有定向测试、Go 测试、`vue-tsc`、主前端构建和 form-runtime 构建。
- 清理构建产物、缓存、日志和凭证，状态停在 `ready_for_manual`。

## 十一、测试矩阵

所有新增或修改测试放根目录 `test/`，按类别归档。

### 目录和权限

- 欧阳改全量分页、游标、失败隔离、重试和真实总数守恒。
- 计划发起人只能看到有权限的模板和候选；无权流程不泄露名称和规则。
- 增量同时受目标版本、Vue/Java 源码摘要、组件版本和分析器版本影响。
- 候选缓存按账号、流程、模板、组件和规则版本隔离。

### Vue 和 Java 规则

- 配置式 NoForm、Element 表单、只读详情和嵌套路由入口。
- `v-model`、初始状态、数组行、显隐、联动、格式校验和动态选项。
- Java DTO、接口、成功响应、字段错误和前后端 payload 对齐。
- 未知路由、未知脚本、未知数据源和未知提交协议进入具体问题。

### 自定义组件和生成器

- 全部运行时注册组件的值形态、候选、回显、保存和换组。
- 身份组件正确透传用户、部门、公司、岗位和权限范围。
- 外部对象无候选不伪造、不复用样本引用，返回 `partial`。
- 关键条件字段始终满足当前完整路径，普通人工字段保持不变。

### 运行时和批量

- FormMaking/Vue 页面加载、回填、宿主校验、保存和销毁。
- 单条生成三态、字段级问题和路径复验。
- 批量任务只读取一次快照，单路径失败隔离，人工值不覆盖，取消恢复可继续。
