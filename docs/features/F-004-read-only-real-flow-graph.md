- 架构依据：`docs/ARCHITECTURE.md` 的“F-002 目标平台只读接入”“F-003 最小计划持久化”“F-004 只读真实流程图”

## 单一用户结果

用户从测试计划点击“继续配置”后，系统使用该计划已经保存的账号、流程来源和目标对象重新核对目标平台，并把目标平台当前真实流程树显示为可平移、缩放、全屏查看和一键适配视口的只读流程图。流程使用板正的树形结构：主干垂直、分叉和汇合各自共用水平轨、分支按列展开，用户不需要沿弯绕线路追踪关系。

F-004 只回答“这条计划当前对应什么真实流程结构”。路径选择和保存属于 F-005，本切片不提供可点击选路、勾选状态或任何目标平台写操作。

## 真实依据

目标平台当前代码确认了以下事实：

- 新发起流程通过 `/web/flowTemplateApi/findById` 读取，返回 `data.flowNodeTemplate`。
- 运行中的实例通过 `/web/flowProxy/findById` 读取，入参是实例记录里的 `flowProxyId`，同样返回 `data.flowNodeTemplate`。
- 已发列表项和待发任务项均提供 `flowProxyId`；F-003 保存的是流程实例 ID，因此 F-004 必须先按原来源精确重查当前可见记录，再取得 `flowProxyId`，不能把实例 ID 错当成代理 ID。
- 节点以 `childFlowNodeTemplate` 串联主线；`conditionNodes`、`parallelNodes` 中每个策略通过自己的 `childFlowNodeTemplate` 进入分支，分支结束后回到分支节点的主线后继。
- 节点类型是 `start`、`empty`、`parallel`、`synergy`、`common`、`condition`、`end`；`condition` 且 `branchExecuteType=custom_choose` 表示手动分支。

F-004 以 `rsh-flow-components/GroupApproveManage` 及其直接引用的 Workflow 组件、工作流中心接口和公共 VO 为依据；V1 的旧扁平 `flowNodeProxyList` 只属于历史交互经验，不进入新解析器。

## 范围

包含：

- 新增按计划 ID 读取真实流程图的后端 API。
- 按 `new`、`started`、`pending` 三类来源重新核对当前账号是否仍能看到保存的目标对象。
- 新发起读取模板树；已发和待发先解析当前 `flowProxyId`，再读取实例代理树。
- 将目标平台嵌套树转换为稳定的只读节点和边 DTO，正确表达直线、条件、手动分支、并行、嵌套分支和汇合。
- 使用 `@vue-flow/core` 与 `@vue-flow/controls`，实现针对结构化分叉—汇合流程的确定性树布局和自定义正交连线；移除不再使用的 dagre 依赖。
- 在计划配置页显示紧凑计划摘要、稳定加载区、流程图、右上角全屏入口、缩放/适配控件、空状态、错误说明和重试。
- 只运行 F-004 相关后端单元、API 契约、前端逻辑、类型检查和构建，由用户在真实环境人工核对三类来源的图形。

- 展示审批人、字段权限、表单内容、条件表达式详情、当前运行轨迹或节点执行状态。
- 预计算所有可能路径、拓扑版本指纹、流程快照或目标响应缓存。
- 启动计划、自动填表、提交、审批、定时调度和运行记录。
- 引入 ELK.js、通用画布框架、WebSocket、Redis、MongoDB 或新服务。

## 来源解析

后端先读取计划，再在同一次目标会话只读操作中完成“精确核对—详情读取”。会话失效沿用 F-002 的规则：清除该账号缓存、重新登录并把整个只读操作重放一次，不做第二次重放。

### 新发起 `new`

1. 使用顶层 `ids=[targetObjectId]` 调用模板列表，并沿用 F-002 的当前用户、`invest` 使用范围、平台范围和排除条件；`data.id` 不参与该列表筛选，只接受响应中 ID 精确匹配项。
2. 匹配成功后调用 `/web/flowTemplateApi/findById`，请求 `data.id=targetObjectId`。
3. 读取 `data.flowNodeTemplate`。

### 已发 `started`

1. 使用顶层 `ids=[targetObjectId]` 调用 `/web/flowInstanceApi/list`，同时沿用已发列表的使用范围和状态范围。
2. 只接受实例 ID 精确匹配项，并读取它当前的 `flowProxyId`。
3. 调用 `/web/flowProxy/findById`，请求 `data.id=flowProxyId`，读取 `data.flowNodeTemplate`。

### 待发 `pending`

1. 调用 `/web/flowJobTaskLink/list`，使用 `data.flowInstanceId=targetObjectId`、`taskStatus=waiting_send` 和 `useScope=invest` 精确重查当前账号的待发任务。
2. 只接受流程实例 ID 精确匹配项，并读取它当前的 `flowProxyId`。
3. 调用 `/web/flowProxy/findById`，请求 `data.id=flowProxyId`，读取 `data.flowNodeTemplate`。

若已发实例不再可见、待发任务已经处理或模板不再属于当前账号可见范围，页面必须说明目标流程当前不可读取；不得使用创建计划时的名称快照伪造流程图，也不得退回模板结构冒充实例结构。

## 图结构映射

公开 DTO 只保留绘图与后续识别真实结构所需字段：

```json
{
  "planId": "12",
  "targetName": "采购申请",
  "flowSource": "new",
  "nodes": [
    { "id": "route-id", "name": "条件", "type": "condition", "typeName": "条件", "mergeTargetId": "merge-id" }
  ],
  "edges": [
    {
      "id": "edge-id",
      "source": "node-id",
      "target": "next-node-id",
      "kind": "sequence",
      "label": "",
      "branchId": ""
    }
  ],
  "warnings": []
}
```

- `nodes[].id` 使用目标平台真实节点 ID，前端不显示编码。
- `nodes[].mergeTargetId` 只在路由节点存在真实主线后继时返回，值为该共享后继的真实节点 ID；它只帮助前端把分支内容止于同一个汇合点，不在界面显示，也不形成路径数据。
- 普通主线边为 `sequence`；条件、手动分支和并行入口边分别为 `condition`、`manual`、`parallel`。
- 分支边名称取策略 `nodeName`，为空时取 `name`；并行无名称时只按目标返回顺序生成展示文案，不伪造业务名称。
- `branchId` 只在分支边保留真实策略 ID，F-004 不据此建立路径数据。
- 分支节点的各分支递归返回末端集合；存在主线后继时，由每个分支末端连接到同一个真实后继节点，表达汇合，不创建虚假业务节点。
- 节点与边按真实 ID 去重；分支顺序优先使用目标 `sort`，缺失时保持响应顺序。
- 同一真实节点只能在所属结构块出现一次；两个分支在显式 `mergeTargetId` 前共享节点、分支入口就是汇合点或形成自连接时拒绝绘图，不能让后端接受而由前端布局崩溃。
- 未识别但仍具备普通子节点结构的节点保留名称并显示为“未知类型”，同时返回提示；未知类型携带分支结构、节点 ID 缺失、循环引用、空分支入口或结构超限时拒绝绘图并报告结构异常。
- 解析上限为 500 个真实节点、递归深度 200；超过上限不截断冒充完整流程。

不向浏览器返回 SID、密码、验证码、AES key、customerCode、platformCode、`flowProxyId`、目标响应原文、审批配置或字段权限。

## API 边界

### 读取计划流程图

`GET /api/plans/{id}/flow-graph`

- ID 非法返回 `400 INVALID_ARGUMENT`。
- 计划不存在返回 `404 PLAN_NOT_FOUND`。
- 后端只使用计划持久化字段确定账号、来源和目标，不接受浏览器覆盖账号或目标 ID。
- 每次进入页面或点击重试都重新读取目标结构；F-004 不把图存进 MySQL 或进程缓存。

### 稳定错误

| 场景 | HTTP / 错误码 | 页面行为 |
| --- | --- | --- |
| 计划 ID 非法 | `400 INVALID_ARGUMENT` | 显示计划地址无效并允许返回列表 |
| 计划不存在 | `404 PLAN_NOT_FOUND` | 显示计划不存在并允许返回列表 |
| 模板、已发或待发记录不再可见 | `404 TARGET_FLOW_NOT_FOUND` | 说明目标流程当前不可读取，不绘制旧结构 |
| 目标流程尚无节点树 | `422 TARGET_FLOW_STRUCTURE_EMPTY` | 显示“目标流程暂未配置节点” |
| 节点树循环、关键 ID 缺失或分支不完整 | `502 TARGET_FLOW_STRUCTURE_INVALID` | 显示目标流程结构异常，不显示半张图 |
| 登录被拒绝 | `401 TARGET_LOGIN_REJECTED` | 提示重新核对账号 |
| 会话重登后仍失效 | `401 TARGET_SESSION_EXPIRED` | 提示重新验证账号后重试 |
| 目标配置缺失 | `503 TARGET_CONFIG_MISSING` | 显示服务尚未完成目标平台配置 |
| 目标服务不可用 | `503 TARGET_UNAVAILABLE` | 保留页面摘要并提供重试 |
| 目标请求超时 | `504 TARGET_TIMEOUT` | 保留页面摘要并提供重试 |

## 页面与交互

- 延续应用壳和计划页的扁平布局；返回入口固定在内容区左上，不随图形平移，也不使用弹跳定位。
- 计划名称、状态、目标流程、账号和来源组成紧凑摘要，流程图是页面唯一主内容；不继续保留 F-003 的大块空状态。
- 加载时保留与最终画布相同的最小高度，错误、空状态和图形之间不造成整页突跳。
- 布局从真实根节点递归构造纵向主干；节点使用固定测量尺寸，长名称最多两行并可悬停查看完整内容。布局可以超出当前视口，禁止为了同屏展示整图而压缩节点和间距。
- 条件、手动分支和并行路由保留真实 ID 和边语义，但前端只把它们作为不可见分叉点，不显示“条件路由”等卡片；入线与出线组成水平树干和向下分支。
- 同一路由点的分支严格按后端已经归一的边顺序从左到右排列；真实 `sort` 缺失时继续沿用目标响应顺序，不允许布局引擎反转。
- 每个路由递归计算分支内容块：分支块顶端对齐并按自身宽度横向展开，块内业务节点沿独立列向下；嵌套路由只扩展所在分支块，不挤入相邻分支。
- 路由节点的 `mergeTargetId` 是该组分支的停止点；所有分支内容只布局到共享后继之前，共享后继在分支块下方居中布局一次并继续主干。
- 连线由布局结果生成确定路径，不再交给通用 step/smoothstep 自动绕线：普通主干只走垂直线，同一分叉共用一条水平分支轨，同一汇合共用一条水平汇合轨，轨道与分支列之间只使用垂直线。
- 静态底线之上使用低对比度、低密度的方向流动效果，不改变几何路径、不遮挡分支名称；系统设置减少动态效果时停用动画。
- 首次数据就绪后只把根节点定位在画布上方并使用可读缩放，不再对整张图执行 `fitView`。来源未变化的重绘、窗口尺寸变化和全屏切换不得反复抢夺用户视口；用户仍可主动点击适配控件查看全貌。
- 允许拖动画布、滚轮缩放、控件缩放、一键适配以及右上角进入/退出页面全屏；页面全屏使用 `fixed` 覆盖层占满当前浏览器内容视口，保留标签栏和地址栏，不调用 Fullscreen API，并可用 `Esc` 退出。禁止节点拖动、连线、删除、多选和位置持久化。
- 发起、审批/协同、空节点、结束节点继续使用现有克制的 Naive 语义色和形状；用户参考图只作为树形关系依据，不复制其节点样式。
- 浅色和深色使用 Naive UI 主题变量；画布与内容区保持同一表面色，不增加卡片底色、渐变或阴影。
- 分支名称显示在对应入口边上；没有真实名称时使用弱化的顺序提示，节点编码和策略编码均不显示。
- 加载中的旧请求使用 `AbortController` 取消；路由计划 ID 变化后旧结果不得覆盖新页面。
- 前端收到意外的非结构化图时在稳定画布区域显示“目标流程结构异常”，保留页面摘要和重试入口，不抛出组件渲染白屏。

## 代码边界

- `internal/adapter/target`：新增目标详情请求和最小原始结构类型，只在这里处理目标 envelope、SID 与来源接口差异。
- `internal/service`：按计划编排来源核对、代理解析和会话重试。
- `internal/model`：定义与目标传输结构解耦的图节点、图边、路由汇合提示和警告。
- `internal/analyzer`：只负责把已取得的目标嵌套树规范化为图并标注路由真实主线后继，不发 HTTP、不读数据库。
- `internal/api`：提供计划流程图路由和稳定错误映射。
- `web/src/features/flow-graph`：图 API、类型、结构化树布局、自定义正交边和只读节点展示，不放计划持久化逻辑。
- `web/src/views/PlanPathsView.vue`：编排计划摘要、加载状态和只读画布；F-005 再扩展路径选择。

## 人工验收

1. 分别准备一个当前账号可见的流程模板、已发实例和待发实例，并各创建或打开一条计划。
2. 核对三类计划显示的是当前真实流程名称、节点名称、节点类型、分支名称和汇合关系；已发/待发不得误显示模板后来修改后的结构。
3. 对包含条件、手动分支、并行和嵌套分支的流程核对：主干垂直、每个分叉只有一条水平轨、各分支按列向下、每个汇合只有一条水平轨并回到主干；没有弯绕、交叉或节点重叠。
4. 确认初次进入时节点文字保持可读且流程顶部自然出现；按目标真实顺序从左到右核对分支，条件、手动和并行路由只显示分叉树干，不显示路由卡片；线条流动方向与自上而下的流程一致。
5. 使用拖动画布、滚轮、缩放和适配按钮，确认展开的大图可以自然浏览；点击画布右上角进入页面全屏，确认浏览器标签栏和地址栏仍保留，再用按钮和 `Esc` 退出，切换前后当前浏览位置不被重置。
6. 切换深浅主题，确认画布与内容区没有异色底块，文字、正交边线和控件清晰。
7. 让待发任务处理完成或使用当前账号不可见的目标后重试，确认页面说明目标已不可读取，不回退旧图。
