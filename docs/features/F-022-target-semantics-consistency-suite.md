# F-022 目标语义一致性套件

- 状态：awaiting_approval
- 产品依据：`docs/PRODUCT.md` 产品原则第 1、2、6 条（目标真实语义为依据、工具问题与目标问题分开、写结果不明确先核对）
- 架构依据：`docs/ARCHITECTURE.md` 参考源码边界、目标适配层边界和测试按类别归档约束
- 纲领依据：`docs/EXECUTION_PROGRAM.md` 第 8.1 至 8.4、9、10 节，以及 F-014 至 F-021 各切片已登记的语义证据
- 前置条件：F-019 已完成全部动作语义接入，F-020 已完成调度，F-021 已完成记录查看；各切片已把实际使用的语义条目和证据写入 `docs/TARGET_SEMANTICS.md`。本切片可触发受控目标写，但只使用用户指定的可污染账号和流程。

## 目标

把目标平台 14 个语义域变成可重复运行的证据和对照测试：参考源码变动、目标部署变动或工具实现偏离时，汇总脚本能明确指出受影响条目，不让语义漂移静默进入执行器。

## 单一用户结果

用户运行一个命令即可得到语义一致性报告：每条语义都有源码位置、参考仓库 HEAD、目标部署版本、对照测试和当前结论；只读条目可在本机重复验证，写条目在受控账号/流程上按白名单执行并记录证据。发生漂移时报告具体条目和下一步人工复核，不自动修改目标或工具代码。

## 语义条目范围

清单固定覆盖：条件求值、手动分支、并行与会签、任务生成与演员解析、审批动作门禁、回退与取回、撤回与重提、加签与移交、转发、表单字段权限、附件与富文本、前端按钮门禁、错误语义、幂等与重复提交。每条条目必须有证据强度（源码可证明/源码推断待实测/部署已验证）、适用切片、测试引用和已知差异。

## 范围

### 包含

- 统一语义文档格式和机器可读证据块；记录参考仓库 HEAD、目标部署版本、部署日期、适配器版本和测试 fixture 来源。
- 只读对照测试：条件、流程结构、任务/人员读取、按钮显隐、字段权限和错误响应的真实目标回放。
- 受控写对照测试：15 个动作、恢复步骤、转发辅助流程、幂等/重复提交和部分生效；每条测试明确账号、流程、前置状态、期望观察点和清理边界。
- 参考仓库同步后的符号存在性、关键分支数量、端点清单和前端按钮结构漂移检测；脚本输出受影响语义，不自动放行。
- 汇总入口、报告归档和失败分类：目标语义变化、工具缺陷、环境不可用和测试数据不足必须区分。

### 不包含

- 修改目标平台源码、部署、权限、数据库或业务数据；不自动修复语义差异。
- 为旧接口、旧字段、旧状态增加兼容层或回退实现。
- 把不稳定的真实写测试当作每次本地构建的默认步骤；真实写测试需显式开关并校验账号/流程配置。
- 替代 F-016 至 F-021 的功能测试、运行记录或 UI 验收；本切片只汇总并补齐语义证据。

## 测试与安全边界

- 测试按 `test/unit/backend/target_semantics/`、`test/integration/f022_*`、`test/contracts/f022/` 和 `test/fixtures/semantics/` 分类保存。
- 只读测试缺配置必须明确失败，不静默跳过；受控写测试默认不执行，显式启用时只允许 `.env.local` 提供的测试账号和流程，日志不进 Git。
- 目标写请求集合由各动作白名单合并得到，任何新增端点先失败并要求人工更新语义证据和计划。
- 语义报告以数据库/日志事实为准，不在脚本中硬编码目标临时 ID、凭证或目标响应正文。

## 详细执行任务

每个任务完成后独立验证并使用中文提交说明；实施前必须确认前置切片已验收。

### T01：清单盘点与证据格式

整理 14 个语义域及其子条目，统一证据块字段、状态取值、来源仓库和部署版本；检查每个触发写的切片是否补齐自身条目，删除空泛“已支持”描述。

### T02：只读对照套件

把 F-012、F-014、F-015 的真实结构、条件、错误和人员读取样本集中到 fixture；新增只读目标集成测试，验证响应形状、状态映射、分支和按钮语义，记录目标抖动与环境不可用而非吞掉失败。

### T03：受控写对照套件

按动作和恢复步骤建立最小真实场景矩阵，覆盖成功、目标拒绝、响应丢失、部分生效、重复提交和演员变化；每个场景最多一次写请求，重放必须先对账，测试完成后只清理工具侧临时记录，不删除目标事实。

### T04：漂移检测实现

解析语义证据块，检查引用的类、方法、组件、端点和关键分支在当前参考仓库 HEAD 仍存在；检查目标部署版本与最近实测时间，发现变化输出条目、证据位置和人工复核提示。不能以“符号存在”代替行为对照测试。

### T05：报告与汇总入口

新增 `test/run-f022.sh`，汇总静态证据、只读测试、契约脚本和显式受控写测试；输出目标写端点集合、失败分类、fixture 来源、三个仓库 HEAD 和报告路径。前端构建与 Go 构建只在该范围必要时执行，不扩大测试范围。

### T06：交接与维护规则

同步 `docs/TARGET_SEMANTICS.md`、`docs/PROGRESS.md`、`docs/ROADMAP.md` 和本文件；写明参考仓库同步后必须先跑漂移检测、再决定是否调整动作目录或判定器，禁止自动修改业务规则。
