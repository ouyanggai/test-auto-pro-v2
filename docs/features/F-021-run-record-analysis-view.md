# F-021 运行记录分析视图

- 状态：awaiting_approval
- 产品依据：`docs/PRODUCT.md` 主导航（运行记录）、计划与运行主线第 4、5 条、产品原则第 4、6 条、运行画布和日志可观测要求
- 架构依据：`docs/ARCHITECTURE.md` 的前端边界、`internal/repository` 只负责存储访问、运行事实 append-only 和日志目录约束
- 纲领依据：`docs/EXECUTION_PROGRAM.md` 第 1、5.4、6.2 至 6.7、7.1 至 7.4、9、10 节，以及 F-016 至 F-020 已验收能力
- 前置条件：F-016 至 F-020 已完成并经用户明确验收；运行、路径运行、步骤、尝试、事件、控制和日志引用字段稳定。本切片只读，不改变任何运行事实。

## 目标

提供一个统一的中文运行记录入口，让用户从运行列表进入路径详情、事件流和具体日志行，三次点击内解释一次失败，并能把运行结果与最终目标事实分开查看。

## 单一用户结果

用户打开“运行记录”即可按计划、状态和时间找到一次运行；进入运行详情后看到所有路径的独立状态和整体汇总；进入某条路径可按步骤、尝试和七阶段查看事实、请求、响应、对账、控制与耗时；点击日志入口可在 code-server 打开对应文件和行号。页面全程只读，不提供重新运行、重放或修改配置的隐式入口。

## 范围

### 包含

- 运行记录列表：计划名称、运行号、触发方式、运行模式、路径数量、整体状态、开始/结束时间和最近错误摘要；支持按计划、状态、时间范围筛选与清空。
- 运行详情：运行整体状态、串并调度摘要、每条路径独立状态、路径结果、最终目标事实和待对账提示；失败路径不遮蔽其他路径。
- 路径运行详情：真实流程画布（复用 F-016）、节点状态、步骤顺序、动作/恢复/导航来源、演员、门禁、七阶段耗时和当前事实。
- 事件流时间线：按数据库 `run_events` 顺序展示中文事件、时间、节点/步骤和状态变化；轮询增量读取，刷新不重排历史事件。
- 尝试和日志引用：展示 `trace_id`、`curl_trace_id`、相对路径、行号、错误分类、请求/响应正文摘要和复制/查看日志入口；正文遵守 F-013 原样记录与有界渲染规则。
- 运行结果与最终目标事实分栏：路径是否完成、是否失败/待对账，与目标实例状态、当前节点、当前待办、已办情况分别呈现。
- 从日志反向定位：日志行包含运行键和步骤键，页面提供复制查询条件；不依赖未验证的 code-server 深链时退化为复制路径和行号。

### 不包含

- 任何运行控制、断点、暂停、停止、对账恢复或重放操作（分别属于 F-017/F-018）。
- 修改计划、路径、人员、表单数据、动作顺序或目标平台事实。
- 独立技术状态页、JSON 配置页、跨运行指标平台、报表导出和自动归档。
- 新建第二套运行画布或重复实现执行状态机；详情页消费既有 API 和组件。

## 只读接口约束

- 列表、详情、事件流和日志引用接口只能读取工具数据库与日志索引，不调用目标平台写端点。
- API 返回中文业务名称和不透明键，目标实例临时标识、SID、凭证和完整正文只在 code-server 日志查看，不经公开 DTO 返回。
- 分页、时间范围和事件游标必须有界；数据读取失败显示可重试的存储错误，不把空列表当作“没有运行”。
- 事件和详情按事实表顺序读取，不通过前端推断状态，不覆盖数据库中的历史记录。

## 详细执行任务

每个任务完成后独立验证并使用中文提交说明；实施前必须确认前置切片已验收。

### T01：运行记录读模型与查询边界

在 `internal/repository` 增加运行、路径、步骤、尝试、事件、控制的分页读取和日志引用聚合；在 `internal/service` 定义列表筛选、详情聚合和错误语义。禁止在仓储层拼接业务结论，禁止读取后写回任何事实。

### T02：运行列表与筛选 API

提供运行列表、筛选、分页和空态接口；统一计划归属与权限核对，状态和触发方式转换为中文。覆盖运行不存在、参数非法、存储不可用和分页游标过期四种错误。

### T03：运行/路径详情 API

聚合运行级、路径级、步骤级和最终目标事实；返回每条路径独立结果、待对账/失败分类、日志引用和耗时。保留真实事件顺序，不把路径结果和最终目标事实合并成单一成功判断。

### T04：事件流与增量读取

实现按 `run_events` 自增键或时间游标的只读增量接口，前端轮询时只追加新事件。事件重复、乱序或缺失时按数据库顺序去重和提示，不使用 WebSocket，不引入消息队列。

### T05：日志深链与正文查看

提供日志文件相对路径、行号、trace 和 curl 引用；实施时实际验证 code-server 深链格式，未验证成功则只提供复制路径/行号。正文默认折叠、有界渲染，复制内容与 `curl.log` 原始字节同源。

### T06：前端运行记录工作区

实现运行列表、运行详情、路径详情和事件流的中文桌面布局，复用 F-016 运行画布与 F-017 侧栏；提供加载、空、错误、无权限和刷新状态，不使用整页 loading 遮蔽已有事实。页面不出现重试、继续、跳过或修改配置按钮。

### T07：可观测性与分析测试

新增 `test/unit/backend/run_records/`、`test/integration/f021_*`、`test/contracts/f021/` 和 `test/run-f021.sh`。覆盖筛选分页、路径隔离、事件增量、日志双向引用、正文有界渲染、存储错误语义和无写端点；前端契约断言三次点击链路与只读边界。

## 人工验收

1. 打开“运行记录”，按计划和状态筛选，确认列表排序、空态和读取失败提示符合中文业务语义。
2. 进入一次多路径运行，确认整体摘要与每条路径的状态、结果、最终目标事实分开显示。
3. 打开一条路径，展开步骤、尝试和七阶段耗时，确认动作、演员、对账、控制和日志引用可追溯。
4. 打开事件流并刷新，确认只追加新事件，历史顺序不变；断网后恢复可重试且不丢已有事实。
5. 从失败步骤点击“查看日志”，确认三次点击内到达正确日志文件和行号；若深链未验证，确认复制路径/行号内容准确。
6. 确认页面没有重放、继续、跳过、修改配置或目标写请求入口。
7. 在项目根执行 `./test/run-f021.sh`，确认无跳过并输出日志双向引用检查结果。
