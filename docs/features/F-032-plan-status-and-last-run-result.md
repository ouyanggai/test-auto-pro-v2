# F-032 计划状态与最近运行结果修复

- 状态：ready_for_manual
- 产品依据：`docs/PRODUCT.md`「计划公开状态」一节（第 87 行）——状态枚举保留，语义由「已完成」修正为「已运行」
- 架构依据：`docs/ARCHITECTURE.md` 计划/运行编排边界，复用现有 `runs` 表，不新增表
- 计划确认时间：2026-09-13 用户批准「开始实施」

## 目标

计划列表状态真实反映运行事实：计划是否运行过、是否正在运行、最近一次运行的结果不再写死为空；运行后路径配置按既有规则正确进入只读锁定。

## 根因（只读排查确认）

1. `internal/service/plan.go:68` 创建计划时状态固定 `not_started`，此后无任何状态流转。
2. `internal/repository/mysql/plan_repository.go:55` 列表查询只读 `test_plans.status`，不结合 `runs` 表。
3. `internal/api/plans.go:184` 附近接口返回的最近运行结果直接写死为空。
4. 隐藏影响：`internal/repository/mysql/execution_path_repository.go:509` 路径配置锁定只允许 `not_started` 修改；计划状态永远不变意味着首次运行后配置锁可能不生效（需在实现时核实真实首次运行是否触发状态更新——现状是没有触发）。

## 范围

- 包含：
  - 计划状态按运行事实流转：无任何运行记录=未运行；存在等待中/运行中记录=运行中；有历史运行且无活跃运行=已运行；永不回退到未运行。
  - 创建运行、运行开始、运行结束、失败、停止、取消、重试等状态变更事务中同步更新计划状态。
  - 计划列表单条 SQL 一次补齐：是否存在运行记录、是否有活跃运行、最近运行号、最近运行状态、最近运行结果与结束时间；禁止 N+1 逐计划查询。
  - 「最近运行结果」返回真实信息：暂无运行记录 / 第 N 次运行中 / 第 N 次：成功 / 第 N 次：失败 / 第 N 次：结果待确认。
  - 保留现有接口枚举键 `not_started/running/completed`，不扩大改动范围。
  - `docs/PRODUCT.md` 同步：计划状态第三档「已完成」改为「已运行」，前端不得把 `completed` 渲染成「已完成」。
- 不包含：
  - 不新增数据库表或迁移（复用现有 `runs` 数据）。
  - 不改变运行编排、重试边界、写后核验、路径配置锁定规则本身（锁定规则只是因状态流转恢复生效）。
  - 不改运行详情页与节点过渡显示（属 F-033）。

## 完成标准

- [x] 新计划显示「未运行」。
- [x] 第一次运行过程中显示「运行中」。
- [x] 第一次运行结束后显示「已运行」。
- [x] 已运行计划仍可再次运行；第二次运行过程中重新显示「运行中」。
- [x] 最近运行结果不再为空，按第 N 次口径显示。
- [x] 运行后路径配置进入只读状态。
- [x] 计划列表无 N+1 查询。
- [x] `docs/PRODUCT.md` 与前端文案一致（已运行/已有运行记录）。

## 实施记录（2026-09-13）

1. 读侧自愈：`plan_repository.go` 的 List/Get/getByCreateKey 一条 SQL 内用 `runs` 运行事实派生计划公开状态
   （存在等待/运行中记录→运行中；存在历史运行→已运行；否则保留存储列），并聚合最近运行号、状态、结果、
   结束时间与活跃运行标记；状态筛选同样使用派生表达式，历史脏数据自动纠正，无 N+1 查询。
2. 写侧同步：`run_repository.go` 新增 `syncPlanRunStatus`，在创建运行、运行聚合推进（等待→运行中、终态）、
   路径收尾聚合、`FinishRunIfAllPathsClosed`、失败重试重开等事务内同步计划存储列，
   保证路径配置锁定与「已有运行记录不能删除」的写侧判断一致；条件更新守卫确保计划状态永不回退到未运行。
3. 展示口径：`api.PlanLastRunText` 按运行事实生成「暂无运行记录 / 第 N 次运行中 / 第 N 次：成功/失败/已停止/已取消」；
   运行级停止含崩溃恢复置为待对账的运行（运行级无独立待对账状态，统一显示已停止）。
4. 前端：`planStatusLabels.completed` 改为「已运行」；`docs/PRODUCT.md` 计划公开状态定义同步修订。
5. 测试：`test/run-f032.sh` 全部通过（后端单元 + 真实 MySQL 集成 TestF032PlanStatusFollowsRunFacts /
   TestF032PlanLockUsesSyncedStatus / TestF032PlanListAggregatesLastRun + 契约与既有计划用例回归 + vue-tsc + 构建）。

## 人工验收

1. 创建新计划 → 列表显示「未运行」。
2. 点击运行 → 运行过程中列表显示「运行中」，最近运行结果显示「第 1 次运行中」。
3. 运行结束 → 状态变「已运行」，最近运行结果显示真实结果（成功/失败/结果待确认）。
4. 已运行计划点击再次运行 → 过程中「运行中」，结束后「已运行」。
5. 运行后进入路径配置 → 配置为只读，不可修改。
