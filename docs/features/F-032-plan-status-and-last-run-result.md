# F-032 计划状态与最近运行结果修复

- 状态：ready_for_manual
- 产品依据：`docs/PRODUCT.md`「计划公开状态」一节（第 87 行）——状态枚举保留，语义由「已完成」修正为「已运行」
- 架构依据：`docs/ARCHITECTURE.md` 计划/运行编排边界，复用现有 `runs` 表，不新增表
- 计划确认时间：2026-09-13 用户批准「开始实施」

## 目标

计划列表状态真实反映运行事实：计划是否运行过、是否正在运行、最近一次运行的结果不再写死为空；计划和执行路径在产生运行记录后仍可修改，用户可以重复启动同一计划。

## 根因（只读排查确认）

1. `internal/service/plan.go:68` 创建计划时状态固定 `not_started`，此后无任何状态流转。
2. `internal/repository/mysql/plan_repository.go:55` 列表查询只读 `test_plans.status`，不结合 `runs` 表。
3. `internal/api/plans.go:184` 附近接口返回的最近运行结果直接写死为空。
4. 隐藏影响：F032 实施时把计划状态同时当作展示状态和写入锁，导致运行后计划、路径、历史来源和节点配置全部被错误锁死；状态只能描述运行事实，不能再承担可编辑性判断。

## 范围

- 包含：
  - 计划状态按运行事实流转：无任何运行记录=未运行；存在等待中/运行中记录=运行中；有历史运行且无活跃运行=已运行；永不回退到未运行。
  - 创建运行、运行开始、运行结束、失败、停止、取消、重试等状态变更事务中同步更新计划状态；状态只用于列表展示和筛选。
  - 计划列表单条 SQL 一次补齐：是否存在运行记录、是否有活跃运行、最近运行号、最近运行状态、最近运行结果与结束时间；禁止 N+1 逐计划查询。
  - 「最近运行结果」返回真实信息：暂无运行记录 / 第 N 次运行中 / 第 N 次：成功 / 第 N 次：失败 / 第 N 次：结果待确认。
  - 保留现有接口枚举键 `not_started/running/completed`，不扩大改动范围；任一状态都允许再次运行和进入编辑。
  - 新增计划更新接口和编辑页面，编辑名称、账号/流程绑定、运行方式、并行上限和定时设置；账号或流程绑定变化时将已有路径配置标记为“受影响”，要求重新核对后才能运行。
  - 执行路径、节点人员/动作和历史业务数据来源继续使用现有编辑入口；运行事实只读保存，不被新配置覆盖。
  - 顶层导航和列表页面使用“任务中心”“任务列表”产品文案，内部 `/runs` API 与路由保持不变。
  - `docs/PRODUCT.md` 同步：计划状态第三档「已完成」改为「已运行」，前端不得把 `completed` 渲染成「已完成」。
- 不包含：
  - 不新增数据库表或迁移（复用现有 `runs` 数据）。
  - 不改变运行编排、重试边界、写后核验和历史运行事实；不再以计划状态锁定计划或路径配置。
  - 不改运行详情页与节点过渡显示（属 F-033）。

## 完成标准

- [x] 新计划显示「未运行」。
- [x] 第一次运行过程中显示「运行中」。
- [x] 第一次运行结束后显示「已运行」。
- [x] 已运行计划仍可再次运行；第二次运行过程中重新显示「运行中」。
- [x] 最近运行结果不再为空，按第 N 次口径显示。
- [x] 运行后计划仍可编辑，执行路径与节点配置仍可编辑；配置变化不改写历史运行。
- [x] 已运行计划可重复启动，新的运行使用启动时保存的最新配置。
- [x] 账号或流程绑定变更会把已有路径配置标记为受影响，不会静默复用旧配置。
- [x] 计划列表无 N+1 查询。
- [x] `docs/PRODUCT.md` 与前端文案一致（已运行/已有运行记录）。

## 实施记录（2026-09-13）

1. 读侧自愈：`plan_repository.go` 的 List/Get/getByCreateKey 一条 SQL 内用 `runs` 运行事实派生计划公开状态
   （存在等待/运行中记录→运行中；存在历史运行→已运行；否则保留存储列），并聚合最近运行号、状态、结果、
   结束时间与活跃运行标记；状态筛选同样使用派生表达式，历史脏数据自动纠正，无 N+1 查询。
2. 写侧同步：`run_repository.go` 新增 `syncPlanRunStatus`，在创建运行、运行聚合推进（等待→运行中、终态）、
   路径收尾聚合、`FinishRunIfAllPathsClosed`、失败重试重开等事务内同步计划存储列，
   保证运行事实冗余列与「已有运行记录不能删除」的删除守卫一致；条件更新守卫确保计划状态永不回退到未运行。
3. 展示口径：`api.PlanLastRunText` 按运行事实生成「暂无运行记录 / 第 N 次运行中 / 第 N 次：成功/失败/已停止/已取消」；
   运行级停止含崩溃恢复置为待对账的运行（运行级无独立待对账状态，统一显示已停止）。
4. 计划编辑与可重复运行：移除状态驱动的计划、路径、历史来源和节点配置写入守卫；新增 `PUT /api/plans/{id}`，身份绑定变更原子标记路径配置受影响，并立即清除带代次保护的流程图缓存，防止旧后台读取回填；列表为所有状态保留“运行”“编辑计划”“编辑路径”。
5. 前端：`planStatusLabels.completed` 改为「已运行」，导航和运行页面改用「任务中心」「任务列表」；`docs/PRODUCT.md` 计划公开状态定义同步修订。

## 人工验收

1. 创建新计划 → 列表显示「未运行」。
2. 点击运行 → 运行过程中列表显示「运行中」，最近任务结果显示「第 1 次运行中」。
3. 运行结束 → 状态变「已运行」，最近任务结果显示真实结果（成功/失败/结果待确认）。
4. 已运行计划仍可点击运行，第二次运行使用新的运行号并重新显示「运行中」。
5. 已运行计划可以进入“编辑计划”保存名称、运行方式和定时设置；修改后列表立即显示新值。
6. 已运行计划可以进入“编辑路径”和节点配置；保存后受影响路径不会被运行前检查误判为就绪。
7. 任务中心页面标题为“任务列表”，导航显示“任务中心”，历史任务详情仍能打开且历史事实不变。
