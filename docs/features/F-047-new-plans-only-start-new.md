# F-047 新建计划先只开放“新发起”

状态：ready_for_manual
批准依据：用户要求暂时禁用另外两种建计划方式，只让“新发起”可创建。

## 要解决的问题

“已发”和“待发”目前还没有完成验证。新建页仍把它们作为可选项，会让用户创建出尚未准备好的新计划。

## 这次怎么做

- 新建计划页保留三个来源名称，只有“新发起”可以选择；另外两个选项明确置灰。
- 账号是否已经验证，都不改变这个限制。
- 服务端也只接受“新发起”，避免绕过页面直接创建“已发”或“待发”计划。
- 已有“已发”或“待发”计划仍可打开和保存其他编辑；保存时沿用它本来绑定的来源与流程对象。
- 不改执行和读取方式，不删旧来源代码，不改数据库。

## 完成标准

- 前端测试确认新建只允许“新发起”。
- 后端测试确认“已发”“待发”和未知来源不能创建。
- 后端测试确认已有“已发”“待发”计划可以编辑名称并保留原来源与目标对象。
- 前端类型检查、后端构建和差异检查通过。

## 实施与验证记录（2026-10-14）

- 完成：新建页三种选项中只有“新发起”可选，页面说明写明用途；后端创建接口强制只接受新发起。
- 保持：编辑接口仍接受已发和待发，并有回归测试验证原来源与目标对象不变。
- 验证：前端来源测试 6 项通过；计划创建/更新后端测试通过；执行器类型检查、Go 构建与 `git diff --check` 通过。
- 状态：`ready_for_manual`。人工核对新建页两个暂停选项不可选；再打开已有已发/待发计划编辑名称并保存，确认来源与流程对象仍保持原值。
