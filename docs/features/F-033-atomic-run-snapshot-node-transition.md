# F-033 运行详情原子状态快照与节点过渡显示修复

- 状态：awaiting_approval
- 产品依据：`docs/PRODUCT.md` 运行详情与白话文案原则（第 79 行）——过渡说明用完整白话，不伪装执行状态
- 架构依据：`docs/ARCHITECTURE.md` 控制服务边界——详情读取收敛为控制服务的原子快照，不新增表
- 计划确认时间：待确认

## 目标

运行推进过程中画布不再出现「无节点高亮」的空白期；当前节点与下一节点之间的过渡有明确的白话说明；分支流程不因前端猜测而错误高亮。

## 根因（只读排查确认）

1. 放行后后端立即返回 HTTP 响应，真正执行在后台协程继续（`internal/engine/control/runner.go:19`）；当前步骤完成后，重新读取目标平台事实、构建下一步预览包含目标读取与退避重试（`internal/engine/control/control.go:1160`）。
2. `internal/service/run_orchestration.go:1079/1101` 详情接口分别读取 `CurrentPreview()` 与 `View()`，不是原子快照，可能拿到「当前步已完成、下一步预览未生成、currentPreview 为空」的中间态。
3. 前端轮询直接覆盖整个详情对象（`web/src/views/RunDetailView.vue:412`），当前节点计算在无 `currentPreview` 且无最新步骤时返回空（同文件 276 行），画布收到空当前节点 ID 后不再高亮。

## 范围

- 包含：
  - 后端：控制服务新增原子快照读取，一次返回当前预览、当前步骤号、是否正在执行、当前阶段、当前阶段说明、过渡中的上一节点；详情接口只读该快照，不再分别读取 `CurrentPreview()` 与 `View()`。
  - 下一节点预览未生成时返回明确过渡状态：当前节点仍作为视觉锚点保留、节点状态显示「已完成」、过渡说明形如「节点“审批”第 3 步已完成，正在读取下一节点的当前待办」；不提前猜测下一节点。
  - 预览生成后一次性切换当前节点与节点状态。
  - 前端：非终态运行保留最后一个有效当前节点，不因一次轮询缺 `currentPreview` 清空；中间态用独立「正在读取下一节点」样式，不把已完成节点伪装成仍在执行；终态运行保留最后一个已完成节点。
  - 放行成功后只增加一次受控快速刷新，拿到新节点后立即更新；不提高全局轮询频率。
- 不包含：
  - 不改变执行引擎、后台协程、重试与退避逻辑本身。
  - 不把全局轮询改成高频请求，不引入 WebSocket。
  - 不改变分支流程判定与节点状态语义。

## 完成标准

- [ ] 当前节点完成后画布无「无节点高亮」空白期。
- [ ] 旧节点显示「已完成、正在读取下一节点」。
- [ ] 下一节点返回后节点和连线一次性切换。
- [ ] 不重复发送动作请求。
- [ ] 轮询请求量不无上限增加。
- [ ] 分支流程不因前端猜测而错误高亮下一节点。

## 测试分类

- 后端单元测试（`test/unit/backend/run*`）：原子快照一致性、过渡态返回、预览生成后的切换。
- 前端（`test/unit/frontend` 如有）：当前节点保留逻辑、终态节点保留。
- 只运行当前功能相关测试。

## 状态记录

正常状态按 `preparing -> awaiting_approval -> implementing -> ready_for_manual -> accepted` 推进。用户明确反馈人工验收未通过时允许 `ready_for_manual -> implementing`，须记录反馈并重新验证后再次停在 `ready_for_manual`。

## 人工验收

1. 放行一个节点动作 → 观察画布：旧节点显示「已完成」+「正在读取下一节点」说明，无空白期。
2. 下一节点预览生成 → 当前节点与连线一次性切换高亮。
3. 分支路径运行 → 高亮节点始终是真实事实节点，不提前跳到猜测节点。
4. 运行到达终态 → 画布保留最后一个已完成节点，不显示空白。
5. 观察网络请求 → 放行后仅一次受控快速刷新，全局轮询频率不变。
