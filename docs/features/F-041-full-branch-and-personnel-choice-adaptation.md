# F-041 完整分支与选人组合适配（并行自选、主管副总、手动复合与全分支流转闭环）

- 状态：ready_for_manual
- 产品依据：`docs/PRODUCT.md` 流程结构、执行路径选择行为、节点动作与人员配置
- 架构依据：`docs/ARCHITECTURE.md` 流程图分析器、人员解析与门禁载荷构造、执行服务
- 计划确认时间：2026-09-23

## 目标

全面适配目标平台所有复杂流转选人与分支组合场景，彻底解决“并行节点中多个审批人自选”、“并行中包含部门主管/分管副总”、“手动分支复合审批人自选”、“会签选人人数限制”等导致的流转被拒或执行中断问题，确保任何复杂审批流程均能稳定通过。

## 范围

- 包含：
  1. 路径图与人员要求解析：全量识别并行网关（`parallel`）下所有分支节点的审批类型（自选 `run_node_choose`、部门主管 `department_supervisor`、分管副总 `branched_passage_manager`），全部纳入可配置人员范畴；
  2. 提交/流转载荷装配：
     - 并行分支全量打包：当流转涉及并行网关时，全量收集该并行下所有自选分支人员，一次性塞入 `nextAuditorList`，绝不遗漏任一分支；
     - 主管与副总自动补齐：对并行或手动分支中的主管与副总节点，自动从当前登录人/发起人的组织目录中解析 ID 并组装进载荷；
     - 手动分支复合自选：同时携带选中分支的入口 `nodeProxyId` 与该分支节点的自选人员 `bizId`；
     - 链路上后续自选节点递归预收；
  3. 执行服务闭环（`executor-service` & `runner.go`）：
     - `parallel_choose` 多分支人员补齐与智能候选兜底，消除“任一分支缺人即放弃重试”的一票否决阻塞；
     - 校验并满足会签节点人数下限限制；
  4. 保持一次写、写后核验与同账号安全边界不变。
- 不包含：
  - 目标平台底层业务规则篡改。

## 完成标准
- [x] 并行网关下的所有自选分支均能正确识别并展示在人员配置中。
- [x] 流转写请求（`submit` / `audit` / `reSubmit`）的 `nextAuditorList` 完整包含全部并行自选分支人员。
- [x] 并行或手动分支中的主管与副总节点能自动解析并在流转时注入人员。
- [x] 手动分支加自选复合体能同时携带分支节点与审批人信息。
- [x] 遇到 `parallel_choose` 时能正确闭环继续执行。
- [x] 全部后端单元测试、vet、构建与前端类型检查通过。
- [x] 功能文档状态推进至 `ready_for_manual`。

## 人工验收

1. 运行包含并行自选节点的流程（如收票登记表）：核验流转至该并行节点时不再报“未设置审批人”或“parallel_choose 未闭环”，正常推进流转；
2. 运行包含并行主管/副总的流程：核验系统自动解析并携带主管/副总人员；
3. 运行包含手动条件分支且分支为自选审批人的流程：核验正确流转至所选分支；
4. 检查节点配置面板：核验并行分支各子节点均能清晰配置或一键配置人员。
