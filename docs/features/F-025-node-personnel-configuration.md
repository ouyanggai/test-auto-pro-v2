# F-025 节点人员配置与范围内选人

- 状态：implementing
- 产品依据：`docs/PRODUCT.md` 的“路径节点与表单配置工作区”及本切片新增人员配置规则
- 架构依据：`docs/ARCHITECTURE.md` 的 F-006 人员分析、F-012 配置模型与目标读取边界
- 规划时间：2026-09-09
- 计划确认时间：2026-09-09（用户明确回复“开始”）

## 目标

让用户在路径节点配置页看见每个业务节点真实的人员规则，并能对目标平台开放选择范围的节点完成安全选人：一键配置默认从当前合法范围随机选择一人（会签按目标人数约束），手动调整只能从同一范围内选择。固定人员、主管/职级/扩展属性、表单人员等由目标运行时决定的规则不伪装成可手选，而是显示清楚来源、当前状态和需要在哪个阶段核对。

本切片只处理配置准备与只读核对，不向目标平台发送流程写请求，不创建运行记录。

## 当前问题与依据

- 当前页面只在 `person.editable=true` 时显示选择控件；发起节点或目标运行时确定的节点会显示说明，因此用户容易误以为“节点没有人员配置”。
- 当前一键配置的 `autoPersonStrategy` 优先使用目标默认名单，没有默认名单才使用随机策略；这与“默认随机选一个”的产品要求不一致。
- 当前人员策略已经保存于路径配置的 `person_strategies`，浏览器只提交不透明候选键，服务端会按最新目标目录复验，具备在现有模型上收敛的基础。
- V1 的人员解析表明目标规则至少包括指定人员、公司/部门/角色/岗位范围、发起人及其主管关系、职级、扩展属性、表单人员和运行时自选；目标 `GroupApproveManage` 的人员选择组件也只从节点声明的范围读取候选，不能退化为全员。

## 人员配置分类

页面和服务端必须把“人员规则来源”和“工具是否允许指定”分开表达，不把所有人员都渲染成同一种下拉框。

| 目标规则 | 配置页展示 | 工具是否可选 | 配置状态 |
| --- | --- | --- | --- |
| 指定人员、目标已固定的人员/组织规则 | 显示规则名称、已解析人员或组织范围、目标审批方式 | 否；目标负责解析 | 已解析或需要核对 |
| `run_node_choose` 且目标返回合法范围 | 显示范围和候选人员 | 是；随机或手动 | 待配置/已配置 |
| `run_node_choose` 但范围缺失、目录读取失败或候选为空 | 显示失败原因 | 否 | 阻塞，不能退化为全员 |
| 发起人、部门主管、分管副总、职级、扩展属性 | 显示目标规则及运行时依赖 | 否；执行时解析 | 运行时确定 |
| `form_person` | 显示对应表单人员字段及数据状态 | 否；由表单数据决定 | 等待表单数据或运行时确定 |
| 加签、移交、转发等动作的接收人 | 在动作记录内显示独立人员配置 | 是；沿动作自身候选范围随机或手动 | 与节点主处理人分开 |

“指定人员”类即使解析出多个人，也不能因为候选数量大就擅自改写为工具随机；只有目标规则本身明确开放用户选择时才允许工具选人。

## 选择规则

### 一键配置

- 计划详情页的“一键配置”同时处理历史数据、节点人员和节点动作；人员部分只处理当前路径上尚未被用户确认的可编辑人员项。
- 每个可编辑人员项默认保存 `strategy=random`，从该人员项当前合法候选范围内选择一人。
- 会签节点按目标 `countersignNum` 约束选择数量：正数选择该数量，`-1` 选择全部合法候选；竞签固定选择一人。候选不足时阻塞并说明“合法候选少于目标要求”，不得重复同一人补足。
- 随机选择使用计划、路径、节点和人员项派生的稳定 seed，保证重复请求幂等；已经存在的人工配置不被一键配置覆盖。
- 一键配置不选择目标自动节点、不修改固定规则、不为动态规则制造候选，也不替动作配置中的人员策略套用节点主处理人。

### 手动调整

- 用户把策略切换为“手动选择”后，只能从服务端本次读取的候选中选择；候选键不透明，显示名称来自目标真实目录。
- 保存时服务端重新读取目标结构与人员目录，校验候选仍属于当前节点声明范围、数量满足 `required/minCount/maxCount`、会签数量和去重约束。
- 候选目录变化、已选人员被移出范围、同一候选标识对应多个名称、范围解析不完整时，保存进入 `affected` 或阻塞并要求重新确认，不自动替换人员。
- 页面显示当前选择人数、目标要求人数、候选范围名称和失效原因；不把内部 ID、平台码或目标接口原文展示给用户。

### 随机与手动的共同边界

- 候选范围按目标返回的所有合法范围合并去重，保持目标响应顺序；不按公司、部门、角色等名称猜测范围，不扩大到全公司。
- 目标 `scramble`/竞签只需要一名完成者；`countersign`/会签的完成条件和选择数量必须分开显示，不能把“全部候选”误认为“至少一人”。
- `isSkip` 节点允许目标规定的零人状态；非跳过节点缺少必需人员时始终阻止保存或运行准备。
- 节点主处理人与动作接收人是两个独立配置域；动作人员的候选、数量和失效不会覆盖节点主处理人。
- 浏览器提交的 `selected` 只作为候选键，服务端重新计算随机结果和数量，不能信任浏览器传入的随机名单。

## 配置页交互

- 当前路径业务节点的侧栏固定显示“处理人员”区；即使人员由目标自动决定，也显示规则、来源、解析状态和中文说明，避免空白造成“没有人员配置”的误解。
- 可选人员项显示：人员规则标题、候选范围、选择方式、当前已选人员和人数约束。默认进入时展示随机结果；切换到手动后展示受限多选控件。
- 运行时确定项显示“目标平台将在执行该节点时确定”，并说明依赖的发起人、表单字段或组织关系；不能在配置页填写假人名。
- 人员目录读取失败、范围为空、候选超安全上限和候选失效使用独立阻塞提示；不与“该节点无需配置”混用。
- 节点没有人员规则的发起、条件、并行、空和结束等系统节点不显示空的人员表单，只显示其自动语义。
- 路径级“一键配置”完成后，页面按节点显示实际结果和未完成原因；不能只提示“已完成”而隐藏人员阻塞。

## 接口与存储边界

- 复用现有路径配置读写端点和 `person_strategies` 存储列，不新增数据库表或迁移；策略结构继续包含稳定人员项键、策略、seed 和已选内部 ID。
- 公开 DTO 增加或补齐人员项的来源类别、候选范围摘要、选择能力、人数约束、解析状态和中文阻塞原因；不返回目标内部人员 ID，继续使用不透明候选 token。
- 目标读取继续集中在 `internal/adapter/target`，目录解析失败必须形成明确 issue；`internal/analyzer` 只投影当前路径可达节点，`internal/service` 负责保存校验和一键配置合并。
- 运行时真实处理人的解析和登录仍复用执行器已有的目标重读边界；本切片不新增目标写端点，不把配置期随机结果当成运行期事实。
- 保存成功后以服务端重读结果为准；幂等重试返回相同正文，修订冲突不覆盖其他人员或动作配置。

## 不包含

- 不改目标平台人员范围、审批方式、会签/竞签语义或目标组织目录。
- 不把固定人员、主管、职级、扩展属性或表单人员改造成手动候选池。
- 不实现新的登录账号管理、人员密码校验、目标写操作、运行调度或运行记录页面。
- 不保留 V1 旧人员 DTO、旧随机回归模型、旧账号字段或兼容转换；只吸收 V1 已验证的范围解析和交互经验。
- 不新增“随机换一组”或不可复现的真随机按钮；本切片的一键随机以稳定 seed 保证可重复，人工调整通过手动选择完成。

## 完成标准

- [ ] 当前路径每个业务节点都能看见人员规则、来源、配置能力和状态；不会因 `editable=false` 而表现为空白。
- [ ] 一键配置对可编辑人员默认使用稳定随机策略；目标默认名单不再覆盖该默认策略。
- [ ] 竞签、会签正数、会签全部、可跳过节点的数量规则有服务端校验和定向测试。
- [ ] 手动选择只能提交当前目标范围内的候选；候选失效、目录变化、范围为空和解析不完整均有阻塞或受影响状态。
- [ ] 固定人员、组织规则、发起人关系、职级、扩展属性和表单人员显示为目标规则或运行时状态，不出现伪造的手选下拉框。
- [ ] 节点主处理人与加签、移交、转发接收人配置相互独立，已有动作场景编译不受破坏。
- [ ] 一键配置重复调用幂等，人工已保存的人员策略不会被覆盖；保存修订冲突不会丢失其他节点配置。
- [ ] 新增或修改的测试按后端、前端契约和集成类别存放在根目录 `test/`，只运行本切片相关测试；前端构建和后端定向验证实际通过。

## 实施顺序

1. 先按本文件补齐目标规则矩阵、服务端人员投影和现有数据契约，确认哪些项可编辑。
2. 再调整一键配置人员策略为稳定随机，并补齐会签/竞签数量及候选失效校验。
3. 最后补齐节点侧栏显示、状态文案、动作人员隔离和路径级结果汇总。
4. 自动验证通过后停在 `ready_for_manual`，不代替用户验收或开始下一切片。

## 人工验收

1. 打开同时包含固定人员、组织范围和运行时自选的真实路径，确认每个业务节点侧栏都出现“处理人员”区或明确的目标运行时说明。
2. 对一个有多个合法候选的可选节点执行“一键配置”，确认默认只选一人且显示候选范围；刷新后结果不漂移。
3. 将同一节点切换为手动选择，尝试选择范围外人员，确认候选不可见或保存被阻止；选择范围内人员后保存成功。
4. 核对会签 2 人、会签全部和竞签 1 人三种节点的默认数量与页面提示。
5. 让目标目录中的已选人员或范围发生变化后重新打开页面，确认显示“需要重新确认”，不自动替换。
6. 检查加签、移交、转发动作的接收人配置与节点主处理人分开，保存动作后节点人员选择仍保持原值。
7. 确认配置阶段没有产生运行记录，也没有向目标平台发出流程写请求。
