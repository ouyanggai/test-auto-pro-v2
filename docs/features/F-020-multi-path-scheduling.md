# F-020 多路径调度与单次定时启动

- 状态：awaiting_approval
- 产品依据：`docs/PRODUCT.md` 计划与运行主线第 4、5 条，测试计划页运行方式与定时行为，产品原则第 4、5、6 条
- 架构依据：`docs/ARCHITECTURE.md` 的 `internal/engine/schedule` 边界、运行状态机、MySQL 事务和单体进程 Worker 约束
- 纲领依据：`docs/EXECUTION_PROGRAM.md` 第 4.1、4.2、4.5、7.1 至 7.4、9、10 节，以及 F-016 至 F-019 计划
- 前置条件：F-016、F-017、F-018、F-019 已完成并经用户明确验收；运行事实、控制事实、动作全集和对账恢复已稳定。当前计划的路径配置和运行方式字段继续作为输入，不重新定义。

## 目标

让一次启动可以按计划配置的串行/并行方式运行多条独立路径，在最大并发约束下互不占用或覆盖真实实例；定时启动只执行一次并强制自动模式，单条路径失败不终止其他路径。

## 单一用户结果

用户在计划页勾选多条已通过运行前检查的路径并点击运行。系统创建一个运行记录，为每条路径分配独立真实主实例和路径运行事实，按串行或并行调度推进；用户能看到等待、运行中、待对账、失败和完成的各路径状态，以及整体汇总。到点的单次定时启动自动创建同样的运行记录，但不提供周期重复。

## 范围

### 包含

- 运行级调度器：串行按稳定路径序号推进；并行按计划 `max_concurrency` 限制同时运行的路径数；同一路径内部仍串行。
- 运行启动时只检查和启动用户勾选的路径，未勾选路径不创建路径运行事实、不占用并发额度。
- 一条路径失败、待对账、停止或取消时，其他路径继续按调度策略运行；运行整体状态由所有路径终态汇总。
- 调度租约、fencing token、崩溃恢复和重复启动幂等；同一运行不会重复创建路径实例或重复占用并发槽位。
- 单次定时启动：到达 `scheduled_at` 后只消费一次，强制自动模式；服务重启后按数据库事实恢复，不重复触发。
- 启动前预检结果与运行中路径状态衔接；未通过的路径明确列为阻塞，不静默跳过，也不影响其他可执行路径。
- 在已有运行列表、路径详情和运行画布展示整体进度、并发占用、下一条等待路径和定时触发信息。

### 不包含

- 周期调度、重复执行、日历规则、外部消息队列或多进程分布式调度。
- 跨计划并发配额；并发上限仅针对同一次运行和计划配置。
- 修改已产生运行事实、重用真实主实例、合并多条路径到同一实例或自动改变路径拓扑。
- 动作执行、对账语义和运行分析视图的重新实现；分别依赖 F-018、F-019、F-021。

## 调度约束

- 计划运行方式继续使用串行或并行；并行计划必须有正整数最大并发，串行计划不显示并发设置。
- 一个运行的路径集合在创建时固化；运行开始后不能新增、删除、取消勾选或修改路径配置。
- 路径运行状态只前进，租约失效的 Worker 不能提交步骤、状态或事件；调度器只分配，不直接发目标请求。
- 定时触发只允许一次，运行模式写为自动；如果到点时计划已运行或路径配置不再可执行，记录明确失败/阻塞事实，不重复创建运行。
- 每条路径拥有独立目标主实例引用和日志目录；并发路径不能共享 SID、实例、步骤游标或恢复次数。

## 详细执行任务

每个任务完成后独立验证并使用中文提交说明；实施前必须确认前置切片已验收。

### T01：运行级调度领域模型

定义运行任务集合、路径队列、并发槽位、调度决策和整体汇总状态。明确串行/并行边界、失败隔离、取消/停止传播和路径终态聚合，不把路径状态更新写进调度器之外的隐式分支。

### T02：持久化启动快照与幂等

为启动请求保存勾选路径快照、运行方式、并发上限、触发来源和定时消费标记；复用 `runs`、`path_runs` 事实表约束，必要时用向前迁移补充一次性调度字段。使用幂等键和唯一约束防止重试创建第二个运行或第二份路径实例。

### T03：串并调度 Worker

实现单体进程内的调度 Worker、租约和 fencing token。串行只取下一条稳定序号路径；并行只在活动数小于上限时取队列；路径失败、待对账或停止只释放自己的槽位。Worker 重启后从持久化状态恢复，不自动重发步骤。

### T04：定时触发与一次性消费

实现基于数据库时间的单次触发扫描，抢占任务后原子写入“已消费”事实并创建运行；服务重启、时钟重复扫描或并发 Worker 只能产生一个运行。定时启动强制自动模式，并记录未执行原因。

### T05：启动与路径 API

扩展运行启动 API 返回运行号、路径排队状态、调度方式和可重试错误；运行停止/取消只作用于当前运行，不能删除已发生事实。接口核对路径归属、预检版本和计划是否已固化，版本冲突返回中文当前状态。

### T06：前端选择与调度状态

在计划右上角运行入口复用 F-015 预检弹窗，默认勾选已配置且数据就绪路径，用户选择只保留在当前启动会话。运行详情显示串并方式、并发槽位、等待队列、定时来源和各路径独立结果，不新增第二套画布。

### T07：测试、压测与文档交接

新增 `test/unit/backend/schedule/`、`test/integration/f020_*`、`test/contracts/f020/` 和 `test/run-f020.sh`。覆盖串行顺序、并行上限、失败隔离、重复启动、租约 fencing、重启恢复、定时一次性消费和前端勾选契约；使用受控虚拟目标验证调度，真实写只复用 F-019 的已验证动作并记录白名单证据。同步路线图、进度和相关语义条目。

## 未决与需要用户裁决的事项

1. 定时到点但部分路径预检失败时，默认只创建可执行路径的运行并把其余路径记为阻塞；若要求整次启动原子失败，实施前需调整启动事务。
2. 并行运行中用户点击停止，默认不打断已发出的写请求，各路径在当前步骤落账后分别停止；这是 F-016/F-017 的停止边界在运行级的延伸。

## 人工验收

1. 建立包含多条路径的串行计划，确认只运行勾选项，路径按稳定序号依次开始且不重复创建实例。
2. 建立并行计划，设置最大并发为 2，确认任意时刻活动路径不超过 2，完成一条后才补下一条。
3. 让一条路径失败或待对账，确认其他路径继续，运行汇总分别显示各自结果。
4. 重复点击运行和刷新页面，确认只得到一个运行号；重启服务后确认租约恢复没有重复写。
5. 设置未来一次定时，确认到点只创建一次运行且模式显示为自动；再次扫描或重启不重复触发。
6. 在运行详情检查等待队列、并发占用、路径日志目录和每条路径独立的目标实例引用。
7. 在项目根执行 `./test/run-f020.sh`，确认无跳过并输出调度边界结果。
