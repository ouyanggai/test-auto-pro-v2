## 2. 目标源码约束

- 目标原生页面存在同 SID 并发读取；只有平台/项目/客户上下文稳定、调用独立且已证明无业务写时，才作为有界并行候选，容量与安全性仍须验证。上下文变化会修改网关缓存，不能混用。
- submit(first) 在权限返回前可能复制代理，不按名字归为纯读。
- 原生 getData 校验与 getValues 完整数据提取不同；setData/refresh/fmDone不保证后续异步收敛。
- 普通发起可能有前置/后置业务保存及绑定；同意、不同意和暂存脚本顺序不同。
- 转发成功后无条件保存新实例当前附言，fuyan只影响原附言复制。
- 选择要求至少包括custom_choose、parallel_choose、run_node_choose、extended_attribute_users；观察不能替代用户选择或自定继续次数。
- 同实例审批事务加行锁，不存在已证明的全动作幂等；未知写不能为了测量自动重放。
- 目标有全局事件总线和存储副作用；观察不额外挂载可触发提交的组件，不调用额外setter/权限探测来“查看”状态。

精确文件与行号、HEAD见新计划的C01～C24登记。实施前还要核对实际部署的构建来源，不能将本机参考HEAD冒充运行版本。

## 4. 实施任务

### T01：版本与原生协议对照

记录参考仓库HEAD、部署构建来源和动态表单配置的可核查边界。先列出两个入口族：普通发起/同意与转发，逐项写明校验、前后置子链、输入归属、合法请求、失败分支及可确认的副作用。普通权限用户和特殊全权限用户分开，不以特权账号测试代替权限覆盖。

### T02：非侵入采集

在实际已有调用的入口/出口旁记录时间和归属，不新增目标HTTP调用、登录、getData/getValues/setData、事件或组件挂载。函数this/参数/返回值/原Promise引用和异常传播保持；采集故障不吞业务错误、不改变分支。观察截止只标记未完成，不取消业务或新增放行。

完整响应正文的读取结束与业务回调结束分别记录；不把HTTP头到达或原包装Promise完成记成全链完成。新事实不回填旧运行；如果确需数据库变更或对外接口变化，先重新规划，不在实现中擅自扩大。

### T03：行为与耗时基准

本地源码假件对照原有调用链和加观察后的链：方法/次数/载荷/因果顺序、确认和校验、实际值/虚拟值、选择、后置保存/绑定/附言、错误/悬挂不变。额外目标请求数必须为0，额外表单API调用数必须为0。

首次/重复装载、无人观察/持续观察、同/跨上下文、正常/延迟/正文中断/401/后置失败分别记录；没有真实测量的项明确未知。分析真实请求依赖图后，再选一个下一切片，不按猜测收益直接实施。
