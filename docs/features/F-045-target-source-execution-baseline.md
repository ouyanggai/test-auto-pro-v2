## 1. 这一步要解决什么

现在能从目标源码看出哪些地方容易早走、白等、漏后续保存或重复写，但还不知道当前执行器具体慢在哪、哪些工作确实重复。

这一步只做一件事：**在原来已经发生的调用旁边记步骤和时间，让下一次优化有事实可比。**

做完应能回答：

1. 普通发起/同意、转发分别实际走了哪些步骤，哪些步骤还没观察到？
2. 时间主要花在请求、已有回调、表单准备、排队还是页面资源上？
3. 哪些读取完全重复，哪些等待有必要，哪些还不能判断？
4. 记录本身花了多少时间，有没有影响原来的执行？

这一步不负责提速，也不顺手修现有执行问题。发现现有行为与目标源码不一致，单独记下来，后续按明确范围修。

## 2. 什么叫“不改变原来的行为”

加记录前后，以下内容必须保持：

| 项目 | 本切片的要求 |
|---|---|
| 发了什么请求 | 方法、端点、完整参数和调用次数不变 |
| 先做什么后做什么 | 校验、读取、主写、选择、前后保存的原有顺序不变 |
| 等多久、谁同时执行 | 现有等待、超时、并发、排队和重试不变 |
| 表单怎样取值 | 不增加 getData/getValues/setData 等调用，不触发额外联动 |
| 调用怎样返回 | this、参数、返回值、原 Promise 对象、原有错误传递不变 |
| 怎样判结果 | 记录只描述发生了什么，不改原来的成功/失败/取消判断 |
| 已经写了什么 | 不重发业务写、不补写、不向同一真实实例跑两套实现 |

记录有自己的截止时间时，只能把这一段记为“尚未观察到结束”。不能因此取消原业务、触发重试、判断成功或继续放行。采集失败也不能吞掉业务错误或触发另一个业务分支。

如果记录让业务行为变化或造成明显性能退化，这个切片没有通过；先减轻记录，不能把它当可信基准。

## 3. 只覆盖哪些地方

### 包含

- 记录本机参考源码与目标部署、前端组件、实际 FormMaking 构建的对应关系；无法对应就写“未确认”。
- 先核对两组动作：**普通 FormMaking 发起/同意**，以及**转发的完整步骤**。
- 只在本项目当前已有调用点记录能直接得到的信息：账号和 SID、平台/项目/客户、实例/任务/批次/节点归属，发送时间、完整响应或错误，已有校验/取值/回调/后续保存的可见开始和结束。
- 按目标源码建立本地模拟调用和方法实验，比较加记录前后的调用和业务结果。
- 对比不开记录与开记录时的耗时、内存分配和慢端开销。
- 提供用户在页面上手工采集真实记录和核对结果的入口、步骤及未验证清单。

通用记录可能顺带看到其他动作，但不能因此宣称其他动作已经核对、优化或验收。

### 不包含

- 删除或合并请求、换端点、缓存结果、缩短等待/超时、改变并发/排队/重试。
- 改人员选择、表单校验、主写判断、后续保存、结果展示或错误处理。
- 修改目标源码、表单业务配置、数据库或对外接口；增加兼容层、资源池或新架构。
- 全局拦截 Promise、定时器或事件；额外挂载组件、登录、读状态、调用表单方法来补齐计时。
- 未获明确授权时自动启动浏览器或向真实目标发业务写；上线部署、自动实施后续 P1～P4。用户后来明确授权代为启动和完全验收，本次受控操作及结果见第 13 节；该授权没有把后续优化纳入本切片。
- 恢复已撤回草案，或使用旧文档里的白名单、默认等待和业务规则。

**完成条件：** 每个业务判断能回到目标源码；没有把未确认内容写成安全依据。

### T02：只在原有调用旁记信息

**要做：** 实施时查看本项目当前代码，找到现有调用入口和出口；只记录那里能直接看见的归属、参数、时间、完整响应/错误和已有回调。保持第 2 节列出的行为。

**完成条件：** 新增目标请求、表单 API 调用和业务事件都为零，没有新增等待或替换原 Promise。

**看不到怎么办：** 内部脚本或回调无法在现有调用点证明结束，就记“未知”。不改目标组件，不做全局异步拦截，不为了记录完整而扩大到 P2 的完成条件改造。若确需数据库或对外接口变化，停下写清新增范围，不能擅自实施。

## 5. 源码里的这些细节不能写错

以下是防止后面实施跑偏的核对表。精确文件、行号和 HEAD 在完整计划附录 C01～C24。

| 目标源码事实 | 对本次记录的要求 |
|---|---|
| setData、refresh、fmDone 不等所有异步联动 | 返回和真正联动结束分开；看不到结束就记未知 |
| getData 有校验，getValues 取完整数据，两者不同 | 不多调一次，也不替换为另一个方法 |
| submit(first) 可能先复制代理，再返回权限 | 记清它可能已经改数据，不能标成无保存的普通查询 |
| 发起可能有前置保存和后置绑定 | 主请求成功与整条业务完成分开 |
| 转发后无条件保存新实例当前附言 | fuyan 只决定原附言复制；空附言也不能漏记第二笔保存 |
| 同意、不同意、暂存的脚本和校验不同 | 不拿一种动作的步骤表套全部动作；暂存不是推进流程 |
| 至少四类选择，含 extended_attribute_users | 不擅自缩为三类、不代选、不自定统一继续次数 |
| 同实例审批加行锁，源码未证明全动作重发安全 | 不为测试重放真实写，超时和响应丢失不能补发 |
| SID 关联平台/项目/客户；页面有全局事件和存储 | 记录完整归属，不混用上下文，不多挂可提交组件 |
| 部分错误或 401 会一直不结束，回调可能晚于响应 | 如实记录未结束，不假造完成时间或吞错后宣称成功 |
