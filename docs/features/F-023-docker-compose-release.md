## 目标

提供一条可重复的 Docker Compose 发布路径，一次启动 MySQL、Go 后端、Vue 前端、`form-runtime` 和 code-server 日志查看器；服务有健康检查、持久化卷、启动顺序和清晰的配置边界，开发/发布环境都不把凭证写入镜像或仓库。

## 单一用户结果

用户准备被 Git 忽略的环境文件后执行一条 Compose 命令，浏览器可访问主前端，后端完成数据库迁移，`form-runtime` 可被 iframe 加载，code-server 能浏览同一份 `logs/`；任一服务失败都有明确健康状态和日志，不会显示虚假启动成功。停止并重新启动后，工具数据库和日志卷仍保持可用，目标平台数据不受影响。

## 服务与边界

| 服务 | 作用 | 对外端口 | 持久化 |
| --- | --- | --- | --- |
| `mysql` | 工具侧 MySQL 与迁移 | 仅 Compose 网络 | 数据库卷 |
| `backend` | Go API、Worker、迁移执行 | `19080` | `logs/` 挂载 |
| `frontend` | Vue 3 生产静态资源与 `/api` 反代 | `19000` | 无 |
| `form-runtime` | 复制目标表单运行时 | `19001` | current/previous 运行时卷 |
| `code-server` | 日志目录查看与编辑 | `19002` | 与宿主 `logs/` 双向挂载 |

目标平台地址、登录凭证、工具库账号和加密密钥只从 Compose 外部环境或被忽略的 env 文件注入；不构建进镜像、不返回前端、不写入 Git。

## 范围

### 包含

- 后端多阶段构建、前端生产构建、`form-runtime` 构建/运行镜像和固定版本 code-server 镜像。
- `compose.yaml`（必要时配套发布覆盖文件）中的网络、健康检查、依赖条件、重启策略、资源边界和卷挂载。
- MySQL 首次启动、数据库连接等待、版本化向前迁移和重复启动幂等；迁移失败时后端不报告健康。
- 前端到后端 `/api` 反代、form-runtime iframe 地址、code-server 19002 日志目录直达和日志双向挂载自检。
- `.env.example`、发布说明、备份/恢复边界和最小运维命令；敏感值只给变量名和示例占位，不写真实值。
- Compose 集成测试：冷启动、健康、迁移、重启持久化、日志可见性、服务停止和端口释放。

### 不包含

- Kubernetes、云厂商托管数据库、自动扩缩容、周期备份或归档体系。
- 修改业务 API、执行器、调度器、目标平台适配和日志字段；这些属于前置切片。
- 把目标平台数据库、Mongo、Redis 或参考仓库挂进 Compose；工具库与目标平台严格隔离。
- 在镜像中保存 `.env.local`、SID、密码、AES key、运行日志或构建缓存。

## 部署约束

- 生产镜像以固定基础版本构建并锁定依赖；构建上下文排除 `.git`、`参考代码`、`logs/`、`.runtime`、凭证和测试产物。
- MySQL 只暴露给 Compose 内网；后端健康检查必须包含迁移完成和 API health，前端/运行时/code-server 依赖其健康状态。
- `logs/` 宿主目录可读写挂载到 code-server，同时后端按计划/路径/运行目录写入；Compose 启动前做挂载可见性自检，失败即退出而不伪造成功。
- code-server 使用已验证固定版本 `codercom/code-server:4.96.4`，无登录，仅在内网暴露 19002；正式环境是否开放由部署者网络控制，不在应用中加入认证旁路。
- 容器停止不删除数据库或日志卷；清理命令只能作用于明确的 Compose 项目资源，不使用宽泛 prune 或递归删除。
- 健康检查失败时重启策略有界，迁移或配置错误不能无限重启刷屏；程序错误写入 `application` 或对应运行目录。

## 详细执行任务

每个任务完成后独立验证并使用中文提交说明；实施前必须确认前置切片已验收。

### T01：镜像与构建上下文

为 Go、Vue、`form-runtime` 编写多阶段 Dockerfile 或等价构建定义，锁定 Node/Go/基础镜像版本，验证生产构建输出不含凭证、参考源码、日志和缓存。前端静态资源通过同一入口提供 `/api` 代理和运行时地址配置。

### T02：Compose 服务编排

创建 Compose 文件，定义五个服务、网络、健康检查、依赖条件、重启策略、资源上限和端口映射。后端启动前等待 MySQL 健康并执行迁移；前端和 form-runtime 只有在自身资源可服务后才报告健康。

### T03：配置与秘密注入

整理 `.env.example` 和发布文档，区分 `TARGET_*`、`PLAN_DB_*`、日志保留期、端口和运行时地址。启动时检查必需变量和格式，错误给中文说明并停止相关服务；镜像层、Compose 日志和 health 响应不得回显敏感值。

### T04：卷、日志与 code-server

挂载工具数据库卷、宿主 `logs/` 和 form-runtime current/previous 卷；实现 code-server 目录直达、UID/GID、挂载双向探针与停止清理命令。验证后端写入的运行日志立即能在 code-server 读到，容器内写入也能回宿主。

### T05：冷启动、重启与故障恢复

编排启动顺序和有界重试；覆盖空数据库迁移、已有数据库重启、MySQL 暂不可用、后端迁移失败、form-runtime 健康失败和日志挂载失败。任何恢复只针对 Compose 服务和工具卷，不触碰目标平台数据。

### T06：发布验证与交接

新增 `test/integration/f023_compose_test.sh`、`test/contracts/f023/` 和 `test/run-f023.sh`，实际启动/停止 Compose 并验证端口、health、迁移、前端、runtime、code-server 和日志可见性。同步 README、路线图、进度和本文件，列出用户手工验收步骤。
