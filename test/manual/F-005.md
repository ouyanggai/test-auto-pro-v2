# F-005 人工验收清单

## 启动

在两个终端分别运行：

```bash
pnpm dev:b
```

```bash
pnpm dev:f
```

打开测试计划列表，选择待配置计划的“继续配置”。本轮不需要额外填写环境变量，不会自动启动浏览器。

## 新发起计划

1. 打开一个直线流程计划，确认普通画布没有右侧面板或可点击分支，右上角依次为“已保存的路径”“新增路径”和页面全屏图标。点击“新增路径”后自动进入页面全屏并出现右侧面板；直线流程无需选择分支即可保存，保存后默认名称使用实际分配的“路径 N”，稳定序号单独可见。
2. 打开包含条件、手动和并行的流程；确认单独点击页面全屏图标仍只能浏览。点击“新增路径”后，条件/手动分支标签至少 32px 高，可用鼠标、Tab 与 Enter/Space 改选，同一路由只高亮一支。
3. 确认并行各支显示“并行必经”且不能取消；面板进度为“已选 N / 待选 M / 共 T”，只统计当前可达的条件和手动路由，并行不计，且已选加待选等于总数。并行同时有多个待选路由时，摘要只突出一个“下一待选点”，其他显示“后续待选”；未完成时“保存路径”不可用。
4. 保存两条不同线路并复制一条；确认相同线路允许作为独立路径保存，序号依次增加。
5. 删除当前最高序号路径后再新增；确认新序号继续增加，不复用、不重排其他路径。
6. 从“已保存的路径”浮层点击一个条目，确认进入“路径详情”只读态：线路高亮和实时流向保留，但没有名称输入、保存、候选按钮或保存气泡。详情底部显示“编辑路径”和“更多”，复制与删除只在“更多”菜单；点击编辑后才允许改名改线，保存后原序号不变，刷新和后端重启后选择仍恢复。
7. 在普通画布打开“已保存的路径”，确认新发起计划的“一键生成全部路径”位于浮层顶部。弹窗先显示总组合、已存在和待新增数量，生成期间按钮忙碌且不能重复提交，完成后列表与数量刷新。全部合法组合都有独立稳定序号与默认名称，再次点击时明确提示全部已存在且不会重复创建；超过 128 条明确拒绝且不产生部分路径。
8. 编辑路径时将名称输入到 50 个字符并保存，回到普通画布后点击“已保存的路径”；确认入口和浮层标题都不拼接数量，浮层约 280px 宽、随条目数量自适应且最高约 320px，稳定序号始终可见，名称省略且悬停可通过 `title` 查看全文，固定行高列表可独立虚拟滚动。

## 已发与待发计划

1. 已发计划只从当前活动节点继续；`run` 和有可映射入口的 `await_sent` 可配置，已结束、终止、丢弃、驳回、撤回实例提示当前不能配置。
2. 待发计划从该实例全部 `waiting_send` 节点继续，并行活动入口不能被拆成多条路径。
3. 已发或待发保存一条后不再显示新增或复制入口；删除后允许重新选择一条。

## 画布与失败边界

1. 确认普通画布右上角只有“已保存的路径”“新增路径”和页面全屏图标，没有右侧面板。编辑、新建或复制后右侧出现约 320px 面板，只包含标题、决策进度、路径名称、独立滚动实时流向和固定底部“取消/保存路径”，没有“路径操作”或“操作提示”，主图没有横跨画布的旧工具条。
2. 查看已保存路径时，确认只有已选线路和并行必经线路使用明显主色、粗线与方向流动，分支名称只读且不可误触。进入编辑后，同路由其他候选才可点击和键盘改选；尚未到达标签静止弱化、显示“尚未到达”且不可点击。开启系统“减少动态效果”后线路和浮层均无滑入动画，状态仍可辨认。
3. 在含三个候选的待选路由上，确认画布保持当前缩放并按全部候选标签的整体中心定位；气泡显示“请在以下 3 个分支中选择 1 个（还剩 M 处）”，三条 SVG 引导线分别准确指向三个候选。拖动、缩放画布后引导实时跟随，系统减少动态效果时箭头、高亮和文案仍静态可见。
4. 使用宽度超过安全视口的候选组，确认画布不为塞入一屏而缩小，左右屏外分别显示“还有 N 个候选”的方向提示。等待选择时气泡不自动消失；手动关闭后本次保持关闭，完成选择并进入下一待选点时重新出现。
5. 点击“已保存的路径”，确认普通画布上展开约 280px、最高约 320px 的小型半透明主题浮层。浮层使用主题边框和轻量模糊，深浅主题文字清楚；固定行高虚拟列表的每项只显示稳定序号和名称，长名称省略且 `title` 可查看全文。点击条目后浮层自动关闭并打开只读详情。
6. 在编辑面板点击“收起”，确认面板宽度仍约 320px，只从纵向向上折叠，并保留标题、已选、待选、共三项摘要和展开按钮，不留下侧边窄条。
7. 新建空草稿或编辑已保存路径但未作改动时，点击“取消”或退出页面全屏应直接回普通画布。输入名称或改变线路后再取消或退出，确认先出现放弃修改提示；选择继续编辑后草稿不变，确认放弃后名称、选择和编辑状态全部清空，普通页不出现“继续选择”入口。
8. 分别在新建、复制和编辑路径后保存，确认只出现一次成功反馈，列表与路径数量立即刷新，并关闭路径浮层、右侧面板和页面全屏回到普通画布；“线路已完整，请保存”气泡同步消失。保存失败时编辑态、名称、线路选择和创建重试键保持不变。
9. 保存前让实例推进或流程结构变化；确认返回“流程已变化，需要重新选择”，最新图中仍能对应的选择保留，失效选择被移除并继续定位下一处，不按名称猜测。
10. 在最新图刷新阶段暂停后端或模拟目标读取失败；确认原草稿、模式和活动路径仍在，面板显示稳定错误和“重新读取”，不能用旧图直接误保存。
11. 让首次创建实际成功但客户端尚未收到响应，再使用同一请求键重试并临时使目标读取失败；确认仍返回同一路径与序号，不新增记录，也不显示目标读取错误。两个同键请求并发到达时也只能产生一条路径。
12. 让批量生成实际成功但客户端丢失响应，再使用同一请求键重试并临时使目标读取失败；确认返回同一批次结果，不重复创建，也不重新依赖目标图。
13. 确认页面和日志不出现 SID、密码、AES key、目标原始响应、`create_key` 或内部 `next_path_sequence_no`。
14. 分别切换浅色和深色主题，确认右下角放大、缩小和全图三个按钮的背景、边框、图标、悬停及禁用状态都清楚可见。

## 保存超时复现记录

用户反馈曾在保存一条包含 3 个分支选择的路径时，对同一幂等键多次看到请求超时，之后成功一次。当前核查确认 Vite 与 Go 健康检查正常，真实图当前读取约 `0.55s`，数据库中该键只有一条路径，同键重试约 `0.011s` 并返回原记录。现有后台日志没有请求分阶段耗时，MySQL 通用日志和慢查询日志也未开启，因此不能据此断定历史卡点位于前端代理、目标读取或数据库事务；本轮未通过增加超时或静默重试掩盖问题。

若人工复验再次出现超时：

1. 不要更换幂等键，保留浏览器 Network 中该请求的发生时间、HTTP 状态、总耗时和响应错误码。
2. 使用原页面的重试操作再次提交，确认最终只出现一条路径，路径 ID 与序号没有新增副本。
3. 同时保留该时间段后端日志；若能稳定复现，再用这些时间点补充分阶段诊断，不根据单次超时猜测修改目标重验或事务边界。

## 范围边界

- 本轮计划状态仍为“待配置”，不提供表单值、人员、节点动作、运行、调度或报告。
- 除用户明确触发且不超过 128 条的完整路径组合外，不保存派生节点集合、流程图快照、版本或指纹，不调用目标写接口。
