# F-005 人工验收清单

## 启动

在两个终端分别运行：

```bash
pnpm dev:b
```

```bash
pnpm dev:f
```

打开测试计划列表，选择待配置计划的“继续配置”。本轮不需要额外填写环境变量，不会自动启动浏览器。

## 新发起计划

1. 打开一个直线流程计划，确认普通页面没有可点击分支；点击“线路选择”后自动进入页面全屏并出现右侧面板。未保存草稿显示“待分配序号”且不预占编号，无需选择分支即可保存；保存后默认名称使用事务实际分配的“路径 N”。自定义名称后保存并刷新，名称保持且稳定序号仍单独可见。
2. 打开包含条件、手动和并行的流程；确认单独点击“页面全屏”仍只能浏览。点击“线路选择”后，条件/手动分支标签至少 32px 高，可用鼠标、Tab 与 Enter/Space 改选，同一路由只高亮一支。
3. 确认并行各支显示“并行必经”且不能取消；嵌套路由剩余待选数准确。并行同时有多个待选路由时，面板只突出一个“下一待选点”，其他显示“后续待选”；未完成时“保存路径”不可用。
4. 保存两条不同线路并复制一条；确认相同线路允许作为独立路径保存，序号依次增加。
5. 删除当前最高序号路径后再新增；确认新序号继续增加，不复用、不重排其他路径。
6. 编辑已保存路径并改选同一路由另一支；保存后原路径序号不变，刷新和后端重启后选择仍恢复。
7. 先建立一个未保存草稿并输入自定义名称，再点击“一键生成全部路径”；确认弹窗先显示总组合、已存在和待新增数量，生成期间按钮显示忙碌且不能重复提交，完成后列表与数量刷新但当前草稿和名称原样保留。全部合法组合都有独立稳定序号与默认名称，再次点击时明确提示全部已存在且不会重复创建。超过 128 条的流程明确拒绝且不产生部分路径。
8. 将路径名称输入到 50 个字符，点击“已保存路径 N”展开左侧路径浮层；确认浮层不撑开 320px 操作面板，稳定序号始终可见，名称省略且悬停可通过 `title` 查看全文，列表可独立纵向滚动。

## 已发与待发计划

1. 已发计划只从当前活动节点继续；`run` 和有可映射入口的 `await_sent` 可配置，已结束、终止、丢弃、驳回、撤回实例提示当前不能配置。
2. 待发计划从该实例全部 `waiting_send` 节点继续，并行活动入口不能被拆成多条路径。
3. 已发或待发保存一条后不再显示新增或复制入口；删除后允许重新选择一条。

## 画布与失败边界

1. 确认画布右上角“线路选择”紧邻“页面全屏”；普通页面和单纯页面全屏没有分支按钮。进入线路选择后右侧出现约 320px 面板，可收起，实时流向区域独立滚动，主图没有横跨画布的旧工具条。
2. 选择一条分支后，确认已选线路和并行必经线路使用明显主色、粗线与方向流动；实时流向摘要也同步显示方向动画。已选分支自身不可重复点击，同路由其他候选可点击和键盘改选。尚未到达子树的条件、手动与并行标签静止弱化、显示“尚未到达”且不可点击。开启系统“减少动态效果”后全部停止动画，状态仍可辨认。
3. 在含三个候选的待选路由上，确认画布保持当前缩放并按全部候选标签的整体中心定位；气泡显示“请在以下 3 个分支中选择 1 个（还剩 M 处）”，三条 SVG 引导线分别准确指向三个候选。拖动、缩放画布后引导实时跟随，系统减少动态效果时箭头、高亮和文案仍静态可见。
4. 使用宽度超过安全视口的候选组，确认画布不为塞入一屏而缩小，左右屏外分别显示“还有 N 个候选”的方向提示。等待选择时气泡不自动消失；手动关闭后本次保持关闭，完成选择并进入下一待选点时重新出现。
5. 点击“已保存路径 N”，确认在右侧操作面板左边展开约 300px 的独立浮层，操作面板本身不再平铺路径按钮。浮层打开时分支引导隐藏，关闭后恢复；点当前路径只关闭浮层，点其他路径成功切换后自动关闭。
6. 修改当前路径名称或线路但不保存，再尝试切换其他路径；确认先出现草稿确认，取消后活动路径、名称和线路均不变。新增、复制、删除成功、退出选择、收起操作面板或退出页面全屏时，路径浮层都应关闭。
7. 在页面全屏且路径浮层打开时按 `Esc`，确认第一次只关闭浮层；再按一次才退出页面全屏。点击“退出选择”后保持页面全屏浏览，再点“继续选择”确认草稿仍在；退出页面全屏后再次进入，同样保留活动路径、未保存选择和当前观察位置。
8. 保存前让实例推进或流程结构变化；确认返回“流程已变化，需要重新选择”，最新图中仍能对应的选择保留，失效选择被移除并继续定位下一处，不按名称猜测。
9. 在最新图刷新阶段暂停后端或模拟目标读取失败；确认原草稿、模式和活动路径仍在，面板显示稳定错误和“重新读取”，不能用旧图直接误保存。
10. 让首次创建实际成功但客户端尚未收到响应，再使用同一请求键重试并临时使目标读取失败；确认仍返回同一路径与序号，不新增记录，也不显示目标读取错误。两个同键请求并发到达时也只能产生一条路径。
11. 让批量生成实际成功但客户端丢失响应，再使用同一请求键重试并临时使目标读取失败；确认返回同一批次结果，不重复创建，也不重新依赖目标图。
12. 确认页面和日志不出现 SID、密码、AES key、目标原始响应、`create_key` 或内部 `next_path_sequence_no`。
13. 分别切换浅色和深色主题，确认右下角放大、缩小和全图三个按钮的背景、边框、图标、悬停及禁用状态都清楚可见。

## 保存超时复现记录

用户反馈曾在保存一条包含 3 个分支选择的路径时，对同一幂等键多次看到请求超时，之后成功一次。当前核查确认 Vite 与 Go 健康检查正常，真实图当前读取约 `0.55s`，数据库中该键只有一条路径，同键重试约 `0.011s` 并返回原记录。现有后台日志没有请求分阶段耗时，MySQL 通用日志和慢查询日志也未开启，因此不能据此断定历史卡点位于前端代理、目标读取或数据库事务；本轮未通过增加超时或静默重试掩盖问题。

若人工复验再次出现超时：

1. 不要更换幂等键，保留浏览器 Network 中该请求的发生时间、HTTP 状态、总耗时和响应错误码。
2. 使用原页面的重试操作再次提交，确认最终只出现一条路径，路径 ID 与序号没有新增副本。
3. 同时保留该时间段后端日志；若能稳定复现，再用这些时间点补充分阶段诊断，不根据单次超时猜测修改目标重验或事务边界。

## 范围边界

- 本轮计划状态仍为“待配置”，不提供表单值、人员、节点动作、运行、调度或报告。
- 除用户明确触发且不超过 128 条的完整路径组合外，不保存派生节点集合、流程图快照、版本或指纹，不调用目标写接口。
