- 自动测试会验证迁移、协议、同步状态机和构建；本清单只核对真实浏览器交互、目标模板呈现和现场只读请求。

## 路径与节点画布

1. 从 `/plans` 打开没有已保存路径的待配置计划；普通详情页只能先“配置路径”，不能出现无效“配置节点”。使用既有 F-005 新增并保存路径，确认路径选择、命名、编辑、复制、删除和页面全屏没有变化。
2. 回到计划详情，每条已保存路径应显示稳定序号、名称、配置状态和“配置节点”。点击后进入 `/plans/{planId}/paths/{pathId}/configure`，主体是当前路径的 Vue Flow 画布，不是整页字段表单。
3. 依次用鼠标点击、Tab 聚焦后按 Enter/Space 切换当前路径上的可配置业务节点。节点应有清晰 pointer、hover、focus 和选中反馈，右侧名称、要求、人员和动作立即跟随切换；路径外、不可配置或无需配置节点不显示点击光标且不能切换侧栏，节点仍不可拖动或连线，画布平移缩放正常。
4. 右侧只出现人员、动作、节点规则和当前节点保存，不出现表单字段、控件类型、“暂不支持”组件缺口或表单状态。即使当前模板包含自定义表单组件，人员动作完整的节点也能独立保存；若服务端返回下一待配置节点，页面应自动选中并在不改变缩放的前提下定位该节点，侧栏立即显示其草稿，不出现跨路径“配置下一条”。模拟正常成功和响应不确定后 GET 对账，两种结果应一致。
5. 完成当前路径最后一个待配置节点：若表单尚未完成，侧栏明确提供“配置表单数据”；若表单也已完成，只显示当前路径完成结果和“返回计划详情”，不得自动跳到另一条路径。保存失败继续保留当前节点、草稿和重试能力。
6. 依次检查发起、审批/协同、条件、手动分支、并行/汇聚/空/结束。点击节点标题旁信息按钮，模板要求只在弹层显示；主面板只突出处理人员和动作计划。固定人员和 `personnel` 范围应显示真实 `dataList` 中的具体中文名称；岗位、岗级、角色、部门、公司和扩展属性也应显示目标返回名称。部门/公司运行节点候选必须限制在对应组织子树，不能扩大到全公司。超过三项时侧栏只显示摘要和“查看全部 N 项”，弹窗内列表可独立滚动。只有确实依赖未来发起人、表单值、任务或届时组织关系的规则才显示具体运行时原因，不能显示业务 ID、模糊名称或用运行时说明掩盖读取失败。
7. 对目标允许选择的节点依次切换目标默认、手动、确定性随机和全选策略。相同 seed 的随机结果应稳定，最终使用区显示具体名称；seed 输入范围为 `1..9007199254740991`，零值、负数或超限值不得造成页面名单和保存名单不同。候选始终受模板范围限制。核对可跳过时零人合法，主动选择后仍满足最低人数，且最高人数、会签/竞签约束不能绕过。
8. 检查发起节点只有提交；审批/协同节点按当前静态约束显示同意、不同意、暂存、回退上一级、加签和移交。取回、撤销、废弃、催办、跟踪、删除和转发不能出现在动作目录。回退目标只包含当前路径更早且可达的业务节点，并行兄弟支线不能互相回退；加签和移交使用同一套受限人员策略。
9. 在一次到达中添加加签前置步骤，或选择移交作为本次到达的最后一步；移交后不能再追加同意等动作。填写可选意见并调整顺序，复制为第 2 次到达后修改动作，确认到达序号连续、最多 10 次，页面不会允许整条路径超过 100 个步骤。保存并刷新后，人员策略、seed、最终名单、动作顺序、参数和到达次数应原样恢复；旧同意/不同意可映射时成为首次到达，不能映射时显示配置失效。

## 真实表单工作区与智能生成

10. 将浏览器内容区设为 1366×768，点击顶部或最后节点完成态中的“配置表单数据”。节点画布和节点侧栏应由宽屏 FormMaking 工作区替换：应用 64px 顶栏和左侧菜单保留，重复的“路径配置”页头及“节点配置/表单数据”导航收起；stage 无卡片边框/圆角，表单占满菜单右侧宽度。54px 工具栏下 iframe 有效高度应约 650px，窗口增高时同步增长；滚动表单时只有 iframe 文档滚动，外层不出现第二条纵向滚动条，也不使用 zoom/scale 缩小。
11. 核对目标模板的 grid/report/table/subform 等布局、中文标题、默认值、选项、隐藏/禁用权限和必填校验；页面必须使用真实 `fm-generate-form`，不能把字段改成 Naive UI 输入框。对真实 `type=custom, el=custome-info-select` 的三个“通用信息选择”，应正常渲染且顶部不显示“存在未适配组件”；新发起按发起节点 `edit` 权限可输入，未授权字段只读或隐藏，已发/待发全部只读。未知未注册 `el` 才在表单工作区显示 `unsupported`；`beforeSubmit`、`beforeSubmitAndDraft`、`eventScript` 等业务提交钩子被安全隔离但不阻塞。
12. 对新发起点击“智能生成”。结果应综合模板默认值/选项、当前账号、当前路径条件和有限近期样本，显示自动填充与仍需手工数量；同一 seed 可复现。样本不足时有明确来源摘要并使用确定性兜底，复杂未知组件不编造值。
13. 手工修改一个生成字段和一个“通用信息选择”后点击“换一组”，人工值必须保留，复杂组件不得被生成器覆盖或清空，其他生成器拥有字段才变化；“恢复已保存”回到当前路径最近一次保存。页面只能出现一处紧凑错误/阻塞提示，提示位于正常文档流且不覆盖表单控件。保存前必须触发真实 FormMaking 必填校验，保存的是 `getValues()` 完整对象，包括自定义组件 JSON、`__condition`、`__formPersonId` 等虚拟/系统辅助字段。
14. 保存成功后刷新并重新打开，完整值、seed、生成字段和人工覆盖字段保持；表单完成但节点未全完成时路径仍是部分完成。另一条路径的数据、状态和会话不得串入当前路径。
15. 新发起点击“保存表单数据”后确认页面成功提示与刷新状态一致；Network 中只能出现 V2 路径配置保存/读取，不得出现目标流程提交、草稿或业务保存请求。已发/待发表单默认显示所选真实实例当前值且全部只读；若模板包含上传、文件关联或业务保存按钮，点击后应显示受限/不支持反馈且 Network 中没有目标写请求；`find/list/get/query` 等已证明查询仍可正常加载并带当前会话 SID。
16. 切换计划、路径、账号或关闭表单工作区后再打开，确认旧会话响应不污染新页面；SID 不出现在 URL、浏览器长期存储、配置响应或维护日志中。深浅主题和较大模板的 iframe 高度/滚动保持可用。

## 表单运行时维护

17. 从“系统设置 → 表单运行时维护”进入维护页。固定来源必须显示 `rsh-flow-components`、`master`、本次可创建任务的当前 HEAD、dirty 和检查时间；页面只有“一键同步并更新运行时”，没有路径、分支、HEAD 或命令输入。
18. 来源干净时创建任务，观察阶段依次为 `INSPECT / SYNC / SYNC_CHECK / BUILD / RESTART / VERIFY / COMPLETED`，在线日志可刷新且过长时提示截断。重复点击或另开页面不能创建第二个活动任务。
19. 先完成 `make refs-sync` 后，新的干净 `master` HEAD 应能创建新任务；任务创建后再改变来源 HEAD 或弄脏来源，Worker 必须拒绝。候选代表性源码变化应进入真实表单服务；候选构建失败时 current 继续可用，19001 或生产 `/form-runtime/` 未报告新 HEAD/摘要时显示 previous 回退结果，恢复后再次打开表单工作区仍可使用。
