# F-002 真实账号与三类只读列表人工验收

## 现场准备

在后端启动终端中提供以下运行时环境变量；真实值不得写入仓库、截图、聊天记录或终端共享日志：

- 必需：`TARGET_API_GATEWAY`、`TARGET_LOGIN_PASSWORD`、`TARGET_LOGIN_AES_KEY`、`TARGET_LOGIN_CODE`。
- 可选覆盖：`TARGET_PLATFORM_CODE`、`TARGET_TEMPLATE_PLATFORM_CODES`、`TARGET_CUSTOMER_CODE`、`TARGET_SESSION_TTL`、`TARGET_HTTP_TIMEOUT`。

准备至少一个可登录且能看到简单流程模板的账号。最好同一账号各有一条已发、待发实例；如果没有，可分别提供账号和预期流程名称，任何账号与流程值都不要写入本文件。

## 启动

1. 在已注入目标环境变量的终端运行根 `package.json` 当前后端前台脚本 `pnpm dev:b`。
2. 在第二个终端运行前端前台脚本 `pnpm dev:f`。
3. 确认 health 正常，再由用户手工打开 `http://127.0.0.1:19000/plans/new`。
4. 验收结束后分别按 `Ctrl+C` 停止两个前台进程。

## 账号与安全

1. 空账号点击“验证账号”，确认只出现字段就地错误且不发目标请求。
2. 输入错误账号，确认不会进入已验证状态，并显示稳定中文失败提示。
3. 输入现场账号，确认显示名和公司名与目标平台一致，不声称保存密码或会话。
4. 检查浏览器网络响应、页面状态、localStorage 和 sessionStorage，确认没有 SID、密码、AES key、customerCode、platformCode 或登录 code。
5. 编辑已验证账号，确认验证立即失效、请求被取消、来源回到“新发起”、旧候选和选择被清空。

## 三类真实候选

1. “新发起”显示当前账号真实可见模板；核对名称、类型、分组、状态和更新时间。
2. “已发”显示当前账号真实已发实例；核对标题、状态、提交时间、当前节点和当前处理人。
3. “待发”显示当前账号真实待发实例；核对标题、草稿/驳回/撤销状态、发起人和提交时间。
4. 三类来源分别测试搜索、清空、空结果、固定高度滚动、滚动追加、选中态和到底提示。
5. 快速连续修改搜索、切换来源和切换账号，确认旧结果不会闪回、混入或覆盖当前选择。
6. 在追加页失败时确认已有条目保留，可点击“重试本页”；网络失败不得出现本地 mock 数据。

## 页面边界

1. 核对候选区加载、空、错误和列表状态都保持相同高度，页面不突然跳动。
2. 核对吸顶返回入口、分隔线、浅色/深色主题、侧栏收缩和主内容独立滚动没有回退。
3. 选择真实候选并补齐表单后点击“创建并选择路径”，确认仍只显示静态边界提示，不保存计划、不跳转路径页、不修改目标平台。

## 验收结论

- [ ] 账号身份与目标平台一致。
- [ ] 新发起、已发、待发三类真实数据与目标平台一致。
- [ ] 浏览器侧没有会话或凭证泄露。
- [ ] 搜索、分页、切换、错误恢复和页面视觉通过。
- [ ] 用户明确回复验收通过后，才可将 F-002 标为 `accepted`。
