# F-006 路径要求核对人工验收

## 准备

1. 使用现有本机配置启动前后端，打开一个至少保存一条执行路径的测试计划。
2. 准备三类计划样本：新发起、已发、待发。优先选择包含普通条件、最后兜底、手动分支、并行、审批/协同和不同人员规则的真实流程。
3. 本轮页面只读；不要期待表单值、人员或动作保存入口，也不要执行目标平台写操作。

## 入口与页面

1. 在路径选择页标题区确认有“核对路径要求”，且它不在画布右上角工具栏内；F-005 普通/页面全屏路径操作保持原样。
2. 点击后进入 `/plans/{计划ID}/requirements`，确认左上角可返回路径选择，左侧按稳定序号显示已保存路径，右侧显示当前路径要求。
3. 直接访问没有已保存路径的计划核对页，确认出现“尚未保存执行路径”的明确引导，没有空白页、保存或运行按钮。
4. 快速切换两条路径，确认右侧最终只显示当前选中路径，旧请求不会迟到覆盖；目标错误时可重试，路径失效时引导返回重新选择。

## 条件与分支

1. 新发起路径选择普通条件分支，核对字段名称、比较方式、固定值以及“并且/或者”为中文业务表达；页面不得出现字段英文名、判断代码或目标节点/分支 ID。
2. 选择字段对字段的条件，确认显示两个中文字段名；同一英文键跨多个表单时，节点字段权限能唯一定位的显示“表单名 / 字段名”，不能唯一定位的显示“未识别的表单字段”并标为“需要人工核对”。两种结果均不得出现英文键、表单 ID 或字段 ID。
3. 准备节点字段权限明确指向表单 A、但字段元数据中同键唯一候选只属于表单 B 的样本，确认不得误显示表单 B 的字段名，而是显示“未识别的表单字段”并标为“需要人工核对”。
4. 核对 `contains` 条件：固定值和人员范围均应显示为“右值/目标配置的人员范围 包含 左字段值”，不能反向显示“左字段包含右值”，人员范围不得出现人员 ID；其他比较符方向保持不变。
5. 选择同一路由最后一个分支，确认显示“其他条件均不满足时进入”，且提示后续数据需保证前序条件不成立。
6. 手动分支确认显示“运行时选择该分支”并归为“待配置”；并行路由显示“全部分支并行必经”且归为“目标平台自动确定”。
7. 已发或待发同时存在多个并行活动入口时，确认每个入口分别显示为并行活动分组；共同汇合后的节点只在主线出现一次。使用没有共同后继的多入口样本时，确认仍保持独立分组且不出现伪造主线。

## 人员、动作与约束

1. 分别核对指定人员、项目指定人员、角色、公司、部门、岗位等规则：有名称显示名称，没有名称只显示类型和数量；不得显示业务 ID。
2. 核对发起人、部门主管、分管副总、岗级、扩展属性，确认归为“运行时确定”；审批人自选和表单人员归为“待配置”。
3. 核对会签/竞签、会签人数或“所有人”、范围摘要和“无处理人是否跳过”。缺范围、未知类型或矛盾人数应只让对应项进入“需要人工核对”，其他节点仍可查看。
4. 发起节点确认要求“提交”；审批和协同确认要求同意/不同意处理结果；空节点和结束节点显示无需额外配置。
5. 回退上一级、添加审批人和转发只作为“运行态特殊操作”限制说明，不得列成当前稳定动作候选。
6. 有延时的节点核对数字、单位和自然日/工作日；目标未配置时不应出现工具补造的默认时限。

## 页面稳定性

1. 核对顶部四类状态计数与各要求标签一致，但不要把“目标平台自动确定”误解为整条计划已可运行；计划状态仍为“待配置”。
2. 使用长路径和多并行分组检查桌面布局：页面主体保持在当前可用视口内，左侧路径列表和右侧要求内容可以分别滚动，互不带动；窄屏恢复自然纵向浏览。继续核对长文本换行、深浅主题与减少动态效果。
3. 使用分组标题重复、节点名称和类型重复的真实或测试数据，确认所有分组和节点均完整显示，没有被错误复用、遗漏或产生控制台 key 冲突提示。
4. 返回路径选择页，确认原路径名称、选择、页面全屏和编辑能力未被核对页修改；页面没有第二张流程图、名称输入、保存、运行或伪下一步控件。

## 通过标准

- 三类来源都按当前真实配置展示，路径切换稳定，中文语义与目标配置一致。
- 页面不泄露内部 ID、字段英文名、目标枚举、SID 或原始表单 JSON。
- 未识别或歧义元数据明确降级为“需要人工核对”，不猜测且不阻断其他要求。
- F-005 路径选择行为无回退；F-006 全程只读，不修改数据库、路径、计划状态或目标平台。
