# F-003 最小计划持久化人工验收

## 准备与启动

1. 当前机器已从 V1 `runnerDb` 安全准备被 Git 忽略的本机计划数据库配置；日常无需执行 `export PLAN_DB_*`，不要展示 `.env.local` 内容。
2. 在项目根目录两个终端分别运行 `pnpm dev:b`、`pnpm dev:f`；确认后端先完成迁移再监听，终端不显示数据库连接值或密码。
3. 手工打开 `http://127.0.0.1:19000/plans/new`；验收结束后在两个终端分别按 `Ctrl+C`。

V1 `runnerDb` 连接变化时，维护者可执行一次 `make plan-db-config-sync V1_CONFIG=/path/to/V1/config.yaml` 刷新本机忽略配置。这不是日常启动步骤，命令不回显配置值，并保留现有 `TARGET_*`。

## 创建计划

1. 输入现场可用账号并验证，分别从“新发起”“已发”或“待发”选择一个流程；确认所选流程名称是候选区中看到的展示名称。
2. 填写计划名称，分别核对串行、并行 2～20 和可选未来定时启动的就地校验。
3. 点击“创建并选择路径”，确认按钮进入 loading 且不能连续提交；成功后进入 `/plans/{id}/paths`。
4. 临时断开数据库后重试同一次创建，确认表单不清空、不会显示成功；恢复数据库后再次提交，确认同一幂等键只得到一条计划。

## 继续配置入口

1. 核对计划名称、目标流程、发起账号、流程来源、运行方式、定时时间和“待配置”与创建时一致。
2. 页面必须明确显示“还没有选择执行路径，计划已经保存，可以稍后继续”，路径数量为 0。
3. 页面不得出现流程图、节点、伪路径、编辑、删除、运行或目标平台写操作。
4. 输入不存在的计划 ID，确认显示计划不存在并可返回测试计划。

## 测试计划列表

1. 返回 `/plans`，确认列表只显示 MySQL 中真实计划，不混入 F-001 静态示例。
2. 新计划显示真实计划名、流程名、账号、路径数量 0、运行方式、可选定时时间、“待配置”和“暂无运行记录”。
3. 按名称和状态筛选，核对匹配、清空、无结果；读取失败时应显示“重试”，不得回退 mock。
4. 刷新页面并重启前后端，确认同一计划仍存在；“继续配置”仍打开同一个 `/plans/{id}/paths`。

## 数据库与安全

1. 数据库服务上使用独立 `test_auto_pro_v2`；其中只有 `schema_migrations`、`test_plans`，没有 `execution_paths`。用户已明确授权直接删除该库内旧重构失败遗留的 21 张 `v2_*` 表，清理未做备份且不能由本项目恢复。
2. 核对 V1 `runnerDb` 原数据库及任何目标平台数据库没有新增或修改表。
3. 浏览器响应、存储和后端终端不得出现 `create_key`、数据库密码、DSN、SID、目标登录密码、AES key、code、customerCode 或 platformCode。

- [ ] 列表筛选、刷新与服务重启后的持久化通过。
- [ ] 继续配置摘要与无路径事实准确。
- [ ] 数据库隔离和敏感信息边界通过。
