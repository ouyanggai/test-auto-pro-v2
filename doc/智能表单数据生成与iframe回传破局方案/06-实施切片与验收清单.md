# 实施切片与验收清单

以下切片按项目 `AGENTS.md` 的门禁执行：一次只实施一个切片，用户批准后进入 implementing，自动验证后停在 ready_for_manual，不自动开始下一项。

## P0：契约基线与事实盘点

**目的**：零行为变化，先把“正确”定义成可回放的证据。

**范围**：

- 盘点 `Field`、`Constraint`、`DateRangeBinding`、`PathVueCustomFieldRule`、自定义 capability 的字段语义和值形态。
- 对 `requestPolicy.js` 做影子观测，按模板/组件统计 `ReadRequests` 覆盖率和可能漏判的写端点。
- 建立至少一条 FormMaking、至少一条 `vue_custom`、至少一个 JSON 字符串自定义组件、至少一个级联/表格、至少一个路径冲突的黄金样例。
- 冻结 `f007-form-runtime/v1` 的 golden JSON：load、setData、getValues、validateAndGetValues、restore、destroy、迟到响应和错误响应。

**建议文件/测试**：

- `internal/formdata/generator.go`（仅补语义注释或诊断，不改行为）
- `internal/service/path_form_solver.go`
- `form-runtime/src/runtime/protocol.js`
- `web/src/features/path-configuration/FormRuntimeFrame.vue`
- `test/unit/backend/` 生成器/求解矩阵
- `test/contracts/` iframe 消息契约
- `test/integration/` 真实规则目录与请求影子报告

**退出标准**：

- 八个现有操作符各有回放用例，当前 F-009/F-010 回归不变。
- 每条失败都能指出来源、字段、约束和阻塞等级。
- 影子报告证明清单覆盖率、空 `ReadRequests` 条目和漏判候选，未达到门槛不切默认拒绝。
- 所有 golden message 证明旧 session/request 的消息不会污染新表单。

## P1：统一 IR 与冲突解释

**目的**：解决“各自为政”，不替换现有结果路径。

**实现边界**：

- 在 `internal/formdata` 增加 IR 类型和编译器；复用现有 `Field`/`Constraint` 字段，不建立平行求解真相。
- 先实现数值区间、枚举集合、required/可编辑和日期绑定的传播。
- 字段依赖只接入静态可证明 DAG；环、动态脚本和未知比较方式进入 needs_attention。
- 现有 `solveTargetPathValues` 保留为有界回退，回退结果必须经过 IR 复验并带 `source=fallback`。

**建议文件**：

- `internal/formdata/constraint_ir.go`
- `internal/formdata/generator.go`
- `internal/service/path_form_solver.go`
- `internal/service/path_config_workspace.go`
- `internal/model/path_config.go`（问题结构若确有需要才扩展）

**验收**：

- `amount > 10000` 与 `amount < 5000` 返回区间空交集，而不是泛化“未找到”。
- `projectType=A → department 必填` 能缩小候选；循环依赖被阻断并说明原因。
- 选中分支成立、靠前分支不成立、兜底分支避开前置条件。
- 同 seed 同规则同候选得到字节级等价 JSON；换 seed 只替换生成器拥有字段。
- 既有计划/路径/批量准备回归全绿。

## P2：FormMaking 与 `vue_custom` 字段契约

**目的**：消除“宿主页面显示成功但回传缺字段”的静默风险。

**实现边界**：

- 为 Vue 字段显式记录 `valueShape`、`serialization`、候选来源、校验能力和证据。
- `HostVuePage` 对字段声明但实例树无法读写、字段路径歧义、深度超限返回结构化 partial/blocked。
- 自定义组件登记虚拟字段、回显和保存往返约束；外部对象候选继续按计划发起人隔离。
- FormMaking `getValues()` 与 Vue `capture()` 输出统一 values envelope，但不共享渲染代码。

**建议文件**：

- `internal/adapter/target/types.go`
- `internal/service/template_catalog.go`
- `internal/service/path_config_workspace.go`
- `form-runtime/src/HostVuePage.vue`
- `form-runtime/src/runtime/formTemplate.js`
- `test/contracts/f010_template_catalog_api_test.go`
- `test/unit/` Vue/组件值形态契约

**验收**：

- 真实 Vue 页面 15 个字段逐一 setData→capture 往返，缺字段不静默成功。
- `custome-info-select`、项目对象、流程列表分别验证 JSON 字符串、虚拟字段和真实候选。
- FormMaking 的级联完整路径、table/subform 行结构、附件/外部对象人工边界回放通过。

## P3：iframe 协议与只读请求清单

**目的**：确保回传完整 JSON，同时避免宿主读接口策略失控。

**实现边界**：

- 继续使用 `f007-form-runtime/v1`，非破坏性增加 `renderType/issues/ruleVersion` 诊断字段；破坏性变化才升版。
- 统一 `validateAndGetValues` payload，包含完整 values、生成/人工路径、validated、issues 和统计。
- requestPolicy 先影子再按规则目录清单默认拒绝；清单为空时显式 issue，保留过渡行为。
- 添加 SID 不入库、不入日志、不进 URL 的断言。

**建议文件**：

- `form-runtime/src/runtime/protocol.js`
- `form-runtime/src/App.vue`
- `form-runtime/src/runtime/formTemplate.js`
- `form-runtime/src/runtime/requestPolicy.js`
- `web/src/features/path-configuration/FormRuntimeFrame.vue`
- `internal/service/path_config_workspace.go`
- `test/contracts/` 与 `test/integration/`

**验收**：

- 表单保存前后 JSON 键、嵌套数组、JSON 字符串和虚拟字段完整一致。
- 旧 origin/source/session/request 的响应被拒绝；Abort/超时后迟到响应不回写。
- 目标只读 POST 可用，已知/影子发现的写端点均被阻断；清单未覆盖请求不会静默放行。
- 切换路径/账号/关闭工作区后 SID、storage facade、Vuex 会话均清理。

## P4：运行输入快照与目标适配预检

**目的**：让已确认表单真正能作为后续运行输入，但仍不执行目标写操作。

**实现边界**：

- 先用当前配置表中的完整 values、模板版本和修订号构造不可变 `RunInputSnapshot`，是否独立建表由真实运行记录需求决定。
- 在 `internal/adapter/target` 新增 FormMaking/Vue 提交体编译与预检接口；不在 iframe 转换。
- 基于 `VueCustomSubmitRule`、Java DTO 和 FormMaking 真实提交协议做字段映射；动态无法证明时 blocked。
- 运行前重读真实流程、模板、权限、候选和规则版本，失败则提示重新配置。

**建议文件**：

- `internal/model/` 运行输入模型
- `internal/adapter/target/` 目标请求编译器
- `internal/service/` 运行前预检服务
- `test/contracts/` 预检状态
- `test/integration/` 快照不可变性与 stale 阻断

**验收**：

- 配置值复制成运行输入后不可被后续编辑覆盖，历史运行输入可追溯。
- FormMaking、Vue custom 各有一条可编译和一条明确 blocked 的样例。
- 当前切片不发目标提交/审批/业务写请求。

## 明确不纳入本轮

- 不直接接入 LLM 生成表单值。
- 不为单个合同/采购模板写专用生成分支。
- 不把未知自定义组件降级为普通文本框。
- 不把路径配置行存在性当作完整可运行状态。
- 不把 iframe `getValues` 当作未经后端复验的目标提交体。
- 不自动进入真实流程执行、调度、运行记录或目标平台写接口切片。
