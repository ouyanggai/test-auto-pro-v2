# 统一可执行总体方案

## 1. 总体原则

### 1.1 四个权威不混淆

| 权威 | 负责什么 | 不负责什么 |
| --- | --- | --- |
| 规则目录 | 模板、Vue 页面、组件、候选来源、只读请求和版本事实 | 不扩大计划账号权限，不保存源码全文 |
| 生成/求解器 | 依据规则、路径、身份和真实候选产生可复现草稿 | 不宣称绕过运行时校验，不执行目标写操作 |
| 真实 iframe 运行时 | 按真实组件渲染、联动、权限和校验，返回完整值 | 不决定路径语义，不调用目标提交/审批/业务保存 |
| Go 后端 | 同一规则快照的最终复验、配置持久化和未来运行输入编译 | 不信任浏览器自报的“已校验”或“可执行” |

### 1.2 配置态与运行态分离

配置态保存的是用户可继续编辑的路径配置和已确认表单值；目标真实运行开始时才复制不可变输入快照。这样既满足“表单 JSON 作为后续运行数据”，又不会把配置阶段误变成目标平台业务写入。

## 2. 统一数据流

```text
计划账号 + 已保存路径
        │
        ▼
读取本地规则目录 ── stale/unknown/blocked? ── 是 ──► 需处理/阻断
        │否
        ▼
规则编译器
  ├─ UnifiedField：路径、值形态、权限、候选、校验、组件能力
  ├─ ConstraintIR：路径条件、模板校验、依赖、日期、组件约束
  └─ ReadRequestManifest：当前账号允许的目标只读端点
        │
        ▼
真实账号候选/身份/有限样本（按账号、flowCode、模板和规则版本隔离）
        │
        ▼
域构造 → 常量传播 → 可证明依赖传播 → 有界确定性回溯
        │                         │
        └──────────────► 同一 IR 路径复验
                                  │
                                  ▼
                         草稿 values + 问题 + 所有权
                                  │
                                  ▼
             iframe 真实 FormMaking / HostVuePage 回显与校验
                                  │
                validateAndGetValues：getData(true) + getValues()
                                  │
                                  ▼
              version/session/request 校验、clonePlain、完整 JSON
                                  │
                                  ▼
          Go 后端按规则快照复验 → 保存 form_values/config 元数据
                                  │
               未来启动时复制不可变 RunInputSnapshot
                                  │
                                  ▼
             target adapter 编译目标平台请求体（另一个运行切片）
```

## 3. 统一字段与约束契约

### 3.1 字段模型

不新增第二套字段真相；以 `internal/formdata.Field` 和 `PathVueCustomFieldRule` 为基础补齐缺失语义：

```text
UnifiedField {
  path, label, source(formmaking|vue_custom)
  valueShape(scalar|number|date|array|object|json_string|file_ref)
  required, readOnly, hidden, editable
  options / candidateSource / candidateVersion
  capability, collectionRoot, validationCapabilities
  evidence, status(complete|needs_attention|blocked)
}
```

要求：

- 路径只使用模板 `model` 或规则目录已证明的 Vue 字段路径，不按中文名称猜测。
- `json_string` 与对象/数组严格区分；自定义组件的 `value` 形态由 capability 决定。
- 外部对象的候选必须绑定计划发起账号；没有候选只能返回 partial/needs_attention，不伪造 ID。
- `required` 只表示“当前可编辑权限下必须有值”；隐藏/禁用字段不因生成器无法改写而被错误标为缺失。

### 3.2 约束 IR

建议先在 `internal/formdata` 内增加编译结构，而不是立即新建独立 solver 包：

```text
ConstraintIR {
  leftPath
  operator(eq|neq|gt|gte|lt|lte|contains|in|not_in)
  rightConstant | rightField
  origin(path_condition|template_validation|dependency|component|date_binding)
  group / selectedBranch
  valueShape
  explain { label, source, humanText, blocking }
}
```

编译来源：

1. `buildPathFormConditionProjection`：路径分支、前置分支、字段对字段比较。
2. `ParseTemplate` / `InventoryTemplateRules`：required、范围、选项、级联完整路径、脚本能力。
3. `VueCustomDependencyRule`：只纳入能从实际源码证明的字段赋值/联动。
4. capability 与 `ComponentCandidateCache`：值形态、候选来源、身份和外部对象边界。
5. `DateRangeBinding`：天数、起止日期和格式一致性。

## 4. 分层求解与冲突处理

### 4.1 求解顺序

1. **规则快照门禁**：规则不存在、stale、`unknown` 或 `blocked` 时不生成“可执行”结果；可保留安全部分值供用户处理。
2. **域构造**：默认值、真实静态选项、级联完整路径、当前身份、当前账号候选和稳定安全兜底值形成有限域。
3. **常量传播**：数值区间求交、枚举过滤、`required` 与 editable/readonly 交互；空域立即报冲突。
4. **可证明依赖传播**：只处理有向无环依赖，限制迭代次数并保证域单调收缩；循环依赖、动态脚本和无法证明的联动转为人工核对。
5. **有界回溯**：继续使用 `path_form_solver.go` 的 20000 次上限、最多 8 个条件变量和稳定 seed；结果标记 `source=fallback`，再由同一 IR 复验。
6. **完整路径复验**：验证命中所选分支、前置分支不误命中、兜底分支成立、字段权限/校验/日期/值形态成立。

### 4.2 结构化问题

每条问题至少包含：

```text
{ code, status(blocking|needs_attention|warning), source,
  fieldPath, fieldLabel, operator, expected, actual,
  relatedFields, message, canRetry }
```

示例：

- `amount`：路径条件要求 `>10000`，模板最大值 `≤5000`，常量区间为空，blocking。
- `projectObj`：当前账号没有真实候选，不能伪造业务对象，needs_attention。
- `items[0].name`：宿主 Vue 实例未暴露声明路径，回传缺失，blocking。
- `unknown-script`：动态脚本无法静态证明，要求人工核对，needs_attention。

页面只展示中文字段名和问题，不暴露字段内部 ID、策略 ID 或源码正文。

## 5. 两种表单运行边界

### FormMaking

- Go 侧递归解析模板，生成器只写入安全值。
- iframe 使用真实 `fm-generate-form`，不是主应用的 Naive UI 替代控件。
- `formTemplate.js/captureFormValues` 先调用 `getData(true)`，再调用 `getValues()`；保存对象必须是后者的完整深拷贝。
- 需保留子表单/表格行、级联完整数组、对象 JSON 字符串、虚拟字段和系统辅助字段。

### `vue_custom`

- 规则目录确认 `componentName/pageKey/fields` 后，iframe 的 `HostVuePage` 只加载 `hostVuePages.js` 已注册的真实组件。
- `setData`/`capture` 通过宿主组件状态树读写，深度和字段缺失必须可观测；不可静默丢弃。
- 保存前由宿主真实 `ElForm.validate` 校验；无法证明动态提交协议的页面不能标成可执行。
- 与 FormMaking 共享 UnifiedField/ConstraintIR/问题/所有权，但不共享渲染器和校验实现。

### 自定义组件六要素

每个 capability 必须声明：

1. `valueShape/serialization`
2. `candidateSource` 与账号权限边界
3. `validation` 与 required 方式
4. `playback`（如何回显）
5. `saveRoundTrip`（如何从 `getValues` 保存/恢复）
6. `virtualFields`（组件可能写入的辅助键）

## 6. iframe 完整 JSON 回传契约

保留当前 `f007-form-runtime/v1`，先做非破坏性扩展：

```json
{
  "version": "f007-form-runtime/v1",
  "sessionId": "uuid",
  "requestId": "uuid",
  "type": "result",
  "payload": {
    "values": {},
    "validated": true,
    "renderType": "formmaking",
    "generatedFieldPaths": [],
    "manualOverridePaths": [],
    "unsupported": [],
    "issues": [],
    "stats": {"autoFilled": 0, "manualPending": 0},
    "ruleVersion": "..."
  }
}
```

强制不变量：

- 父页检查 `event.origin`、`event.source`、版本、当前 session 和 pending request；iframe 同样检查父源。
- `requestId` 只消费一次；超时/Abort 后的响应丢弃。
- 切换账号、计划、路径或关闭工作区先发送 `destroy`，再清除 session、请求策略、storage facade、Vuex 和 SID。
- `clonePlain` 是唯一跨 iframe 边界复制方式，禁止把 Vue Proxy 或 `structuredClone` 代理错误带入请求。
- 后端不信任 iframe 自报 `validated`、`ruleVersion` 或字段类型；这些值只作诊断，最终按服务端当前快照重新计算。
- 协议只有在字段语义或消息类型不兼容时才升版，并提供版本协商失败的明确错误。

## 7. 只读请求与 SID

### 过渡策略

1. P0 对 `requestPolicy.js` 当前路径段词表做影子记录：请求路径、方法、规则条目、判定结果和组件来源，不记录业务正文；内网目标请求本身可保留 SID 查询参数用于链路排查。
2. 将 F-010 目录 `ReadRequests`、组件候选接口和实际运行日志汇总成按模板/组件的只读清单。
3. 清单覆盖率达到门槛后，切换为“清单优先、未知默认拒绝”；清单为空的存量条目暂保留旧启发式并生成 issue，不能静默全量阻断。
4. 已知写接口仍由显式拒绝规则和宿主按钮隐藏双重保护；不能只依赖名称词表。

### SID 生命周期

- Go `RuntimeSession` 只从已验证账号缓存取得短期 SID。
- SID 进入当前 iframe 的内存认证、storage facade，以及已授权目标请求的 URL、请求头和请求体，便于内网链路排查。
- 本轮不新增 SID 数据库字段或规则目录字段；会话销毁后清理内存认证、storage facade、Vuex 和请求策略。
- SID 失效时返回会话过期/只读请求失败，禁止自动降级为目标写请求；用户重新验证账号后创建新 session。

## 8. 后端保存与后续运行数据

### 配置保存

当前 `SaveForm` 保持：幂等键、表单修订号、`form_values` 完整对象、seed、生成/人工路径、sample summary、`form_template_version`、`form_validated` 和 `data_status`。保存流程固定为：

```text
请求版本/幂等核对
  → 规则目录 stale/blocked 核对
  → 值形状、可编辑权限、required、日期和路径条件复验
  → 乐观锁写入
  → 重读服务端事实返回
```

### 运行输入

未来真实运行切片开始时创建不可变 `RunInputSnapshot`：

```text
pathId, planId, sequenceNo, accountRef
formValues, renderType, templateRuleVersion, shapeDigest
pathChoices, node/action/person snapshot, createdAt
```

不包含 SID，不覆盖历史运行记录。`internal/adapter/target` 根据 FormMaking 的目标提交映射或 `VueCustomSubmitRule`/Java DTO 规则，把快照编译成目标请求体；动态、无法证明的协议必须在运行前阻断。iframe 永远不直接提交。

## 9. 可执行性判定

路径只有同时满足以下条件才允许进入未来运行预检：

- 路径拓扑仍能精确对应当前真实流程。
- 规则目录非 stale，模板渲染类型不是 unknown/blocked。
- 所有条件字段、必填字段和可编辑字段通过同一 IR 复验。
- 外部对象均来自当前账号真实候选，虚拟字段/值形态完整。
- iframe 真实运行时校验通过且完整 `getValues` 已保存。
- 后端按当前规则快照重读复验通过。
- 节点人员、动作和循环配置状态满足 F-008 约束。

任一不满足，状态为 `needs_attention` 或 `blocked`，显示第一条可操作原因，不能以“表单已保存”冒充“可运行”。
