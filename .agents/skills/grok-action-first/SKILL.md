# Grok 行动优先

## 目标

对已获授权的修改任务，在取得足够证据后立即完成一个最小原子修改并验证。项目 `AGENTS.md`、当前功能文档和用户指令始终优先；本技能只约束执行节奏，不扩大权限或范围。

## 开始工作

1. 先判断任务属于只读诊断/审查，还是已授权修改。只读任务保持只读；功能未批准、状态不允许实施或存在会改变结果的关键选择时，说明阻塞并等待用户。
2. 修改前用一句话写出本轮完成标准。大任务只选择第一个可独立验证的工作包，不把所有工作包同时纳入首轮上下文。
3. 首轮只读取完成当前原子修改必需的内容：`AGENTS.md`、`CONTEXT.md`、当前功能文档的相关章节、预计修改的源码及其最近测试。使用一次 `rg` 批量定位入口，避免逐文件漫游。
4. 不因任务文档很长而先做全仓审计。未影响当前原子修改的后续工作包、历史文档和旁支源码留到后续迭代。

## 循环中断规则

- 最多连续进行两轮纯读取/搜索工具调用。第二轮结束时必须形成一个可验证的修改假设。
- 第三轮必须执行首个最小文件修改；若仍不能安全修改，必须给出具体阻塞、缺少的证据或需要用户决定的问题并停止，不得继续用“再核对”“继续摸清”“先全面了解”等理由读取。
- 同一文件的同一区间不得在没有新错误、新测试结果或新调用链证据时重复读取。
- 每轮只维护四项执行账本：当前原子目标、已读关键文件、下一处修改、验证命令。不要重新规划整个任务。
- 用户在执行中追问为何还没改文件时，立即回答当前阻塞；如果没有真实阻塞，下一次工具调用必须是修改文件。

## 修改与验证

1. 先改能形成闭环的最小代码和对应测试，不先堆积跨工作包的半成品。
2. 修改后立即运行当前范围的定向测试或可执行验证；失败时围绕失败证据修正，不返回全仓重新分析。
3. 检查同一调用链内的同类问题，但不借机重构无关代码。
4. 验证通过后仅提交当前原子成果，提交说明使用中文。工作区已有其他改动时，只暂存本轮明确修改的文件。
5. 未完成全部工作包时，只报告当前原子成果，不把整个功能标记为完成或进入人工验收。

## 推荐调用

需要强制启用时，在 pi 中输入：

```text
/skill:grok-action-first 本轮只完成 <工作包或具体修改>，完成后运行 <定向验证>
```

任务描述必须指出单个工作包或具体文件范围。若用户给出完整大任务但没有指定顺序，默认从文档列出的第一个可独立验证工作包开始。
