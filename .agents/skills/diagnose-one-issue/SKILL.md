# 诊断单个问题

## 限定问题

1. 读取项目指令、当前功能文档和直接相关源码。
2. 写出预期、实际、最小复现条件和本次不调查的范围。
3. 保持只读；诊断不等于修复授权。

## 建立证据

1. 实际复现并保存完整错误信息，测试脚本放在根目录 `test/` 对应分类。
2. 沿调用链读取相关源码、配置与日志，不凭经验猜测接口行为。
3. 搜索完整错误信息并优先读取相关源码或官方文档。
4. 检查同一范围内的相似入口，确认影响是否局限。
5. 若第二次尝试仍失败，切换到不同诊断策略；第三次失败时列出三个独立根因假设并逐一验证。

## 输出

- 先给出最可能根因和直接证据。
- 说明受影响与不受影响的范围。
- 给出最小修复方向、风险和验证方法，但不直接实施。
- 只有缺少用户才能提供的信息或权限时，才报告阻塞。
